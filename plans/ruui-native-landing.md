# 如UI 桌面／手机落地路线

日期：2026-10-23。状态：建议稿，待拍板。

## 一个判断

如UI 库本身已经跨端就绪——它是纯如代码，只产出如观命令流、只收标准事件
（鼠标、文入、资源就绪、每帧）。真正的平台差异全部收在**如观宿主**里。
所以落地问题不是「改写如UI」，而是**给每个目标平台写一个如观宿主**。
宿主的实现契约在浏览器侧已有参考（`rulang/browser_runtime.js` 约 600 行），
照抄结构即可。

宿主必须实现的面（已有协议直接复用，不新造）：

1. 画布生命周期：`观 其 画布 宽 高 fps`、帧循环、关闭（帧补发契约照旧）。
2. 渲染：矩形／圆角矩形／文字／图／实心块／变换／裁剪／透明度。
3. 输入：按下／移动／松开（带坐标与按键）。
4. 文入协议：`入焦点／入更新／入失焦` 出，`组开始／组更新／组结束／字符／键按下／剪贴／退格／删除／回车` 回——SDL 的 text input、WebView 的 IME 均与此一一对应。
5. 测文：真实字体测量钩（三档设计：宿主实测＞注入字度表＞缺省）。
6. 资源：`图载／件载` 出，`就绪／失败` 回，配额照旧。

## 现状缺口（实测确认）

- C 后端在 generation 层拒绝如观：「普通命令行（含 C／JavaScript 编译）不提供如观画布宿主」。
- Node `--target js` 同样无如观宿主（generation.py:154）。
- HTML 宿主（app_builder.py）只挂 `mousedown/mousemove/mouseup`，
  **没有 touch 监听**——手机浏览器里滚屏部件基本不可用。
- 窗口缩放 → 画布尺寸 → 重排的回路只在「运行期主动改尺寸」方向通了
  （host 463 行），反向（用户拖窗口）没有进应用层。
- 如见是 Win32 原始部件范式，仅 Windows x64、仅 Python 解释器／C allow-native，
  不是如UI 的宿主候选，只留作底层逃生门。

## 宿主服务通道（如观升级；档/网/声/智 的总线）

目标：如UI（及任何如观应用）与宿主之间的**通用服务通讯层**，
宿主提供应用级服务：文件、网络、音视频、AI 等。先例：Flutter
platform channels、Tauri commands、小程序 wx.*。

**信封**：管道现成（帧流带命令出、事件注入送消息回），只需三个通用形状：

```
出: {type:'service_request',  服务:'档', 操作:'写', 参数:{...}, 号:N}
入: {type:'service_response', 号:N, 成:真, 值:...} 或 {成:假, 误:...}
推: {type:'service_event',    服务:'智', 事:'块', 数据:...}   ← 订阅式流
```

请求/响应管一次性服务（读写档、一次 HTTP）；事件管流式服务
（网络 chunk、AI token、播放进度）。出入两方向零新管道。
宿主可在建画布后推一条 `service_ad` 广告所供服务。

**分层**：信封归如观宿主契约（任何如观应用可用）；如UI 在通道上提供
类型化门面。服务目录用**注册表**：`档 取 (应用 其 服务 '档').`、
`应用 其 能 '网'`——`应用` 只新增 `服务`/`能` 两个固定成员，
**词表零增长**（服务名是字符串，服务各为带自有成员的形）。

**家法不变**：校验与配额全在库侧、宿主保持笨；无此服务则回调如实失败、
`能` 查询供应用按能力显隐功能；`--allow-net`/`--allow-fs` 分级沿用
`--allow-native` 哲学；对话框类操作天然用户授权。

**服务路线图**：

| 服务 | 内容 | 宿主实现 |
|---|---|---|
| 档 | 读写列除＋原生对话框 | Python fs／壳原生／手机沙箱，同一协议 |
| 网 | HTTP GET/POST、流式下载 | 浏览器 fetch 现成；壳走原生 |
| 声像 | 播放、录音、摄像头 | 浏览器 WebAudio/getUserMedia；壳差异最大，靠后 |
| 智 | AI 问答（流式 token） | Python 宿主接生成设施；壳由用户配 endpoint+key |

**档服务的具体设计**（通道的第一个实现）：

- **读＝零新协议**：`件 其 载 '存档/1.txt'`＋`件就绪`/`件失败` 回调
  今日已存在；壳只需把 `机 其 件目` 指向应用数据目录，
  `file_request` 在壳里落成真实读取。路径包含校验（拒绝对对路径与 `..`）
  与配额（≤64 MiB）白捡。浏览器端件目仍指嵌入式资产表，读档天然受限、语义诚实。
- **写/列/对话框＝通道上的服务**：`档 其 写 路径 文 追加? 遇成:`、
  `档 其 列 径 遇成:`、`档 其 开 遇成:`/`档 其 存 文 遇成:`，
  内部即 service_request/response。配额：文 ≤8 MiB，路径校验同件载。
- **浏览器降级**：无档服务 → 回调失败「浏览器宿主无档服务」。

相对「解锁标准库 IO」方案的收益：编译器零改动（`FORBIDDEN_NAMES`
原封不动，`件`/`录`/`件作成果` 等 CLI 词汇不进 GUI）；
不冒充同步签名；沙箱校验复用件载。

## 路线

### 桌面

**D1 · WebView 壳（最快出真东西，周级）**
`--target ui` 产物本就是自包含单文件。套系统 WebView：
Windows WebView2／macOS WKWebView／Linux WebKitGTK。
新增 `--target desktop`，产出可双击的分发目录或安装包。
壳的职责是两件：**开窗嵌 WebView**，以及**实现通道的服务端**
（档/网在壳里落成原生调用，见上节「宿主服务通道」）。

三壳的注入机制现成：WebView2 `AddHostObjectToScript`／
WKWebView `WKScriptMessageHandler`＋`evaluateJavaScript`／
WebKitGTK `register_script_message_handler`。

诚实的定位：壳里跑的**仍然是 JS 运行时**——启动要暖 WebView 引擎
（百毫秒级）、内存是 WebView 量级（百 MB 级）、Linux 上缺 webkit2gtk
要装。想要「单二进制、几十 MB 内存、无网页引擎」那是 D2 的目标，
D1 不替代它。但 D1 逼你提前解决与渲染无关的全部产品管线
（构建→分发→安装→签名），D2 做完时只换渲染器。

**D2 · SDL2 原生宿主（正路，是乘数）**
两步：
1. 给 C 目标定义如观宿主 ABI（vtable）：发出的 C 程序只调
   `ru_host_create／push_commands／poll_events／measure_text／load_resource／run_loop`，
   平台代码全在壳里。先在 generation.py 解锁如观（替换现在的硬拒绝）。
2. 写 SDL2 壳（约 1.5–2k 行 C）：窗口＋SDL_Renderer＋SDL_ttf（文字与测量）＋
   SDL_image（图）＋事件泵＋`SDL_StartTextInput`（IME 直接映射文入协议）＋剪贴板。

收益：单个二进制、无 Python／JS／WebView；同一壳重编译即得 Android 原生——
手机原生从工程问题降格为打包问题；顺带把 C 后端 FFI 的工作喂给自己吃。
最大的质量风险是字体：CJK 字体 5–15 MiB，需定策略（打包 Noto Sans SC 子集／
系统字体回退），且每端实测测文以保双端一致承诺。

**D3 · 如见路线：不投。** 范式不同、平台单一。

### 手机

**M1 · WebView 壳（Android 先行）**
复用 D1 产物。Android 端一个约百行的 WebViewActivity＋资产打包；
iOS 端 WKWebViewController（Swift 壳）。没有 Apple 开发者账号就没有 iOS 分发——
如实写进文档，不假装能绕开。
需要补：touch→pointer 事件（当前零监听）、安全区刘海、生命周期暂停帧循环、
返回键语义。WebView 的输入法与现有隐藏 input 桥兼容，须实测但风险低。

**M2 · SDL2 原生（D2 之后自然长出）**
SDL2 支持 Android NDK 与 iOS；壳代码复用 D2，剩签名、商店、平台脚手架。

### 协议补强（全宿主共享，先于 M1/D2 部分工作）

1. touch 事件为一等公民（带 pointerId 的多点）。
2. 窗口缩放 → 画布尺寸 → 应用重排（反向回路）。
3. 生命周期（前后台 → 停／复跑帧循环）。
4. 安全区 insets。

## 排序

1. D1（本周级）——立刻有可分发的桌面应用，验证全链。
2. 协议补强的 touch＋缩放（M1 与 D1 共用，先做）。
3. D2（关键路径）——C 如观 ABI＋SDL2 壳。
4. M1 Android WebView 壳；iOS 壳随文档交付。
5. M2 在 D2 稳定后启动。

## 不做的

- 不按平台重写如UI（它已是可移植的）。
- 不上 Electron（hello world 五十兆，与项目最小主义相悖）。
- 不用 Flutter／RN 互操作（自己握栈正是意义所在）。
- 不把如见扩成如UI 宿主。
