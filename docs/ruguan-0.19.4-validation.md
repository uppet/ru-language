# 弧与扇形小批验证：Ru 0.19.4／如书 0.8.4

日期：2026-10-14。基线提交 `fb4c9c2e3eaa2b8f9a3eb3fea02f1f1c7e57725b`。本批生产代码、示例、规范及测试冻结为 `140415199b5a7d52dde3a46daf924d4ce9f4369d`，树 `b6a9465dad7fe94df9a44b424c98b6d3d14aeacf`。待验报告已随冻结树建立；冻结后只补充本报告，不改生产文件。

## 本批契约

- 新增普通画布成员 `弧 横 纵 宽 高 始角 转角`／`扇形 横 纵 宽 高 始角 转角`，六参必需，返回空，不新增保留字。
- 外接框同现有椭圆，横纵为左上角，宽高非负；包括角度在内的六个参数均为绝对值不超过 100000 的有限数，不接受事实、空或句。零宽高沿用原生退化椭圆行为。
- 始角／转角均为弧度，零角在右；转角是带符号扫过量。局部正方向顺时针，负方向逆时针；负缩放镜像其屏幕方向。非圆椭圆使用原生参数角，并非几何极角。
- 零转角仍保留一条命令、消耗命令与字节预算，只不画像素；输入回调提交它也形成新的完整场景。绝对转角至少 2π 时只画一整圈，不取模归零、不重复叠画；整圈扇形无径线。
- 弧只描边，fill 在命令中固定为空串；部分扇形原生闭合至圆心，按当前 fill／stroke／line width 绘制，描边包括两半径。填充沿用 nonzero。没有逐点采样、扫线、路径 builder、折线或贝塞尔接口。
- 两端产生同一数据命令，保留原始 start／sweep；每条命令快照既有矩阵、裁剪及有效样式。alpha、背景、保存恢复、回调重置规则和所有执行／数据预算不变。
- 新指令经过 IPC 数值／颜色／变换／裁剪验证，主线程完整验证后绘制；历史导入与导出复用同一验证，恢复静态画面且不恢复回调。
- 同步唯一规范、四种导出提示词、如书／Emacs 成员提示及完全同源的披萨分份示例。未改 VS Code 扩展或打包流程。

## 真实 Chrome 验收

在同一冻结提交的云端 Linux Chromium，通过实际如书编辑器、Run／Save 控件、鼠标和键盘验证默认 Python 与显式 browser-js。界面显示如／规范 0.19.4、如书 0.8.4；初末 runtime／app／example 摘要完全一致，唯一工作树差异为本报告。

- 独立直接 Canvas 2D 参考的 61 个场景全部逐 RGBA 完全一致，每场比较 200 × 160 像素。涵盖正负扫角、跨零、负始角、±100000 始角、整圈／多圈／最大转角、零转角、空样式、零宽高、负缩放镜像、多重变换裁剪及随后普通矩形的状态恢复。
- 附加像素断言确认开放弧不填充中心／弦区，四分之一扇形有两条半径；整圈与多圈扇形没有内部径线，半透明色内部 alpha 始终为 128，没有重复叠画变深。零转角保留命令但无像素，退化尺寸等同原生 ellipse。
- 双后端实际 UI 探针各保存 16 条命令（其中 14 条曲线），仅剔除随机 canvas_id 后场景逐字相同。验证位置／全命名参数、颜色小写化、原始正负角度、整圈／多圈／零转角保留、镜像和裁剪快照、保存恢复以及后续矩形无状态泄漏。
- 完整同源披萨示例在两端各完成 8 个真实输入状态：初始 3／8，鼠标加到 4／8，方向左键回 3／8，0 清空，方向左键保持下界，8 选满，方向右键保持上界，鼠标减到 7／8。每个状态均通过实际 Save 下载，17 条命令（5 条曲线）逐字匹配；零份保留两个零转角命令，满份五个曲线均为整圈。代表性初始／零份／满份截图已视觉检查，无中心辐条。
- 负宽、句始角、事实转角、越界转角及未知半径命名参数五类错误各在两后端实际运行，10／10 显示正常定位诊断。每次错误后均独立执行恢复程序成功画出一弧一扇形，共 10／10 次恢复；最终恢复场景两端一致。
