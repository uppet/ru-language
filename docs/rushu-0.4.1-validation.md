# 如 0.16.1／如书 0.4.1 验证（2026-10-12）

## 问题与修复

浏览器编译原本将 `/__rushu_browser__/root.ru` 原样用作模块图键，共享编译器则用 `Path.resolve()` 生成根路径。Windows 会在规范化时补盘符并使用本地分隔符；因此同一个根 AST 被放入两个模块键、收集两次，同一生成函数编号也出现两次。在浏览器 ES module 的严格块作用域中，这会产生函数重复声明语法错误。

已用 Windows 路径解析模型重现；另外在 Linux 上以 `/__rushu_browser__/sub/../root.ru` 作为未规范化的等价键，也重现两个模块、重复函数及 Node ES module 的 `Identifier ... has already been declared`。本轮没有取得用户报错的原始源码，不将模拟复现描述为对其源码的直接验证。

修复只把浏览器的虚拟根路径预先规范化，与共享编译器保持同一键；不对函数列表做掩盖性去重，不改变如语言变量或函数重定义规则、闭包、导入或执行语义。源代码改动不涉及解释器、C／CLI Node.js 后端及标准库裁剪。
