# ru_notepad Markdown 双撤销：Mi／LLVM 候选

后续已完成[增量算法对照](notepad-incremental-2026-10-22.md)，在密核之上增加有界检查点与尾部复用。本文保留前一轮候选的原始结果。

候选保留现有 C 应用路径，以如言编写密扫描核，直接编译为 LLVM 机器码。本地真实 Windows 已通过原应用的 12 个 Markdown GUI 阶段，涵盖多行、1 MB 单长行与未闭合围栏各自的打开、插入、退格和双撤销；每阶段沿用原 30 秒门槛，双撤销的两次操作共用同一个计时窗口。逐项实测见 [summary.json](notepad-mi-undo-2026-10-22/summary.json)。

可运行目录为 `dist/ru-notepad-mi-undo-candidate`，保留 EXE 和三份 DLL 在一起即可运行。本轮没有替换 `S:\Apps\ru_notepad`，没有推送或发布候选；这是本地实验，并非正式完整产品验收。

## 基线与比较

原安装包是应用 `d964ea9`、编译器 `85c7821` 的预览，保留的 CI 记录显示：单长行双撤销在 30009.541 ms 时仍在 folding。该原失败记录未改写。本机原安装包已经能过原门槛，单长行双撤销约 17.49 s、未闭合围栏约 24.20 s，说明本机计时不能代替原 CI 机器验收。

最终普通／密模式对照使用同一应用补丁、当前如言工作树、LLVM 14.0.6 和相同 DLL。两份生成的 C 文本仅有一个事实值差异，密 LLVM IR 逐字节相同；源文件、清单、编译器输入和 DLL 哈希相同。唯一差异是选择普通 `喂入`，还是候选密消费者。因此结果反映启用这套消费者优化的成本变化，不是 LLVM 对 C 的独立性能比较。

比较保留全部 12 阶段，包括中性的或变慢的观察。它是同机单次完整进程对照，没有绑定 CPU、清理文件缓存或足够样本推算 p95／p99；不宣称所有 Markdown／所有机器具有相同倍率。

| 双撤销场景 | 普通路径 | 密模式候选 |
| --- | ---: | ---: |
| 多行 100 KB | 2.639 s | 2.644 s |
| 单长行 1 MB | 17.025 s | 3.356 s |
| 未闭合围栏 1 MB | 23.433 s | 14.595 s |

本次单长行耗时下降约 80.3%，未闭合围栏下降约 37.7%；多行双撤销基本相同。多行的插入和退格观察分别为 1.079 → 1.337 s、1.071 → 1.336 s，完整原始阶段值均保留在汇总中。

## 实现

- `borrow_ro_utf8` 是显式实验清单的输入合同：C／LLVM 桥保留已有不可变句的 GC 根，借用其 UTF-8 存储，内核长度与位置均为字节。借用入口本身不复制、不分配，普通算的绑定／调度仍可能分配。它可以在所属线程的同步如言回调中调用无调用／无 GC 的核；原 NativeMemory 桥的线程、重入和同根写入／关闭限制保持原合同。
- 单长行采用一般的重复 ASCII 段扫描。在前缀已满 32 字、首字符连续段或后缀状态已有充分信息时，批量更新精确计数，最后 11 个字符仍经原 `_字符` 维护小写滚动尾。CR、LF、`>`、反引号和非 ASCII 取保守路径。
- 已打开的围栏在新鲜物理行、无 CR carry、输出队列低于 59 项且父标题已确认时，可批量处理完整、不可能关闭围栏的 ASCII LF 行。潜在关闭行、CR、非 ASCII 和 `>` 在当前行之前停止；保留一次原 `_行` 的效果并合并等深非标题范围，最后按原 `_清行` 建立新状态。64 范围、1024 标量／块、既有字节读取、64 行原生发布和 UI 预算继续适用。
- 五个计算核均为普通如言源码，经通用密 IR 发射。C 仅承载原动态值应用和 ABI／所有权边界；没有手写 C Markdown 解析器，没有按固定样本内容替换结果，也没有 JIT。

普通 `喂入` 和原辅助函数保留作为独立 oracle。补丁可对固定 d964 基线干净应用；生成两份应用的事实值在 AST 中显式选择，源文件未被构建器重写。复现入口见[实验目录](../experiments/notepad_undo/README.md)。

## 验证与边界

WSL/Linux 和真实 Windows 的最终逐块对照均通过：56,529 次完整状态返回、324 次错误顺序／状态检查、8 次范围队列暂停；重复段核调用 72,618 次，围栏批核调用 2,158 次，其中 965 次实际返回可消费范围。对照覆盖 24 槽、折叠区间、保留的栈／标题／关闭标记别名、Unicode 宽度、CRLF 切分、潜在关闭围栏、空输入及修订回放，退出时 GC live 为零。Linux 的 C 对照另通过 UBSan。

新增不可变 UTF-8 套件两平台各 16/16，覆盖 C、直接 LLVM、C 调用方＋LLVM 核，包含真实 FFI 回调中的核失败、错误传播后再次成功调用、Unicode 字节偏移、错误输入、禁止双视图，以及无原生权限的 CLI 独立产物。相关既有密／NativeMemory 回归和三代自举结果记录在汇总；本轮三代自举两平台各 105/105、八项门限全真。密编译自身仍未移植到如言自举前端。

早期“整个应用直接 LLVM”的候选改善了单长行，但未闭合围栏双撤销仍在 30 秒超时；该失败保留在汇总中。最终候选采用 C 应用＋直接 LLVM 密核，以保留当前动态值路径的效率。

本轮未运行远端 CI、完整产品全部验收组或人工日常使用验收。原 CI 的失败状态仍有效，待发布代码后由原环境重新核验。先前 `mi-llvm-2026-10-22` 是接入不可变 UTF-8 前的快照；当前候选以本报告的输入校验值和二进制哈希为准。
