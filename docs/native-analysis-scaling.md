# 原生 ABI 分析：有限抽象域与按需精化

本文说明 `rulang/native_c.py` 的保守静态数据流和 `rulang/native_tiered.py` 的生产入口。当前为本地未发布候选；下面的算法和局部验证不是 Windows、LLVM 或完整 CI 已通过的声明。

这不是执行如程序。分析器遍历 AST，传播原生类型、函数、签名及可变对象的**抽象值**，保守合并分支并计算固定点，以决定需要生成哪些 C ABI 跳板。不会加载 DLL、调用用户原生函数，或执行任意如语言运算。没有新增语法、标准库接口或运行时缓存。

## 不以项目规模决定能否编译

- 移除固定全图 200000 表达式访问配额，仍如实统计访问量。
- 移除延迟回调全图 128 轮扫描和局部循环 128 轮门槛，以依赖队列及真正的抽象固定点结束。
- 移除通用可变所有者/函数候选的 128 个准入上限，以及编译器 ABI 组合/签名数量的 1024 配额。没有换成另一个更大的固定数。
- 数字、字符串的长字面量历史可合并为相应类别的抽象顶值；当前精度阈值 128 是保守宽化策略，不是拒绝正常数据集合的门槛。顶值不能被当作一个已知 ABI 类型名或调用约定。所有可达对象、函数和描述符构造器仍保留，不因宽化而丢失别名。

函数摘要最多 4096 条、表达式/块摘要合计最多 16384 条、纯字面量阵内容缓存最多 1024 条；这些容量只影响重复工作。依赖或传递调用足迹超过每份证明的容量时，不保存不完整摘要，或者保守订阅全部后续变化；不截短证明后继续命中，也不因此拒绝项目。

真实 ABI/运行时合同不因取消分析配额而改变：每个原生签名最多 64 个参数，回调槽仍为进程内最多 1024 个不重复使用的槽。后者不是可声明签名的数量。生成编号还须能由运行时对应的 C 整数类型表示。这些合同与静态分析工作量不同，不能静默放宽。

## 有限堆和调用上下文

旧方案把不断产生的新抽象对象身份带入下一轮调用上下文；即使程序的业务操作正常，循环内构造容器也可能制造新的身份，再制造新的环境和分配身份。单纯撤掉 128 错误会暴露这种无界增长。

新方案把可变容器映射到有限的 AST 分配点与调用路径。重访同一抽象分配点时只合并旧/新可能值，不重新制造身份，也不清空已经失效的对象。失去位置精度的阵仍单调保留全部可达别名；不以“新运行时对象”为由重置同一抽象所有者。

精细引擎的堆上下文是有限的同步调用路径，路径由调用点/函数 AST 对组成。活动函数检查在进入新上下文前执行：无法证明与原生描述符无关的递归仍拒绝，严格证明的纯标量自递归返回保守结果，不无限展开。源码的词法层级、AST、分配点及调用点有限，非私有函数作用域不再按可能不断变化的实际对象集合拆分；私有作用域所需的实参区分基于该有限所有者域。标量顶值、单调绑定和有限对象可达边确保每个状态只能增长到固定点。

这是实现不变量及反例测试支持的终止论证，不是机器核验的形式化证明。有限不等于小或线性：大量无环调用路径、精细上下文和实际 ABI 组合仍可能产生组合爆炸。后续若增加新抽象值、改变分配身份、局部绑定或合并规则，必须重新检查这些不变量。

## 粗粒度先行，必要时全新精细计划

生产 `Compiler` 通过 `build_native_c_plan` 使用两阶段策略；直接 `NativeCPlan` 保留为精细参考引擎。

1. 首阶段只使用当前调用点/函数 AST 对作为堆上下文。不同历史路径可能合并到同一所有者，减少真实大型项目中的重复分析；所有合并仍保守。
2. 每个签名构造点必须有唯一确切的返回/参数 ABI 形状。任意多个同形状参数阵都可接受，不设置数量门槛。若出现多个形状、未知 ABI 或静态拒绝，则精化。
3. 形状检查在参数笛卡尔积展开前执行，也用于最终晚期别名复核，避免先制造粗合并造成的巨量组合再决定精化。
4. 释放失败粗计划及循环引用后，从原 AST 创建**全新**精细计划。不能清空已污染对象、删除未知值或沿用粗阶段的不完整结果。
5. 实际内存/调用栈资源错误、诊断主动停止及用户取消不是精化信号，不能自动重试两倍工作。

粗计划成功依赖同一套作用、别名、捕获、递归和最终签名复核。精化改善假阳性，不把不确定当作安全。某些动态生成 ABI 或不支持的捕获变化仍会被精细引擎保守拒绝；本改动不承诺任意动态程序都可静态编译。

## 赋值与缓存的安全边界

赋值按运行时顺序分析接收者、索引/成员式“位”的实参、右侧值。先失效接收者旧内容，再保留新存入 RHS 的单调可达边：普通存储本身不应立即污染新 RHS，但后续未知读取、写入或逃逸必须继续追踪它。可达边变化推进所有者版本，进入摘要依赖与结构固定点见证，字面量重入不能截掉这些边。未知目的地则保守失效 RHS。

函数/表达式/语句块摘要保留首次读取版本、缺失名称与后续遮蔽、可变所有者、递归调用足迹及路径依赖。结束时的版本不能替换先读后写证据。依赖不完整时回到普通分析。模块级函数不扫描无关历史私有作用域，但实际读取和嵌套闭包的捕获检查不省略。

稳定块按至多三条语句分段，声明仍在整个正文上统一提升，执行/返回顺序不变。普通块按环境区分。只有 AST 严格限定为字面量及其一元/二元表达式的语句块，且抽象代数未变、依赖/私有读/调用足迹全部为空且完整、没有分配路径或返回值时，才可跨环境共享。**仅有空的版本变化证据不够**：同值的局部绑定写入也可能负责初始化新环境，因此任何绑定、名称读取、调用、容器、声明、控制流或返回语句都不进入该共享路径。此狭窄复用避免新鲜上下文令无关常量工作完全重复，不合并环境身份。

纯字面量阵仅共享不可变初始化内容，不共享运行时可变所有者。合并去重使用与原比较器一致的键；未知扩展值及嵌套候选回退到原有顺序比较器，不能为散列性能改变真假/数字或对象身份语义。

## 调度、取消与资源不足

延迟回调按函数 AST/捕获环境登记，依赖变化唤醒受影响任务；首次读取不稳定则重新入队。证据溢出的任务保守订阅全部变化，不能假设缺失部分无影响。队列清空且局部固定点稳定后，再复核所有已发现签名的参数阵与回调。

实际 `MemoryError` 或 `RecursionError` 明确报告宿主资源耗尽，未完成计划不能生成部分 ABI 跳板。取消继续向宿主传播，不吞掉或变成成功。操作系统直接杀进程可能来不及产生诊断；没有默认墙钟保证，也不以另一全局时间/对象/AST 数量门槛替代旧配额。外部构建系统仍可以取消或隔离资源，中止不算分析通过。

## 诊断与复现

`--profile-native-analysis` 为选择性诊断，不改变正常程序 stdout。schema 2 的 `step_limit` 为 `null`。总步数是两阶段实际访问之和，包括缓存命中、首次字面量元素访问及块摘要命中，不会把粗阶段失败工作隐藏。`stages` 逐阶段记录完成状态与成本，`refinement_reason` 记录是否精化；总时间包含释放失败计划的工作。

`tools/benchmark_native_analysis.py` 默认测量生产两阶段入口，在结构/代数固定点模式间用新进程交替配对；`--strategy full` 明确选择精细参考引擎。可选 `--diagnostic-step-limit` 只用于测试子进程的主动诊断停止，跨阶段累计，不修改生产行为。报告区分规划时间和跳板生成时间，进程峰值 RSS 覆盖整个 worker；解析和宿主 C 编译不计入这两段时间。不同配额、不同策略、不同源码的时间不能直接拼成加速比。

## 当前本地验证范围

冻结的赋值修复/两阶段版本在原始 `ru_notepad` cb0339c 输入上完成 main、app_i18n、app_markdown、app_ru、app_streaming、app_tabs 六入口。tabs 使用 474368 步，约20秒，77 签名/2 回调；六份生成跳板与旧精确参考逐字节一致。它们都完成粗阶段，未精化。43项真实解释器对照在精细引擎和生产入口均未发现静态错误接受，并经独立复核。原始机器记录留在私有交付包，不提交本机原始日志。

当前生产整合新增了闭合常量块共享；它尚须连同迁移后的语义/缓存反例重新进行全量验收。旧内部对象身份、私有作用域历史与已删除配额断言不再代表新设计的正确结果，但真实别名、错误来源、递归、缓存失效以及成本回退不能靠删除断言处理。Windows/LLVM、实际原生 C 构建和 GUI 验收仍以最终提交 CI 为准，Linux 跳过不算通过。
