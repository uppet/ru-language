# 如:密：本机类型与原生调用（如 0.21.2 开发版）

`密 取 外言 '如:密'.` 导入通用原生接口。它承载机器宽度类型、精确转换、受管理内存、DLL 绑定与同步回调，不改变如的 `数`，不新增语言关键字，也没有 `ffi.ru` 入口。

`见 取 外言 '如见'.` 导入另一个独立目录中的随附三方库。它用如:密组织 Win32 绑定，当前不属于如语言标准，也不是 `如:见` 或如观。两库都受同一个宿主权限边界约束。如:密保持通用原生适配边界；如见面向跨平台 GUI 的长期方向，当前只有 Win32 驱动，不能据此宣称 Linux、macOS 或 Android GUI 已受支持。完整语义以 [语言规范](../rulang/language-spec.md) 为准。

## 1. 先确定执行环境

稳定版如 0.20.0 只允许 **Windows x64 上的本地 Python 解释器** 执行原生调用。开发版 0.21.0 增加显式启用的 **Windows x64 C 原生后端**：如源码经 C 编译器生成独立 `.exe`，运行时不需要 Python 或 libffi。它仍依赖 Windows 系统库以及所调用的 DLL，不等于把全部系统依赖静态装进程序。

本页描述 0.21.2 开发接口，不代表该版本已发布或真实 Windows 验证已完成。64 位指针不意味着支持 Windows ARM64、32 位 Windows／Python、Linux、macOS 或 Android 原生执行。

```sh
# 任何受支持的开发宿主都可检查源码与导入图；不加载或执行 DLL
python3 ru check --target python example.ru

# 只在 Windows x64 的本地 Python 中，审阅后显式运行
py -3 ru run --allow-native example.ru

# 0.21.0：在开发宿主检查 C 原生签名；不执行源码，不需要 C 编译器
python3 ru check --target c --allow-native example.ru

# 0.21.0：使用面向 Windows x64 的 C 编译器构建，不自动运行
py -3 ru build --allow-native example.ru -o example.exe --emit-c example.c
```

- 原生能力默认关闭；C 构建须另行选择 `build --allow-native`，普通 `build` 不会因导入如:密而打开它。`run --allow-native` 必须写在源码文件名前；`run` 文件名后的内容是程序外参，不是权限开关。
- `check` 默认仍为 C 目标；`check --target python` 只解析、校验源码及静态导入，不执行模块顶层，不加载 DLL，不调用原生函数，不授予执行权限。检查通过不证明 ABI、DLL、导出符号或回调正确。
- `check --target c --allow-native` 进一步检查静态签名能否降为 C，但仍不加载 DLL、不执行用户代码、不验证真实 ABI。`check --target python` 不接受也不需要 `--allow-native`。
- 未显式启用的 C 目标，以及 Node.js 与 browser-js 目标，拒绝原生依赖，包括间接导入、函数内导入和不可达分支中的导入。JavaScript 没有对应的原生授权入口。
- 如书 Python 和 browser-js 均不能启用原生能力；在格内导入、修改源码或生成提示不能打开它。REPL 和生成后自动运行也不是原生能力入口。
- `--allow-native` 是一次明确的能力选择，**不是沙箱**。DLL 与当前进程具有相同真实权限，可以读写文件、联网、创建进程或产生其他系统副作用。错误 ABI、无效指针和错误生命周期可使整个进程崩溃或破坏内存，`试`／`救` 无法保证恢复。

只运行自己理解并信任的 DLL 和绑定。不要让模型自动开启原生权限，也不要把 `generate --run` 当作原生程序的执行方式。

### 从 C 源码到 Windows 程序

编译宿主与产物运行平台不同。在其他开发宿主做无执行检查或生成 C，不会开放该宿主的原生运行能力。原生 C 中的目标检查要求真正的 Windows x64 工具链与头文件／系统库；不能用 Linux 本机 `gcc`、伪造平台宏或换一个 `.exe` 后缀代替 Windows 目标。交叉编译时须自行提供合适的工具链，例如通过 `--cc` 指定，并显式给出 `.exe` 输出名；构建不会运行产物。

`--emit-c` 保存的文件包含如运行时、所需的原生支持和按签名生成的有类型调用／回调跳板，可用相同目标工具链独立复编，不依赖本仓库头文件。这里没有 Python 解释器、libffi、运行时 ABI 猜测或动态生成机器码。所调用 DLL 的名称、路径、导出名和实际参数仍可在运行时决定，必须遵守下面的加载与类型规则。

普通程序不导入原生依赖时，不会加入这套原生运行时及跳板；原有 C 裁剪与普通 OJ 例子的 64 KiB 源码预算继续单独检查。使用原生回调的 GUI 输出可能明显更大，不受该普通 OJ 预算约束，也不承诺任意程序都小于 64 KiB。

## 2. 机器类型与精确标量

以下成员返回不透明类型描述符，不是如语言的类型注解或用户形：

| 描述符 | 含义 |
| --- | --- |
| `i8` / `u8` | 8 位有符号／无符号整数 |
| `i16` / `u16` | 16 位有符号／无符号整数 |
| `i32` / `u32` | 32 位有符号／无符号整数 |
| `i64` / `u64` | 64 位有符号／无符号整数 |
| `intptr` / `uintptr` | 指针宽度的有符号／无符号整数，首版为 64 位 |
| `f32` / `f64` | 32 位／64 位浮点数 |
| `指针` | 不透明机器地址，不提供任意地址解引用 |
| `无值` | 仅用于无返回值函数签名 |

`描述符 其 值 输入` 做受检查的值转换。输入可为安全的如数、精确十进制句或已有原生标量；整数必须是整数且落在目标范围，不静默截断、绕回或饱和。事实、空和其他对象不会作为普通数字隐式转换。指针描述符另接受 `空` 生成空指针。`f32`／`f64` 接受有限数或原生数值，按目标浮点宽度舍入并拒绝非有限结果，不接受十进制句代替浮点输入，也不接受指针或携带资源所有权的原生整数作为浮点输入。

如数仍为有限 binary64。整数经如数传入时必须在 `-9007199254740991` 至 `9007199254740991` 内。超出此范围的整数应从十进制句构造，不能先写成数值字面量、经历浮点计算，再要求恢复原来的位。

```ru
密 取 外言 '如:密'.
无号长 取 密 其 u64.
大值 取 无号长 其 值 '18446744073709551615'.
显 大值 其 句.                         # 精确十进制，不经过如数
显 大值 其 位段 0 16.                  # 65535
```

原生标量成员：

- `其 数`：显式转回如数。整数若超出安全整数区间则拒绝，不以浮点近似返回句柄或地址。
- `其 句`：文本表示；原生整数及地址保留精确十进制值。
- `其 为空`：检查零值，返回事实；判断原生空地址时使用它，不把对象本身的真值当成地址非零。
- `其 位段 起 宽`：从整数／指针的机器位模式提取无符号位段，起位从最低位 0 计数，位宽为 1～53，结果能安全表示为如数。起位与位宽必须是有效整数，范围不得超出原宽度。

`目标描述符 其 重释 原生标量` 按同宽度位模式重释，只用于整数／指针，不进行算术数值转换，也不允许浮点位转换或跨宽度截断。它适合在指针宽度整数与地址之间传递句柄位模式；结果仍是不透明标量。

```ru
密 取 外言 '如:密'.
有号指宽 取 密 其 intptr.
指针型 取 密 其 指针.
负一 取 有号指宽 其 值 (-1).
特殊句柄 取 指针型 其 重释 负一.
显 特殊句柄 其 为空.                    # 假
```

上例只展示位模式，不把特殊句柄交给任何 API。每个 API 是否接受某个句柄，必须按其实际合同判断。

## 3. 结构与受管理内存

`密 其 结构 字段阵` 接受形如 `[['横', 类型], ['纵', 类型]]` 的字段阵，返回布局描述符。字段名为句、类型为描述符，按 Windows x64 原生布局计算大小、对齐和偏移，可嵌套结构。字段数为 1～128，字段名非空、不重复且不能以下划线开头；不能以 `无值` 作字段。它不是如的 `形`，也不暴露如对象的内存布局。

布局成员：

- `其 大小`、`其 对齐`：以字节表示
- `其 偏移 字段名`：指定字段的零起点字节偏移
- `其 新建`：分配对应的受管理内存

```ru
密 取 外言 '如:密'.
整型 取 密 其 i32.
点型 取 密 其 结构 [['横', 整型], ['纵', 整型]].
点 取 点型 其 新建.
点 其 写 '横' 12.
点 其 写 '纵' (-3).
横值 取 点 其 读 '横'.
显 横值 其 数.                         # 12
显 点型 其 偏移 '纵'.                    # 4
显 点 其 大小.                          # 8
点 其 关闭.
```

内存成员为 `读 字段名`、`写 字段名 值`、`地址`、`大小`、`关闭`，字符串内存另有有界的 `解UTF8`／`解UTF16`。结构字段按描述符读取为原生标量或嵌套结构内存，写入检查类型和范围。嵌套结构读取是锚定父内存的视图，不是深复制；关闭父内存会使该视图失效。写入嵌套结构要求同一个结构描述符。它不成为任意外部地址的读取入口。

`密 其 缓冲 字节数` 分配 1～16777216 字节（16 MiB）的受管理字节缓冲；结构及编码内存也受 16 MiB 上限约束，编码内存的终止零计入大小。`密 其 UTF8 文本` 与 `密 其 UTF16 文本` 分配有结尾零的编码内存，拒绝输入中已有 NUL。UTF-16 用 Windows 的 UTF-16LE。两个解码成员均无参数，严格解码到界内第一个 NUL；缺少界内终止零、无效编码或 UTF-16 字节数为奇数时报错。解码只在本库拥有的内存边界内进行，不沿外部指针寻找终止零；不要把 DLL 返回的指针当作可解码内存。

```ru
密 取 外言 '如:密'.
标题 取 密 其 UTF16 '你好，如'.
显 标题 其 解UTF16.
标题 其 关闭.
```

把受管理内存直接作为指针实参传入，或用其不透明地址。地址保留原内存／回调的所有权关联；重释不丢掉该关联，关闭资源后旧地址不能重新用于调用。调用期间实现保持实参及其所有权关联；原生 API 若保存地址，必须按 API 合同保持它存活，直到原生端不再使用，才能关闭。显式关闭后不得继续读写或传入原生调用。操作系统不会因为如变量仍存在而知道一个外部资源已经释放。

首版不提供结构按值传参／返回、任意地址读写、裸指针算术、用户对象内存布局或自动资源管理。结构通过指针参数传递。

## 4. DLL、签名与调用成果

`密 其 系统库 基名` 只从 Windows 系统目录 System32 加载 DLL，参数必须是基名，如 `'kernel32.dll'`，不能夹带目录。`密 其 动态库 绝对路径` 用显式绝对路径加载其他 DLL，不隐式搜索当前目录。不要把这项路径约束当作 DLL 本身可信的保证。

`密 其 签名 返回描述符 参数描述符阵 约定` 创建至多 64 个参数的固定参数签名。约定仅为 `'win64'` 或 `'cdecl'`；在当前 Windows x64 平台都受 x64 ABI 约束，不意味着支持 x86 栈约定或任意平台。`无值` 只能作返回描述符；结构只经指针传递，没有可变参数、COM 或 C++ 类 ABI。

`库 其 绑定 导出名 签名` 查找精确导出名，返回绑定函数；`函数 其 调用 实参数阵` 检查实参数量／类型后调用并返回成果。标量实参可为匹配的原生标量或受检查的安全数；指针位置只接受 `空`、原生指针标量、受管理内存或原生回调，不接受普通数值地址。把地址作为整数实参时，也须先用 `intptr`／`uintptr` 显式重释，不能把指针标量隐式传给整数位置。

```ru
密 取 外言 '如:密'.
系统 取 密 其 系统库 'kernel32.dll'.
无号整 取 密 其 u32.
签 取 密 其 签名 返回:无号整 参数:[] 约定:'win64'.
进程号 取 系统 其 绑定 'GetCurrentProcessId' 签.
成果 取 进程号 其 调用 [].
结果 取 成果 其 值.
显 结果 其 数.
```

成果成员：

- `其 值`：返回描述符对应的原生标量；无返回值签名则为空
- `其 错误码`：调用边界捕获的 Windows 错误码，类型为如数
- `其 回调错误`：无回调错误时为空，否则为错误说明句

错误码不是通用成功位。许多 API 在成功时不清除 last-error，也有 API 用返回值、HRESULT 或其他机制报告失败。必须按被绑定 API 的文档判断，不能把 `错误码 == 0` 当作统一成功条件。返回 `0` 的原生标量也不是如的 `空`。

`库 其 关闭` 使库和已有绑定函数不可再用，不主动卸载仍可能被原生端引用的 DLL。

绑定签名不会自动验证 DLL 的真实 C 声明。错误参数宽度、返回类型、结构布局或回调约定可以破坏进程；Python 异常处理或 C 回调错误边界不能把任意本机崩溃变成如成果。

### C 后端的静态签名子集（0.21.0）

C 后端必须在构建时列出有限的 ABI 形状，生成精确 C 函数类型及调用／回调跳板；它不是可在运行时接受任意新签名的通用 FFI。Python 原生入口的动态签名能力不能直接推广到 C。

- 返回和参数类型限本页列出的机器标量／指针描述符；`无值` 只能用于返回，结构只能通过指针传递。每个签名至多 64 个参数。
- 返回描述符、参数描述符阵及 `'win64'`／`'cdecl'` 约定必须能静态确定。直接声明、模块／类型／函数引用别名、`尽取`、命名实参、可追踪的包装函数与闭包，以及能收敛的分支／循环描述符数据流可以参与分析。
- 固定阵中的有限类型选择可以形成多个预生成形状；不是任意运行时计算都能追踪。签名参数阵在整个分析中须保持可证明不变，后续发现的回调／方法等修改也会保守拒绝，即使运行时曾先保存签名快照。来自外部输入的类型／约定、不能静态解析的传参，以及无法证明安全的可变容器／可调用对象逃逸会报编译错误。未调用函数与不可达分支也接受检查，不能把动态签名藏在其中。
- 原生分析允许可证明与 ABI 无关的纯标量直接自递归，例如阶乘，也可从按钮回调调用。这个子集只读取参数／局部标量，使用标量运算和直接自调用，不读取捕获值、不访问成员／容器、不调用其他函数，返回值须可证明为普通标量（数／事实／句）。其他无法证明与描述符无关的递归路径会报编译错误；未启用原生后端的普通 C 程序不受这些限制。
- 整个程序最多 1024 种不同 ABI 形状；单处有限参数类型组合最多 128 种，其他过于复杂或无法收束的静态分析也会报编译错误。不要依赖分析器执行如代码来计算签名。
- DLL 路径／名称、导出符号名、调用的实际数值及回调失败默认值仍按普通运行时规则求值；它们不要求字面量。静态检查通过不会预先加载 DLL 或核实导出声明。

上面的 `GetCurrentProcessId` 示例使用直接可确定签名，可用于两种原生入口。遇到“无法静态确定”诊断，应把 ABI 类型与参数阵写成可追踪声明，把运行时变化留在实参值或有限已声明签名的选择中；不要自动回退到 Python、libffi 或未经检查的 ABI 调用。

## 5. 同步回调与错误收束

`密 其 回调 签名 算 安全默认值` 创建原生回调。不接受 `作` 代替需要返回结果的 `算`。默认值在注册时按返回描述符检查，应是 API 能安全接受的失败结果；无值返回使用空，指针返回的失败默认值只能是空指针，避免关闭后返回失效地址。如算参数数目必须与签名一致。回调输入为对应的原生标量，返回值也按签名检查。 回调返回受管理内存／回调的非空地址时，其所有者保持到该回调关闭；每个回调最多保留 128 个不同返回资源，超限按回调错误处理。关闭前须确认原生端已不再使用这些返回地址。

`密 其 回调中` 是零参只读查询，返回当前所属执行线程是否仍在任何原生回调内；已逻辑关闭但尚未返回的回调也计入，正常返回或错误退出后恢复。它可供上层库拒绝不支持的重入操作。

回调只允许在创建它的所属执行线程上同步执行，并在可能被原生端调用期间固定保持。支持同步重入不意味着支持异步任务、外部线程回调或并发执行如代码。不得把回调交给会在不受控线程／稍后持续调用它的 API。

`回调 其 地址` 返回不透明地址；`回调 其 关闭` 结束其可用生命周期。必须先按原生 API 合同解除注册／销毁相关资源，再关闭回调，不能依靠退出局部作用域代替解除注册。已进入的同步回调可在关闭后完成标量／空返回；关闭中的回调若尝试返回拥有型非空指针，则按回调错误处理。关闭后保留不执行如代码的安全占位，不把已泄露的可执行地址释放为悬空地址；这不允许原生端继续使用其他已关闭资源。本进程最多创建 1024 个回调，已关闭的占位仍计入，达到上限需要重启进程。

如回调发生错误时，错误不穿过 C ABI 向外抛出：回调返回事先检查的安全默认值，首个回调错误记录到相关原生调用成果的 `回调错误`。这包括如错误、主动 `卒` 与返回值不符合签名；不意味着访问违规、栈损坏或 DLL 内部崩溃可被捕获。业务代码应在原生调用返回后检查回调错误。Python 与 C 都遵守这个收束合同，不自动重试回调或原生调用，也不回滚已经发生的副作用。

C 原生回调内不能首次初始化一个外言；应在第一次可能触发回调的原生调用之前导入并完成所需依赖的初始化。回调内重复导入已经成功初始化的模块仍可用。静态依赖图中已收集源码不等于模块顶层已经执行；未预先初始化的导入会被作为回调错误收束。此限制不把所有模块改成启动时自动导入。

阻塞式原生事件循环可能不会因一个失败返回值自行退出。可选的 `回调 其 失败时 原生绑定函数 实参数阵` 注册失败钩子；钩子必须是已绑定的原生函数和预先检查的参数，不是任意如代码。注册时浅复制实参数阵并保留资源引用；之后仍不得提前关闭这些资源。如见的 Win32 驱动用它调用 `PostQuitMessage`，让消息循环在回调失败后有机会返回并报告错误。该机制是通用库能力，不把 Windows 消息循环写进语言语法；也不保证任意阻塞函数都能被解除。

## 6. 与如见、生成器和验证的分工

- 如:密提供通用机器表示、布局、内存和调用能力；平台实现保持在适配边界，Win32 名称、常量、结构与消息循环留在独立的如见目录。其他平台驱动需要另行实现及验证，不从当前 Win32 驱动推定可用。
- 如见是随工具链分发的三方库，不因预装而成为语言标准；导入名精确为 `'如见'`。标准命名空间仍使用 `如:`，两种模块都不能被当前目录同名文件偷偷替换。
- 完整规范与提示导出会描述两库的存在以及权限边界。这只传输知识，不授予能力；如书导出的 Python 提示也不能启用原生调用。
- 原生相关代码先按目标用 `check --target python` 或 `check --target c --allow-native` 做无执行检查，再由使用者在受支持的本地环境审阅并显式运行／构建。不要生成自动授权、自动运行或把地址／64 位值经浮点来回传递的代码。
- 非 Windows 平台的契约测试可证明解析、边界检查及测试专用宿主中本地编译 C 夹具的通用 ABI 行为；这不开放 Linux 原生执行。真实 Windows DLL、Windows ABI、回调与窗口验证须在 Windows x64 上运行；便携夹具、模拟行为或静态检查不替代这项证据。
