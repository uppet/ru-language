## 验收入口

拉取 `wip` 后重新启动 `python3 -m rushu`（Windows 可用 `py -3 -m rushu`）。打开终端给出的完整本机地址，先看到模板起始页：

- 基础入门：问候与变量绑定，两格短例。
- 文本处理：去首尾空白与替换词语，两格短例。
- 如竞题解：扫描固定样本 `3 5` 并输出 `8`，不等待标准输入。
- 如观互动：点击移动圆点，画布获得焦点后按 `r` 清空。
- 如是我言生成：带末行标记的意图起点，源码为空；先配置提供方、明确生成，再审阅和运行。
- 空白如书：一个空代码格。首屏和新建对话框顶部均有直接新建空白入口。

起始页不创建后台内核；选择后创建普通书本与独立会话，但不会运行源码或请求模型。「新建」再次打开选择器，取消或 Escape 保留原书，选择后才确认未保存内容。无连接凭据时仍可本地创建、编辑、导出，运行与生成不可用。

## 生成等待标记

在同一冻结版本的真实 Chromium 中，固定 16px SVG 在等待期间旋转；跨越两次耗时计时器更新，状态文字、文字／SVG／格子节点身份保持一致，状态区零 DOM 变动、矩形布局不变，而实际 transform 改变。390px 视口同样无布局变化。开启 `prefers-reduced-motion: reduce` 后 animation 为 none；成功、失败、取消、再次生成与切换书本均停止或清除标记。全程仅模拟提供方，零页面错误。

## 复跑

常规回归：

```sh
python3 -m unittest discover -s tests -v
node --test rushu/tests/*.mjs
make examples
make examples-js
```

真浏览器测试需已有 Playwright 与 Chromium，并在另一个终端启动本机如书服务。将终端给出的完整地址传入 `RUSHU_QA_URL`：

```sh
RUSHU_QA_URL='http://127.0.0.1:端口/#token=启动凭据' \
CHROMIUM_PATH='/path/to/chromium' \
node rushu/tests/start-templates-browser.cjs
# 同样的环境变量可运行纯模拟生成状态测试：
# node rushu/tests/generation-animation-browser.cjs
```

该脚本只操作专用测试页和新建书本，无真实模型请求。截图与导出默认写入系统临时目录 `rushu-start-template-qa`，可用 `RUSHU_QA_DIR` 覆盖。

Windows 控制台专属项需相应平台；本机未安装 Emacs，未运行 ERT。Node 中四个可选 renderer 测试需要对应浏览器环境，实际页面端到端另行执行。远端 CI 应按发布的精确 SHA 另查，不能用本机成功代替 CI 通过。
