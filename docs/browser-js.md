# 如书浏览器 JS 执行

如书 0.8.6／如 0.19.6 的代码格默认仍用 Python。显式勾选「JS 加速」后，如源码在本机服务中检查、编译为 JavaScript，再在当前浏览器新建的专用 Worker 中执行。Canvas 仍由页面绘制；逐帧计算和如观回调走 Worker 消息，不绕回 Python 求值。

这不是如自己实现的机器码 JIT。如负责 AST 到 JavaScript 的编译，浏览器引擎自行解释、优化或 JIT 执行生成代码。实际速度受源码、浏览器、CPU、画布尺寸、字体和页面负载影响，不能仅凭使用了 JavaScript 宣称达到 60 FPS。

## 选择与状态

- Python 格共用原有持久会话，已有普通格及旧书本保持这个默认。书本格式仍为版本 1，代码格可保存 `execution_backend: "browser-js"`；请用如书 0.4.0 或更新版本打开含 JS 格的书本，旧版本可能忽略此选择并按 Python 执行。
- 每次 JS 运行都创建新 Worker。JS 格不读取、不修改 Python 格变量，也不继承其他 JS 格的变量；重跑本格亦从零开始。请把所有导入、数组、初始化、画布和回调放在同一格。
- 切换执行方式不会自动执行源码。停止、重跑、切换书本、重启和离开页面会失效旧 Worker；保存的画面只是静态快照，不保留回调或运行变量。
- 「复制输入」复制本格实际源码文本，不包含输出、生成意图、历史版本或后台编译产物。
- 学习格生成请求按显式执行方式携带对应宿主说明；browser-js 返回源码还经过同一浏览器编译器的能力检查，失败会显示检查错误并保留源码供修改。检查只编译并丢弃产物，不执行源码；通过不代表运行或安全验证。Python 仍为默认生成目标，只做语法／结构检查。生成与恢复历史均不执行。
- 给其他 LLM 导出对应提示词时，用 `python3 ru rushu-prompt --target browser-js` 或 `python3 ru ruguan-prompt --target browser-js`。这与 CLI 构建的 `--target js` 不同，见 [提示词导出](prompt-export.md)。

## 目标区别

1. 如书 Python：原解释器与完整会话功能；如观请求帧率为 1～30。
2. 如书 browser-js：独立 Worker，支持如观请求帧率 1～60，页面用 requestAnimationFrame 调度且一次仅派发一个回调。请求帧率是上限，不是实测帧率保证。
3. CLI `ru build --target js`／`ru generate --target js`：独立 Node.js／CommonJS 产物，仍拒绝标准如观导入；不会打开浏览器，也不获得如书画布宿主。
4. CLI C 目标及普通 CLI 解释运行：如观限制不变。

browser-js 是明确选择的浏览器能力子集，不提供文件 I/O、网络、交互输入或命令行访问。不支持的能力明确报错，不会偷偷退回 Python。普通数学、文本、阵、典、闭包以及如观接口沿用语言规范。模块支持以本机编译器检查结果为准。

## 保护边界

Worker 提供可终止的执行边界：外层初始化限时 5 秒、每次回调 1 秒；编译产物最多 4 MiB、每批消息 1 MiB／128 事件、Worker 全生命周期文本输出 1 MiB、输入等待队列 32 项。编译器还插入每次执行最多 500000 步的语句／循环计数（不同于 Python 跟踪行），单次文本输出最多 256 KiB。宿主另限制图形命令数和帧大小；页面丢弃旧运行标识的消息。大画布和静态快照仍受现有容量限制。输出／书本／像素容量限制各自独立，不等于进程内存限制。

本机编译请求并发最多 2 个、源码最多 200000 字符、AST 最多 20000 节点，并处理过深递归；编译阶段没有独立子进程的墙钟时间硬中断。Worker 的超时终止也受浏览器调度影响，不构成绝对实时承诺。

浏览器没有可以强制施加到这个 Worker 的 64 MiB 堆内存配额。Python 的 64 MiB 回调新增分配检查、500000 跟踪行与平台地址空间限制不适用于 JS；不可把它们写成 JS 保证。快速分配大量内存仍可能影响标签页或浏览器进程。Worker、CSP、语言能力检查和超时保护不是不可信代码安全沙箱；请审阅陌生源码后再运行。

## 示例与验证

直接打开 [JS 太阳系示例书](../rushu/examples/solar-system-browser-js.rushu.json)，或使用 [自然数学太阳系](../rushu/examples/ruguan/solar-system-math.ru) 在一格内使用真实如数学库、数组与循环计算轨道；把帧率改为 60 并显式选择 JS，可验证新路径。Python 运行时保持不超过 30。比较原生 Canvas 时，应使用同一场景、画布 backing 尺寸与 CSS 尺寸、相同文本与交互、同机同浏览器，并分别记录初始化、回调／消息成本和实际绘制提交间隔。绘制提交 FPS 不是显示器实际呈现 FPS。

本轮同机完整太阳系两次 60 FPS 请求实测为 57.57～57.86 提交 FPS，原生 JS 同场景约 60.00；接近原生但不保证稳定 60。见 [验证与性能数据](rushu-0.4.0-validation.md)。

## Windows 函数重复声明修复（0.16.1）

如书 0.4.1 将浏览器编译的虚拟根路径先规范化，再放入模块图；避免 Windows 加上盘符及本地分隔符后，同一根源码被当成两个模块并重复生成函数。此修复不改变变量、命名函数或匿名闭包规则，也不改变 CLI C／Node.js 后端及其产物体积。见 [修复验证记录](rushu-0.4.1-validation.md)。

## 输入中断与旧运行清理

0.18.1／如书 0.6.1 对 Python 与 browser-js 使用同一图形输入生命周期：拖出画布后释放、失焦、指针取消与标签页隐藏都会清理已接收的按下状态；隐藏时按顺序保留有界的释放事件，恢复可见后交付。停止、重跑或销毁则丢弃旧运行的输入，不再执行其回调。只使用已有 `鼠标松开`／`松键`，详见 [图形输入规则](ruguan-guide.md)。

## 原生形状、变换与裁剪（0.19.0／如书 0.8.0）

Python 与 browser-js 都支持三角形、多边形、六参数仿射变换、保存／恢复与矩形裁剪；两端采用相同的数字、栈深、裁剪数及帧大小限额。具体矩阵顺序、每回调状态重置、样式持久化、背景与鼠标语义以[如观指南](ruguan-guide.md)及随附完整规范为准。浏览器逐形状恢复其状态快照，不把前一个形状的变换或裁剪泄漏到后一个形状。旧快照无新增字段时仍可显示。

打开 [形状、变换与裁剪示例书](../rushu/examples/transform-shapes.rushu.json)，直接运行默认 Python，或勾选「JS 加速」后重新运行同一格；每次只有当前格的一个活动画布。示例帧率为 20，适合两种后端，不代表实测性能保证。

## 透明度与颜色（0.19.1／如书 0.8.1）

Python 与 browser-js 同样接受 `#RRGGBB`／`#RRGGBBAA`；模块函数 `观 其 颜色 红 绿 蓝 不透明度` 接受四个必需的 0～255 有限整数，返回小写八位色值。背景清除旧命令／像素后在透明底绘指定色，忽略变换和裁剪并保留状态；逐帧完整重绘，不保留上一帧像素。运行[透明叠色示例书](../rushu/examples/alpha-colors.rushu.json)时可切换两种后端；参数、空样式及拖尾边界见[如观指南](ruguan-guide.md)。

## 文字对齐（0.19.2／如书 0.8.2）

两后端同样接受 `图 其 文字对齐 横向:'中' 纵向:'中'.`，参数均必需，横向仅为左／中／右，纵向仅为上／中／下／基线。默认左上，设置跨回调保留并纳入保存／恢复；文字命令冻结设置，实际绘制由同一 Canvas 页面完成。缺少新字段的历史按左上显示，不恢复交互。中部依据字体 em 方框；不同机器的默认字体可能不同，不承诺字形像素一致。见[文字对齐示例书](../rushu/examples/text-alignment.rushu.json)与[完整指南](ruguan-guide.md)。

## 真实时间（0.19.3／如书 0.8.3）

`经过秒`／`间隔秒` 是两后端一致的无参数只读数值成员。Python 采用宿主单调钟，browser-js 采用独立 Worker 的 `performance.now()`；不接收页面事件提供的时间数值。同一次回调冻结读取值，执行预算继续使用独立实时时钟或步数检查，不会随快照暂停。

经过秒从创建画布起计时，包含显式暂停及隐藏页间隔。帧间隔只在帧回调表示与上一实际帧开始的间隔；第一帧和暂停后首帧为 0，输入回调为 0 且不改变上一帧时间。隐藏恢复保留实际 gap，不补帧也不截断；目标 FPS 只影响调度，不能推导实际秒数。不同平台在系统休眠期间的单调钟行为可能不同，不保证物理墙钟休眠时长一致。见[示例书](../rushu/examples/elapsed-time.rushu.json)与[完整指南](ruguan-guide.md)。

实现测试与嵌入宿主可通过私有 `now_seconds`（Python）或 `nowSeconds`（browser 编译模块）注入单调钟，以进行可重复验证；这不是如语言公开成员，也不读取事件中的时间字段。直接加载 browser 编译模块而没有私有注入时，使用所在平台的 `performance.now()/1000`（包括 Node 测试）；平台缺少该时钟时给出友好错误，不回退为帧数或 `Date.now()`。这条测试／嵌入路径不会让 CLI Node.js 编译目标获得图形能力，原有拒绝规则仍然成立。

## 弧与扇形（0.19.4／如书 0.8.4）

两后端共用 `弧 横 纵 宽 高 始角 转角`／`扇形 横 纵 宽 高 始角 转角`，六参必需，返回空。外接框与椭圆一致；始角和带符号转角为弧度，在未镜像的局部屏幕坐标中正转角顺时针。非圆椭圆使用参数角，负缩放镜像整个形状。弧只描边，部分扇形描边含两条半径；绝对转角达到一周时只画一整圈、无中心辐条，零转角没有像素但仍保留命令并计入预算。

每条命令冻结样式、透明颜色、矩阵和裁剪；零宽高沿用原生退化路径，2048 条／约 256 KiB 帧预算不变。保存书本只重放静态画面，不恢复交互；旧快照继续兼容。具体数值、空样式及角度语义见[如观指南](ruguan-guide.md)。[披萨分份示例书](../rushu/examples/pizza-portions.rushu.json)在一格内包含全部导入、共享状态与输入回调，可直接切换 Python／JS 加速，没有逐帧动画，也不需要外部依赖。

## 折线（0.19.5／如书 0.8.5）

两后端共用普通成员 `图 其 折线 点阵`，唯一必需参数支持位置或 `点阵:` 调用，返回空。点阵是包含 2～256 个 `[横, 纵]` 的如阵，坐标均为绝对值不超过 100000 的有限数；拒绝事实、空与其他类型。重复或全部重合的点合法。整条开放路径只描边一次，不闭合、不填充，半透明折点不逐段叠色；封闭填充区域继续使用 `多边形`。提交时深复制顶点及当时的描边、线宽、矩阵和裁剪，忽略填色但保留填色状态。无描边或零长度命令仍计入既有 2048 条／约 256 KiB 帧预算。

运行[一周气温示例书](../rushu/examples/weekly-temperature.rushu.json)，点击选一天、用按钮或方向键改数值，按 r 复原。Python 和显式「JS 加速」运行同一格，无持续动画。完整边界见[如观指南](ruguan-guide.md)；本版不新增二次贝塞尔、路径构造器或文字测量。

## 贝塞尔（0.19.6／如书 0.8.6）

两后端共用普通成员 `图 其 贝塞尔 起横 起纵 控一横 控一纵 控二横 控二纵 终横 终纵`，八参全必需、支持全位置或全命名调用，返回空。单段三次曲线经过起终点，控制点不必经过；坐标均为绝对值不超过 100000 的有限数，拒绝事实、空等其他类型。原生 `moveTo` 加 `bezierCurveTo`，只描边一次，不闭合、不填充，保留当前填色。重合或共线点沿用原生退化行为，无描边也保留一条命令并计入既有 2048 条／约 256 KiB 预算。

坐标、透明描边、线宽、矩阵与裁剪在提交时深复制为快照；后续状态变更不移动已提交曲线，保存书本只重放静态画面。运行[弯弯小桥示例书](../rushu/examples/curved-bridge.rushu.json)，按钮或 1／2 选控制点，方向键移动、图内点击定位、r 复原。默认 Python 与显式「JS 加速」运行逐字相同的源码，无持续动画。完整边界见[如观指南](ruguan-guide.md)；二次贝塞尔、通用路径构造器、查询和文字测量仍不提供。
