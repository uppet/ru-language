# 2026-11-03：分析、字符串与字带改进

本轮基于 `b93b23dd545e5e392544b4c411db30e9c2d7d15a`。保留现有语法、字符索引单位和普通值共享语义，不改变应用编译器 pin 或普通记录默认布局。

## 原生签名分析

增加 `check/build --native-analysis`，在标准错误输出耗时、步数、模块／函数分布及既有摘要缓存命中次数；失败也保存已累计统计。复杂度错误明确当前位置只是停止处。

固定点检查由反复构造全图结构快照改为已有变化代数的“未变”判据；允许保守地多迭代，不忽略依赖。既有摘要缓存、递归约束、候选值和默认 200000 步保护不放宽。对照工具的额外诊断预算只作用于独立测量进程，不改变产品默认值。详见[复现说明](native-analysis-performance.md)。

## 长字符串顺序切片

UTF-8 字节长度达到 1024 的不可变句，才在存储尾部附加字符数和单一顺序游标；短句保留对象及存储尺寸。元数据通过 `memcpy` 读写，不要求尾部对齐；字符数惰性计算，ASCII 直接定位，Unicode 顺序访问沿游标推进。

保留边界、码点索引与别名语义。完整运行时包含缓存；裁剪产物只在切片路径可达时启用。仅单字符索引或量查询的裁剪产物仍使用原扫描。随机、逆序和多个别名交错访问不保证同样收益。既有 P1010 的 50000 字节、词频例的 65536 字节门槛及历史 Mi 产物摘要不改写。

复现工具为 `tools/benchmark_string_slices.py` 和 `tools/benchmark_string_storage.py`，分别保存生成 C、运行时摘要、独立进程时间、RSS 和输出；计时不作为机器相关单元测试门槛。

## 字带：拥有存储的字节容器

新增[如:字带](byte-buffer.md)，形名为 `字带`。字带是可读写、可扩容的字节容器，内部复用 `NativeMemory`，每字节占一个原生字节，不是普通值阵包装。提供长度、容量、追加、界内读写、扩容、改长、独立快照和共享关闭状态；单块上限为 16 MiB。

底层 `读字节`、`写字节`、重叠安全的 `复制到` 只接受无结构、无父视图的拥有缓冲，检查两侧边界、关闭状态和写入目标的只读借用。扩容先分配、复制成功，再切换拥有者并关闭旧拥有者。库不暴露裸地址或借用视图；快照为普通数阵副本，不宣称零拷贝。

沿用 `--allow-native` 和 Windows x64 支持边界，不开放浏览器／Node 或 Python LLVM 原生能力。Linux 测试适配器验证内存机制，不代替真实 Windows ABI 验收。

## 紧凑记录对照

[实验](../experiments/record_layout/README.md)对比同算法的普通形对象阵和真实连续存储，涵盖四个 u8 字段扫描及三个 u32 字段稳定归并排序。完整输出分别由独立整数公式和 Python 稳定排序 oracle 验算。记录范围受限，不等价于一般动态记录语义。

存储更紧凑不自动消除成员分派、边界检查和编解码成本。本轮不改变普通记录默认表示；性能结论须以独立测量样本为准，不将负载字节数当作端到端提速。
