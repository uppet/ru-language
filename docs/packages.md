# 包与具名模块（如 0.22.0）

包把文件组织成有正式名字的模块，依赖来源写在静态 `集录.ru`。旧脚本仍可用字符串文件路径；标准库继续写 `外言 '如:数学'`。完整合同见[规范第 9 节](../rulang/language-spec.md#9-模块包与程序入口)。本功能随 `main` 上的如 0.22.0 提供，安装与更新见[稳定入口](stable-entry.md)。

## 一个可运行的本地例子

仓库随附 `examples/packages/工程` 与 `examples/packages/应用`：

```sh
python3 ru run examples/packages/应用/main.ru
python3 ru check examples/packages/应用/main.ru
python3 ru build examples/packages/应用/main.ru -o bin/packages
python3 ru build examples/packages/应用/main.ru --target js -o dist/packages.js
```

三个运行目标输出 `6`、`1`、`20` 各一行。第二行证明具名导入和文件路径导入共享同一计数状态。

工程包的清单：

```text
典:
    '名' 对 '工程'.
    '版' 对 '1.0.0'.
    '需如言' 对 '>=0.22.0 <1.0.0'.
    '公开' 对 ['力学', '流体/管道'].
成.
```

默认源码根为 `src`，所以公开文件分别是 `src/力学.ru`、`src/流体/管道.ru`。也可用已讨论的显式写法：

```text
'公开' 对 典:
    '力学' 对 'src/力学.ru'.
    '流体/管道' 对 'src/流体/管道.ru'.
成.
```

显式路径始终相对集录所在目录。清单只有 `名` 必填，版缺省 `0.0.0`，公开和依赖缺省为空；正式发布应明确写出版本。顶层只接受 `名`、`版`、`需如言`、`源码根`、`公开`、`依赖`。不运行清单中的代码，也不允许计算字段值。

模块文件可声明自己的正式名：

```ru
吾 言 工程 其 力学.
算 动量 质量 速度: 得 质量 * 速度. 法.
```

应用清单把工程包取别名为“物理”：

```text
典:
    '名' 对 '应用'.
    '依赖' 对 典: '物理' 对 典: '路径' 对 '../工程'. 成. 成.
成.
```

```ru
力 取 外言 物理 其 力学.
显 力 其 动量 2 3.
```

作者仍声明 `工程 其 力学`，不用随消费者别名改源码。声明可省略以兼容旧文件；一旦写出就必须匹配正式名。极少数旧调用若完整写成 `吾 言 工程.`，会优先视为声明；可写 `吾 (言) 工程.` 保持原调用。`吾`、`言` 仍可用于其他普通名称。静态模块名中的整条 `其` 链都属于名字；若不先赋值，访问成员时需括号：`(外言 物理 其 力学) 其 动量 2 3`。

## 依赖来源与显式同步

本地相对路径以写下依赖的集录为基准，也支持当前宿主的显式绝对目录。绝对路径按原样使用并标为不可搬迁，不猜测其他机器的盘符或替代位置；异平台路径写法不能在本机假装成为相对目录。纯本地包无需先同步即可运行；可使用以下命令记录当前依赖图：

```sh
python3 ru deps sync examples/packages/应用
```

远程来源在依赖描述中互斥，不提供“找不到就换来源”的 fallback：

```text
'工程' 对 典:
    'Git' 对 'https://example.org/team/engineering.git'.
    '引用' 对 'v1.0.0'.
    '子目录' 对 'packages/工程'.
成.
```

Git 支持 HTTPS 与 SSH 仓库，引用可以是分支、标签或完整 commit，缺省 HEAD；子目录缺省仓库根。使用已有的安全 SSH 认证环境，不写密码、token 或私钥；交互认证失败时会明确报错，不静默提示或运行自定义 Git hook。

```text
'工程' 对 典:
    '目录' 对 'https://example.org/ru'.
    '包' 对 '工程'.
    '版' 对 '>=1.0.0 <2.0.0'.
成.
```

示例 URL 仅说明协议，没有默认线上目录。版本支持三段 exact 或空格分隔的比较区间交集，拒绝 `^`、`~`、通配符、预发行和逻辑或。同一真实来源包在一个图中只选择一个版本，冲突报错。

只有显式获取命令才可能联网；普通 run/check/build、如书和生成检查从不自动同步。`ru deps sync [目录]` 的选择规则如下：

- 没有锁：解析声明的 Git 引用／目录版本范围，验证整个图后原子写入 `集锁.json`。
- 已有有效锁：只恢复锁定的完整 commit／版本，不重新选择，不改变锁文件字节；完整缓存命中时不联网。
- `ru deps sync --locked [目录]`：还要求锁必须存在，适合另一台机器或 CI 按同一锁恢复。缺失、旧格式、损坏或清单不符直接失败，不悄悄变成升级。
- `ru deps sync --update [目录]`：明确重新解析当前分支／标签和版本范围，全部成功后原子替换锁。与 `--locked` 互斥；本命令可能改变选择。

默认缓存为当前机器的 `RU_PACKAGE_CACHE` 指定目录或 `~/.cache/ru/packages`。format 2 锁不保存自动展开的工程／缓存绝对位置：本地包按已验证的声明边定位，远程及其内嵌包按来源派生 cache key 和安全包内位置定位。相对依赖保持同样的工作树布局时，可把工程与锁搬到另一目录，并在新缓存执行 `--locked`；显式绝对依赖仍需要原声明目录可用。Python API 的 `cache_dir` 只决定本次同步的缓存位置，后续普通运行仍须配置相同的 `RU_PACKAGE_CACHE`，不会从锁猜测旧机器的位置。

锁记录真实来源、完整 Git commit 或目录 exact version／归档 SHA-256、缓存树摘要和清单摘要。缺缓存时只获取这些精确内容；旧 commit 无法获取、目录删除了旧版本或同版本内容摘要变化，都明确失败，不能用移动分支或新版本替换。恢复仍核清单身份、依赖和版本约束；没有“来源找不到就换来源”。尚未发布的 format 1 锁在获取前拒绝，须明确 `--update` 重建，并接受可能改变选择。

新 format 2 远程记录以 `tree_hash_algorithm: relative-posix-v1` 标明跨宿主一致的树摘要顺序。早期 format 2 无标签锁仅兼容已定义的旧 POSIX／Windows 顺序，仍须完整实际内容匹配原摘要，默认／`--locked` 不改锁、不重选；未知算法或错摘要拒绝。不能为了修复纯摘要算法兼容而擅自执行 `--update`。

路径依赖明确标为可变，显式绝对 path 另标不可搬迁；锁不能让本地源码变成不可变内容。锁恢复要求路径包的清单／版本／依赖描述未变，普通源文件修改不触发远程升级。需要改变清单时显式 `--update`。下载不会执行包源码、hook 或安装脚本；归档拒绝链接、穿越、重复覆盖及包括隐式父目录的大小写拼法冲突；文件与隐式目录合计最多 4096 个节点，单路径最多 64 层，并受单文件及展开总量上限约束。

## 模块边界和兼容

- 当前包可用正式根导入自身模块，包括源码根内私有模块。
- 跨包只能通过声明的依赖进入公开模块；字符串路径也检查同一边界。依赖之间不能借消费者的依赖名访问未声明包。
- `..` 或符号链接不能绕过公开入口；集录文件本身不能是符号链接，嵌套包有自己的边界。
- 同一真实文件只有一个初始化、状态、形身份和失败缓存。循环仍明确报错。
- 没有清单的旧脚本保留路径导入；进入一个有清单的包时只能读取它公开的入口。
- 这是导入解析边界，不是安全沙箱，不能替代源码审阅或操作系统权限。

如书 Python 以其进程当前目录作为无文件代码格的包基准；书本文件不会打包清单或缓存。browser-js 仍只允许固定标准库，具名本机包会明确拒绝。Python、C、Node.js 都使用同一离线模块图；C／Node.js 构建产物不再需要原包源码。

公共目录的本地查询／发布命令、只读协议、不可变版本和未上线范围见[目录原型](package-registry.md)。编辑器配套与独立扩展的待办边界见[工具影响清单](package-tooling.md)。
