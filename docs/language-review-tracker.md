# 如语言审查问题追踪

记录日期：2026-10-08。审查基线：[937e443](https://github.com/uppet/ru-language/commit/937e44302b41f0d44173a1e9a0fe624ec71b0038)。

这是一份逐项决策清单，不是新的语言规范，也不是已承诺的实现计划。基线提交只记录问题；后续经确认的变更及验证记录列于对应条目。现行实现仍以 [language-spec.md](../rulang/language-spec.md) 为准。

## 使用方式

- 每项有稳定编号；讨论、修复提交与测试引用编号，后续不重新编号。
- 初始状态均为 **待确认**。可依次改为：待修复、处理中、已解决、确认忽略、暂缓。
- “确认忽略”表示明确接受现状，必须写理由、确认日期；“暂缓”保留复议条件。未回复不等于忽略。
- “已解决”必须填写决定、实现或文档提交、验证结果；涉及语义时同步规范与三个后端。
- 分类区分：**已复现缺陷**、**已文档化的设计取舍**、**规范／交互缺口**、**未实现提案**。优先级是讨论建议，不代表排期：P1 优先核对正确性；P2 影响日常使用；P3 扩展设计。
- 下列“现状／证据”来自基线审查及当时的探针；代码例子用于复现，不表示本次文档提交重新运行了语言回归。文件例子可保存为 `.ru` 后运行 `python3 ru run 文件.ru`；标明代码格的例子必须在同一会话按顺序执行。

## 保持现有决定

本清单不重新打开已明确的 binary64 数值、共享引用对象与垃圾回收、词法闭包、严格索引、成对块结束词。数组的检查点语义等也先按现行规范记录；只有显式确认才改变。

“典”的表面写法倾向为 `典: ‘上’ 对 0. ‘下’ 对 2. ‘中’ 对 1. 成.`，查询为 `其 查 ‘上’`；键的引号不可省略，此前未加引号的写法是笔误。下文 ASCII 单引号便于复制。这仍是未实现提案，各项语义尚待确认。

## 1. 跨格类型别名

<a id="ru-001"></a>

### RU-001：跨代码格形别名不能用于后续类型注解

- 分类：已复现缺陷
- 优先级：P1
- 状态：已解决

**现状／证据**

同一 REPL／如书会话按三格运行：
```ru
形 点 值 为 数. 象
```
```ru
别名 取 点.
```
```ru
算 读点 物 为 别名: 得 物 其 值. 法
```
第三格报 `未定义类型：别名`。将第三格换为 `形 盒 项 为 别名. 象` 也失败；合在同一提交则合法。

增量校验传入既有函数和形，但已保存的普通绑定未进入 known_bindings。

**已确认方向（2026-10-08）**：移除一等形值和普通形别名，形名称仅作类型用途；不扩大跨格类型别名能力。直接声明及经 `尽` 导入的形仍可用于类型注解、`新` 和 `如`。

**影响**：变量明明存在，却在下一格不能充当参数或字段类型。

**验收范围**：同格／跨格形别名均拒绝；保留形注解、构造、继承、导入、实例别名、函数值及返回实例的工厂。

**基线来源**：[rulang/interpreter.py:L247-L248](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/interpreter.py#L247-L248) · [rulang/frontend.py:L623-L628](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/frontend.py#L623-L628) · [rulang/language-spec.md:L304-L310](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/language-spec.md#L304-L310)

**解决记录／确认忽略理由**：用户于 2026-10-08 确认通过移除一等形值能力解决；0.7.0 为破坏性变更。规范第 6.1、8、9.2、15 节及 README 已加入限制与迁移指南；生成请求仍逐次携带完整同版规范。解释器、C、JavaScript 及会话形类型专项 19 项通过；完整 Python 回归运行 383 项，成功结束，Linux 上跳过 4 项 Windows 专属测试。实现与文档随 0.7.0 交付；详见 [验证记录](../VALIDATION.md)。

## 2. 继承覆写与类型身份

<a id="ru-002"></a>

### RU-002：跨模块覆写按类型文字比较，未核对形身份

- 分类：已复现缺陷
- 优先级：P1
- 状态：已解决

**现状／证据**

保存为 `base.ru`：
```ru
形 原物: 象
参数型 取 原物.
形 父:
 算 接 值 为 参数型: 得 1. 法
象
算 用 接收 为 父 值 为 原物: 得 接收 其 接 值. 法
```
同目录 `main.ru`：
```ru
尽 取 外言 'base.ru'.
形 别物: 象
参数型 取 别物.
形 子 如 父:
 算 接 值 为 参数型: 得 2. 法
象
显 (用 (新 父) (新 原物)).
显 (用 (新 子) (新 原物)).
```
解释器、C、JS 均接受覆写，先输出 `1`，随后报实参须为 `参数型`。C 可用 `python3 ru build main.ru -o main`；JS 可用 `python3 ru build main.ru --target js -o main.js` 后运行产物。

父、子模块中的同名别名指向不同形；签名文本相同，实际可接受值不同。

**已确认方向（2026-10-08）**：覆写签名按各方法声明模块解析后的类型身份比较；同名异形不兼容，导入／转导出的同一形保持兼容，阵元素类型逐层比较。随 RU-001 移除普通形别名，不再引入可重绑定形别名的签名规则。

**影响**：基类接口接受子形后，原本合法的实参失效，破坏覆写契约。

**验收范围**：统一解释器、C、JavaScript 的声明模块身份检查，覆盖同名异形、合法导入／转导出、形阵与不兼容覆写。

**基线来源**：[rulang/interpreter.py:L316-L344](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/interpreter.py#L316-L344) · [rulang/compiler.py:L215-L219](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/compiler.py#L215-L219) · [rulang/runtime.js:L249-L253](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/runtime.js#L249-L253) · [rulang/language-spec.md:L534-L540](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/language-spec.md#L534-L540)

**解决记录／确认忽略理由**：用户于 2026-10-08 确认修复；规范第 8.3 节及 README 已明确声明模块、形身份和阵元素类型比较。方法参数身份在形解析时固定，普通函数注解仍在调用时解析；导入的字段／方法类型须先经 `尽` 可见，本地声明可前向引用。三后端形类型专项 19 项覆盖跨模块、转导出、形阵及会话身份；完整 Python 回归运行 383 项成功结束（Linux 跳过 4 项 Windows 专属测试）。实现与文档随 0.7.0 交付；详见 [验证记录](../VALIDATION.md)。

## 3. 错误转换建议

<a id="ru-003"></a>

### RU-003：类型错误建议不存在的转换

- 分类：已复现缺陷
- 优先级：P2
- 状态：已解决

**现状／证据**

```ru
形 盒: 象
算 用 值 为 盒: 得 值. 法
用 1.
```
报 `实参「值」须为盒，请显式使用「为 盒」转换`。但 `为 盒` 不是合法转换，照做会再次产生语法错误。

通用错误模板把形、算、作、带元素类型的阵等都当成可转换类型。

**已确认方向（2026-10-08）**：报告期望／实际类型，实参诊断带函数名及参数名，字段诊断带字段名；移除所有笼统的转换建议，不扩大语言转换能力。

**影响**：诊断引导用户写错误代码。

**验收范围**：三种运行时文案一致体现期望与实际类型，覆盖实参、字段、形、算／作、阵元素约束，不产生虚构转换建议。

**基线来源**：[rulang/interpreter.py:L828-L831](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/interpreter.py#L828-L831) · [rulang/runtime.h:L932](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/runtime.h#L932) · [rulang/runtime.js:L283](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/runtime.js#L283) · [rulang/language-spec.md:L267-L279](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/language-spec.md#L267-L279)

- 分类：已文档化的设计取舍


**影响**：程序成功运行但条件可能与作者意图相反。

**下一步决定**：确认警告／禁止／保持现状；不要无决定改变现行语义。

## 6. 捕获写入与局部声明

<a id="ru-007"></a>

### RU-007：共享捕获缺少显式新建局部绑定的写法

- 分类：已文档化的设计取舍
- 优先级：P2
- 状态：确认忽略（接受现行语义）

**现状／证据**

```ru
算 工厂:
 临时 取 99.
 算 办事:
  临时 取 1.
  得 临时.
 法
 办事.
 得 临时.
法
显 工厂.       # 1
```

取更新最近已存在的非模块捕获绑定；没有显式局部声明出口。

**决定（2026-10-08）**：保留现行 `取` 与共享词法闭包语义，自然支持闭包读写。不增加 `另取` 等局部声明关键字，也不改为默认仅写当前局部。需要独立绑定时仍可改名或通过参数遮蔽。

**影响**：外层新增同名临时变量可能改变内层赋值范围，重构不够稳健。

**说明支持（已实现，2026-10-08）**：如书、Emacs 和 VS Code 已为代码中的 `取` 提供保守的规则提示，解释当前局部、已有非模块捕获绑定与新建局部，以及直接救正文的局部写入规则；不声称已静态确定具体名称的运行时归属。生成规范可在有帮助时用已实现的 `批.` 或非嵌套 `解.…释.` 注释说明捕获更新，见 [RU-025](#ru-025)。这只是解释与编辑辅助，不新增声明或改变捕获语义。

## 7. 参数类型与数组约束

<a id="ru-008"></a>

### RU-008：参数必须标类型，但缺少通用值类型

- 分类：规范／交互缺口
- 优先级：P2
- 状态：已解决

**基线现状／证据**

```ru

```
`任意` 不是现有内置类型；直接写这个泛型原样函数会报未定义类型。

返回值、对、阵可承载任意值，用户参数却必须属于现有类型；可用单元素阵包装绕过。

**决定与实现（2026-10-09，0.9.0）**：允许省略参数类型，省略时接收任意运行时值（包括 `空`）；显式 `为 数` 等继续运行时检查。适用于有名／匿名算与作、方法、嵌套声明及闭包，支持空白或逗号分隔的混合参数。示例：`算 原样 值: 得 值. 法`、`算 重复 内容, 次数 为 数: … 法`。

**验收范围**：三后端的任意值与显式类型检查、混合声明、匿名／引用消歧、必需实参数量和名字、闭包／方法覆写、REPL 与生成规范一致性。

- 优先级：P3
- 状态：已解决
