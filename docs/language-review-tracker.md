# 如语言审查问题追踪

记录日期：2026-10-08。审查基线：[937e443](https://github.com/uppet/ru-language/commit/937e44302b41f0d44173a1e9a0fe624ec71b0038)。

这是一份逐项决策清单，不是新的语言规范，也不是已承诺的实现计划。本次提交只记录问题，不修改解释器、后端或语言规则。现行实现仍以 [language-spec.md](../rulang/language-spec.md) 为准。

## 使用方式

- 每项有稳定编号；讨论、修复提交与测试引用编号，后续不重新编号。
- 初始状态均为 **待确认**。可依次改为：待修复、处理中、已解决、确认忽略、暂缓。
- “确认忽略”表示明确接受现状，必须写理由、确认日期；“暂缓”保留复议条件。未回复不等于忽略。
- “已解决”必须填写决定、实现或文档提交、验证结果；涉及语义时同步规范与三个后端。
- 分类区分：**已复现缺陷**、**已文档化的设计取舍**、**规范／交互缺口**、**未实现提案**。优先级是讨论建议，不代表排期：P1 优先核对正确性；P2 影响日常使用；P3 扩展设计。
- 下列“现状／证据”来自基线审查及当时的探针；代码例子用于复现，不表示本次文档提交重新运行了语言回归。文件例子可保存为 `.ru` 后运行 `python3 ru run 文件.ru`；标明代码格的例子必须在同一会话按顺序执行。

## 保持现有决定

本清单不重新打开已明确的 binary64 数值、共享引用对象与垃圾回收、词法闭包、严格索引、成对块结束词。数组的检查点语义等也先按现行规范记录；只有显式确认才改变。

“典”的表面写法倾向为 `典: ‘上’ 对 0. ‘下’ 对 2. ‘中’ 对 1. 成.`，查询为 `其 查 ‘上’`；键的引号不可省略，此前未加引号的写法是笔误。下文 ASCII 单引号便于复制。这仍是未实现提案，各项语义尚待确认。

## 1. 跨格类型别名

<a id="ru-001"></a>

### RU-001：跨代码格形别名不能用于后续类型注解

- 分类：已复现缺陷
- 优先级：P1
- 状态：待确认

**现状／证据**

同一 REPL／如书会话按三格运行：
```ru
形 点 值 为 数. 象
```
```ru
别名 取 点.
```
```ru
算 读点 物 为 别名: 得 物 其 值. 法
```
第三格报 `未定义类型：别名`。将第三格换为 `形 盒 项 为 别名. 象` 也失败；合在同一提交则合法。

增量校验传入既有函数和形，但已保存的普通绑定未进入 known_bindings。

**可选方向（未决定）**：让增量校验看到已有绑定，并保留运行时形身份检查；或明确缩小别名跨提交能力（会损伤会话一致性）。

**影响**：变量明明存在，却在下一格不能充当参数或字段类型。

**下一步决定**：确认按缺陷修复；验收覆盖参数、字段、非形值别名、同格与跨格。

## 2. 继承覆写与类型身份

<a id="ru-002"></a>

### RU-002：跨模块覆写按类型文字比较，未核对形身份

- 分类：已复现缺陷
- 优先级：P1
- 状态：待确认

**现状／证据**

保存为 `base.ru`：
```ru
形 原物: 象
参数型 取 原物.
形 父:
 算 接 值 为 参数型: 得 1. 法
象
算 用 接收 为 父 值 为 原物: 得 接收 其 接 值. 法
```
同目录 `main.ru`：
```ru
尽 取 外言 'base.ru'.
形 别物: 象
参数型 取 别物.
形 子 如 父:
 算 接 值 为 参数型: 得 2. 法
象
显 (用 (新 父) (新 原物)).
显 (用 (新 子) (新 原物)).
```
解释器、C、JS 均接受覆写，先输出 `1`，随后报实参须为 `参数型`。C 可用 `python3 ru build main.ru -o main`；JS 可用 `python3 ru build main.ru --target js -o main.js` 后运行产物。

父、子模块中的同名别名指向不同形；签名文本相同，实际可接受值不同。

**可选方向（未决定）**：比较所属模块解析后的类型身份；同时决定可重绑定别名在签名中是声明时固定还是调用时查找。

**影响**：基类接口接受子形后，原本合法的实参失效，破坏覆写契约。

**下一步决定**：先定身份及别名绑定时机，再统一三个后端与跨模块回归。

**基线来源**：[rulang/interpreter.py:L316-L344](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/interpreter.py#L316-L344) · [rulang/compiler.py:L215-L219](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/compiler.py#L215-L219) · [rulang/runtime.js:L249-L253](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/runtime.js#L249-L253) · [rulang/language-spec.md:L534-L540](https://github.com/uppet/ru-language/blob/937e44302b41f0d44173a1e9a0fe624ec71b0038/rulang/language-spec.md#L534-L540)

## 7. 参数类型与数组约束

<a id="ru-008"></a>

### RU-008：参数必须标类型，但缺少通用值类型

- 分类：规范／交互缺口
- 优先级：P2
- 状态：待确认

**现状／证据**

```ru
算 原样 值 为 任意: 得 值. 法
```
`任意` 不是现有内置类型；直接写这个泛型原样函数会报未定义类型。

返回值、对、阵可承载任意值，用户参数却必须属于现有类型；可用单元素阵包装绕过。

**可选方向（未决定）**：新增通用值类型；允许省略类型；或保留限制并写明容器包装方式。

**影响**：通用函数、典键／值处理接口不自然。

**讨论中的具体方案（未批准）**：2026-10-08 针对“算法参数必须写类型，这个问题怎么处理”的讨论，建议允许省略参数类型：省略时接收任意值（包括 `空`）；显式 `为 数` 等仍进行运行时检查；允许混用，例如 `算 重复 内容, 次数 为 数: … 法`。这不是类型推断，也不自动转换；函数体中的不合法运算仍会报错。精确的可空／联合类型可后续单独讨论，见 RU-009。

**下一步决定**：确认是否采用可省略参数类型方案；实施前核对匿名函数与显式函数引用的前瞻解析是否产生歧义，并统一三后端。此记录不授权实现。

### RU-009：参数缺少可空／联合类型表达

**影响**：前端、意图扫描器、如书与 Emacs 若不同步，会出现运行与编辑行为分歧。

### RU-026：裸声明名调用与保存的函数值读取不同

- 分类：已文档化的设计取舍
- 优先级：P2
- 状态：待确认

**现状／证据**

```ru
算 答: 得 7. 法
回 取 算 答.
显 答.       # 7
显 回.       # <算 答>
显 回().     # 7
```
`列 其 量()` 则尝试调用已经取得的数值。
