## 真实 Chromium 端到端与原生 Canvas 对照

自然循环例 SHA-256：`c0dceb4e68275d545e060119c211bcff7496a846e5f64322540a7c927ce66085`。两端均为 1120×760 backing store、DPR 1，同一云端真实 Chromium 154.0.8037.57 和 1500×1200 viewport。首次原生测量用 1120×760 CSS；完整回归结束后补测匹配如书显示外框867.984375×589.640625 的原生页面，未改如书代码或重新执行如书性能样本。匹配 CSS 补测三档分别为 19.9954／30.0011／60.0026 FPS，CPU 提交 p50 均约 0.20 毫秒，结论不变；这仍不是 GPU 完成或物理屏幕呈现测量。独立基准曾出现 rAF 限帧的浮点边界超发，已修正期限推进并废弃异常轮次，此处仅采用修正后的完整重测。

每轮先预热 2 秒，再采样 10 秒。原生 Canvas 每帧计算同样的 sin/cos、九个移动天体与太阳、轨道、文字及介绍，运行态 42 条命令，未删减文字或采用静态层缓存：20／30／60 FPS 目标均达到，CPU 计算与 Canvas 提交 p50 约 0.20 毫秒。

如书自然例请求 20 FPS，10 秒取得 161 帧，提交速率约 16.10 FPS。相邻完整帧提交间隔 p50 61.90、p95 65.20 毫秒；帧 POST 发出至完整画面提交 p50 60.10、p95 63.20 毫秒。Canvas 绘制调用部分 p50 0.20、p95 0.40 毫秒，不含场景验证与 backing-size 重设。以上均为 CPU／Canvas 提交测量，不是 GPU 完成或物理屏幕呈现。

结论：回调显著提速，但仍未接近原生 JavaScript Canvas 的执行效率；HTTP／子进程／轮询与解释器仍有显著成本，不能把回调提速倍数当作端到端 FPS 倍数。前端调度和协议本轮未改。

真实交互验收通过：太阳与九个移动天体的悬停标题和三行介绍、全部轨道冻结、暂停时选择另一目标、回到画布空白恢复；重复运行仅一个活动画布；停止关闭回调；保存后重开为不触发隐藏执行的静态历史；重新运行恢复动画。无页面错误，悬停最多 44 条命令、5008 字节。

既有边界保持：悬停时直接移出画布仍暂停，因为宿主没有 pointerleave 回调；返回画布空白恢复。本轮未将它宣称为已修复。

## 使用

关闭旧如书服务后重新启动 `python3 -m rushu`（Windows：`py -3 -m rushu`），在如书打开 `rushu/examples/solar-system-math.rushu.json` 并运行代码格；源文件为 `rushu/examples/ruguan/solar-system-math.ru`。另外提供 `circle-motion.rushu.json` 和 `seeded-stars.rushu.json`。仅刷新浏览器不会替换已启动的 Python 解释器。

模拟 Responses 回归使用预先编写的源码，经真实本机 HTTP、提示传输、校验及显式运行验证，不调用真实付费模型，也不证明真实模型生成质量。
