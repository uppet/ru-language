# 如书生成诊断与模型输出

生成诊断自如 0.18.2／如书 0.7.1 加入，现已随 `main` 上的如 0.20.0／如书 0.8.8 提供，用于分辨本机准备、提供方请求、响应解析、源码提取及目标检查的位置。它不运行生成源码，也不会自动重试付费请求。

## 可观察到什么

- 准备：验证意图与草稿、读取配置和当前语言规范；说明本次是否显式发送输出 token 预算。默认省略 `max_output_tokens`，提供方默认上限可能未知，不表示无限。
- 发起请求与等待：记录本机开始连接提供方的阶段、时间与已等待时长；发起请求不证明提供方已收到（DNS／连接仍可能失败），等待不表示模型的思考进度。
- HTTP 响应与解析：区分收到响应、解析响应和提供方返回的完成状态。拒绝、未完成、响应格式或通讯错误保持独立诊断。
- 用量与输出形状：只汇报提供方返回的数值 usage（包括返回时的 `input_tokens`、`output_tokens`、`total_tokens`、`cached_tokens`、`reasoning_tokens`），仅接受已识别字段的非负安全整数计数，并给出 `output` 项类型摘要。没有字段就不编造数值；类型与计数不包含模型隐藏推理正文。
- 模型文本：仅展示提供方实际返回的助手可见文本；未完成响应已含可见部分文本时也可供诊断参考。只有 reasoning 项或其他没有可见助手文本的响应会明确说明，没有 token 流时不会伪造实时输出，不展示模型隐藏推理。
- 源码提取：可对照清理前的模型文本与提取后的如源码，定位代码围栏或意图结语等提取问题。
- 目标检查：默认 Python 仅检查语法／结构；显式 browser-js 复用浏览器编译器的能力与模块检查。成功不等于代码正确或安全。
- 最终结果：区分生成成功、失败和页面取消等待。取消等待不保证终止提供方处理或计费，不会启动自动重试。

诊断不包含请求正文、完整 system 提示、配置、认证头或原始 HTTP 响应体。当前凭据在展示前脱敏；模型正文仍可能包含你主动发送的私密信息，分享前请自行检查。失败的模型文本供诊断参考，不自动成为可执行源码。

## 配置预算

CLI 与如书共用配置，优先级为 CLI／如书启动参数 > 环境变量 > JSON > 省略：

```sh
# 单次命令；--timeout 是等待秒数，--max-output-tokens 是独立的输出预算
python3 ru generate intent.md -o draft.ru --max-output-tokens 32768 --timeout 3600 --verbose
# 如书启动参数；也可设置 RU_LLM_MAX_OUTPUT_TOKENS=32768
python3 -m rushu --max-output-tokens 32768 --generation-timeout 3600
```

JSON 可写 `"max-output-tokens": 32768` 或 `"max_output_tokens": 32768`，不可同写。显式配置须为 1 至 2147483647 的整数；环境变量／CLI／启动参数只接受最多 10 位 ASCII 十进制数字，不接受空格、正负号或科学计数法。JSON 数字不能换成布尔值、字符串或 `null`，0、负数和小数也无效。如书对无效预算明确提示“未发送请求”。上例的 32768 不是建议的通用预算，提供方／模型可以限制允许范围。不设置预算时，从 JSON、环境变量和启动／CLI 参数中省略相应配置。

## 怎么理解未完成与空输出

- `incomplete`／`max_output_tokens`：提供方报告达到输出预算。先查看本次请求是否设置预算及实际返回的用量，再决定调整预算或缩小需求后手动重新生成；提供方采用的默认上限可能未知。仅增加等待秒数没有作用。
- `incomplete`／`content_filter`：提供方报告内容过滤。检查请求与提供方规则；增加预算或超时不是对应的解决办法。这不是账号权限或额度不足的结论。
- 其他／缺失的未完成原因：明确报告未完成和已知信息，不猜测账号原因或未返回的预算。
- 只有 reasoning 项、没有可见助手文本：说明当前响应没有可提取源码。返回的 `reasoning_tokens` 只是提供方用量计数，不代表已返回可见回答，也不能用来还原隐藏推理。缺少计数时不推断为零；不据此推断模型具体想了什么。
- 部分助手文本：如书可折叠查看已返回的可见部分，帮助辨认是否已开始输出，但不会把 `incomplete` 结果当完整源码、加入模型版本、保存为生成产物或运行。当前意图和草稿保持原样。诊断 JSON 仍可由用户手动导出。

CLI 的 `--verbose` 把阶段、预算、数值用量及输出项摘要写到 stderr，不输出隐藏推理或原始响应；`--stdout` 仍只在生成与检查完整成功后输出产物。以上诊断不触发额外模型请求，每次手动重新生成仍可能再次计费。

## 保存与容量

诊断属于一次生成，不写入书本历史或自动保存文件；它不是持久审计日志。关闭本机服务后服务端日志丢失，刷新页面后浏览器中的诊断视图丢失。浏览器最多保留最近 8 个代码格的生成记录（合计最多 16 MiB），每格仅保留最近一次；页面记录可能少于服务端记录。每个服务最多保留 8 次生成，记录保留 1 小时；满额时先移除最旧的已结束记录，活动请求不会被替换。

单次记录最多 64 个事件，每个事件附带文本最多 1 MiB（UTF-8），每次文本合计 2 MiB；每条说明最多 1024 字符。超限明确标记截断。容量限制前先做凭据脱敏。「清除此格诊断」只清除日志，不取消模型请求或撤销费用；已清除的生成标识在一小时内不能重复用于新生成。若清除先于已发出的生成 POST 到达，首次延迟到达的请求仍可继续，但不再保留它的日志。如果服务端清除请求失败，页面仍可移除自己的记录，但会说明尚未确认服务端清除。

展开「生成诊断 · API过程与模型原文」查看追加的阶段记录；模型可见文本与提取源码分别折叠并分页展示。如需保留或交给别人排查，请使用「复制诊断JSON」或「下载诊断JSON」，并先检查其中的模型输出。不把下载的诊断误当作已运行或已验证安全的程序。

## 本机接口边界

生成请求使用独立 32 位小写十六进制 generation_id。受启动令牌与本机来源保护的 `/api/generation/trace/<id>` 接口读取诊断，可用 `after=<seq>` 只取新增事件；删除接口只清除该次日志。事件有单调递增序号、UTC 时间、耗时、阶段与安全说明，文本按实际返回附带。旧页面、已取消请求和其他生成标识的响应不得覆盖当前代码格。

本轮提供方验证仅使用模拟 Responses 服务；不会为了演示诊断而额外请求真实付费模型。测试不能证明真实端点、账号权限、模型兼容性或实际预算；具体完成与未完成检查见[验证记录](generation-token-budget-validation.md)。
