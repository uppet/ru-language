# 如观回调逻辑工作预算

本文固定 Python 解释器的 `logical-work-v2` 计量合同。它替代旧的 Python 跟踪行数预算，不适用于 C/LLVM 后端，也不宣称是精确 CPU 指令数或安全沙箱。

**当前候选默认**：每个最外事件回调最多 **262144 工作单位**，常规检查间隔 **256 工作单位**。原 **1 秒墙钟、64 MiB 净追踪分配、如书会话 10 秒外看门狗**不变。候选数值来自本轮原始计数与大文本费用校准后的待验方案，不是把旧 500000 Python 行改名；是否适合发布仍须通过同一精确版本的 GUI、平台与回归验收。

## 一、范围和生命周期

计时与净内存基线保持原回调边界：执行回调前取起点与 `tracemalloc` 当前值，执行回调和栈平衡检查，之后退出保护区。后续协议 `flush` 不因本次适配被加入同一秒；回调中主动进行的绘图、文件或原生调用属于保护区内工作。

一个最外事件创建一份共享预算。函数、外言 owner、隐式 `印`/`同`、排序比较器、同线程同步原生回调、嵌套如观宿主事件均继承它，不重置剩余额度、截止时间或内存基线。正常后续事件在外层上下文清理后获得新预算；因失败已经关闭的画布不会因此复活。

普通非图形解释执行没有活动回调预算。内部校准可显式选择记录策略，但记录成功不等于产品接受。用户语言、事件协议与环境变量没有关闭逻辑预算的开关。历史 Python trace 基线须使用原版本源码，不在当前默认路径安装 `sys.settrace`，也不改动调用者已有的 trace。

## 二、原始事件与收费单位

保留六类原始计数；统计不依赖 Python 源码行、生成器 `send` 次数或显式栈的内部状态切换。

|类别|一次原始事件|收费|
|---|---|---|
|`expr`|实际访问表达式或引用目标节点；叶值和一般求值路径口径相同，未执行的短路分支不计|1|
|`stmt`|访问一条语句节点，包括执行扫描中的声明|1|
|`loop`|一次循环条件/次数边界尝试；含最后的终止尝试，`break` 后不另加尝试|1|
|`call`|实际选中的 Ru 调用或内建成员操作分派；转发 wrapper 不重复收|1|
|`helper_item`|辅助算法实际访问的输入项、字段、候选、Pair 对、比较、类型层、图边或文件项|1|
|`bulk_unit`|已知整块操作的保守输入规模：字符串按 Unicode codepoint，二进制按 byte，容器复制按元素|每个原子操作 `ceil(n / 64)`|

bulk 逐操作向上取整，不把整次事件的小操作凑在一起取整：

- 长度 0 收 0，但仍检查已有耗尽、墙钟和净内存。
- 长度 1、63、64 各收 1；65 收 2。
- 64 次长度 1 操作收 64，不等于一次长度 64 操作。
- 费用用常数次整数算术计算，不为计算费用再遍历输入；不是对任意精度整数位复杂度的承诺。

语义单位和 bulk 单位是有意定义的工作模型，不保证不同类别具有相同机器成本。辅助算法的真实输入访问/复制变化可能改变费用；单纯移除 wrapper 或改变 continuation 组织不应改变计量。

### 调用收费归属

- 普通、匿名、成员、跨外言与隐式 Ru 调用统一在实际 `_invoke_step` 收一次。`invoke_value` 等包装和转发不重复收费。
- `读`、典操作、固有句/阵/字段成员各在选中的实现收一次。典的索引查询与相同典成员操作走同一入口。
- 图形、I/O、竞赛、实用、原生运行库的失败类型探测不收费；实际选中的运行库操作收费，其内部纯 helper 不再算新的 Ru 调用。
- 原生函数内部再次同步回调 Ru 是另一次真实 Ru 调用，继承原预算。

### 整块费用口径

- 文本比较、哈希、搜索、拆分、替换按对应已验证输入长度计。字符串相等比较在同类型确认后、identity 快捷路径之前收费，同一对象与等值不同对象的逻辑费用相同；这是保守输入费用，不是实际逐字比较次数。单纯取得字符串引用不收长度费。输入类型错误不为了计量提前扫描未知对象。
- 拼接/join 按参与文本总长度和实际分隔符长度；切片、快照、复制按复制元素数。快照与后续遍历是不同的真实工作，可以分别计。
- 编码/解码和原生缓冲处理按已知 codepoint/byte 长度；不为了算费用先创建完整编码结果。
- `display` 按实际值遍历和文本组装收费，保留循环对象处理。
- `split`/`replace` **只收输入费用**并在成功返回后检查墙钟/净内存，没有额外按生成结果收费；结果的后续使用再按后续操作计。输入费用不能冒充对生成输出的事前内存保证。
- 文件长度只有读完才知道时，读后长度费用只约束后续处理。既有文件大小上限、路径/符号链接校验不为计量改变。

如竞的单次 `_Writer.write(text)` 视为一次已知长度编码操作，整段 bulk 一次；实现分块只增加真实 helper 访问和检查，不按编码 chunk 重新取整。真实 `flush` 的 pending bytes 解码和之后独立写入各有自己的输入费用。

## 三、覆盖点与观察边界

计量进入解释器表达式/语句/空循环、声明与参数、名称链、类型数组/继承、典哈希/碰撞比较、数组遍历/排序、显示输出；也覆盖回调可达的竞赛扫描与输出、实用文本、I/O、图形命令编码、原生参数/锚点/缓冲、首次外言解析验证，以及离线包 manifest/锁/缓存遍历。

包路径仍严格离线。计量不增加下载、Git、解压、写锁或缓存发布；原 manifest 1 MiB、锁/缓存文件大小与图数量等限制保留。同步命令没有活动回调预算时，其原业务行为不变。

每个收费入口先检查已有耗尽和工作限额。常规墙钟/净内存检查按已收费工作量间隔执行；事件边界、已知整块操作、原生/I/O 成功边界和有界 helper chunk 有额外强制检查。不能只在生成器 `yield` 检查，因为显式表达式栈和 helper 可以不让出控制。

**1 秒仍是合作式截止，不是任意系统调用可抢占的保证。**单个 C/操作系统调用可能阻塞，前后检查不能中断其内部；如书会话的外部 10 秒看门狗仍不可替代。直接调用 `GraphicsHost` 的测试进程不因此自动拥有如书看门狗。净 64 MiB 也不是瞬时峰值或所有 native 内存的上限。

## 四、失败和必要收尾

耗尽保存首个 `BudgetExceeded`（`RuError` 子类，类别为预算错误），包含原始样本、阈值与来源。它不是可被如言 `救` 捕获的 `Panic`。首错 sticky：即便原生 trampoline 捕获异常并返回 fallback，下一 Ru 入口、原生返回边界或最外结束检查仍拒绝继续工作。

已有预算首错优先；但操作先抛用户错误、尚未观测到超限时，不在异常退出时首次采样来覆盖原错误。成功返回的强制检查照常执行。解析推测回退、缓存和包错误转换不能吞掉或改写已经存在的预算首错；必要 `finally` 清理仍完成。

原生已预注册的 `失败时` 动作可能用于唤醒阻塞调用。仅在预算已耗尽时允许该**精确函数/参数/context/callback/budget**的一次性收尾，仍执行原资源、线程、借用和参数安全检查：

- 参数浅快照，许可先消费；执行或校验失败也不能再用。
- 普通原生入口不能转移/复用许可，所有 Ru/原生 callback 用户入口仍拒绝 sticky 错误；不得再执行用户 Ru。
- 只在精确收尾的动态作用域内暂停工作收费/预算抛错，首错不清除，10 秒外看门狗不变。
- 退出先撤销许可，再恢复上下文；复制的 context 也不能带走许可。
- 普通业务 `Panic`、预算未耗尽时仍保留原失败动作的合法同步重入行为。

## 五、可审计快照和验收

快照 `schema_version=2` 包含：

- `counts`、`raw_total`，以及兼容原始含义的 `total`/`attempted_total`；
- `weighted_counts`、`charged_units`、`attempted_units`；
- `model_version`、`work_limit`、事件序号、首次耗尽种类、最近墙钟/净分配样本与 `closed`。

`charged_units == sum(weighted_counts)`，`raw_total == total == sum(counts)`；失败本次预扣由 attempted 字段表达，不混入已接受费用。观察只在事件退出后读取不可变快照，不调用被计量的用户观察器。

接受必须针对最终精确源码，包含默认策略下的原 GUI 断言、原墙钟/净内存/看门狗负控、bulk 边界、短路、空循环、跨模块与重入、首错保持、上下文撤销、真实 Windows 原生收尾与旧业务错误行为。历史 raw-v1 数据可解释模型选择，但不代替 weighted-v2 或当前候选的通过证据。

### 候选选择的历史依据（不是 v5 验收）

2026-10-25 本地 Linux / Python 3.12 的旧 raw-v1 观测中，固定 full256 的 mixer 单事件原始量最大 29987，两个 scroll 场景各最大 12991；三场景观测到的最大 handle 墙钟分别约 0.2192、0.0922、0.0961 秒。full256 的177个计划尝试全部保留，其中168完成、9触发预算；不能写成177全部功能通过。

另9次大文本固定实验（64Ki、256Ki、1Mi输入各3次）均完成；1Mi输入原始计数为1048675，但保护区墙钟约1.46—1.61毫秒、净追踪分配2100394字节。这说明把每个bulk输入单位等同一次语义工作会过罚快速整块操作，因此提出逐操作ceil(n/64)，而非直接沿用raw总数作限额。262144/256是保留交互余量的**候选策略选择**，不等于由这些有限数据证明所有合法程序都能通过。字符串比较/包覆盖等后续修正也意味着旧数值不能直接当新版本费用。
