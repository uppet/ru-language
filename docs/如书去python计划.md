# 如书去python计划

状态：计划，尚未实施。基于 `bs` 已完成的 M5 原生解释内核与如观能力。

## 目标与边界

让如书以如言编写、LLVM AOT 编译的本机程序启动，日常运行不需要 Python，保留当前 HTTP 接口、持久会话、输入输出、停止／重启、绘图、AI 生成和独立浏览器 JS 加速功能。

解释器、客体闭包和如观状态已经由如言实现；代码格继续解释执行。浏览器编辑器、Canvas 绘制、书本打开／保存与历史重放继续沿用现有 JavaScript。书本格式保持版本 1，不新增服务端书本数据库，也不保存活对象或恢复历史回调。

“运行如书不需要 Python”与“从源码构建工具链不需要 Python”分别验收。代码格 AOT、ORC JIT、Dart 性能对齐、完整包工具链移植不属于本计划的前置条件。

## 实现原则

- 网络、TLS 和必要的系统能力优先集成成熟 C 库，放在根目录 `third_party`，记录来源、固定版本、许可证和更新方式；具体库尚未选定。
- 通过有限的静态 C 适配接口向如言开放能力，如言负责路由、协议和会话业务。不要求先实现通用 FFI，不把业务重新写进 C。
- 接口明确字节长度、Unicode、错误、资源所有权和关闭语义。C 回调与如言 GC／线程的关系须先设计验证，不能直接从任意 C 线程进入如言求值器。
- 保持每会话独立内核进程和可终止性。浏览器 JS 加速仍为每格独立 Worker，不与原生会话共享活对象。
- 保留现有回环监听、启动令牌、Host／Origin 校验、静态文件白名单、请求／输出限额与生成请求约束。
- 先跟进 `wip` 的语法和版本变化，同步 Python、如言自举前端与原生解释器的能力声明；用回归证明兼容，不能只解决文本冲突。

## 工作模块

| 模块 | 当前 Python 实现 | 待建设能力 |
| --- | --- | --- |
| HTTP 服务端与启动入口 | `rushu/server.py` | 回环监听、路由、静态资源、请求解析与限制、鉴权、命令行、退出清理和可选打开浏览器 |
| JSON 与基础工具 | Python 标准库及各宿主模块 | 严格 JSON 读写、UTF-8 与字节限额、配置／环境变量、随机令牌、源码 SHA-256、时间与诊断辅助；现有手写绘图输出不能替代完整 JSON 接口 |
| 进程与管道 | `rushu/native_kernel.py` | 启动／等待／终止／强杀、三路标准流、短读写、EOF 与异常退出、Windows／Linux 资源回收、RU2 握手与传输 |
| 会话管理 | `rushu/kernel.py` | 会话与执行身份、generation、输入 request_id、事件游标与容量、迟到结果过滤、重启、图形校验／限流和硬看门狗 |
| AI 生成服务 | `rushu/generation.py`、`rulang/generation.py`、`rulang/generation_trace.py` | HTTPS／证书校验、配置和密钥、规范与提示打包、Responses 请求／提取、源码静态检查、脱敏诊断日志、并发和超时语义 |
| 浏览器 JS 编译服务 | `rushu/browser_compile.py`、`rulang/browser_compiler.py`、`rulang/js_compiler.py` | 如言实现浏览器目标的语义检查和 JavaScript 发射、内置标准库处理、能力限制与来源诊断；不能暗中继续调用 Python 编译器 |

## 推进顺序与验收

### P1：系统接口与 JSON

- [ ] 盘点服务端实际所需接口，选定并固定 C 依赖，建立可重复的 Windows／Linux 构建方式。
- [ ] 提供 JSON、随机源、哈希、环境／配置、进程／管道和 HTTP 所需的有限接口；已有文件与单调时间能力优先复用。
- [ ] 验证错误、资源生命周期、Unicode 路径、短读写与进程回收，不扩展语言语法来代替宿主接口设计。

### P2：无 Python 基础版如书

- [ ] 用如言实现 HTTP 宿主和会话管理，连接现有原生解释内核，沿用 RU2 与前端 HTTP 合同。
- [ ] 保留停止、重启、崩溃恢复、阻塞回调硬超时，以及 generation／执行／画布身份校验。
- [ ] 在没有 Python 可执行入口的独立运行目录验证：启动、打开页面、共享变量与闭包、Unicode 输入、错误恢复、输出限额、停止／重启和多会话。
- [ ] 真实浏览器验证 Canvas、缓存图像、鼠标／键盘／帧回调、保存重开与历史静态重放；Windows 和 WSL／Linux 分别实际运行。

本阶段交付基本编辑、执行与绘图闭环；AI 生成和 JS 编译尚未移植时，必须明确标示能力边界，不能宣布现有全部功能已经去 Python。

### P3：AI 生成服务

- [ ] 移植配置、HTTPS 请求、规范全文与哈希打包、响应提取、生成源码静态检查、日志与诊断。
- [ ] 静态检查不得执行生成代码或导入用户文件；使用可用的如言前端检查能力，必要时增加独立检查入口。
- [ ] 保留密钥不下发浏览器、日志脱敏、仅显式点击发送、输出预算、全局请求并发限制，以及超时／页面取消后的重复请求约束。
- [ ] 使用本地模拟提供方回归，不自动发起真实付费模型请求；浏览器目标检查依赖 P4。

### P4：浏览器 JS 编译

- [ ] 用如言实现 JS 目标，复用可复用的前端与语义检查，补齐浏览器特有的标准库／能力／计步与图形桥接。
- [ ] 保持每格独立 Worker、结构化诊断和原有浏览器能力限制。
- [ ] 用既有浏览器编译差分及真实 Worker／Canvas 回归验收，补齐 P3 的浏览器目标生成检查。

P3 的 HTTP 客户端与 P4 的编译器可独立推进；保留全部现有功能的无 Python 版本需两者均完成。

### P5：发布与构建链边界

- [ ] 打包服务端、原生内核、标准库和前端资源，明确资源定位、版本、许可证及平台依赖。
- [ ] 两平台在独立目录验收全部功能，确认运行时不调用 Python，不依赖 LLVM 工具链。
- [ ] 另行移植 `tools/bootstrap.py`、`tools/build_rushu_kernel.py` 等构建驱动，使已有原生编译器可驱动后续构建；首次 stage0 引导单独说明。

## 完成判据

基础版以 P1／P2 验收通过为准；完整功能运行时以 P1—P4 及 P5 的打包验证通过为准。构建链也去 Python 须再完成构建驱动条目，不能用可运行的原生内核代替服务端或完整工具链的完成证明。

现有基线见[原生内核指南](rushu-native-interpreter.md)和 [M5 验收](rushu-m5-validation.md)。这些报告记录迁移前的冻结实测，不自动证明后续移植或上游整合后的版本通过。
