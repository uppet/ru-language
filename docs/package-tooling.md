# 0.22.0 包系统工具影响清单

## 本仓库已经配套

- Python 前端：可选顶层一次模块声明；吾／言只在完整上下文识别，不加入保留字。导入 AST 保留静态 name 元组与可读 path，整条其链不求值。
- Python、C、Node.js：共同使用 canonical 真实路径的离线模块图。声明不执行，也不创建导出值。裁剪／完整运行时共享身份与失败缓存的回归相同。
- 如书 Python：沿用工作目录解析，不自动下载；书本 JSON 不包含依赖文件。browser-js：允许无运行效果的声明，仍拒绝本机文件／包，并保留固定标准库白名单。
- 两种提示词导出（如书、如观）及两种 target：完整嵌入同一 0.22.0 规范与摘要；不生成不存在的依赖，不把集录混入源码，不自动同步／发布。browser-js 提示再次限定固定标准库。
- 如书编辑器与 Emacs：完整声明内吾／言使用关键字样式，静态模块段使用类型／名称样式；普通吾／言保持普通名称；其段等原先成员词在静态链里不误提示为内置成员。声明不增加结构缩进块。
- 集录的典／阵由既有词法高亮支持，hover 解释静态清单与显式同步；编译器负责重复／未知字段、类型与边界诊断。高亮本身不是 schema 验证，不会联网或自动安装。
- 资产检查工具区分集录数据与可执行 `.ru`，静态验证集录后再检查其余示例的句点风格。

## 独立 ru-vscode 仓库的配套检查

如言 VS Code 扩展在[独立仓库](https://github.com/uppet/ru-vscode)发布，当前配套版本见[稳定入口](stable-entry.md)。以下是需要保持同步并在扩展仓库单独验证的合同，不能仅因语言测试通过就认定扩展已配套：

1. TextMate／语义 token：仅完整 `吾 言 名 (其 名)* .` 声明识别 contextual 吾／言；禁止全局新增关键词。全角句点、注释间隔和 Unicode 名称同样支持。
2. 具名外言：`外言 工程 其 流体 其 管道` 整条链是静态名字。`其` 后的“段”“量”等模块段不能错误使用字符串／集合成员提示；字符串外言和标准库既有高亮保持。
3. 文档／hover／snippet：添加 `吾 言 工程 其 力学.`、具名 `取 外言`／`尽取 外言` 片段与集录静态示例；保留完整语句句点风格，不能把声明误当成新块。
4. `集录.ru` 文件识别：提供仅静态数据提示；顶层合法字段名／版／需如言／源码根／公开／依赖，依赖三种单一来源、静态字面量、公开相对路径语义。若现有扩展没有 schema 验证能力，明确仅补全／说明，避免假诊断。
5. 运行／检查／构建任务：继承工具链的离线诊断；“缺依赖”可提示用户显式执行 `ru deps sync`，不得自动联网、安装或发布。默认同步保留有效锁；`--locked` 严格恢复、`--update` 会重选，两者不能混用；编辑器不能在错误后擅自改用 update。清单不能作为普通源码运行。
6. 定义／模块导航（若已有）：依赖别名选择包实例后按作者正式名查找；只有已获取的公开入口可导航，不额外请求网络。若目前不支持模块导航，不能宣称本批新增了此能力。

建议扩展回归向量：

```text
吾 言 工程 其 力学.
吾 言 工程 其 流体 其 管道。
吾 取 1. 言 取 2. 显 吾 + 言.
算 吾 言: 得 言. 法.
力 取 外言 工程 其 段.
显 (外言 工程 其 力学) 其 动量 2 3.
力 取 外言 '如:数学'.
显 '吾 言 工程.'. # 吾 言 工程.
```

另覆盖：声明重复／嵌套、未完成输入、只含注释、相邻标点、字符串 URL、重复清单字段、源码根与 map 路径基准、alias 与作者根不一致、依赖缺失、旧标准库提示。以对应扩展 commit 的真实测试和 VSIX 验收为完成依据。

## 验证边界

具体通过数量以本版本验证报告为准；没有 Emacs 的执行环境只能做静态定界检查，不能据此声称 ERT 或字节编译通过。独立扩展、实际浏览器 UI、真实 Windows／SSH／HTTPS 服务端均须分别记录验证，不能用本机 fixture 结果替代。
