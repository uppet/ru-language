# 用如解题：如竞标准库

本页对应 `main` 上的如 0.22.0，全量导入使用连写的 `尽取 外言`。从旧版本升级时，先核对[版本](stable-entry.md)，再按[全量导入说明](import-all-migration.md)迁移源码。

本页是可直接照着运行的解题指南。语言及完整接口以 [如语言规范](../rulang/language-spec.md) 为准。下列四道题是本仓库原创练习，不对应任何在线评测平台的题号，也不代表已经在外部评测站获得通过。

如竞的标准导入名现为 `如:竞`，公开函数及调用方式不变。旧 `如竞` 与 `如:竞赛` 会给出明确迁移错误，不保留兼容别名。参见 [标准模块导入迁移](standard-module-imports-migration.md)。

## 最短的读写骨架

```ru
尽取 外言 '如:竞'.
入 取 读入.
出 取 蓄出.
循
    值 取 入 其 数.
    若 值 == 空 则 破. 然.
    出 其 行 值.
环.
出 其 清.
```

- `读入` 一次读完剩余标准输入，验证 UTF-8 和 NUL 后建立游标；适合非交互题，会占用与输入大小成正比的内存
- `入 其 数` / `词` / `行` 的 EOF 是 `空`，数值 `0`、空行 `''` 都不是 EOF
- 内置读流成员直接写 `入 其 数`，不要写 `入 其 数()`；`出 其 清` 同理。它们没有函数引用
- `蓄出` 提供最多 64 KiB 的 UTF-8 缓冲，写满时自动输出；程序结束前仍须 `出 其 清.`，否则末段可能丢失
- 标准输出只写答案，去掉交互提示、调试文字和计时信息。库的输入、转换和输出错误是写到标准错误的致命错误，不是 `件作成果`，也不能由 `救` 捕获

若担心导入名冲突，可用限定访问：

```ru
竞 取 外言 '如:竞'.
入 取 竞 其 读入.
拆分 取 算 竞 其 拆词.
显 (拆分 '甲 乙').
```

`读入`、`排序` 等是随工具链发布的普通如函数，可以取引用、传参；没有导入时它们不是全局内置。`如:竞` 属于保留的 `如:` 标准库名称空间， 不会被当前目录中恰好同名的文件替换。实现用的 `__如竞` 不是应用接口。读流／出流没有公开类型名，当前不能直接声明专用类型参数；可让闭包捕获它，再把读取／输出回调传给其他函数。

## 从源码到评测框里的 C

在仓库目录执行，以第一题为例：

```sh
python3 ru check examples/contest_sum_eof.ru
printf '1 2\n-5 8\n0 0\n' > /tmp/ru-contest-input.txt
python3 ru run examples/contest_sum_eof.ru < /tmp/ru-contest-input.txt
python3 ru build examples/contest_sum_eof.ru -o bin/contest_sum_eof --emit-c dist/contest_sum_eof.c
./bin/contest_sum_eof < /tmp/ru-contest-input.txt
cc -std=c11 -O2 dist/contest_sum_eof.c -o bin/contest_sum_eof_c11
./bin/contest_sum_eof_c11 < /tmp/ru-contest-input.txt
```

预期三次运行均输出 `3`、`3`、`0`，各占一行。`dist/contest_sum_eof.c` 是完整单文件：把它的**全部内容**复制到评测提交框，选择站点提供的 **C11 / GNU C11、开启 O2** 的编译选项。也可下载或上传该文件，具体取决于站点。不要只复制源文件末尾的函数；运行时与标准外言已经一起编入，无需附带 `.ru`、Python 或项目头文件。

默认导出的 C 按生成代码需要的函数及其传递依赖裁剪运行时，并按实际成员名称裁剪分派分支；`如竞` 中未引用的声明也会在安全时移除。分析覆盖依赖模块、别名、函数引用和闭包；模块值逃逸等无法确定的情况会保守保留。它不会删除用户函数或用户模块顶层副作用，也不会改变原始完整依赖图的检查。生成代码保持可读，仍是普通独立 C99，不依赖压缩、手工删代码或题目专用模板。

提交前检查实际源码字节数，并和站点限制比较：

```sh
wc -c dist/contest_sum_eof.c
```

运行时裁剪不能保证任意程序都低于某个源码长度上限。排查裁剪前后行为时，可另外生成完整版本并用相同输入比较：

```sh
python3 ru build examples/contest_sum_eof.ru -o bin/contest_sum_eof_full --emit-c dist/contest_sum_eof_full.c --full-runtime
./bin/contest_sum_eof_full < /tmp/ru-contest-input.txt
```

`--full-runtime` 保留完整运行时和已导入标准库声明；通常更大，用于诊断而非缩短提交源码。JavaScript 构建也支持该选项，不过这里的评测提交步骤使用 C。

本地 `ru build` 默认使用 C99 和 `-O2`，并在适用平台链接 `-lm`。上述四个示例可按 C11 / O2 路径复编；这不承诺每个评测站的操作系统、编译器版本、源码长度和时间 / 内存限制都兼容。**使用 `%` 浮点余数的程序仍可能需要链接 `-lm`**；站点不提供它时，不能把无 `-lm` 的普通样例成功推广到取余题。任意编译器选项、其他平台和 Windows 原生构建不能由这些样例推定兼容；独立复编的具体检查见 `VALIDATION.md`。

先用样例和自己构造的边界输入比对解释器与生成 C，再提交。四个练习的数值范围都刻意留在目前的安全实用范围内；不会据此声称语言已有 `int64`。

## 练习一：成对求和，直到文件结束

源文件：[contest_sum_eof.ru](../examples/contest_sum_eof.ru)

给定零组或多组整数对。按输入顺序，分别输出每一对整数的和。

输入：以 ASCII 空白分隔的整数，每连续两个数构成一组，不提供组数；每个数的绝对值不超过 `10^9`。保证整数个数为偶数。换行只是分隔符，一行可以有多组，空输入合法。

输出：每组的和占一行；空输入不输出内容。

输入样例：

```text
1 2
-5 8
0 0
```

输出样例：

```text
3
3
0
```

解法：先读左数，明确比较 `左 == 空` 才结束；再读右数、相加、输出。时间为输入长度的线性量级；除整份输入及输出缓冲外只保存常数个值。奇数个数、非数字词等不属于题目合法输入，示例不尝试纠正。

## 练习二：区间账本

源文件：[contest_prefix_sum.ru](../examples/contest_prefix_sum.ru)

有一列整数，回答若干闭区间内元素之和。位置从 1 开始编号。

输入：第一部分为整数 `N Q`，随后是 `N` 个整数，再随后是 `Q` 对整数 `L R`。所有部分用 ASCII 空白分隔，不要求实际行数。范围为 `1 ≤ N ≤ 200000`、`0 ≤ Q ≤ 200000`、每个元素绝对值不超过 `10^6`，每次询问满足 `1 ≤ L ≤ R ≤ N`。

输出：依次输出每次询问的区间和，每个答案占一行。`Q = 0` 时没有输出。

输入样例：

```text
5 4
3 -2 7 0 5
1 5
2 4
3 3
4 5
```

输出样例：

```text
13
5
7
5
```

解法：`前缀[0] = 0`，逐项把累计和追加到阵。询问答案是 `前缀[R] - 前缀[L-1]`。如的阵是 0 起点；这道题显式保留一个空前缀，才能直接用题目的 1 起点位置。时间 `O(N + Q)`（另加读取输入的时间），辅助阵空间 `O(N)`；最大答案绝对值为 `2 × 10^11`。

## 练习三：逐行数词

源文件：[contest_line_words.ru](../examples/contest_line_words.ru)

对输入中的每一行，输出这一行包含的词数。一个词是由至少一个非 ASCII 空白字符组成的最长连续片段；标点也是词的一部分，不做自然语言分词。

输入：有效 UTF-8 文本，不含 NUL，总输入不超过 1 MiB。ASCII 空白包括空格、Tab、CR、LF、VT、FF。LF 结束一行，紧贴 LF 之前的一个 CR 一并去掉；独立 CR 不分行。最后非空的未终止片段也是一行。允许空输入和空行；末尾 LF 不额外创造一行。全角空格和不换行空格不是这里的分词符。

输出：每行一个非负整数。空行输出 `0`；空输入没有输出。

输入样例（第二行为空行）：

```text
青山 白云

  alpha   beta gamma  
末行
```

输出样例：

```text
2
0
3
1
```

样例的末行有无 LF，结果相同；若还多出一个 LF，则另有一个真正的空行，须再输出 `0`。实现先 `入 其 行`，再 `拆词 文`，因此不会把空行误认为 EOF。时间为输入长度的线性量级；除了整份输入与输出缓冲，临时拆分空间与当前行长度成正比。

## 练习四：保留先后次序的成绩单

源文件：[contest_stable_records.ru](../examples/contest_stable_records.ru)

读入若干条姓名与分数记录，按指定方向对分数排序。分数相同的记录必须维持输入时的先后次序；不能改按姓名排序。

输入：先给出整数 `N D`，随后给出 `N` 组 `姓名 分数`，均用 ASCII 空白分隔。`0 ≤ N ≤ 200000`；`D = 1` 表示升序，`D = -1` 表示降序；分数是绝对值不超过 `10^6` 的整数。姓名是非空、不含 ASCII 空白或 NUL 的有效 UTF-8 词，可重复。总输入不超过 8 MiB。

输出：排序后的每条记录占一行，格式为姓名、一个 ASCII 空格、分数；`N = 0` 时没有输出。

输入样例：

```text
6 -1
阿青 80
小石 95
阿禾 80
小满 95
远山 60
清河 80
```

输出样例：

```text
小石 95
小满 95
阿青 80
阿禾 80
清河 80
远山 60
```

解法：用 `形 记录` 保存姓名和分数，用 `造比较 方向` 返回捕获该方向的算闭包。比较器返回 `(左分 - 右分) × 方向`：负数表示左项先，零表示同序，正数表示右项先。给 `排序` 的是算的函数值，不是一次比较的结果。

`排序` 返回新的浅复制阵，保持原阵顺序；阵里的记录对象仍与原阵共享。稳定性由排序库保证，无需额外添加输入序号。比较器应当纯粹，不能依赖调用次数或靠修改记录改变排序关系。排序需要至多 `O(N log N)` 次比较，额外阵空间 `O(N)`，再加整份输入及记录本身。比较器的调用次数和顺序不保证在两后端相同。实际耗时还包含动态值、闭包调用与回收等开销，应按题目限制实测。

## 常用接口速查

下面均是 `尽取 外言 '如:竞'.` 之后的普通算；也可用 `竞 其 名称`。需要把函数本身交给另一个算时，使用 `算 名称` 或 `算 竞 其 名称`。

比较器也可直接使用匿名算字面量，例如：

```ru
尽取 外言 '如:竞'.
原列 取 [3, 1, 2].
结果 取 排序 原列 (算 左 为 数 右 为 数: 得 左 - 右. 法).
显 结果. # [1, 2, 3]
```

这里 `法` 关闭比较器，右括号关闭分组，最终句点结束赋值；匿名正文中的 `得` 自己仍有句点。匿名比较器与有名比较器有相同的有限数返回要求和共享词法捕获规则。

| 调用 | 用处 |
| --- | --- |
| `读入` | 读完标准输入，得到读流 |
| `扫句 文` | 在已有句上建立独立游标 |
| `拆词 文` | 按六种 ASCII 空白拆成句阵，不保留空词 |
| `拆行 文` | 按读流的行规则拆成句阵，保留真正空行 |
| `字列 文` | 拆为 Unicode 码点句阵，不按 UTF-8 字节或视觉字形拆 |
| `合句 列 隔` | 用分隔句连接句阵；数字要自己 `为 句` |
| `排序 列 比较` | 按算比较器稳定排序，返回新浅阵 |
| `取整 值` | 向零截断，`取整 (-2.9)` 为 `-2` |
| `整除 左 右` | 先 binary64 除法，再向零截断；除零报错 |
| `小 左 右` / `大 左 右` | 两数中较小 / 较大者 |
| `绝对 值` | 数的绝对值（保留原有负零显示行为） |
| `蓄出` | 建立有界标准输出缓冲 |

读流成员为 `词`、`数`、`行`，无参数；出流成员为 `写 内容:句`、`行 值:句或数`、`清`，成功返回 `空`。例如：

```ru
尽取 外言 '如:竞'.
入 取 扫句 '12 rest\r\n\n尾\r'.
显 入 其 数.   # 12，游标停在 12 后面的空格
显 入 其 行.   # ' rest'，不丢弃词后面的分隔空格
显 入 其 行.   # ''，真正的空行
显 入 其 行.   # '尾\r'，末尾没有 LF，因此保留 CR
显 入 其 行.   # 空
```

在混合读数与读行时，词后分隔符尚未被消费。如果只想读取下一整行，须先读掉当前行剩余部分；不要无条件“跳过一行”而丢掉有效内容。

## 让「如是我言」先写一个解法

把题目、完整输入输出格式、数据范围和样例写入意图文档，再补充这些约束：

```text
请用当前规范的如，导入 外言 '如:竞'，解答上面的题目。
只向标准输出写题目要求的答案，不写提示语。
使用读入与蓄出；EOF 明确比较空，结束前调用出流的清。
只用当前规范提供的接口，不假设有 int64 或填充数组；映射使用内置典及其现有接口。
如使用匿名比较器，写 算 左 为 类型 右 为 类型: … 法，不写箭头或括号参数表。
如是我言
```

配置生成服务后执行 `python3 ru generate 题目.md -o 解答.ru`。生成工具每次附带当前完整语言规范，先检查再保存，默认不执行。随后仍须阅读代码、运行样例和边界测试，再 `build --emit-c`。`generate` 会访问已配置的在线服务；`check`、`run`、`build` 不因此联网。未配置服务时直接参考四个手写解法即可。

## 当前范围与容易踩的坑

- `数` 始终是 binary64。连续整数的精确范围止于 `2^53`；大整数、`int64` 和位运算尚未实现。默认显示使用约 `.15g` 的 15 位有效数字，即使内部恰好存得下一个大整数，输出也可能舍入或采用科学计数法
- 有精确 64 位整数、大模数乘法或严格小数位格式要求的题，不能直接套此模板。`整除` 是浮点除法后截断，不会恢复已经丢失的精度
- 不存在数组长度填充构造。重复对象时应在 `循` 内逐次 `新` 再 `增`，避免重复保存同一引用
- `读入` 必须先读到 EOF，不能当作交互式评测输入；需要逐行可检查 I/O 时使用原有 `读取 其 读`
- 缓冲内容不会在 `卒`、错误、返回、垃圾回收或进程结束时自动兜底输出。正常路径要显式 `清`；与 `显`、其他出流混用时，也须先清，才能保持预期输出顺序
- 字符串仅支持 Unicode 文本。`字列` 按码点拆分，组合字符和 emoji 序列可能包含多个元素
- 新库没有新增保留词或调用语法；Emacs 模式识别新的内置桥接名及读写成员，普通库函数名仍可用于用户自己的声明
