# 如观：在如书里画图与互动

如观是如书的二维绘图模块。第一版提供形状、文字、颜色、逐帧动画和鼠标／键盘回调，便于把数据和算法变成可观察、可操作的画面。

它借鉴 Processing 的画图与事件模型，不执行 Processing.js 程序，也不承诺与其 API 完整兼容。实现使用浏览器 Canvas 和原有 Python 如言会话；回调仍是如言的算／作，不是拼接执行 JavaScript。

## 从一幅柱状图开始

在如书的代码格中运行下例。普通命令行及 C／JavaScript 编译目标目前不提供画布；请不要把图形程序当成会自动弹窗的桌面程序。

```ru
观 取 外言 '如观'.
图 取 观 其 画布 480 280.
图 其 背景 '#f4f6fb'.
图 其 描边 空.
图 其 填色 '#4677ff'.
图 其 矩形 60 160 80 60.
图 其 矩形 200 100 80 120.
图 其 矩形 340 40 80 180.
图 其 填色 '#202530'.
图 其 字号 18.
图 其 文字 '甲：10' 60 250.
图 其 文字 '乙：20' 200 250.
图 其 文字 '丙：30' 340 250.
```

坐标原点在画布左上角，横坐标向右增加，纵坐标向下增加。矩形／椭圆使用外接框的左上角和宽高。文字位置是文字框左上角。

颜色写成 `'#RRGGBB'`，例如 `'#ff8800'`。`填色 空` 表示不填充，`描边 空` 表示不描边；背景必须指定颜色。第一版不提供图像、音视频、三维或外部资源加载。

## 动起来，再加入互动

在一个新代码格中完整运行下例。圆点随帧前进，鼠标点击会改变填色；聚焦画布后按空格暂停，按 `r` 继续。帧率是请求上限，回调较慢时实际速度会降低。

```ru
观 取 外言 '如观'.
图 取 观 其 画布 480 240.
图 其 描边 空.
图 其 填色 '#4677ff'.
图 其 帧率 20.
图 其 每帧 (作 帧:
    图 其 背景 '#f4f6fb'.
    图 其 椭圆 (帧 % 440) 90 40 40.
为).
图 其 鼠标按下 (作 横 纵 键:
    图 其 填色 '#ef476f'.
为).
图 其 按键 (作 键:
    若 键 == ' ' 则 图 其 停. 然
    若 键 == 'r' 则 图 其 继续. 然
为).
```

`每帧` 收到从 1 开始的帧序号，不是秒数。它不是固定实时计时器；如需基于时间的模拟，应等待后续明确的计时接口，而不要把“帧数／目标帧率”误认为真实经过时间。

回调可用算或作，返回值被忽略。参数名字可自行取，数量必须匹配。例如鼠标按下的三个参数依次是横坐标、纵坐标、鼠标按钮编号。

## 接口速查

模块导入名是精确的 `'如观'`；没有 `'如:如观'` 别名。这里用 `观 取 外言 '如观'.` 绑定模块，便于在同一会话反复运行；不要用重复 `尽` 导入来重建画布，以免触发已有名称冲突规则。

| 调用 | 用途 |
| --- | --- |
| `观 其 画布 宽 高` | 创建本次活动画布 |
| `图 其 背景 色` | 清除此前图形并设置背景 |
| `图 其 填色 色` / `图 其 描边 色` | 设置后续图形样式，空取消 |
| `图 其 线宽 粗` / `图 其 字号 大小` | 设置线宽和文字大小 |
| `图 其 矩形 横 纵 宽 高` | 绘制矩形 |
| `图 其 椭圆 横 纵 宽 高` | 绘制椭圆；宽高相等时为圆 |
| `图 其 线 横一 纵一 横二 纵二` | 绘制线段 |
| `图 其 文字 文 横 纵` | 绘制句内容，不解析 HTML |
| `图 其 宽` / `图 其 高` / `图 其 帧` | 读取画布大小／当前帧序号 |
| `图 其 帧率 率` | 设置 1～30 的整数帧率上限 |
| `图 其 每帧 回调` | 注册一参回调，并开始动画 |
| `图 其 鼠标按下 回调` / `图 其 鼠标松开 回调` | 注册三参回调：横、纵、按钮 |
| `图 其 鼠标移动 回调` | 注册二参回调：横、纵 |
| `图 其 按键 回调` / `图 其 松键 回调` | 注册一参回调：键名句 |
| `图 其 停` / `图 其 继续` | 暂停／继续逐帧动画；暂停时仍可响应输入 |
| `图 其 关闭` | 终止画布交互，释放回调 |

这些是普通成员调用，零参成员不要再加一组 `()`。同一种事件再次注册会替换之前的回调。

## 一帧、一个会话的边界

- 每个回调提交完整画面；每帧都应重新绘制本帧需要的背景和图形，不依赖上一帧的像素残留。
- 输入回调如果只修改数据或样式而不画图，会保留当前画面；如果画图，则应绘制想保留的整个场景。没有每帧回调的静态画布也可以响应已注册的输入事件。
- 第一版每个会话只有一个活动画布。创建新画布、运行另一个代码格或停止／重启会话，会关闭旧交互；旧输出可继续作为静态画面展示。请把画布创建和回调注册放在同一个绘图格里。
- 可以先在前面的格中准备数据，再运行绘图格。之后修改数据格会关闭当前交互，需要重跑绘图格。
- 暂停动画不同于停止会话。`停` 保留鼠标／键盘回调；关闭后的画布不能再通过旧变量继续绘图，应重新创建。
- 书本、历史源码和图形运行状态不是同一件事。保存书本不保存闭包、正在运行的动画或会话变量；重新打开时不会自动执行图形代码。

## 限额与出错

- 画布宽高各为 1～2048 的整数；坐标须为 ±100000 内有限数，形状宽高为 0～100000，线宽和字号为 1～256。
- 每帧最多 2048 条绘制命令，数据大小不超过约 256 KiB；单条文字最多 4096 个 Unicode 码点。
- 浏览器按实际 canvas backing 宽高限制总计 16 Mi 像素（约 64 MiB RGBA 像素存储，不是浏览器总内存上限）；较旧画面暂存为命令，点「重新查看画面」仅恢复静态绘制，不执行回调，保存的数据不丢失。
- 回调预算为 100 毫秒／50000 Python 跟踪行／64 MiB 新增分配（并非如源码行）；支持 RLIMIT_AS 的平台还在回调期间使用 512 MiB 地址空间上限。1 秒硬看门狗能终止阻塞进程并重启，会清空全部会话变量。预算触发会关闭交互并报告错误；请缩小数据、简化回调，再重跑绘图格。
- 鼠标移动及动画请求会节流，不保证交付每一个物理输入事件，也不保证每秒准确收到指定数量的帧。
- 不要在回调里等待终端输入或执行长时间任务。资源限制是本机运行保护，不是运行不可信代码的安全沙箱；如言程序仍可能使用文件等已有能力。

## 如竞迁移

原 `'如:竞赛'` 模块现改名为 `'如竞'`。公开算法保持原义，例如 `读入`、`字列`、`合句`、`排序`；请更新导入字符串。原导入名会给出迁移提示，不保留兼容别名。

如竞与如观的用途不同：如竞仍可用于命令行与竞赛程序；如观第一版的画布交互仅在如书中运行。普通竞赛程序无需导入如观。

## 可验收的完整示例书

打开 `rushu/examples/ruguan.rushu.json`，先运行共享阵的数据格，再运行柱图格。柱高及位置从阵计算；点击柱所在列加五，按 r 恢复原数据。这条路径包含真实如回调读写与重新绘图。源码也可查看 [interactive-bars.ru](../rushu/examples/ruguan/interactive-bars.ru)。
