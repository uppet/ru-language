# 如语言规范 0.10.0

规范版本：0.10.0

适用实现：本仓库如工具链 `0.10.0`（元初实现）；源码扩展名惯例为 `.ru`；文档编码为 UTF-8。

本文件是供学习者、实现维护者与源码生成模型共同使用的**单一版本化语言规范**。它规定当前已经实现的语言、标准 I/O 和工具入口，不以中文词语的日常含义推导额外能力。模型生成如源码时必须遵守本文件；用户意图不能改变关键字、类型、求值规则或凭空增加库。

## 1. 地位、用语与实现边界

### 1.1 当前要求与原型选择

文中的“必须”“只能”“报错”描述本版可执行约束。“默认”描述本版明确采用、但未来可能修改的选择，例如双精度数、位置调用绑定方式、字段缺省为空、文件写入默认截断。本文件是 **0.10.0 的实现规范，不是已经冻结的永久语言标准**；未来改变应更新版本、实现、测试及规范，不能让生成模型自行猜测。

解释器使用 Python 3.10+ 标准库；原生后端把 AST 直接降为 C99，再调用 Clang、GCC 或兼容编译器。原生程序包含运行时动态值操作，不包含如词法分析器、语法分析器或源码解释器，执行时不需要 Python、`ru`、原 `.ru` 文件、项目头文件或生成的 `.c` 文件。它仍依赖构建目标的系统和运行库。

JavaScript 后端同样把 AST 直接降为 JavaScript 函数、表达式和控制流，输出内联运行时的独立 CommonJS 文件，目标为 **Node.js 18+**，不是浏览器脚本。执行只需 Node 及其内置标准库，不需要 Python、`ru`、项目文件、npm 包或原 `.ru` 依赖；静态外言在构建时打包。输出不嵌入如解析器或 AST 解释器，不通过 `eval` / `new Function` 解释如源码。数仍遵守本规范的 IEEE-754 双精度语义，不自动变为 BigInt。此实现尚未自举。

三种执行路径使用本规范的相同语言接口；垃圾回收、平台文件权限、最大调用栈与可用资源由各宿主实现决定。Node 的栈溢出会作为运行错误退出，不保证与 Python / C 相同的最大递归深度。JavaScript 目标不添加 DOM、异步、JavaScript FFI 或任意库调用。

编译输出默认做保守的依赖裁剪，不改变源码语法或上述语义。C 保留生成代码可达的运行时函数及传递依赖，并按完整模块图的成员名称保留分派分支；根据可达构造器可省略不可能存在的对／阵路径，根据全模块图可省略未使用的用户形查找与「卒／试」传播状态；C / JavaScript 都可移除能证明未被引用的随附标准库声明。分析考虑别名、闭包、函数引用及转导出；模块值逃逸或无法确定时保留所需的保守集合。用户声明、用户模块及初始化副作用不会作为标准库裁剪对象，完整原始依赖图仍先接受检查。C 输出保持可读、独立，不做代码压缩或题目专用替换。JavaScript 另外只在未引用时省略可选 I/O / 竞赛运行时区段。第 12 节的 `--full-runtime` 可关闭这些裁剪以供诊断。

`check`、`build` 和生成结果检查会解析整个依赖图，检查结构及可静态识别的函数调用；它们**不是完整静态类型检查器，也不是安全审计或执行沙箱**。未定义的普通变量、实际参数类型、字段值、索引、除零、路径权限等仍可能在运行时报错。检查通过不等于所有路径可运行、程序终止或程序安全。

### 1.2 可观察行为与错误

- 文件执行按语句顺序进行；函数和形声明预先登记以支持前向引用，导入和其他有副作用的语句仍按实际执行顺序生效
- 普通语法、结构、编译、类型及运行错误会终止该次文件执行。REPL 报告后通常继续接收下一段输入
- 只有显式 `卒` 能由 `救` 恢复；受检查 I/O 失败返回成果对象，不自动 `卒`
- 参数及字段类型不匹配报告期望类型与实际收到的类型，参数诊断标明函数和参数名，字段诊断标明字段名；不一律建议 `为 类型` 转换。用户形、算 / 作和带元素约束的阵不是通用转换目标。
- 错误文字可随后端或操作系统变化。前端/解释器通常报告文件、行、列；原生普通运行错误主要报告文件和行，未救之卒还保存原始来源位置。不要依赖完整诊断文字进行业务判断
- 语法错误、运行错误或 `卒` 均不会撤销之前已完成的绑定、对象修改或 I/O。错误发生后的后续语句不继续执行，除非进入匹配的 `救`
- 普通调用的成功路径与可恢复 `卒` 的求值顺序按第 4 节。对于本来就无效的程序，不依赖各后端对普通错误的检查时机及错误前实参副作用完全一致；编译器可能更早拒绝整段程序

## 2. 源码、词法与名称

### 2.1 编码、空白和注释

文件源码为有效 UTF-8，文件开头允许 UTF-8 BOM。词法分析器把 Unicode 空白视为空白；换行没有结束语句的含义，缩进用于阅读而非语法。位置中的列号按源码 Unicode 字符计数。

`#`、`//` 或 `批.` / `批。` 从字符串外开始到行尾为注释，允许接在代码后。`/` 是除法；相邻两个 `/` 开始注释，语言没有整数除法 `//`。

`解.` / `解。` 开始非嵌套块注释，以首个 `释.` / `释。` 结束，可跨行。块内引号、关键词、`如是我言` 和新的 `解.` 都只是文字；即使结束标记出现在看似字符串的文字内，也立即关闭该块。字符串内的所有注释标记均为普通文字。

中文标记中字与句点必须紧邻，不能写 `批 .`、`解 .` 或 `释 .`；开始标记仅在词法名称边界识别，`批评`、`解释`、`总批` 等完整名称不被拆开。`批`、`解`、`释` 不新增为保留字。块内结束标记直接按原文寻找，不要求名称边界。标记中的句点属于注释，不替代前一条源码语句的结束符，例如应写 `显 1. 批. 说明`。文件中的未闭块在开始位置报语法错误；REPL 则继续等待结束标记。

```ru
批. 本行不执行
显 1. 批。 行尾说明
解。 多行说明；可以包含若、法和引号。
这里仍在注释中。释.
显 '解. 字符串不开始注释'.
```

简单语句以 `.` 或 `。` 结束。多余句点是允许的空语句。声明及控制流块结束词 `法`、`为`、`然`、`环`、`象`、`终` 后允许一个句点，也可以不写；外层还可接空语句。匿名函数 / 过程字面量是表达式，其 `法` / `为` 只关闭字面量，不消费句点；随后句点属于外层简单语句，见 4.6。

以下全角标点与 ASCII 标点等价：`。` → `.`、`：` → `:`、`（` → `(`、`）` → `)`、`，` → `,`、`［` → `[`、`］` → `]`。全角算术符号没有这种替换规则。成员分隔符是 `其` 或 ASCII `@`，不是点号。

### 2.2 名称与保留字

名称以 `_` 或 Python Unicode `isalpha()` 判定的字母起始，后续由 `_` 或 Unicode `isalnum()` 判定的字母/数字组成。名称大小写敏感，不做 Unicode 规范化；组合附加符并不因为视觉上属于字母就自动可用于名称。ASCII 数字不能开头；emoji 不属于名称字符。

词法采用最长名称：`为乐` 是一个名称，不能拆成关键字 `为` 加 `乐`。相邻的中文名称或关键字应以空白或标点隔开；`值取3` 不是 `值 取 3`。`信@含`、`左+右` 可以紧贴运算符。

本版完整保留字集合如下，不能作普通名称：

```text
显 取 为 得 完 破 若 则 另 然 循 次 环 算 作 法 其
且 或 非 空 真 假 典 成 对 形 象 如 新 外言 尽 试 救 卒
```

另有**受保护的内置名称** `读`、`件`、`录`、`件作成果`、`读取`、`显出`、`错误`、`__竞赛`，不可声明同名顶层函数/形，不可用作绑定或参数名。它们不是上述词法保留字；例如对象可以有名为 `读取` 的方法。

`数`、`句`、`阵`、`事实` 是类型写法，不是词法保留字，也不是可直接求值的内置类型对象；不要为了生成代码方便而把它们当作构造函数。自定义形名不得为 `数`、`句`、`阵`、`事实`、`典`。`典` 同时是保留字与内置类型；`典:` 才开始典字面量。标准成员词 `含`、`位`、`段`、`增`、`量`、`囫`、`囵` 与 `查`、`除`、`列` 使用普通成员调用语法，不是全局保留字。`元初` 在主文件入口位置有特殊约定，其余使用服从普通名称规则。竞赛库导出的 `读入`、`排序` 等是普通函数名，须先导入；它们不是全局保留字。`__竞赛` 仅为内部桥接，不作为应用接口，见 11.7–11.11。

`终` 是**上下文结束词**，没有加入保留字集合：在 `试` 或 `救` 的正文等待下一条语句时，它关闭当前恢复块；其他名称位置仍可使用它，例如顶层 `终 取 2.` 和 `其 段 始:0 终:2`。因此不要在恢复块中用以 `终` 开头的语句表示变量操作；生成代码建议始终另选变量名。字符串 `'终'` 不结束块。

### 2.3 字符串字面量

支持四对引号：`'…'`、`"…"`、`‘…’`、`“…”`；弯引号必须使用匹配的右引号结束。允许真实换行。支持且只支持下列反斜杠转义：

| 转义 | 值 |
| --- | --- |
| `\n` | LF 换行 |
| `\r` | CR 回车 |
| `\t` | 制表符 |
| `\\` | 反斜杠 |
| `\'`、`\"`、`\’`、`\”` | 相应引号字符 |

未知转义报错；没有 `\uXXXX`、`\xNN`、插值或原始字符串语法。请直接在 UTF-8 字符串中写 Unicode 字符。字符串不能包含 NUL；`\0` 也不是合法转义。字符串值不可变，不自动合并相邻字面量。

### 2.4 数字字面量

无符号字面量的词法形式为：

```text
([0-9]+ ('.' [0-9]+)? | '.' [0-9]+) ([eE] [+-]? [0-9]+)?
```

正负号是独立的一元运算符。因此 `1`、`-2.5`、`.5`、`1e3`、`2.5E-1` 可用，十六进制、二进制、数字下划线、中文数词与全角数字字面量不可用。源码 `1.` 读成数字 `1` 加语句结束符，不能依靠尾随小数点构成浮点字面量。字符串转数另有允许 `'1.'` 的规则，见第 5 节。

每个数都是有限 IEEE-754 binary64 双精度浮点数。字面量溢出为非有限数时拒绝；很小的数可能舍入/下溢为零。没有独立整数、大整数或十进制定点类型；`事实` 是独立的真假类型，不属于数。约 15 位十进制有效数字后应考虑精度损失；不应用于需要精确金额或任意精度整数的计算。`0` 与 `-0` 比较相等且均为真；显示可以保留负零符号。

## 3. 文法概览

下面的 EBNF 说明结构，需同时遵循第 4 节的 Pratt 优先级和调用边界；不能把其中 `调用实参` 简化为其他语言的圆括号参数列表。`{…}` 表示重复，`[…]` 表示可选，单引号中的字符表示语言终结符，`名称`、`字符串`、`数字` 采用第 2 节。代码内的空白不是强制数量。

```ebnf
程序       = { 语句 | '.' } ;
语句       = 简句 '.' | 算定义 | 作定义 | 形定义 | 条件 | 循环 | 恢复 ;
简句       = '显' 表达式
           | 名称 '取' 表达式
           | 可写目标 '取' 表达式
           | '得' 表达式
           | '破'
           | '卒' 表达式
           | '尽' '取' '外言' 字符串
           | 表达式 ;
算定义     = '算' 名称 { 参数 [','] } ':' 程序 '法' ['.'] ;
作定义     = '作' 名称 { 参数 [','] } ':' 程序 '为' ['.'] ;
算字面量   = '算' { 参数 [','] } ':' 程序 '法' ;
作字面量   = '作' { 参数 [','] } ':' 程序 '为' ;
参数       = 名称 ['为' 类型] ;
类型       = 类型基本名 { '阵' } ;
类型基本名 = 名称 | '空' | '对' | '算' | '作' | '典' ;
形定义     = '形' 名称 ['如' 名称] [':'] { 字段 | 算定义 | 作定义 | '.' } '象' ['.'] ;
字段       = 名称 '为' 类型 '.' ;
条件       = '若' 表达式 '则' 程序 ['另' 程序] '然' ['.'] ;
循环       = '循' [表达式 '次'] 程序 '环' ['.'] ;
恢复       = '试' [':'] 程序 '救' 名称 [':'] 程序 '终' ['.'] ;
原子       = 数字 | 字符串 | '真' | '假' | '空' | 名称
           | '(' 表达式 ')'
           | '[' [表达式 {',' 表达式} [',']] ']'
           | '外言' 字符串
           | '新' 名称 { 命名实参 [','] }
           | '其'
           | ('算' | '作') 引用目标
           | 算字面量 | 作字面量 | 典字面量 ;
典字面量   = '典' ':' { 键表达式 '对' 表达式 '.' } '成' ;
引用目标   = 引用原子 { '[' 表达式 ']' | ('其' | '@') 名称 } ;
引用原子   = 名称 | '(' 表达式 ')' | '其' [名称] ;
显式零参调用 = 表达式 '(' ')' ;
命名实参   = 名称 ':' 表达式 ;
可写目标   = 表达式 '[' 表达式 ']'
           | 表达式 ('其' | '@') 字段名
           | 表达式 ('其' | '@') '位' 索引实参 ;
```

`程序` 在对应块结束词前停止。函数/过程可以直接声明在模块、函数/方法或救的正文中；形内可声明方法。条件、循环及受保护的试正文中不能直接声明函数/过程，不能依靠分支是否执行来条件性建立定义。匿名字面量是表达式，可在这些正文中的表达式位置求值，不受有名声明的位置限制；其内部正文沿用函数 / 过程正文规则。形与 `尽 取 外言` 仍只能位于模块顶层，不能嵌套声明形。

有名函数 / 过程声明及匿名字面量的冒号均必需，形定义的冒号可省略，`试` 和 `救 原因` 后的冒号也可省略。`得` 只能在 `算` 的正文中；`破` 只能在当前函数/过程或顶层自身的循环内，不能跨调用退出调用者的循环。没有无表达式的 `得`、`继续`、`否则若` 或三元表达式语法；需要时在 `另` 中嵌套 `若`。

## 4. 表达式、调用及求值顺序

### 4.1 运算优先级和结合性

从紧到松排列如下。括号可显式限定整个表达式。

| 优先级 | 形式 | 结合规则 |
| --- | --- | --- |
| 80 | `[索引]`、`[始:终]`、空 `()` 显式调用 | 后缀连续应用 |
| 75 | `其 成员`、`@成员` | 后缀；标准成员实参见下文 |
| 70 | 一元 `+`、`-`、`非` | 作用于右侧表达式 |
| 60 | `*`、`/`、`%` | 左结合 |
| 50 | `+`、`-` | 左结合 |
| 40 | `<`、`<=`、`>`、`>=` | 左结合，不是数学链式比较 |
| 30 | `==`、`!=` | 左结合 |
| 20 | `且` | 左结合、短路 |
| 10 | `或` | 左结合、短路 |
| 7 | `对` | **右结合** |
| 5 | `为 数`、`为 句`、`为 阵` | 作用于已形成的左侧表达式 |

调用在读取名称原子时识别，实参具有特殊的向右贪婪规则，不能简单理解成“调用永远比算术紧”。例如 `平方 2+1` 的唯一实参是 `2+1`；`(平方 2)+1` 才把结果加一。

转换结合左边的完整较高优先级表达式：`1+2 为 句` 是 `(1+2) 为 句`。`1 对 2 对 空` 是 `1 对 (2 对 空)`。`1<值<5` 按左结合普通运算求值，不是区间测试；应写 `1<值 且 值<5`。

### 4.2 位置调用、命名调用及零参数调用

```ru
算 平方 根 为 数:
    得 根*根.
法
算 差 左 为 数 右 为 数:
    得 左-右.
法
显 (平方 9.9).
显 (平方 根:9.9).
显 (差 9 4).
显 (差 右:4 左:9).
```

- 位置实参按声明顺序匹配；命名实参按参数名匹配，顺序可变
- 一个调用只能全位置或全命名，不能混用；参数名不可重复，未知或缺少的参数报错
- 普通用户函数/方法没有缺省参数、可变参数或重载；参数数量必须完全匹配
- 多个实参可用空白或逗号分隔。每个实参尽量读取完整表达式，直到不能继续或遇到下一个实参边界
- 在一个普通实参中嵌套带实参调用时，必须加括号：`差 (平方 3) (平方 2)`，或 `差 左:(平方 3) 右:2`。`差 甲 乙` 中的 `甲`、`乙` 分别是实参，不自动解析成 `差 (甲 乙)`
- 裸声明函数/过程名称保留零实参自动调用；普通变量/参数名称读取值，即使其中保存函数值也不自动调用。取得声明的函数/过程本身写 `算 名` / `作 名`；调用保存的零参函数值写 `回调()`，见第 4.5、6.4 节
- `+`、`-` 不在名称后直接开启第一个位置实参，以保留 `变量-2` 与 `零参函数-2` 的算术含义。第一个负数/正号实参加括号，例如 `平方 (-2)`。后续负数可写 `差 2 (-3)` 或 `差 2, -3`；`差 1 -2` 只有实参 `1-2`
- 命名实参可直接带符号：`平方 根:-2`
- 空 `()` 是显式零参调用。非空 `函数(表达式)` 仍可被读作“函数加一个括号表达式实参”，不是传统参数列表；`函数(甲,乙)` 仍不成立。多参统一写 `函数 甲 乙` 或 `(函数 甲,乙)`
- 函数返回结果再参与外围运算时，优先使用 `(调用) 运算符 …`，避免实参吞入外围运算

### 4.3 索引、成员与名称空白

`列[0]` 中名称和 `[` 同一行紧邻时，解析为索引；`求和 [1,2]` 中的数组是位置实参。写数组实参时推荐保留空白，复杂情况使用 `求和 ([1,2])`。普通表达式后也能应用索引，例如 `([1,2])[0]`。典的 `表[键]` 是 `表 其 查 键` 的读取简写，按键查找而非数值位置；缺失返回 `空`，详见第 7.6 节。

`其` 与 `@` 是相同的成员访问/调用操作。为提高可读性和减少贪婪调用歧义，推荐 `对象 其 方法`；对复杂接收者加括号，如 `(取得对象 1) 其 字段`。

所有成员使用普通实参语法，参数名字与数量由接收者决定，不按 `增`、`查`、`量` 等名称全局固定。例如阵的 `增 值` 接受一参，典的 `增 键 值` 接受两参；对象可以定义同名的其他签名。

- `列 其 增 1+2` 等于 `列 其 增 (1+2)`，追加 3
- `列 其 位 位置+1`、`列 其 段 (起点+1) (终点-1)` 使用完整表达式实参
- 命名调用继续要求全部命名，不得混用位置参数
- 嵌套调用参数必须适当加括号，如 `'甲' 其 含 (回 '甲')`
- 成员结果再参与外层运算时加括号，如 `(列 其 位 0)+2`；继续成员调用也可用 `(链 其 囵) 其 囫`

0.10.0 移除了旧标准成员专用的紧结合与固定签名限制。旧代码依赖 `列 其 位 0+2` 先取第 0 项再加 2 时，须改为 `(列 其 位 0)+2`。

### 4.4 求值顺序

在合法调用中，接收者先求值，实际参数按**源码从左到右**求值，再按声明名字/位置绑定；命名实参不按声明顺序重排求值。构造字段值和数组元素也按源码顺序求值。普通二元操作先左后右；`且`、`或` 例外地短路。索引先求接收者再求索引，切片先接收者、始、终。

赋值先求目标接收者和索引，并检查目标可写且索引有效，再求右侧值；目标不合法时不执行右侧副作用。右侧若 `卒`，该次赋值尚未发生，但此前已完成的副作用保留。名称绑定在右侧成功后才更新。

求值过程中发生 `卒` 时，未求值的后续操作数、实参和语句不执行，直接沿调用栈寻找匹配 `救`。不要依赖普通类型/结构错误前的副作用时机，见 1.2。

### 4.5 函数引用与通用调用

`算 名` 取得算的函数值，`作 名` 取得作的过程值，取得时不执行正文；引用种类必须与目标声明一致。`算 名.` 在语句位置是引用表达式语句，不是定义；`算 名:`、`算 名 参数:` 或 `算 名 参数 为 类型:` 才开始有名定义，作同理。

调用函数值沿用已有规则：保存为变量后写 `回调 实参`，显式零参数写 `回调()`。普通变量的裸名字仍然是值；例如 `显 回调.` 显示函数值，而 `显 回调().` 执行后显示结果。直接声明的零参函数裸名字保留自动调用兼容性。

索引、括号表达式或对象字段取得的函数值也可被调用，如 `回调们[0] 3`、`(回调) 3`、`(算 平方) 3`、`对象 其 回调 3`；无参形式分别可用 `回调们[0]()`、`(回调)()`、`对象 其 回调()`。这些是对值的调用，参数仍为全位置或全命名、从左到右求值；非函数值被调用时报普通运行错误。

用户方法引用写 `算 对象 其 方法` / `作 对象 其 方法`，保存接收者，使以后调用仍作用于同一对象。模块函数引用写 `算 模块 其 函数`；读取值为函数的字段也可通过相同引用形式检查其算/作种类。方法内部可使用自身作为引用接收者。普通成员访问仍保持原有方法调用语义，取方法本身必须显式引用。

`算 列[0]` 可从阵元素取得并检查函数值；`算 (对象表达式) 其 方法` 可取得计算接收者的方法引用。引用目标中实际写出的计算或调用会正常执行，但最终选中的函数本身不因取引用而执行；单纯给名称/成员加括号不等于调用它。分组一个引用推荐写 `(算 某声明函数)`，计算后再取函数值则可写 `算 (造函数())`。接收者 / 被调用值先于实参求值，避免以实参副作用改变本次已选中的闭包。

本版引用范围为用户声明的函数/过程、用户方法与保存的函数值；不提供 `读`、集合标准成员、内置 I/O 方法、竞赛读流/出流成员的函数引用。`如:竞赛` 导出的普通算可正常取引用，见 11.7。匿名字面量见 4.6；没有箭头函数或通用反射语法。动态函数值的具体签名不能总在 `check` 中确定，实际调用仍进行参数数量、名字和类型检查。

### 4.6 匿名函数 / 过程字面量

表达式位置的 `算 参数 为 类型: … 法` 创建匿名函数值；`作 参数 为 类型: … 为` 创建匿名过程值。省略的是定义名，参数裸写为 `名称` 或 `名称 为 类型`，可以用空白或逗号分隔并混用有类型与无类型参数。省略类型的参数接受任何运行时值，包括 `空`；显式注解继续检查类型。没有参数时写 `算: … 法` 或 `作: … 为`。冒号不可省略，不使用箭头，也不在参数序列外添加圆括号。

```ru
平方 取 算 值 为 数: 得 值 * 值. 法.
问候 取 作 名 为 句: 显 ('你好，' + 名). 为.
报到 取 作: 显 '到了'. 为.
显 (平方 4).       # 16
问候 '小如'.      # 你好，小如
报到().           # 到了
```

消歧须识别完整头部：`算:` / `作:`，或完整的参数头（如 `算 值:`、`作 内容 次数 为 数:`）开始字面量；`算 名称` / `作 名称` 本身仍是引用。语句位置的 `算 名称:` / `作 名称:` 仍是零参有名声明；带参有名声明可写 `算 名称 参数:` / `作 名称 参数:`，也可在参数后显式标注类型。因此 `值 取 算 参数: … 法.` 是匿名表达式，而独立的 `算 参数: … 法` 是零参有名声明。没有头部冒号的 `算 名称 为 句` / `作 名称 为 阵` 仍是原有的引用加转换，不会变成不完整字面量。引用目标的圆括号规则保持不变：`算 (表达式)` / `作 (表达式)` 不会解释为匿名参数表。

无类型参数头可能与引用后的命名实参重叠，例如 `算 回 值:1.`。消歧优先采用具有完整正文及对应结束词的有名声明或匿名字面量；若不能形成完整声明／字面量，而整段可按既有引用调用解析，则保留引用调用。位置引用调用 `算 回 值.`、命名引用调用 `算 回 值:1.` 和表达式中的 `显 算 回 值:1.` 均保持原有含义：取得 `回` 的函数值后调用它。单凭实参名后的冒号不会把一个完整引用调用改成未闭合字面量；需要清楚分组时仍可写 `(算 回) 值:1`。

```ru
算 回 值: 得 值. 法
算 回 值:1.
显 算 回 值:2.             # 2
内容 取 3.
显 算 回 内容.             # 3
显 ((算 回) 值:4).         # 4
```

字面量的 `法` / `为` 只关闭这个表达式。上例最终句点属于赋值语句；返回匿名值时写 `得 算 … 法.`，句点属于 `得`。作为实参、阵元素或其他子表达式时，结束词后可以继续外层逗号、括号和后续表达式，不要求也不能多插一个“字面量结束句点”；字面量正文内部的简单语句仍须以句点结束。

```ru
算 应用 回调 为 算 值 为 数:
    得 回调 值.
法
显 (应用 (算 值 为 数: 得 值 * 值. 法) 5). # 25
操作们 取 [算: 得 1. 法, 作: 显 '完成'. 为].
显 操作们[0]().
操作们[1]().
显 ((算 值 为 数: 得 值 + 1. 法) 4).      # 5
```

对刚创建的字面量立即带参调用时，用括号先分组字面量，再按原规则写实参：`(算 值 为 数: … 法) 4`，不是 `算 (值 为 数): …` 或 `回调(4)`。零参调用可写 `(算: … 法)()`。调用仍遵守 4.2 的实参边界、全位置或全命名和从左到右求值规则。

每次实际求值字面量都会创建一个新闭包，不提前运行正文，也不提升成有名定义。字面量可赋值、传参、返回、放入阵 / 对 / 字段，或在条件、循环和受保护的试正文中的表达式位置创建。正文可包含嵌套有名声明、匿名字面量和控制流。参数与有名函数采用相同类型 / 数量 / 名称检查；匿名算的实际路径必须 `得`，匿名作不能 `得`，可用 `完.` 提前返回 `空`。`破` 不能跨越匿名函数 / 过程的调用边界。捕获及状态更新完全沿用 6.1、6.4 的共享词法绑定规则。

## 5. 值、转换、算术与比较

### 5.1 值种类与真值

运行时可见值包括 `数`、`句`、`事实`、`空`、`对`、`阵`、`典`、函数/过程值、形的对象和模块值。`真`、`假` 是事实字面量，不是数或空；`假 == 空`、`假 == 0`、`真 == 1` 均为 `假`。不存在把真当作通配相等值的规则。

条件只将 `空` 与 `假` 视为假；其他值均为真，包括 `0`、`-0`、`''`、`[]` 和空典。没有 `true`、`false`、`null` 的内置别名。

`非`、相等和大小比较、标准句包含测试、`且`、`或` 返回事实 `真` 或 `假`。它们不返回原操作数：`空 或 9` 为 `真`。`且` 仅在左侧为真时求右侧，`或` 仅在左侧为假时求右侧；`假 且 (1/0)` 安全短路，`0 且 (1/0)` 会除零。

迁移：用 `值 != 0`、`句 != ''`、`阵 其 量 > 0` 显式判断非零/非空；计数或数值算法不能再直接把比较结果作 0/1。需要数字时用分支显式给出 0/1。旧比较输出、条件、数类型参数与文件 `在` 的结果须同步更新。

### 5.2 转换

仅有以下源码转换：

| 写法 | 行为 |
| --- | --- |
| `值 为 事实` | 按上述真值规则得到真或假；事实保持自身 |
| `值 为 数` | 数保持数；句按严格十进制规则转换；其他值报错 |
| `值 为 句` | 对任何值使用与 `显` 相同的显示格式 |
| `值 为 阵` | 新建只包含该值的单元素阵，不展开、不深复制 |

句转数允许首尾 ASCII 空白（空格、Tab、CR、LF、VT、FF），中间必须符合 `[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)([eE][+-]?[0-9]+)?`。所以 `'1.'` 合法；空串、只有空白、`'0x10'`、`'nan'`、`'Infinity'`、含非 ASCII 数字或内部空白的字符串不合法。结果须有限；没有自动转零或隐式转换。

`空 为 阵` 为 `[空]`；若 `甲` 是阵，`甲 为 阵` 的唯一元素是同一个 `甲`。`为` 不用于把对象强制变成另一形，也不等同于字段/参数声明中的类型要求。

### 5.3 运算

数支持 `+ - * / %` 及一元正负号；除法与余数的右侧为零时报错，非有限结果报错。`%` 使用浮点余数，符号跟随被除数，例如 `-7 % 3` 为 `-1`，不是 Python 的取模规则。

`+` 也允许两个句连接；数字与句混合时必须显式转换。阵拼接、字符串重复、幂、位运算、复合赋值、自增均未实现。除同的相等协议外不支持运算符重载。

`< <= > >=` 只接受两个数或两个句；句按 Unicode 码点字典序比较，不按拼音、区域排序或视觉字形。`== !=` 对任意值可用：

- 不同种类的值不相等；`空` 只与 `空` 相等，和 `'空'`、`0`、`''` 不相等
- 数比较数值，句比较字符序列
- 事实只按真假比较；`!=` 严格是 `==` 的取反
- 对递归按左右项从左至右比较，内部阵/典按身份，对象按下述同协议比较；同一对对象的身份快捷路径不会再遍历内部成员
- 阵、典、函数/过程值、模块按身份比较；两个内容相同但分别创建的阵/典/闭包不相等。同一声明在同一激活环境中重复取得引用是同一闭包；每次求值匿名字面量或建立绑定方法引用得到新函数值，其别名保留该身份

同一具体形的两个实例：若定义或继承 `算 同 另一`，调用左实例的同，以右实例为唯一实参，必须返回事实；无同则按身份相等。不同具体形直接不相等，即使有继承关系或同名方法。显式参数类型按通常规则检查。同须为一参算；错误签名或非事实结果报错。对内嵌实例也沿用此规则。相等协议应由作者保证自反、对称、传递；运行时不会证明这些性质，也不会在编译时执行同。

### 5.4 显示

`显 表达式.` 把显示文本写到标准输出并加一个换行。句原样输出，不加引号；数最多显示 15 位有效十进制数字；事实显示 `真` 或 `假`；空显示 `空`；典显示 `{键: 值, ...}`（顺序不保证）；对显示 `(左 对 右)`；阵显示 `[甲, 乙]`。嵌套容器中的句也不加引号，因此显示文本不保证可再次解析为原值。

对象显示为 `<形 名称>`，模块显示 `<外言>`，函数/过程值分别显示为 `<算 名称>` / `<作 名称>`；容器中发现当前展开路径的循环引用时显示 `<循环>`。这不是序列化协议或调试反射接口。`显` 输出失败属于普通运行错误，不返回成果，不由 `救` 捕获。

## 6. 绑定、作用域、函数与控制流

### 6.1 绑定和作用域

`名称 取 表达式.` 建立或更新绑定，绑定本身不固定类型。读取沿**词法环境**向外查找，不采用调用者的局部变量。顶层绑定属于当前模块；顶层函数/方法以其声明模块为外层，嵌套函数以声明时的函数或救环境为外层；匿名字面量以实际求值时的当前词法环境为外层。

函数体执行 `值 取 …` 时，先更新当前局部已有的同名绑定；若没有，则更新最近的、已经存在的被捕获**非模块**绑定（外层函数或救的绑定）；若仍没有，则在当前函数局部建立绑定。不会用 `取` 修改同名模块全局，只有全局同名值时仍创建局部影子。参数始终在当前调用局部绑定。捕获按共享绑定而非一次性值快照，详细规则见 6.4。

直接执行救正文的 `取` 始终写救的局部，保持原有局部遮蔽；在救中声明的闭包可以读取并更新该捕获救环境。通过共享阵或对象修改内容也仍对所有别名可见。条件与循环不创建作用域；试正文也不创建，救正文创建子作用域，见第 10 节。

函数/过程名和直接声明的形名不可同时作为变量或参数名；参数名不能重复。通过 `尽` 导入的函数/形同样受保护。形名称（包括内置形）不是运行时普通值，只用于类型注解、`新`、`如` 和合法的形导入。`别名 取 某形.` 不合法，不能将形本身显示、比较、放入容器、作为实参或返回值；通过模块成员读取形作为普通值也不合法。形实例、实例别名及函数/过程值仍可正常保存、传参和返回。

### 6.2 函数与过程

`算 名 参数: … 法` 或 `算 名 参数 为 类型: … 法` 声明函数；实际执行路径必须执行 `得 表达式.`，否则报错。返回值不声明类型，可为任何值。允许递归、前向函数调用和函数内 I/O，不要求纯函数。

`作 名 参数: … 为` 或 `作 名 参数 为 类型: … 为` 声明过程；过程内不能 `得`。自然结束和执行 `完.` / `完。` 都返回 `空`。单独过程调用在 REPL 不额外回显，放入表达式时得到 `空`。没有参数的函数/过程仍需要定义冒号。

`完.` 是不携表达式的简单语句，必须以 ASCII 或中文句点结束；`完 值.`、`完 空.` 均不合法。它立即退出当前过程调用，可从条件、循环及试 / 救正文离开，清理经过的恢复处理状态，不触发 `救`，也不撤销已完成的副作用。它不关闭语法块，源码仍须写完各块结束词（包括过程的 `为`），不可达语句仍须通过语法和结构检查。

合法性按最近的函数 / 过程边界判断：有名过程、过程方法、匿名过程以及嵌套过程均可使用；顶层、形正文、任何 `算` 内均禁止，包括嵌套在 `作` 中的 `算`。嵌套过程的 `完` 只结束该次内层调用，外层继续执行。`算` 仍只能用 `得 表达式.` 返回值；裸 `得.` 不合法。

0.8.0 迁移：过程结果从空句 `''` 改为 `空`，旧结果比较、句参数和拼接须相应调整；需要真正的句结果时用 `算` 和 `得 ''.` 或在调用后显式提供文本。`完` 新增为保留字，旧同名绑定 / 参数 / 成员须改名；最长名称规则仍适用，`完成`、`完毕` 等是普通名称。

```ru
作 展示 值 为 数:
    若 值 < 0 则 完。 然
    显 值.
为
显 (展示 (-1)) == 空. # 真
```


0.9.0 起，每个参数的 `为 类型` 均可省略；适用于有名／匿名算与作、方法、嵌套声明及闭包。省略类型的参数接受任何运行时值，包括 `空`、模块值、对象和函数值；不做类型推断或隐式转换，正文中的非法运算仍报错。形名称仍不是运行时值，不能因为参数省略类型而传入形本身。不新增 `Any` 或 `任意` 等公开内置类型／关键字。

声明可混用有类型与无类型参数，空白和逗号均可分隔，例如 `算 重复 内容, 次数 为 数:` 或 `算 重复 内容 次数 为 数:`。这里省略的是类型，不是实参：所有用户参数仍必需，没有默认值或可省略实参；数量、名称检查、全位置／全命名调用和求值顺序不变。`元初` 仍必须显式声明唯一的 `句 阵` 参数（见第 10 节）。

```ru
算 原样 值: 得 值. 法
算 配对 左, 右 为 数: 得 左 对 右. 法
显 (原样 空).                    # 空
显 (配对 '内容' 2) 其 囫.         # 内容
传回 取 算 值: 得 值. 法.
显 (传回 [1, '二']) 其 量.        # 2
```

调用时检查显式声明的参数类型，不做隐式转换。可用类型为 `数`、`句`、`事实`、`空`、`对`、`阵`、`典`、`算`、`作`、直接声明或经 `尽` 导入的用户形名、内置形名，以及重复后缀 `阵`：

- `列 为 阵` 接受任意元素的阵
- `列 为 数 阵` 要求调用时每个元素均为数；空阵满足此检查
- `矩阵 为 数 阵 阵` 逐层检查二维阵；类似地可使用自定义形的阵
- `对象 为 父形` 接受该形或其子形的实例
- `操作 为 算` 只接受算的函数值，`操作 为 作` 只接受作的过程值；不混同两类。注解不编码参数数量/返回类型，真正调用时还需匹配被调用声明的参数
- `操作们 为 算 阵` 可约束函数值阵；不存在把任意值 `为 算` 或 `为 作` 的转换
- 参数 `数`、`算`、`作` 等不接受 `空`；字段普遍允许 `空` 是独立的字段规则

类型注解只在参数进入/字段写入等检查点检查，不给可变阵附加永久元素类型限制。例如参数接受 `数 阵` 后，函数仍可向该阵追加句；以后的受类型约束调用可能因此失败。

调用嵌套上限为 128，跨函数、方法和模块共享调用深度计数。源码表达式/块嵌套及模块依赖也有限制；应拆分深层表达式，而非利用实现栈极限。没有尾调用优化保证。

### 6.3 条件与循环

```ru
累计 取 0.
循 5 次
    累计 取 累计+1.
环
若 累计 == 5 则
    显 '完成'.
另
    显 '未完成'.
然
```

`若 条件 则 … [另 …] 然` 求条件一次，只执行选中正文。

`循 次数表达式 次 … 环` 进入循环时只求次数一次，要求数值为 `0` 到 `9007199254740991`（2^53−1）的整数。次数为零不执行正文；后来修改计算次数用到的变量不改变本轮总次数。

`循 … 环` 不带次数，是无限循环。`破.` 退出当前最内层循环；在函数/过程内部不能越过调用边界破外层循环。循环中允许函数 `得`、过程 `完` 或 `卒` 离开；没有隐式循环索引或 `continue`。无限循环需要程序自身 `破` 或由使用者中断。

### 6.4 词法闭包、提升与共享状态

嵌套有名 `算` / `作` 与匿名字面量都是一等词法闭包：即使外层调用已经返回，保存的函数值仍保留需要的词法环境。不会复制捕获值，也不会退回到调用者环境寻找同名变量。每次调用工厂函数创建独立环境；同一次调用产生的多个闭包共享该环境中的绑定。

```ru
算 造计数 起点 为 数:
    数值 取 起点.
    算 增加 步 为 数:
        数值 取 数值+步. 批. 更新外层已捕获的数值绑定
        得 数值.
    法
    算 查看:
        得 数值.
    法
    得 [算 增加,算 查看].
法
第一组 取 造计数 0.
第二组 取 造计数 10.
加一组 取 第一组[0].
看一组 取 第一组[1].
显 (加一组 2).       # 2
显 看一组().         # 2，同组闭包共享状态
显 (第二组[0] 3).    # 13，另一工厂调用相互独立
显 看一组().         # 2
```

直接嵌套函数/过程声明在每次进入其所属模块、函数/方法或救环境时预先登记，支持前向引用、自递归和同一作用域的相互递归。匿名字面量不提升，只在表达式实际求值时建立新函数值。提升的是有名定义，不是普通 `取` 语句：捕获值在实际读取时必须已经绑定，普通赋值仍按顺序执行。尚未建立的局部不会被提前初始化为 `空`。

写捕获绑定使用 6.1 的“最近已有非模块绑定”规则：内层参数/局部优先；其次是最近捕获的函数或救绑定；模块全局不在更新目标内。如果内层在外层建立某名字之前就写该名字，该次写入会建立内层局部，不预先为未来的外层绑定建单元。条件、循环、试不创建新的捕获环境，因此循环中反复保存同一闭包仍共享同一环境；想获得独立状态，应逐次调用工厂函数。

救直接正文的局部遮蔽不变，救中声明或通过字面量创建并返回/保存的闭包保留救的原因和局部绑定，救结束不使它们悬空。方法内嵌套函数可捕获自身及方法局部；模块内产生的闭包保留原模块环境。闭包退出、返回或卒时捕获环境仍按可达性存活，不能依赖确定的销毁时刻。

若需要由闭包生成若干互不相同的对象，使用已有 `循` 与 `其 增`，每次实际调用生成器并执行一次 `新`；没有新增“填充阵”或按索引隐式生成的语法。完整例见 `examples/closures.ru`；匿名工厂、传参及共享状态见 `examples/anonymous.ru`。

## 7. 对、阵和句的标准成员

### 7.1 空与不可变对

`甲 对 乙` 创建一个二元组，左右项可为任意值。`其 囫` 读取左项，`其 囵` 读取右项，两者都无参数且不能赋值。它不复制项中的阵/对象。

```ru
链 取 1 对 2 对 3 对 空.
和 取 0.
循
    若 链 == 空 则 破. 然
    和 取 和+链 其 囫.
    链 取 链 其 囵.
环
显 和. # 6
```

`对` 自身不可变，但内部共享对象可变；用 `空` 作为链尾是约定，不是对的强制结构限制。

### 7.2 可变阵

**数组字面量是当前 0.5 原型约定，构造语法尚未冻结**；这里准确记录已经实现的 `[]` / `[甲,乙]`，不把它解释为未来版本永久承诺。数组元素访问与改写使用第 7.3 节的零起点方括号规则。

`[]` 创建空阵，`[甲,乙]` 创建可混装任意值的阵，元素之间必须有逗号，允许尾逗号。每次字面量创建新阵。赋值、实参、返回值和对象字段传递同一引用。

数组元素中的带参数调用应加括号：`[(平方 2),3]` 或 `[(平方 2),(平方 3)]`。由于调用自身也接受逗号分隔实参，`[平方 2,3]` 会把 `2` 和 `3` 都读成 `平方` 的实参，不能表示“平方结果和 3”两个元素。

带字段实参的 `新` 构造同样应加括号，避免元素逗号被继续读为构造实参。阵可以直接保存学生等对象，下面创建两个独立学生对象：

```ru
形 学生:
    名 为 句.
    龄 为 数.
象
学生们 取 [(新 学生 名:'小明' 龄:8),(新 学生 名:'小红' 龄:9)].
显 学生们[0] 其 名.   # 小明
显 学生们 其 量.      # 2
```


标准成员和索引：

| 接收者 | 操作 | 参数名 | 结果 |
| --- | --- | --- | --- |
| 阵或句 | `其 量` | 无 | 数，元素数/码点数 |
| 阵或句 | `其 位 索引` 或 `[索引]` | `位` | 对应元素/单码点句 |
| 阵或句 | `其 段 始 终` | `始`、`终` | 浅切片阵/子句 |
| 阵 | `其 增 值` | `值` | 在尾部追加一项，返回**同一个阵** |
| 句 | `其 含 子句` | `句` | 包含返回真，否则假 |
| 对 | `其 囫`、`其 囵` | 无 | 左项、右项 |

数组可用 `列[索引] 取 值.` 或 `列 其 位 索引 取 值.` 改写已有位置；没有自动扩容赋值。追加使用 `增`。阵不提供删除元素、插入、排序或迭代器成员，需要自行实现算法；典的哈希映射接口见第 7.6 节。

### 7.3 严格索引与浅切片

阵和句的索引从 `0` 开始，必须为数且是整数，满足 `0 <= 索引 < 长度`。负索引、小数、句索引、越界和对空集合取元素均报错，不作自动转换或回绕。

阵和句的 `值[始:终]` 左闭右开，要求 `0 <= 始 <= 终 <= 长度`。省略始为 `0`，省略终为长度，`[:]` 取全部，`[长度:长度]` 为空。越界不截断，反向区间报错；没有步长参数、负步长或切片赋值。

`其 段` 必须提供两个参数；要省略边界使用方括号形式。阵切片产生新的外层阵，但元素引用保留，所以是浅复制：

```ru
内 取 [1].
原 取 [内,2].
副 取 原[:].
副[1] 取 8.
副[0][0] 取 9.
显 原[1].       # 2
显 原[0][0].    # 9
显 原 == 副.   # 假
显 原[0] == 副[0]. # 真
```

### 7.4 二维与不规则嵌套阵

本版用“阵中存阵”表示二维数据，没有额外的矩阵类型。下面使用当前原型的数组字面量构造写法：

```ru
矩阵 取 [[1,2,3],[4,5,6]].
显 矩阵[0][1].     # 第 0 行、第 1 列：2
矩阵[1][2] 取 9.
显 矩阵[1][2].     # 9
```

行、列均从 0 开始，连续索引逐次检查对应阵的边界。各行可不同长度，例如 `[[1],[2,3]]`，没有隐式矩形形状约束。参数 `矩阵 为 数 阵 阵` 要求每行均为数阵，不要求行数或列数相同。

每次内层字面量创建独立行；如果刻意重复同一行引用，则两行共享：

```ru
行 取 [1,2].
矩阵 取 [行,行].
矩阵[0][1] 取 8.
显 矩阵[1][1].     # 8，两项指向同一个行阵
```

### 7.5 Unicode 句操作

句长度、索引和切片按 **Unicode 码点**，不是 UTF-8 字节、显示宽度或字素簇。`'甲😀é乙'` 长度为 4；组合附加符、emoji ZWJ 序列可占多个位置。句不可改字符或追加。

```ru
文 取 '甲😀é乙'.
显 文 其 量.       # 4
显 文[1].          # 😀
显 文[1:3].        # 😀é
显 文 其 段 始:1 终:3.
显 文@含 '😀é'.     # 真
```

`含` 测试连续子句包含，没有取反含义，也不进行 Unicode 规范化；空句包含于任意句。取反写 `非 (文 其 含 '子句')`。阵没有内置包含测试。

### 7.6 典：可变哈希映射

```ru
方向 取 典: ‘上’ 对 0. ‘下’ 对 2. ‘中’ 对 1. 成.
空表 取 典:成.
显 方向 其 查 ‘上’.
显 方向[‘上’].      # 同样输出 0
显 方向[‘未知’].    # 空
方向 其 增 ‘右’ 3.
显 方向 其 除 ‘下’.
显 方向 其 量.
方向 其 列 作 键 值: 显 键. 显 值. 为.
```

典字面量以 `典:` 开始，以 `成` 结束，每项为 `键表达式 对 值表达式.`；所在语句另有终止句点。支持对应全角标点。条目按源码顺序逐项求值：先键、后值，然后插入，再求下一项。同键后值覆盖前值，保留已存的键对象；不会以新等价键替换原键引用。键表达式若含对须用括号，但对本身不是合法键。实现使用实际哈希索引与冲突处理，不是逐项线性查找。显示和列的枚举顺序不作保证，不应依赖当前后端的遍历次序。

键只能为有限数、句、事实或实现同和印的用户形实例。空、对、阵、典、函数/过程、模块及不支持协议的内置实例均拒绝。数按数值比较，0与负零同键；句按字符内容；事实与数分离，真不等于1、假不等于0。

形实例键必须同时具备一参 `算 同 另一: … 法` 与零参 `算 印: … 法`，继承的方法也可用。同的参数类型可省略或按普通规则显式标注；同必须返回事实。印必须返回有限、无小数且绝对值不超过 9007199254740991 的数，不接受事实。同一具体形且印值相同的候选键再调用已存键的同；同印不意味着相等，不同具体形不相等。缺少任何一项或错误签名/返回类型均报错，不降级为身份键。作者必须保证相等键有相同印，以及同的等价关系；不满足时查询结果无语义保证。

```ru
形 坐标:
    横 为 数.
    算 同 另一 为 坐标: 得 其 横 == 另一 其 横. 法
    算 印: 得 其 横. 法
象
表 取 典: (新 坐标 横:2) 对 ‘二’. 成.
显 表 其 查 (新 坐标 横:2).
```

- `典 其 查 键` 或 `典值[键]`：返回已存值，缺失返回空。因此无法区分缺失与已存空，这是本版明确选择
- `典 其 增 键 值`：新增或覆盖，返回同一个典；命名实参为 `键:`、`值:`
- `典 其 除 键`：删到返回真，否则假
- `典 其 量`：返回当前条目数（数）
- `典 其 列 回调`：回调可为算或作，必须接受两个位置实参（键、值）。忽略回调结果，完成返回空；从调用开始的浅条目快照遍历，顺序不保证。回调内可增删原典，不影响本轮条目集合；共享可变值的后续改变仍可见。完只结束当前过程回调，卒按普通调用传播

`典值[键]` 先求接收者，再求键，各一次，使用与 `查` 完全相同的合法键类型、同／印、版本保护、卒传播和共享值规则。数键不受阵的零起点整数范围限制；事实键与数键分离。连续读取逐层按实际接收者分派，例如 `表['项'][0]` 或 `列表[0]['心']`。不提供典的方括号赋值或切片、`其 位`／`其 段`、隐式含测试或深复制；更新仍使用 `其 增 键:… 值:…`。典本身可变且别名共享；键和值中的对象、阵、典保留共享引用，数按值，句共享不可变内容。典参与身份相等和循环垃圾回收，循环显示为 `<循环>`。作者自行负责插入后修改键字段或影响同/印的方法导致的索引失效；实现不冻结、重新索引或新增任意方法修改机制。若同/印执行期间修改正在查找的典，本次操作报清晰的运行错误，以避免使用失效索引；先前已完成的修改不会回滚。协议回调只在运行时调用，受通常调用深度、卒及垃圾回收规则约束。

## 8. 形、对象、继承与方法

### 8.1 声明和构造

```ru
形 计数器:
    值 为 数.
    作 增加 步 为 数:
        其 值 取 其 值+步.
    为
    算 报数:
        得 其 值.
    法
象
形 命名计数器 如 计数器:
    名 为 句.
    算 报数:
        得 其 值+1.
    法
象
甲 取 新 命名计数器 名:'计数' 值:2.
乙 取 甲.
乙 其 增加 3.
显 甲 其 报数. # 6
```

字段仍须显式写类型：`名称 为 类型.`，不是变量绑定，也不支持字段声明中的初始化表达式。字段、方法在同一形中不能重名。

`新 形名称 字段名:值 …` 只接受命名字段；未知或重复字段报错，可初始化继承字段。用户形的所有省略字段缺省为 `空`；字段也可稍后重新赋为 `空`。除 `空` 外，写入值必须满足字段类型。内置 I/O 形的缺省值见第 11 节。

构造器只分配对象和写字段，不隐式调用任何用户初始化方法。没有 `构造`、`析构`、访问修饰符或计算属性语法。`新` 后必须是单一形名称，来源为直接声明、`尽` 导入或内置形；不能写普通值别名或 `新 模块 其 类型`。跨模块构造须先使用 `尽` 导入形，或调用原模块中返回实例的工厂函数。需要保存或传递构造行为时，使用返回实例的函数值，例如 `算 造 值 为 数: 得 新 计数器 值:值. 法 工厂 取 算 造. 甲 取 工厂 1.`。工厂返回的是对象，不是形。

### 8.2 成员和自身

`对象 其 字段` 读取，`对象 其 字段 取 值.` 写入。只能写已声明字段；不能动态新增字段，不能给方法、对成员、模块导出或字符串元素赋值。

`对象 其 方法 实参` 调用方法，位置和命名规则同函数。方法内裸 `其` 是当前对象，`其 字段` 是自身字段的简写；方法及其词法闭包之外不能使用自身形式。方法局部变量不自动映射为字段，必须显式写 `其 字段`。方法通过其声明模块读取全局，但自身保留实际对象身份。

### 8.3 单继承和覆写

`形 子 如 父` 只支持单继承。父形须为本模块直接声明或通过已执行的 `尽 取 外言` 导入的形名；不存在普通运行时形值别名。直接形声明允许前向引用，但导入的父形仍要求导入语句先执行。

子形继承字段与方法。新增字段不能与继承字段/方法冲突；方法不能覆盖字段。覆写方法必须保持**参数名字、类型及算/作种类完全一致**。无类型只与对应的无类型参数匹配；无类型与任何显式类型均不兼容，不能在覆写时增加或去掉注解。类型在各方法的声明模块中解析：用户形按声明身份比较，同名但不同模块的形不相同；经导入或转导出的同一形仍保留身份。有元素类型的阵逐层比较元素类型及阵层数，内置类型按其类型类别比较，不能仅比较签名中的名称文字。没有按参数类型重载。继承循环报错，过深继承受实现嵌套限制。

方法参数的类型身份在所属形解析时绑定，之后调用该方法使用已绑定的身份；继承来的方法保留原声明模块及原参数身份。形解析也检查字段注解引用的类型是否存在。因此字段／方法注解使用的导入形必须通过已经执行的 `尽` 可见，不能把相应导入放在形语句之后；若构造或继承使形更早解析，导入也须在该解析之前完成。同一模块／同次 REPL 提交中的直接形声明会预先登记，仍允许本地形名前向引用。

REPL 后续重新声明同名形会创建新的身份，不改变旧实例或旧方法参数已绑定的身份。普通函数（包括嵌套与匿名函数）的参数注解则在调用时按其声明模块解析；这不提供形值别名，也不意味着所有函数签名都在声明时固定。

方法内部通过 `其` 再调用其他方法，按实际对象类型动态分派，因此继承来的方法可调用子形覆写的方法。父形类型参数接受子形对象；不相关的同字段形不是彼此兼容的结构类型。没有父方法调用语法、多继承或接口。内置 `件`、`录`、`件作成果` 虽能作为参数类型或用于 `新`，但不能作为 `如` 的父形；它们的内部 I/O 方法不是可继承的用户方法。

### 8.4 成员名与特殊协议

成员语法不固定全局签名。对象字段和用户方法可以使用 `含`、`位`、`段`、`增`、`量` 等普通名称；参数与返回值按声明决定。`同` 和 `印` 仅在相等及典键协议中有额外约束，见 5.3、7.6。普通调用本身仍使用方法原有签名。

## 9. 本地模块与程序入口

### 9.1 外言的解析和初始化

```ru
数学 取 外言 'modules/math.ru'.
显 数学 其 平方 9.
```

`外言` 后必须是**非空字符串字面量**，内容只能是本地文件路径或已知标准外言名称；不能是变量、插值或任意表达式，不允许含 `://` 的 URL。以 `如:` 开头的名称保留给随工具链发布的标准库，本版只接受 `如:竞赛`，解析到包内 `stdlib/竞赛.ru`；未知 `如:` 名称直接报错，不回退到本地同名文件。当前目录、导入文件目录中恰好名为 `如:竞赛` 的文件不能替换此标准外言。

其他字符串为本地相对/绝对路径，路径相对**写下导入语句的源码文件目录**，不相对进程工作目录。REPL 没有源文件时，以当前工作目录为基准。若确实要导入本地带此名字的文件，可显式写 `./如:竞赛`，它属于普通本地导入而非标准库名称。模块不要求在线注册或下载；标准库也按下面的规范化路径缓存、检查和打包规则处理。

文件命令 `run`、`check`、`build` 及生成结果验证会规范化绝对路径，并预先解析所有静态出现的导入，包括函数和不可达分支中的导入；这些源文件仍必须存在且语法/结构合法，静态依赖图中的循环即使不会执行也报错。模块依赖嵌套上限为 128。

REPL 提交本身不预先构建整个导入图：仅在某个导入表达式实际执行时才加载其依赖图，随后对该图中的静态依赖应用上述检查。因此 REPL 中暂未调用的函数内导入可延后到调用时才发现路径或依赖错误；不要据此推断同一文件程序也能通过检查。

解析和检查不执行模块顶层。运行时第一次实际执行某导入表达式，才按顺序执行该模块顶层；相同规范化路径成功初始化一次，后续返回同一模块实例，包含菱形依赖复用。不同拼写规范化为同一路径时共用缓存。

原生编译在构建时把依赖图一起编入输出；运行二进制不会再读取 `.ru` 文件，但模块初始化语句仍在首次实际导入时执行。

### 9.2 导出、限定访问与尽取

模块导出自己的顶层函数/过程、形与实际建立的全局绑定，没有额外 `export` 声明；也可转导出通过 `尽` 导入的名字。内置名称本身不是用户模块的导出内容。函数的全局环境始终属于原定义模块。

`模块 其 导出名` 读取普通绑定，或调用导出的零参函数；形导出仅供 `尽` 引入类型名称，不能通过成员读取变成普通值。有参数函数写 `模块 其 函数 实参`。模块导出的 `量` 等同名函数也使用普通实参语法，按实际声明调用。

```ru
尽 取 外言 'modules/math.ru'.
显 (平方 4).
```

`尽` 把导出名字引入当前模块顶层，不能放入条件、循环、函数或救正文。与已存在绑定、声明或内置名称冲突时明确报错，不默默覆盖。某些冲突能在检查阶段发现，依赖实际执行分支的冲突在运行时发现。

尽取的普通值绑定可在导入方重新绑定而不改变原模块绑定；阵/对象仍共享原引用。尽取函数/形名称受保护，不能重新绑定。导入不是目录权限隔离，源码可导入有读权限的本地文件。

### 9.3 初始化失败

循环导入报错，不向外返回半初始化模块。初始化期间若发生未被模块内部处理的 `卒`，外部生效的 `试` 可以救；此路径被记为失败模块。该模块环境会保留，使初始化前已通过共享容器传出的对象仍有有效所属环境。

同一路径再次导入时，重新抛出缓存的原始原因和来源位置，**不重新执行初始化，不重复已发生副作用**。重新启动进程，或 REPL `:reset`，才清空此缓存。这个可恢复失败缓存约定针对显式 `卒`；普通模块读取、语法、类型/运行错误不是可救的模块失败结果。

### 9.4 元初与退出码

```ru
显 '先执行顶层'.
算 元初 外参 为 句 阵:
    显 外参 其 量.
    得 0.
法
```

主文件可不声明 `元初`，正常执行后退出码为 0。若声明入口，必须是主文件自己声明的 `算 元初`，恰好一个 `句 阵` 参数，参数名可自定。先执行主文件顶层，再调用入口一次，外参数组不含程序文件名。

入口必须返回数值为 `0` 到 `255` 的整数；空、句、小数或范围外数值报错。导入模块的 `元初` 不因导入或尽取自动执行；REPL 也不自动调用入口。可通过 `ru run source.ru -- 你好 世界` 或原生程序 `./app 你好 世界` 传参。

## 10. 卒、试、救与终

```ru
算 检查 值 为 数:
    若 值 < 0 则 卒 '值不能为负数'. 然
    得 值.
法
试
    显 (检查 (-1)).
救 原因
    显 '已处理：'+原因.
终
显 '继续'.
```

`卒 表达式.` 先求表达式，结果必须为句；不是句会产生**普通类型错误**，不会转成可救的卒。合法卒携带原因句及原始源码位置，寻找最近的**动态生效** `试`，可跨函数、方法及模块边界传播。

`试 … 救 原因 … 终` 必须有 `救` 和一个合法原因名称，正文可以为空。无卒时跳过救正文；有卒时中止试正文的剩余执行，在救正文中以原因名称绑定该句。处理结束从 `终` 后继续，不返回到卒发生位置。

- 试正文与外部同一作用域，之前完成的绑定可继续使用
- 救正文具有以外部作用域为父级的子作用域；原因名以及救中 `取` 的绑定不覆盖或泄露到外部，包括与外部同名绑定
- 救仍可通过读取外层引用修改阵/对象内容，改动共享且不会回滚
- 原因名不可与函数名、形名或受保护内置名称冲突
- 救内再次 `卒` 向外层动态生效的试传播，不被自己处理；可显式写 `卒 原因.` 传播原因，但这是新的卒位置，没有独立“原样重抛”语法
- `得`、`完`、`破` 可以正常离开试/救，并清理对应处理状态；其合法性仍由所在函数/循环结构决定
- 无匹配救时，命令非零结束，在 stderr 报告原因和源位置；REPL 报告后等待下一段输入
- 没有 finally、异常对象、可救错误类层次、自动资源管理或隐式事务

除零、未定义名称、普通类型错误、越界、调用深度超限、传统 `显`/`读` 的错误等不是 `救` 可捕获的卒。I/O 成果的 `'失败'` 也不是卒，需要程序显式选择 `卒 成果 其 错误信息.`。

## 11. 标准 I/O 与竞赛库的完整接口

### 11.1 形、字段及缺省值

本节的方法“签名”表示参数要求及默认值，不是可直接粘贴的用户方法定义。除传统 `读`、`显` 外，下述真实 I/O 均返回一个新的 `件作成果`。

| 名称 | 构造/获得方式 | 字段与缺省值 |
| --- | --- | --- |
| `件` | `新 件 [路径:句]` | `路径` 缺省 `''` |
| `录` | `新 录 [路径:句]` | `路径` 缺省 `'.'` |
| `件作成果` | 操作返回；也可 `新 件作成果` | `结果:'成功'`、`值:空`、`错误信息:''` |
| `读取` | 已有标准输入对象 | 无公开字段 |
| `显出` | 已有标准输出对象 | 无公开字段 |
| `错误` | 已有标准错误对象 | 无公开字段 |

`件`、`录`、`件作成果` 为可直接使用的内置形名，跨模块类型身份一致。标准流对象的内部显示名称为输入流/输出流，但没有提供可用于 `新 输入流`、`新 输出流` 的公开内置形名，也不提供用户打开/关闭流的接口。

构造件/录只创建对象，不读、写、创建或探测路径。路径相对**运行进程工作目录**，与 `外言` 相对源码文件的规则不同；语言 I/O 不自动展开 `~`、环境变量或通配符。

三个内置形的字段按普通对象规则可修改，字段允许 `空`。`件作成果` 的 `结果`、`错误信息` 除空外须为句，`值` 可保存任意如值，包含阵/对象引用；手动改写成果不改变已完成的操作，不保证三字段之间的逻辑一致。业务代码应检查操作原样返回的成果。

### 11.2 成果协议与错误分类

成功时：`结果 == '成功'`，`值` 按操作定义，`错误信息 == ''`。失败时：`结果 == '失败'`，`值 == 空`，`错误信息` 是说明原因的句。没有公开的数值错误码字段；错误文字中可能含 errno，但不是稳定解析协议。

必须区分：

1. **调用形状错误**：未知成员、缺少/多出参数、重复或未知参数名、混用位置和命名形式，是普通语言错误，不能靠检查成果或救恢复
2. **操作输入/系统错误**：在合法签名下，内容不是句、路径为空/不可用、`追加` 不是数 0/1、UTF-8 无效、NUL、权限、读写刷新关闭失败等，返回失败成果
3. **构造/字段赋值错误**：例如 `新 件 路径:3` 违反普通字段类型，构造直接报普通语言错误；`路径:空` 可按字段规则构造，但之后操作返回失败成果

每个成果是普通引用对象。`值` 中的有效载荷不深复制；例如目录列表内的各件和列表阵可按普通引用规则继续使用。

### 11.3 件的方法

| 调用 | 参数 | 成功的值 | 说明 |
| --- | --- | --- | --- |
| `文件 其 读` | 无 | 句 | 一次读完整文件文本，保留文件内原有换行 |
| `文件 其 写 内容:句 追加:数` | `内容` 必需，`追加` 缺省 `0` | 空 | 0 截断/创建，1 追加/创建；不自动加换行 |
| `文件 其 在` | 无 | 事实真或假 | 路径指向普通文件为真；不存在/非普通文件为假 |
| `文件 其 除` | 无 | 空 | 删除普通文件或符号链接自身；不删除目录 |

位置形式也可用，例如 `文件 其 写 '文本'`、`文件 其 写 '文本' 1`；命名形式允许重新排序。`追加` 只能是数 `0` 或 `1`，不是任意真值，句 `'1'`、空、其他数返回失败成果。

- `读` 的空文件成功返回 `''`，不是 EOF 的 `空`
- `读`/`写` 只操作普通文件。FIFO、设备、套接字、目录等不受支持；POSIX 用非阻塞打开和文件类型检查避免把特殊文件当普通文本流等待
- 写入先检查内容/追加等参数；默认写入会截断已有文件。没有覆盖确认机制，程序作者必须控制目标路径
- `在` 遇到不存在或路径中某段不是目录时成功返回 0；权限等 stat 失败则返回失败成果，不将所有错误伪装成不存在
- `除` 遇到不存在、普通目录、其他不支持文件种类返回失败；删除符号链接时允许其目标是目录或已经不存在，因为删除的是链接自身
- 每次操作独立打开并关闭，没有持久文件句柄、游标、seek、二进制模式参数或锁接口

### 11.4 录的方法与符号链接

`目录 其 列` 无参数，非递归返回一个阵，元素是新建 `件` 对象，各项 `路径` 是目录路径和文件名连接而成的可继续使用路径。按文件名 Unicode 字符序排序，不按文件大小/时间，且不受区域排序规则控制。空目录成功返回 `[]`。

只包含普通文件及指向普通文件的符号链接，不包含子目录、指向目录的链接或特殊文件。列表不是原子快照：遍历时已经消失的项或悬空链接略过；其余扫描、文件检查或关闭错误使整个操作失败，不返回貌似完整的部分列表。

文件读、写、存在判断及列目录时的文件判断**跟随符号链接**；删除操作只删除链接。`录` 的路径本身可以通过系统路径解析指向目录。常规文件权限和 umask 生效，不提升权限、不主动修改既有权限。检查与实际操作之间存在常规文件系统竞争，不能把这些接口当作安全路径沙箱。

### 11.5 标准流与传统便捷写法

| 调用/语句 | 参数 | 返回/行为 |
| --- | --- | --- |
| `读取 其 读` | 无 | 成果；成功值为一行句或 EOF 的空 |
| `显出 其 写 内容:句` | 必需 `内容` | 成果；写 stdout，不加换行，返回前刷新 |
| `错误 其 写 内容:句` | 必需 `内容` | 成果；写 stderr，不加换行，返回前刷新 |
| `读` / `读 提示:句` | `提示` 可省略，缺省 `''` | 直接返回一行句，EOF/失败为普通运行错误 |
| `显 表达式.` | 任意值表达式 | 直接显示并加换行，失败为普通运行错误 |

标准流写可使用一个位置实参；**不接受 `追加`**。标准流操作不关闭标准流。

行读取以 LF 分行，去掉末尾 LF，再去掉末尾一个 CR；因此普通 LF/CRLF 都不保留，末行没有 LF 也可读，末行尾部单个 CR 也被去掉。单独 CR 不作为中途分行符。到 EOF 且本次未读到字符时，`读取 其 读` 返回成功且 `值 == 空`；用户按回车的空行返回成功且 `值 == ''`。不要只按值的真值判断 EOF。

传统 `读` 先把提示写到 stdout，不加换行并刷新；提示必须为句。`读 '输入：'` 等价于 `读 提示:'输入：'`。它在 EOF 报错以避免旧程序无输入时不停循环，不返回空哨兵；传统 `显`/`读` 不返回 `件作成果`。

### 11.6 编码、失败和平台界限

源码、语言字符串、件文本与标准输入均按 UTF-8 处理；无效 UTF-8 和 NUL 不受支持。文件内容不做 BOM 去除或换行标准化；读取到的文本 BOM 是普通字符。目录文件名也须可作为有效 UTF-8 句表示。

所有已返回的成功都经过该操作需要的读写/刷新/关闭检查，包括短写检查。失败可能已发生部分写入、截断、创建或部分输出；无事务、回滚、原子替换、持久化 `fsync` 或断电恢复保证。极端资源耗尽等运行时致命错误不能保证转成成果。

当前原生 I/O 在 Linux/POSIX 上验证；源码有 Windows 宽字符路径分支，但 Windows 原生编译/运行未实测，macOS/其他架构也不能由 Linux 测试推定兼容。原生输出按目标平台重新构建。该原型没有权限隔离、网络文件协议抽象或异步 I/O。

### 11.7 竞赛标准外言与公开函数

0.5.0 增加随工具链发布的标准外言 `如:竞赛`。它是普通如源码模块，公开函数均为 `算`，沿用普通调用、类型要求、命名实参、尽取冲突及函数引用规则。它不自动导入，也不新增词法保留字或数组构造语法。

```ru
竞 取 外言 '如:竞赛'.
入 取 竞 其 读入.
拆分 取 算 竞 其 拆词.
显 (拆分 '甲 乙').
```

或在模块顶层使用 `尽 取 外言 '如:竞赛'.` 后直接调用公开名称。下面是本版完整导出清单，表中参数按位置声明顺序列出；所有参数均必需，无参函数除外：

| 公开算 | 参数 | 返回值 |
| --- | --- | --- |
| `读入` | 无 | 剩余标准输入的读流对象 |
| `扫句` | `文 为 句` | 在该句上建立的新读流对象 |
| `拆词` | `文 为 句` | 按 ASCII 空白分割的句阵 |
| `拆行` | `文 为 句` | 按下述行规则分割的句阵 |
| `字列` | `文 为 句` | 每个 Unicode 码点各为一个句的阵 |
| `合句` | `列 为 句 阵`、`隔 为 句` | 以隔连接元素得到的句 |
| `排序` | `列 为 阵`、`比较 为 算` | 稳定排序得到的新浅复制阵 |
| `取整` | `值 为 事实` | 按上述真值规则得到真或假；事实保持自身 |
| `值 为 数` | 向零截断后的数 |
| `小` | `左 为 数`、`右 为 数` | 较小者 |
| `大` | `左 为 数`、`右 为 数` | 较大者 |
| `绝对` | `值 为 事实` | 按上述真值规则得到真或假；事实保持自身 |
| `值 为 数` | 值的绝对值 |
| `整除` | `左 为 数`、`右 为 数` | 先执行普通数除法，再向零截断 |
| `蓄出` | 无 | 新的标准输出缓冲对象 |

所有公开函数都能取引用，例如 `算 读入`、`算 竞 其 排序`。保存的零参函数值需显式调用，例如 `造入 取 算 竞 其 读入. 入 取 造入().`。这与下述内置对象成员不提供函数引用的限制不同。

受保护名称 `__竞赛` 是实现桥接；不从该模块导出，也不是应用代码的公开接口。读流与出流是可保存、共享引用、由闭包捕获的对象，但不导出可供 `新` 或 `为 类型名` 使用的类型名，所以本版不能直接为读流／出流声明专用类型参数。需要传递读取或输出能力时，可直接传给无类型参数，也可用捕获该对象的算／作回调，或把对象装入阵／对后传参。不提供公开字段、游标重置、文件路径或关闭成员。只使用下列成员。两份变量指向同一个读流时共享游标，指向同一个出流时共享缓冲；两次 `扫句` / `蓄出` 则建立独立对象。

### 11.8 竞赛读流、EOF 与编码

`读入` 不打印提示，**一次读取到标准输入 EOF**，并在返回前验证整份输入为有效 UTF-8 且不含 NUL。错误字节即使在尚未扫描的后半段，也使这次读入失败；不会先返回合法前缀的词。BOM 不去除，是普通字符。后续游标读取不重新验证整份输入。空间与整份输入大小成正比，不是定长流式读取；交互式题不能用它等待下一条消息。一般程序只调用一次 `读入`，后续调用只会读到标准输入尚未消费的部分。

`扫句 文` 使用已有有效句建立游标，不读标准输入。两种读流具有相同的三个无参成员：

| 调用 | 返回与游标效果 |
| --- | --- |
| `入 其 词` | 跳过当前 ASCII 空白，读取最长非空白片段为句；没有片段时返回空 |
| `入 其 数` | 按词的规则读取并按第 5.2 节严格转数；EOF 返回空，坏数字或非有限结果报错 |
| `入 其 行` | 从当前游标读到下一个 LF，返回去掉 LF 及紧靠它之前一个 CR 的句；已经处于 EOF 时返回空 |

这里的 ASCII 空白**只有**空格 U+0020、Tab U+0009、LF U+000A、CR U+000D、VT U+000B、FF U+000C。全角空格、不换行空格、其他 Unicode 空白均是词内容；此规则不同于源码词法的 Unicode 空白规则。数字输入可用正负号、十进制小数和指数，不能用全角数字、`nan`、十六进制或千位逗号；`数` 不限于整数，也不会把坏词变成零或 EOF。

读词/数只跳过**读取前**的空白，读到词尾即停止，不消费尾部分隔符。之后读行从该位置继续，所以当前行剩余部分可以以空白开头；如果词紧接 LF，下一次读行返回 `''` 并消费该 LF。不要把词读取和行读取混用时的一次空行误当成 EOF，或假设读词已自动跨行。

行读取不跳过开头空白，不以独立 CR 分行。没有结尾 LF 的非空剩余内容仍是一行，且其尾部 CR 保留。`''` 是真正空行，EOF 是 `空`，必须以 `值 == 空` 判断；数值 `0` 同样不是 EOF。末尾一个 LF 不会额外产生空行，连续两个 LF 则在两者之间有一个空行。到 EOF 后继续任意次读取均返回空。

```ru
尽 取 外言 '如:竞赛'.
入 取 扫句 '12 rest\r\n\n尾\r'.
显 入 其 数.   # 12
显 入 其 行.   # 句 ' rest'
显 入 其 行.   # 句 ''
显 入 其 行.   # 句 '尾\r'，保留未跟 LF 的 CR
显 入 其 行.   # 空
```

成员使用裸写法 `入 其 词` / `数` / `行`。**不能写 `入 其 数()`，也不能取 `算 入 其 数` 引用**；这些是内置成员，不是普通用户方法。需要回调时，可声明普通算在正文中执行该读取，再取该算的引用。读流成员的参数数量必须为零。

竞赛库的读入、坏数字和类型错误属于普通致命运行错误：文件执行终止、诊断写 stderr、非零退出，不返回 `件作成果`，也不是可由 `救` 捕获的 `卒`。这不替换第 11.1–11.6 节的受检查 I/O 协议。特别地，原有 `读取 其 读` 对未终止末行尾部 CR 的处理不同，不能用两者混读来推断新库的游标行为。

### 11.9 有界缓冲输出

`出 取 蓄出.` 建立标准输出缓冲，支持以下内置成员；既可用全位置实参，也可用表中的全命名实参：

| 调用 | 行为与返回 |
| --- | --- |
| `出 其 写 内容:句` | 追加该句，不加换行；成功返回空 |
| `出 其 行 值:句或数` | 追加句原文或数的显示，再加一个 LF；成功返回空 |
| `出 其 清` | 输出待写字节并刷新标准输出；空缓冲也刷新；成功返回空 |

`写` 只接受句。`行` 只接受句或有限数，不接受事实、空、对、阵、典、对象或函数；要显示这些值先显式 `为 句`。数使用第 5.4 节的 `.15g` / 15 位有效数字格式，没有固定小数位、填充、科学记数格式选择或 64 位整数专用输出。位置例子为 `出 其 写 '答案：'. 出 其 行 42. 出 其 清.`。这三个成员不提供函数引用；零参 `清` 使用裸成员写法，不能附加 `()`。

缓冲待写内容最多为 **65536 字节（64 KiB）**，不是 65536 个码点。达到容量或剩余容量放不下下一整个 UTF-8 码点时自动刷新；刷新边界不截断码点。单次写入很大的句也会分段输出，不把整次写入长期保存在一个无界缓冲中。`写` / `行` 成功只表明内容已接受并完成当时需要的写入，不代表缓冲中所有内容已经送至标准输出。

**最后必须显式 `出 其 清.`**。正常进程退出、`得`、`完`、`卒`、其他错误或垃圾回收均不承诺自动清空最后一段。清后对象仍可继续写。多个出流有独立缓冲，混用 `显`、`显出` 或另一个出流前应先清，以免输出次序与调用次序不符。缓冲不关闭标准输出。

底层写入或刷新失败为普通致命错误并写 stderr，不返回成果，不由 `救` 恢复。失败可能已经写出部分答案，没有回滚保证。

### 11.10 拆分、码点与合句

`拆词` 等价于在同一文本上从头反复读取 `词`，把非空结果加入新阵，直到 EOF。连续 ASCII 空白不产生空词；空文本或只有 ASCII 空白的文本返回空阵。

`拆行` 等价于从头反复读取 `行`，保留真正的空行，不添加末尾虚构的行：`拆行 ''` 是 `[]`，`拆行 '\n'` 是 `['']`，`拆行 '甲\n'` 是 `['甲']`，`拆行 '甲\n\n'` 是 `['甲','']`，`拆行 '甲\r'` 是 `['甲\r']`。CR 只在紧贴实际 LF 时剔除。

`字列` 逐 Unicode 码点返回新句阵，每个元素含一个码点；中文汉字和一个单码点 emoji 各算一个元素，组合附加符和多码点 emoji 序列分别拆开。空句得到空阵；不按 UTF-8 字节、字素簇、单词或拼音拆分，也不规范化文本。

`合句 列 隔` 只接受句阵及句分隔符，不把其他元素隐式转句。空阵返回 `''`，单元素阵返回该元素的内容，其他情况只在相邻两项之间插入隔，不在开头/结尾额外加隔。`合句 ['甲','乙'] ','` 得到 `'甲,乙'`。以上操作不修改输入句或阵；返回内容保留原来的 Unicode 和空白。

### 11.11 稳定排序与数值辅助

`排序 列 比较` 在调用开始时浅复制列中元素，并返回一个**新的阵**，空阵及单元素阵也不会返回原阵本身。按比较器确定的顺序稳定排列：比较结果为零的元素保持输入次序。排序操作本身不重排原阵；其中的对象、嵌套阵、闭包等仍是原引用，不做深复制。

比较器必须为 `算` 函数值，可以是词法闭包或绑定用户算方法，不可为 `作`。库以两个位置实参（左项、右项）调用它；参数数量和类型仍按普通调用检查。结果必须是有限数：负数表示左项排在前面，零表示同序，正数表示右项排在前面。返回数的真值不是比较协议；返回 `左 < 右` 所得的事实会报类型错误，不能表达三向顺序。

```ru
尽 取 外言 '如:竞赛'.
算 造比较 方向 为 数:
    算 比较 左 为 数 右 为 数:
        若 左 < 右 则 得 -方向. 然
        若 左 > 右 则 得 方向. 然
        得 0.
    法
    得 算 比较.
法
原列 取 [3,1,2,1].
比较器 取 造比较 1.
有序 取 排序 原列 比较器.
显 有序.  # [1, 1, 2, 3]
显 原列.  # [3, 1, 2, 1]
```

比较器须为同一批元素提供一致的顺序（含传递的同序关系），应避免副作用。它的调用次数、顺序和算法细节不保证在各后端一致；不能依赖次数计数或在比较中改变排序键。若回调主动修改原阵、对象或其他共享状态，该修改照常生效，库不承诺撤销。输入快照防止回调改变原阵长度影响这次待排元素集合，但共享对象内容仍可被回调改变；这样的不一致比较不受排序结果契约保护。

比较器中的显式 `卒` 按正常调用规则向外传播，可由外层 `救` 恢复；这次排序不返回结果，排序本身没有改动原阵次序，但此前回调的副作用保留。错误的比较结果或参数则为不可救的普通运行错误。空/单元素输入可能根本不调用比较器，不据此推断一个回调在更多元素时一定合法。实现使用至多 `O(n log n)` 次比较和 `O(n)` 额外阵空间，回调自身的时间、内存及副作用另计。

`取整` 朝零截断，例如 `取整 2.9` 为 `2`、`取整 (-2.9)` 为 `-2`。输入已经没有小数部分时保持数值；负数截断到零时可以保留负零。`整除 左 右` 的定义就是 `取整 (左/右)`，不是向负无穷取整，也不引入整数类型；除零及除法的非有限结果仍报错。`小` / `大` 对相等值返回右实参；`绝对` 仅在值小于零时取负，所以负零不变。

所有数仍是 binary64，连续整数可精确表示到正负 `2^53`，更大的整数可能已舍入，运算及 `.15g` 显示还可能进一步失去十进制精度。没有 int64、大整数、位运算、整数格式化或数组填充构造。不能把这些辅助函数用于规避原有数值边界。

EOF 求和、前缀区间和、逐行数词、闭包比较器记录排序的完整原创题目、样例及源码见 `../docs/contest-library.md` 与 `../examples/contest_*.ru`。库随依赖图内联到输出 C 或 JavaScript，复制完整输出即含实现；目标编译器及资源限制仍需验证。C99/C11 `-O2` 的普通竞赛程序可测试无 `-lm` 复编，使用 `%` 的程序仍可能需要 `-lm`，不保证任意题目或 Windows 原生环境的兼容性。

## 12. CLI、检查与 REPL

```sh
python3 ru --version
python3 ru                    # 默认进入 REPL
python3 ru repl
python3 ru check source.ru
python3 ru run source.ru -- 参数一 参数二
python3 ru build source.ru -o app --emit-c app.c
python3 ru build source.ru -o app-full --emit-c app-full.c --full-runtime
python3 ru build source.ru --target js -o app.js
node app.js 参数一 参数二
python3 -m rulang --help
```

`run` 执行解释器；`check` 解析依赖并调用编译前端完成结构/调用检查，不运行用户顶层，也不需要 C 编译器或 Node。`build` 默认 `--target c`：生成 C99 并调用编译器，不自动运行输出。C 编译器依次选 `--cc`、环境变量 `CC`，否则自动找 `clang`、`gcc`、`cc`；参数以 argv 调用，不经 shell。

C 默认输出为源文件去扩展名路径（Windows 添加 `.exe`）；`build --target js` 默认输出为同名 `.js`，也可用 `-o` 指定 `.cjs`。构建 JavaScript 不需要或调用 Node / C 编译器，不读取 `CC`，不接受 `--cc` 或 `--emit-c`。通过 `node app.js` 执行产物；`元初` 的外参为脚本路径之后的参数，退出码规则不变。

JavaScript 产物是 CommonJS：放在 `package.json` 含 `"type":"module"` 的目录树中时，应使用 `.cjs` 扩展名（例如 `-o app.cjs`）；不支持把该产物当 `.mjs` / ES module 或浏览器脚本直接加载。文件路径 I/O 仍相对运行进程的当前工作目录，而不是输出脚本的目录。

`build --full-runtime` 同时适用于 `--target c` 和 `--target js`。它保留完整目标运行时及所有已导入随附标准库声明，用于和默认裁剪输出作诊断对比，不自动导入额外标准库，不改变检查、程序语义或执行方式。默认输出及完整输出均为独立产物；裁剪不保证所有程序都符合特定平台的源码长度、编译时间或内存限制。

两种构建都在完整生成成功后才原子替换既有程序输出，输出不得覆盖源码/外言依赖。程序输出与 `--emit-c` 输出彼此也须不同；输出 C 内联运行时，可独立用 `cc -std=c99 -O2 app.c -lm -o app` 构建。`--emit-c` 文件可能在之后 C 编译失败前就已经写出。JavaScript 运行仍受 Node、操作系统、调用栈和时间 / 内存限制约束；Windows 与 macOS 的 Node 路径尚未在本次环境实测。

正常无入口退出为 0，入口返回其有效退出码，常规错误为 1，CLI 参数解析错误为 2，文件命令 Ctrl-C 取消为 130。

REPL 重定义同名形会产生新身份；旧方法参数保留已绑定的原身份，普通函数参数注解按调用时的声明模块解析（详见 8.3）。

REPL 跨提交保留变量、函数、形及模块缓存；多行输入在所需句点/结束词尚未齐全时继续等待。单独表达式会回显，文件模式中则丢弃其结果。提交中已经执行的副作用在错误后不回滚。`读` 和 REPL 消费同一 stdin；它会读取后续输入行。

`:help` 显示帮助；`:退`、`:quit`、`:q`、`:exit` 等价退出；`:reset` 清空状态并新建解释器；Ctrl-C 取消当前输入/执行。REPL 命令单独占一行，不加句点，允许前后空白；仅在没有待续源码时识别。多行字符串里的 `:退` 等仍是源码文本，不能当命令执行。管道输入不显示交互提示符。REPL 不自动调用 `元初`，也不自动联网生成代码。

配套 Emacs 模式的 `C-M-n` / `C-M-p`（Ctrl+Alt+n / p）成对跳过同层下一 / 上一完整代码块或括号；`C-M-u`（Ctrl+Alt+u）回到最内层包围结构开头，再按回到外层。代码块采用本规范的六类配对（算 / 作 / 形 / 若 / 循 / 试），括号含半角与全角形式，忽略字符串和注释中的伪结构。没有同层目标或目标不完整时前后跳转提示且不移动；向外跳转仍可回到未闭合结构的开头。原有 `C-c C-n` / `C-c C-p` / `C-c C-u` 行为保留；详细边界与数字前缀见 `emacs/README.md`。编辑模式只提供容错辅助，不改变源码语义。 如书、Emacs 和 VS Code 对代码中的 `取` 提供保守的赋值规则提示，解释当前局部、已有非模块捕获绑定和新建局部的顺序，以及直接救正文的局部写入规则；提示不声称已判断具体名称在运行时绑定到哪里。

## 13. 如是我言：意图生成及规范传输契约

### 13.1 文档边界

“如是我言”不是普通 `.ru` 执行语句，而是**显式意图文档入口标记**。最后一个非空行必须单独为 `如是我言`，允许前后空白；它必须位于如字符串之外。其前的 UTF-8 文本作为需求，可为 Markdown、Org 或自由文字，无需先满足如语法，且不能为空。

识别器跟踪如的四类引号、反斜杠转义、行注释（含 `批.`）及非嵌套 `解.…释.` 块注释；注释中的标记不触发意图识别，未闭块内的标记也不触发。前文引号须闭合。仅对两侧紧邻 ASCII 字母的单引号作英文词内撇号处理，例如 `Don't`；不要依赖这个意图识别特例改变源码字符串语法。ASCII 名称后直接紧贴引号存在意图识别歧义，应在源码中保留空白。

`run`、`check`、`build`、REPL 识别到这种文档只提示显式使用 `generate`，**不读取生成配置、不联网、不执行文档**。只有使用者明确执行下面的命令才发起生成：

```sh
python3 ru generate intent.md
python3 ru generate intent.md -o draft.ru --timeout 120
python3 ru generate intent.md --target js -o draft.js
python3 ru check draft.ru
# 人工审阅 draft.ru 的行为以后，再自行选择 run 或 build
```

### 13.2 每次请求必须携带本版完整规范

生成请求必须明确告诉模型：遵守所附、与工具链版本一致的如语言规范，用户文档是任务需求，不能覆盖语言规则；只返回完整可检查的如源码，不附说明、围栏或 `如是我言` 标记，不声称执行，不调用工具，不虚构模块或未来语法。

**每一次实际模型请求都必须读取并传输本文件的完整实际内容**，同时标明规范版本与实际规范字节的 SHA-256；不能只发送“参考仓库规范”、文件路径、链接、旧的短提示词或人工摘要。语言知识不应依赖模型预训练是否见过这个新语言。包内规范缺失、无效、版本与工具链不匹配时应在联网前失败，不能静默退回不完整提示。

请求系统输入分别标注当前语言版本、随附规范版本、随附规范 SHA-256，并将完整规范置于独立的明确边界内；规范从固定的包内资源逐次读取，不接受用户配置替换，也不使用旧内容缓存兜底。

规范版本标识用于防止规则/工具链错配；SHA-256 用于辨认实际发送内容，不表示代码经过安全审计或提供方可信。这里的“规范”是附给 Responses 的版本化语言文档，不是让模型自由变更的 JSON 输出 schema；生成输出是源码文本，最终由本地语言前端检查。

### 13.3 配置与协议

默认配置路径为 `~/.ru-lang.json`，`RU_LANG_CONFIG` 可指定另一 JSON 文件。一个不含真实凭据的配置形状如下：

```json
{
  "base-url": "https://open.bigmodel.cn/api/v1",
  "model": "glm-5.3-flash",
  "api-key": {"file": "~/.config/ru/api-key"}
}
```

密钥由使用者在仓库外安全配置；不得写入源码、意图、生成输出或日志。`api-key` 字符串通常是字面密钥；显式 `@file:路径` 或仅含 `file` 成员的对象才读取密钥文件，文件内容可有末尾换行。普通路径样式字符串不会自动当文件读取。

`api_key`、`base_url` 可作为下划线别名，但同字段不能同时用两种拼法。环境变量优先：`RU_LLM_API_KEY`（始终字面值）优先于 `RU_LLM_API_KEY_FILE`（始终文件路径），再使用 JSON 的密钥配置；另有 `RU_LLM_BASE_URL`、`RU_LLM_MODEL`。配置路径相对工作目录；密钥文件相对路径，无论来自 JSON 还是环境变量，均相对配置文件目录；支持 `~` 展开。

当前缺省提供方根地址和模型为上例值，这是可配置的本版选择，不是语言语义，不保证远端账户/模型可用。密钥无缺省值，缺少时不联网。生产远端必须 HTTPS，URL 不得含账号信息、查询或片段；根地址不得已带 `/responses`，实现固定追加该路径。仅本地协议测试支持实现规定的假令牌和字面回环 IP 的 HTTP 组合，不允许用此例外传送真实密钥。

一次调用发一个非流式 `POST /responses` 请求，`stream:false`、`store:false`，不启用模型工具，不自动切到 Chat Completions，不自动换提供方/模型，不跟随重定向，不自动重试。默认连接/读取超时为 1800 秒（半小时），可用 `--timeout 秒数` 覆盖；须为有限正数，没有固定 300 秒上限；超时/取消后提供方仍可能计费。提供方接收用户意图及完整规范，凭据仅用于请求认证。

### 13.4 响应、验证与保存

只接受已完成 Responses 响应中的 assistant 输出文本；忽略 reasoning 内容。拒绝未完成/取消/失败、拒绝消息、工具调用、非文本项目、无效 JSON 或空输出；兼容只返回已完成响应 `output_text` 的服务形式，但仍检查所有结构化项，不允许其中隐藏工具调用。

模型按要求应输出纯源码；清理器兼容恰好一段完整 Markdown 源码围栏（空语言标记或 `ru`/`rulang`/`text`）或 Org `ru`/`rulang` 源码块。混合说明、多段、残缺围栏、仍为意图文档或空程序均拒绝。

输出先进行词法/语法、结构、显式调用和本地外言依赖检查，不执行源码或模块顶层；文件模式中生成代码的外言相对**输出源码路径**解析；`--stdout` 模式则相对意图文档所在目录解析。检查通过只证明这些有限检查通过，仍需人工阅读文件读写/删除及其他副作用。

`generate` 默认 `--target ru`，输出为意图文件旁的 `原名.generated.ru`；显式 `-o` 必须为 `.ru` 路径，默认要求新文件。`--target js` 仍要求模型生成符合本规范的如源码，经过相同检查后由本地 JavaScript 后端编译，输出默认为 `原名.generated.js`，显式 `-o` 必须为 `.js` 或 `.cjs` 路径，默认要求新文件。它不请求模型直接编写 JavaScript、不发起第二次模型请求，也不另存中间 `.ru` 文件；默认不调用 Node 或执行，只有显式 `--run` 才运行已保存的程序。要审阅并保留两种产物，先 `generate -o draft.ru`，再 `build draft.ru --target js -o draft.js`。

两种生成目标在文件模式下都相对最终输出文件所在目录解析静态外言；JavaScript 会将依赖内联。父目录必须已存在，默认不能覆盖既有文件；始终禁止覆盖输入意图、符号链接（包括悬空链接）、目录、特殊文件或已有外言依赖，也拒绝与意图/依赖同 inode 的输出。完整输出写到同目录临时文件、刷新同步后，默认以不覆盖现有目标的原子发布方式保存；未启用 `--force` 时，目标在检查后被他人创建也会拒绝覆盖。JavaScript 编译失败同样不保存输出，不自动创建目录。显式 `--force` 才允许替换已有普通输出文件；仍在完整验证、写入和同步临时文件后原子替换，生成或验证失败保留旧产物。可与 `-o`、`--run` 组合；失败生成不会自动运行旧文件。

响应最多 2 MiB，意图与生成源码最多 1 MiB，配置最多 64 KiB，密钥文件最多 16 KiB；包内规范最多 1 MiB，并以严格 UTF-8 校验。生成错误不回显密钥、认证头、提供方原始错误正文或无效生成源码；检测到当前密钥出现在意图、实际构造的系统提示/规范、返回源码、JavaScript 编译产物或输出路径时停止处理。这不是任意秘密探测器，不能据此把其他秘密放入文档。

`--stdout` 在所有检查和目标编译完成后将完整产物写入标准输出，不创建默认文件或临时输出文件；诊断写入标准错误。与 `-o` / `--output`、`--run`、`--force` 互斥，冲突在配置读取和联网前拒绝。依赖相对意图文档目录解析，与 shell 重定向的目标无关；shell 本身可能在命令启动前创建或截断重定向文件。

`--verbose` 仅在标准错误汇报真实的读取、请求、等待、检查等阶段及累计耗时，等待时定期更新；非流式接口无法提供模型 token 进度或百分比。通讯错误安全区分 TLS 证书验证、其他 TLS 错误、HTTP 状态、超时、连接失败和响应中断，不泄露原始报文或凭据。

**默认生成只保存，不执行。** 只有显式 `--run` 才在检查并保存成功后运行本次文件：Ru 使用普通 `ru run` 的解释器、入口及退出码语义；JavaScript 使用 Node，缺少 Node 时在请求前拒绝。标准输入/输出/错误继承正常交互行为，生成提示写入标准错误；运行失败保留已保存文件，不自动重试生成。`--run` 执行具有当前用户权限，检查不是安全审计或沙箱，需由用户明确选择承担跳过人工审阅的风险。如书生成仍须另行手动运行，不因本开关改变。

如书的生成请求默认也等待 1800 秒，启动时可用 `--generation-timeout 秒数` 配置有限正数。提供方连接/读取和服务端等待使用同一值，页面不另设短截止时间；取消等待不会保证取消远端请求，服务端在真实请求结束前保留并发保护。可展开低调的诊断区域查看可观察阶段、耗时及安全错误类别。

本地模拟协议测试不等同于真实提供方账户、端点、计费或模型兼容性验证。

## 14. 完整可运行示例

下面各段除明确的双文件模块示例外，均可单独保存为 `.ru`，先执行 `python3 ru check 文件.ru`，再按注释选择运行。短例优先演示可预测输出；不会自动调用外部模型。

### 14.1 函数、数组与显式转换

```ru
算 总和 列 为 数 阵:
    和 取 0.
    位 取 0.
    循 列 其 量 次
        和 取 和+列[位].
        位 取 位+1.
    环
    得 和.
法
数据 取 [3,1,2].
显 '总和：'+((总和 数据) 为 句).
```

输出 `总和：6`。数组长度返回数；计次循环不隐式创建索引，故显式维护 `位`。

### 14.2 检查标准输入并处理 EOF

```ru
循
    一行 取 读取 其 读.
    若 一行 其 结果 != '成功' 则
        卒 一行 其 错误信息.
    然
    若 一行 其 值 == 空 则 破. 然
    输出 取 显出 其 写 内容:(一行 其 值)+'\n'.
    若 输出 其 结果 != '成功' 则
        卒 输出 其 错误信息.
    然
环
```

此程序回显每一行，空行也会回显，真正 EOF 才退出；最后无换行的输入仍会得到一个输出换行。I/O 失败显式卒，若调用上下文无试则以错误退出。

### 14.3 只读目录清单

```ru
目录 取 新 录 路径:'.'.
清单 取 目录 其 列.
若 清单 其 结果 == '成功' 则
    文件们 取 清单 其 值.
    序 取 0.
    循 文件们 其 量 次
        显 文件们[序] 其 路径.
        序 取 序+1.
    环
另
    显 清单 其 错误信息.
然
```

此程序只读取当前工作目录中的普通文件清单，不写文件、不递归。结果取决于运行目录。

### 14.4 救的局部绑定与共享修改

```ru
原因 取 '外部原因'.
状态 取 '原状态'.
共享 取 [1].
试
    卒 '需要处理'.
救 原因
    状态 取 '仅救内可见'.
    共享[0] 取 2.
    显 原因.
终
显 原因.
显 状态.
显 共享[0].
```

依次输出 `需要处理`、`外部原因`、`原状态`、`2`。

### 14.5 两个文件组成的模块程序

同一目录的 `math.ru`：

```ru
算 平方 根 为 数:
    得 根*根.
法
```

同目录的 `main.ru`：

```ru
数学 取 外言 'math.ru'.
算 元初 外参 为 句 阵:
    显 数学 其 平方 9.
    得 0.
法
```

`python3 ru run main.ru` 输出 `81`，退出码 0。也可构建 `main.ru` 后运行独立程序，依赖模块已静态打包。

## 15. 尚未实现的功能与生成检查清单

以下均不是本版能力：自举、FFI/调用任意 C/Python/JavaScript 库、系统命令或 subprocess、网络/HTTP 语言库、在线包管理、动态计算模块路径、循环模块、箭头函数、泛型系统、接口/多继承、运算符重载、反射、完整静态类型推断、通用用户代码优化器、任意精度整数、十进制定点、位运算、字典、异步/线程、二进制 I/O、持久文件句柄、目录创建/递归删除、事务和自动资源管理。上述保守运行时 / 随附标准库裁剪不是通用用户代码优化。CLI 的 Responses 客户端不是可由如源码调用的网络内置。

不要把 `助人`、`为乐` 等自然语言词语当内置命令；它们可以是用户定义名称，但必须确实声明。不要凭其他语言习惯发明 `print`、`return`、`if`、`try/catch`、`throw`、`len`、`append`、点成员或圆括号实参列表。

生成源码前逐项检查：

1. 是否符合本文件所标版本，简单语句是否有句点，块是否正确配对
2. 是否只使用实际提供的关键字、类型、成员和已存在的本地模块或本版标准外言
3. 每次调用是否全位置或全命名，负位置实参和嵌套调用是否加括号，外围算术是否意外进入实参
4. 句/数混合是否显式转换；显式参数类型、字段、索引和循环次数是否满足规则；省略参数类型是否仍提供全部实参，未虚构 `Any` 类型、默认值或可省略实参
5. 是否理解阵/对象的共享引用、切片浅复制、词法闭包共享绑定、函数不改模块全局及救的子作用域
6. 是否在取 I/O 成果值前检查结果，是否把 EOF 的空和合法空句区分开
7. 文件写入是否会默认截断，路径是相对工作目录还是相对源文件，是否存在意外删除/覆盖行为
8. 是否只用卒表达程序主动选择的失败，未误以为救能捕获普通运行错误
9. 入口签名和返回码是否正确；程序是否有可解释的终止条件
10. 使用竞赛库时，是否区分内置成员与普通函数引用，最后清空输出缓冲，且比较器是返回有限数的算
11. 是否注意 binary64 计算与 15 位显示的限制，没有假设 int64、位运算或数组填充
12. 匿名字面量是否省略名称、参数裸写名称及可选的 `为 类型` 且带冒号；是否保留有名 / 括号引用，结束词后句点归属外层语句，立即带参调用是否先分组字面量
13. 是否只在类型注解、`新`、`如` 或合法导入中使用形名，未生成 `别名 取 学生.` 或 `别名 取 模块 其 学生.`；跨模块构造是否使用 `尽` 或返回实例的工厂，覆写类型是否在各自声明模块中指向同一身份
14. 注释是否使用合法的 `批.` 行注释或非嵌套 `解.…释.` 块注释，标记紧邻句点且不代替语句结束符；必要时可用说明性注释指出更新外层捕获绑定，不发明新的作用域语法
15. 是否只在最近的 `作` 边界内使用不携表达式的 `完.`，没有在嵌套 `算` 内使用它；是否把过程自然结束和提前结束的结果都视为 `空`，而非空句；是否避免把保留字 `完` 当名称
16. 典读取可用 `表[键]` 或 `其 查`，缺失返回空；未把典当成阵做数值位置检查，也未虚构典的方括号赋值或切片
17. 是否只输出源码，且清楚本地检查通过之后仍需审阅再执行
