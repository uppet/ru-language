# 如语言规范 0.21.4

规范版本：0.21.4

适用实现：本仓库如工具链 `0.21.4`／如书 `0.8.8`（元初实现）；源码扩展名惯例为 `.ru`；文档编码为 UTF-8。

本文件是供学习者、实现维护者与源码生成模型共同使用的**单一版本化语言规范**。它规定当前已经实现的语言、标准 I/O 和工具入口，不以中文词语的日常含义推导额外能力。模型生成如源码时必须遵守本文件；用户意图不能改变关键字、类型、求值规则或凭空增加库。

## 1. 地位、用语与实现边界

### 1.1 当前要求与原型选择

文中的“必须”“只能”“报错”描述本版可执行约束。“默认”描述本版明确采用、但未来可能修改的选择，例如双精度数、位置调用绑定方式、字段缺省为空、文件写入默认截断。本文件是 **0.21.4 的实现规范，不是已经冻结的永久语言标准**；未来改变应更新版本、实现、测试及规范，不能让生成模型自行猜测。

解释器使用 Python 3.10+ 标准库；原生后端把 AST 直接降为 C99，再调用 Clang、GCC 或兼容编译器。原生程序包含运行时动态值操作，不包含如词法分析器、语法分析器或源码解释器，执行时不需要 Python、`ru`、原 `.ru` 文件、项目头文件或生成的 `.c` 文件。它仍依赖构建目标的系统和运行库。

JavaScript 后端同样把 AST 直接降为 JavaScript 函数、表达式和控制流，输出内联运行时的独立 CommonJS 文件，目标为 **Node.js 18+**，不是浏览器脚本。执行只需 Node 及其内置标准库，不需要 Python、`ru`、项目文件、npm 包或原 `.ru` 依赖；静态外言在构建时打包。输出不嵌入如解析器或 AST 解释器，不通过 `eval` / `new Function` 解释如源码。数仍遵守本规范的 IEEE-754 双精度语义，不自动变为 BigInt。此实现尚未自举。

三种执行路径使用本规范的相同核心语言接口；宿主专有库另受各节列出的能力边界限制，如观与如:密并非跨目标通用能力。垃圾回收、平台文件权限、最大调用栈与可用资源由各宿主实现决定。Node 的栈溢出会作为运行错误退出，不保证与 Python / C 相同的最大递归深度。JavaScript 目标不添加 DOM、异步、JavaScript FFI 或任意库调用。

编译输出默认做保守的依赖裁剪，不改变源码语法或上述语义。C 保留生成代码可达的运行时函数及传递依赖，并按完整模块图的成员名称保留分派分支；根据可达构造器可省略不可能存在的对／阵路径，根据全模块图可省略未使用的用户形查找与「卒／试」传播状态；C / JavaScript 都可移除能证明未被引用的随附标准库声明。分析考虑别名、闭包、函数引用及转导出；模块值逃逸或无法确定时保留所需的保守集合。用户声明、用户模块及初始化副作用不会作为标准库裁剪对象，完整原始依赖图仍先接受检查。C 输出保持可读、独立，不做代码压缩或题目专用替换。JavaScript 另外只在未引用时省略可选 I/O / 竞赛 / 实用库运行时区段。第 12 节的 `--full-runtime` 可关闭这些裁剪以供诊断。

`check`、`build` 和生成结果检查会解析整个依赖图，检查结构及可静态识别的函数调用；它们**不是完整静态类型检查器，也不是安全审计或执行沙箱**。未定义的普通变量、实际参数类型、字段值、索引、除零、路径权限等仍可能在运行时报错。检查通过不等于所有路径可运行、程序终止或程序安全。

### 1.2 可观察行为与错误

- 文件执行按语句顺序进行；函数和形声明预先登记以支持前向引用，导入和其他有副作用的语句仍按实际执行顺序生效
- 普通语法、结构、编译、类型及运行错误会终止该次文件执行。REPL 报告后通常继续接收下一段输入
- 只有显式 `卒` 能由 `救` 恢复；受检查 I/O 失败返回成果对象，不自动 `卒`
- 参数及字段类型不匹配报告期望类型与实际收到的类型，参数诊断标明函数和参数名，字段诊断标明字段名；不一律建议 `为 类型` 转换。用户形、算 / 作和带元素约束的阵不是通用转换目标。
- 错误文字可随后端或操作系统变化。前端/解释器通常报告文件、行、列；原生普通运行错误主要报告文件和行，未救之卒还保存原始来源位置。不要依赖完整诊断文字进行业务判断
- 语法错误、运行错误或 `卒` 均不会撤销之前已完成的绑定、对象修改或 I/O。错误发生后的后续语句不继续执行，除非进入匹配的 `救`
- 普通调用的成功路径与可恢复 `卒` 的求值顺序按第 4 节。对于本来就无效的程序，不依赖各后端对普通错误的检查时机及错误前实参副作用完全一致；编译器可能更早拒绝整段程序

## 2. 源码、词法与名称

### 2.1 编码、空白和注释

文件源码为有效 UTF-8，文件开头允许 UTF-8 BOM。词法分析器把 Unicode 空白视为空白；换行没有结束语句的含义，缩进用于阅读而非语法。位置中的列号按源码 Unicode 字符计数。

`#`、`//` 或 `批.` / `批。` 从字符串外开始到行尾为注释，允许接在代码后。`/` 是除法；相邻两个 `/` 开始注释，语言没有整数除法 `//`。

`解.` / `解。` 开始非嵌套块注释，以首个 `释.` / `释。` 结束，可跨行。块内引号、关键词、`如是我言` 和新的 `解.` 都只是文字；即使结束标记出现在看似字符串的文字内，也立即关闭该块。字符串内的所有注释标记均为普通文字。

中文标记中字与句点必须紧邻，不能写 `批 .`、`解 .` 或 `释 .`；开始标记仅在词法名称边界识别，`批评`、`解释`、`总批` 等完整名称不被拆开。`批`、`解`、`释` 不新增为保留字。块内结束标记直接按原文寻找，不要求名称边界。标记中的句点属于注释，不替代前一条源码语句的结束符，例如应写 `显 1. 批. 说明`。文件中的未闭块在开始位置报语法错误；REPL 则继续等待结束标记。

```ru
批. 本行不执行
显 1. 批。 行尾说明
解。 多行说明；可以包含若、法和引号。
这里仍在注释中。释.
显 '解. 字符串不开始注释'.
```

简单语句以 `.` 或 `。` 结束。`段: … 落.` 的冒号和结束句点都必需；语句位置的 `{ … }` 是等价作用域块，右花括号后的句点可省略。多余句点是允许的空语句。声明及控制流块结束词 `法`、`为`、`然`、`环`、`象`、`终` 后允许一个句点，也可以不写；外层还可接空语句。匿名函数 / 过程字面量是表达式，其 `法` / `为` 只关闭字面量，不消费句点；随后句点属于外层简单语句，见 4.6。

以下全角标点与 ASCII 标点等价：`。` → `.`、`：` → `:`、`（` → `(`、`）` → `)`、`，` → `,`、`［` → `[`、`］` → `]`、`｛` → `{`、`｝` → `}`。赋值符号 `:=` 与 `取` 等价，也接受连续的 `：=`；冒号和 ASCII 等号必须相邻，`: =`、`： =`、`：＝` 均不是赋值符。全角算术符号没有这种替换规则。成员分隔符是 `其` 或 ASCII `@`，不是点号。

### 2.2 名称与保留字

名称以 `_` 或 Python Unicode `isalpha()` 判定的字母起始，后续由 `_` 或 Unicode `isalnum()` 判定的字母/数字组成。名称大小写敏感，不做 Unicode 规范化；组合附加符并不因为视觉上属于字母就自动可用于名称。ASCII 数字不能开头；emoji 不属于名称字符。

词法采用最长名称：`为乐` 是一个名称，不能拆成关键字 `为` 加 `乐`。相邻的中文名称或关键字应以空白或标点隔开；`值取3` 不是 `值 取 3`。`信@含`、`左+右` 可以紧贴运算符。

本版完整保留字集合如下，不能作普通名称：

```text
显 取 为 得 完 破 若 则 另 然 循 次 环 算 作 法 其
且 或 非 空 真 假 典 成 对 形 象 如 新 外言 尽取 尽 试 救 卒
```

`尽取` 是全量导入关键字，须连写；旧式 `尽 取 外言` 已停用，遇到时明确提示改为 `尽取 外言`，不静默兼容。单字 `尽` 继续保留用于迁移诊断，不能作为变量、函数、参数或成员名称。完整名称 `尽取值`、`尽取器` 不拆分，仍可作普通名称。`外言` 保留原名，不增加 `进取` 或 `言` 别名。

另有**受保护的内置名称** `读`、`件`、`录`、`件作成果`、`读取`、`显出`、`错误`、`__如竞`、`__实用`，不可声明同名顶层函数/形，不可用作绑定或参数名。它们不是上述词法保留字；例如对象可以有名为 `读取` 的方法。

`数`、`句`、`阵`、`事实` 是类型写法，不是词法保留字，也不是可直接求值的内置类型对象；不要为了生成代码方便而把它们当作构造函数。自定义形名不得为 `数`、`句`、`阵`、`事实`、`典`。`典` 同时是保留字与内置类型；`典:` 开始文字形式的典字面量，表达式位置的 `{` 开始等价的符号形式；语句位置的 `{` 开始作用域块。标准成员词 `含`、`位`、`段`、`增`、`量`、`囫`、`囵` 与 `查`、`除`、`列`、`排序`、`另成`、`逐位`、`逐目` 使用普通成员调用语法，不是全局保留字。`元初` 在主文件入口位置有特殊约定，其余使用服从普通名称规则。如竞库导出的 `读入`、`排序` 等是普通函数名，须先导入；它们不是全局保留字。`__如竞` 与 `__实用` 仅为内部桥接，不作为应用接口，见 11.7–11.11。

`终` 是**上下文结束词**，没有加入保留字集合：在 `试` 或 `救` 的正文等待下一条语句时，它关闭当前恢复块；其他名称位置仍可使用它，例如顶层 `终 取 2.` 和 `其 段 始:0 终:2`。因此不要在恢复块中用以 `终` 开头的语句表示变量操作；生成代码建议始终另选变量名。字符串 `'终'` 不结束块。

`段` 与 `落` 也是上下文词，没有加入保留字集合。只在等待语句且完整名称 `段` 后接冒号时开启作用域块；只有该块正文等待语句且完整名称 `落` 后接句点时结束。允许空白、换行及注释隔开这些标记。`段 取 1.`、`落 := 2.`、`其 段 始:0 终:2` 仍按原来的名称／成员语法处理，`落 取 值.` 不会误关块；`段落`、`落叶` 不拆开。字符串和注释中的伪标记没有结构作用。

### 2.3 字符串字面量

支持四对引号：`'…'`、`"…"`、`‘…’`、`“…”`；弯引号必须使用匹配的右引号结束。允许真实换行。支持且只支持下列反斜杠转义：

| 转义 | 值 |
| --- | --- |
| `\n` | LF 换行 |
| `\r` | CR 回车 |
| `\t` | 制表符 |
| `\\` | 反斜杠 |
| `\'`、`\"`、`\’`、`\”` | 相应引号字符 |

未知转义报错；没有 `\uXXXX`、`\xNN`、插值或原始字符串语法。请直接在 UTF-8 字符串中写 Unicode 字符。字符串不能包含 NUL；`\0` 也不是合法转义。字符串值不可变，不自动合并相邻字面量。

### 2.4 数字字面量

无符号字面量的词法形式为：

```text
([0-9]+ ('.' [0-9]+)? | '.' [0-9]+) ([eE] [+-]? [0-9]+)?
```

正负号是独立的一元运算符。因此 `1`、`-2.5`、`.5`、`1e3`、`2.5E-1` 可用，十六进制、二进制、数字下划线、中文数词与全角数字字面量不可用。源码 `1.` 读成数字 `1` 加语句结束符，不能依靠尾随小数点构成浮点字面量。字符串转数另有允许 `'1.'` 的规则，见第 5 节。

每个数都是有限 IEEE-754 binary64 双精度浮点数。字面量溢出为非有限数时拒绝；很小的数可能舍入/下溢为零。没有独立整数、大整数或十进制定点类型；`事实` 是独立的真假类型，不属于数。约 15 位十进制有效数字后应考虑精度损失；不应用于需要精确金额或任意精度整数的计算。`0` 与 `-0` 比较相等且均为真；显示可以保留负零符号。

## 3. 文法概览

下面的 EBNF 说明结构，需同时遵循第 4 节的 Pratt 优先级和调用边界；不能把其中 `调用实参` 简化为其他语言的圆括号参数列表。`{…}` 表示重复，`[…]` 表示可选，单引号中的字符表示语言终结符，`名称`、`字符串`、`数字` 采用第 2 节。代码内的空白不是强制数量。

```ebnf
程序       = { 语句 | '.' } ;
语句       = 简句 '.' | 算定义 | 作定义 | 形定义 | 条件 | 循环 | 恢复 | 作用域块 ;
简句       = '显' 表达式
           | 名称 赋值符 表达式
           | 可写目标 赋值符 表达式
           | '得' 表达式
           | '破'
           | '完'
           | '卒' 表达式
           | '尽取' '外言' 字符串
           | 表达式 ;
赋值符     = '取' | ':=' ;
作用域块   = '段' ':' 程序 '落' '.' | '{' 程序 '}' ['.'] ;
算定义     = '算' 名称 { 参数 [','] } ':' 程序 '法' ['.'] ;
作定义     = '作' 名称 { 参数 [','] } ':' 程序 '为' ['.'] ;
算字面量   = '算' { 参数 [','] } ':' 程序 '法' ;
作字面量   = '作' { 参数 [','] } ':' 程序 '为' ;
参数       = 名称 ['为' 类型] ;
类型       = 类型基本名 { '阵' } ;
类型基本名 = 名称 | '空' | '对' | '算' | '作' | '典' ;
形定义     = '形' 名称 ['如' 名称] [':'] { 字段 | 算定义 | 作定义 | '.' } '象' ['.'] ;
字段       = 名称 '为' 类型 '.' ;
条件       = '若' 表达式 '则' 程序 ['另' 程序] '然' ['.'] ;
循环       = '循' [表达式 '次'] 程序 '环' ['.'] ;
恢复       = '试' [':'] 程序 '救' 名称 [':'] 程序 '终' ['.'] ;
原子       = 数字 | 字符串 | '真' | '假' | '空' | 名称
           | '(' 表达式 ')'
           | '[' [表达式 {',' 表达式} [',']] ']'
           | '外言' 字符串
           | '新' 名称 { 命名实参 [','] }
           | '其'
           | ('算' | '作') 引用目标
           | 算字面量 | 作字面量 | 典字面量 ;
典字面量   = '典' ':' { 键表达式 '对' 表达式 '.' } '成'
           | '{' [表达式 ':' 表达式 {',' 表达式 ':' 表达式} [',']] '}' ;
引用目标   = 引用原子 { '[' 表达式 ']' | ('其' | '@') 名称 } ;
引用原子   = 名称 | '(' 表达式 ')' | '其' [名称] ;
显式零参调用 = 表达式 '(' ')' ;
命名实参   = 名称 ':' 表达式 ;
可写目标   = 表达式 '[' 表达式 ']'
           | 表达式 ('其' | '@') 字段名
           | 表达式 ('其' | '@') '位' 索引实参 ;
```

`程序` 在对应块结束词前停止。函数/过程可以直接声明在模块、函数/方法、救或显式作用域块的正文中；形内可声明方法。条件、循环及受保护的试正文中不能直接声明函数/过程，不能依靠分支是否执行来条件性建立定义。匿名字面量是表达式，可在这些正文中的表达式位置求值，不受有名声明的位置限制；其内部正文沿用函数 / 过程正文规则。形与 `尽取 外言` 仍只能位于模块顶层，不能嵌套声明形；模块顶层的显式作用域块内部也不是模块顶层。显式作用域块可位于条件、循环和受保护的试正文中，块内可以直接声明函数／过程并在每次进入该块时提升。

`:=` 只用于赋值语句，不能嵌在表达式中，也不替换典条目、参数或块头的冒号。名称、对象成员和合法的可写索引均支持 `:=`；`模块 := 外言 '工具.ru'.` 也与 `取` 等价。`尽取 外言` 是独立导入语句，`尽取` 是一个完整关键字，不含赋值符；不能改写成 `尽 := 外言` 或 `尽取 := 外言`。

有名函数 / 过程声明及匿名字面量的冒号均必需，形定义的冒号可省略，`试` 和 `救 原因` 后的冒号也可省略。`得` 只能在 `算` 的正文中；`破` 只能在当前函数/过程或顶层自身的循环内，不能跨调用退出调用者的循环。没有无表达式的 `得`、`继续`、`否则若` 或三元表达式语法；需要时在 `另` 中嵌套 `若`。

## 4. 表达式、调用及求值顺序

### 4.1 运算优先级和结合性

从紧到松排列如下。括号可显式限定整个表达式。

| 优先级 | 形式 | 结合规则 |
| --- | --- | --- |
| 80 | `[索引]`、`[始:终]`、空 `()` 显式调用 | 后缀连续应用 |
| 75 | `其 成员`、`@成员` | 后缀；标准成员实参见下文 |
| 70 | 一元 `+`、`-`、`非` | 作用于右侧表达式 |
| 60 | `*`、`/`、`%` | 左结合 |
| 50 | `+`、`-` | 左结合 |
| 40 | `<`、`<=`、`>`、`>=` | 左结合，不是数学链式比较 |
| 30 | `==`、`!=` | 左结合 |
| 20 | `且` | 左结合、短路 |
| 10 | `或` | 左结合、短路 |
| 7 | `对` | **右结合** |
| 5 | `为 数`、`为 句`、`为 阵`、`为 事实` | 作用于已形成的左侧表达式 |

调用在读取名称原子时识别，实参具有特殊的向右贪婪规则，不能简单理解成“调用永远比算术紧”。例如 `平方 2+1` 的唯一实参是 `2+1`；`(平方 2)+1` 才把结果加一。

转换结合左边的完整较高优先级表达式：`1+2 为 句` 是 `(1+2) 为 句`。`1 对 2 对 空` 是 `1 对 (2 对 空)`。`1<值<5` 按左结合普通运算求值，不是区间测试；应写 `1<值 且 值<5`。

### 4.2 位置调用、命名调用及零参数调用

```ru
算 平方 根 为 数:
    得 根*根.
法
算 差 左 为 数 右 为 数:
    得 左-右.
法
显 (平方 9.9).
显 (平方 根:9.9).
显 (差 9 4).
显 (差 右:4 左:9).
```

- 位置实参按声明顺序匹配；命名实参按参数名匹配，顺序可变
- 一个调用只能全位置或全命名，不能混用；参数名不可重复，未知或缺少的参数报错
- 普通用户函数/方法没有缺省参数、可变参数或重载；参数数量必须完全匹配
- 多个实参可用空白或逗号分隔。每个实参尽量读取完整表达式，直到不能继续或遇到下一个实参边界
- 阵中并列调用结果须显式分组：`[(表 其 查 '键'), 值]` 是两个元素；`[表 其 查 '键', 值]` 会把两个实参交给 `查`。多余实参的条件式诊断提示不改变这个解析规则
- 在一个普通实参中嵌套带实参调用时，必须加括号：`差 (平方 3) (平方 2)`，或 `差 左:(平方 3) 右:2`。`差 甲 乙` 中的 `甲`、`乙` 分别是实参，不自动解析成 `差 (甲 乙)`
- 裸声明函数/过程名称保留零实参自动调用；普通变量/参数名称读取值，即使其中保存函数值也不自动调用。取得声明的函数/过程本身写 `算 名` / `作 名`；调用保存的零参函数值写 `回调()`，见第 4.5、6.4 节
- `+`、`-` 不在名称后直接开启第一个位置实参，以保留 `变量-2` 与 `零参函数-2` 的算术含义。第一个负数/正号实参加括号，例如 `平方 (-2)`。后续负数可写 `差 2 (-3)` 或 `差 2, -3`；`差 1 -2` 只有实参 `1-2`
- 命名实参可直接带符号：`平方 根:-2`
- 空 `()` 是显式零参调用。非空 `函数(表达式)` 仍可被读作“函数加一个括号表达式实参”，不是传统参数列表；`函数(甲,乙)` 仍不成立。多参统一写 `函数 甲 乙` 或 `(函数 甲,乙)`
- 函数返回结果再参与外围运算时，优先使用 `(调用) 运算符 …`，避免实参吞入外围运算

### 4.3 索引、成员与名称空白

`列[0]` 中名称和 `[` 同一行紧邻时，解析为索引；`求和 [1,2]` 中的数组是位置实参。写数组实参时推荐保留空白，复杂情况使用 `求和 ([1,2])`。普通表达式后也能应用索引，例如 `([1,2])[0]`。典的 `表[目]` 是 `表 其 查 目` 的读取简写，按键查找而非数值位置；缺失返回 `空`，详见第 7.6 节。

`其` 与 `@` 是相同的成员访问/调用操作。为提高可读性和减少贪婪调用歧义，推荐 `对象 其 方法`；对复杂接收者加括号，如 `(取得对象 1) 其 字段`。

所有成员使用普通实参语法，参数名字与数量由接收者决定，不按 `增`、`查`、`量` 等名称全局固定。例如阵的 `增 值` 接受一参，典的 `增 目 相` 接受两参；对象可以定义同名的其他签名。

- `列 其 增 1+2` 等于 `列 其 增 (1+2)`，追加 3
- `列 其 位 位置+1`、`列 其 段 (起点+1) (终点-1)` 使用完整表达式实参
- 命名调用继续要求全部命名，不得混用位置参数
- 嵌套调用参数必须适当加括号，如 `'甲' 其 含 (回 '甲')`
- 成员结果再参与外层运算时加括号，如 `(列 其 位 0)+2`；继续成员调用也可用 `(链 其 囵) 其 囫`

0.10.0 移除了旧标准成员专用的紧结合与固定签名限制。旧代码依赖 `列 其 位 0+2` 先取第 0 项再加 2 时，须改为 `(列 其 位 0)+2`。

### 4.4 求值顺序

在合法调用中，接收者先求值，实际参数按**源码从左到右**求值，再按声明名字/位置绑定；命名实参不按声明顺序重排求值。构造字段值和数组元素也按源码顺序求值。普通二元操作先左后右；`且`、`或` 例外地短路。索引先求接收者再求索引，切片先接收者、始、终。

赋值先求目标接收者和索引，并检查目标可写且索引有效，再求右侧值；目标不合法时不执行右侧副作用。右侧若 `卒`，该次赋值尚未发生，但此前已完成的副作用保留。名称绑定在右侧成功后才更新。

求值过程中发生 `卒` 时，未求值的后续操作数、实参和语句不执行，直接沿调用栈寻找匹配 `救`。不要依赖普通类型/结构错误前的副作用时机，见 1.2。

### 4.5 函数引用与通用调用

`算 名` 取得算的函数值，`作 名` 取得作的过程值，取得时不执行正文；引用种类必须与目标声明一致。`算 名.` 在语句位置是引用表达式语句，不是定义；`算 名:`、`算 名 参数:` 或 `算 名 参数 为 类型:` 才开始有名定义，作同理。

调用函数值沿用已有规则：保存为变量后写 `回调 实参`，显式零参数写 `回调()`。普通变量的裸名字仍然是值；例如 `显 回调.` 显示函数值，而 `显 回调().` 执行后显示结果。直接声明的零参函数裸名字保留自动调用兼容性。

索引、括号表达式或对象字段取得的函数值也可被调用，如 `回调们[0] 3`、`(回调) 3`、`(算 平方) 3`、`对象 其 回调 3`；无参形式分别可用 `回调们[0]()`、`(回调)()`、`对象 其 回调()`。这些是对值的调用，参数仍为全位置或全命名、从左到右求值；非函数值被调用时报普通运行错误。

用户方法引用写 `算 对象 其 方法` / `作 对象 其 方法`，保存接收者，使以后调用仍作用于同一对象。模块函数引用写 `算 模块 其 函数`；读取值为函数的字段也可通过相同引用形式检查其算/作种类。方法内部可使用自身作为引用接收者。普通成员访问仍保持原有方法调用语义，取方法本身必须显式引用。

`算 列[0]` 可从阵元素取得并检查函数值；`算 (对象表达式) 其 方法` 可取得计算接收者的方法引用。引用目标中实际写出的计算或调用会正常执行，但最终选中的函数本身不因取引用而执行；单纯给名称/成员加括号不等于调用它。分组一个引用推荐写 `(算 某声明函数)`，计算后再取函数值则可写 `算 (造函数())`。接收者 / 被调用值先于实参求值，避免以实参副作用改变本次已选中的闭包。

本版引用范围为用户声明的函数/过程、用户方法与保存的函数值；不提供 `读`、集合标准成员、内置 I/O 方法、如竞读流/出流成员的函数引用。`如竞` 导出的普通算可正常取引用，见 11.7。匿名字面量见 4.6；没有箭头函数或通用反射语法。动态函数值的具体签名不能总在 `check` 中确定，实际调用仍进行参数数量、名字和类型检查。

### 4.6 匿名函数 / 过程字面量

表达式位置的 `算 参数 为 类型: … 法` 创建匿名函数值；`作 参数 为 类型: … 为` 创建匿名过程值。省略的是定义名，参数裸写为 `名称` 或 `名称 为 类型`，可以用空白或逗号分隔并混用有类型与无类型参数。省略类型的参数接受任何运行时值，包括 `空`；显式注解继续检查类型。没有参数时写 `算: … 法` 或 `作: … 为`。冒号不可省略，不使用箭头，也不在参数序列外添加圆括号。

```ru
平方 取 算 值 为 数: 得 值 * 值. 法.
问候 取 作 名 为 句: 显 ('你好，' + 名). 为.
报到 取 作: 显 '到了'. 为.
显 (平方 4).       # 16
问候 '小如'.      # 你好，小如
报到().           # 到了
```

消歧须识别完整头部：`算:` / `作:`，或完整的参数头（如 `算 值:`、`作 内容 次数 为 数:`）开始字面量；`算 名称` / `作 名称` 本身仍是引用。语句位置的 `算 名称:` / `作 名称:` 仍是零参有名声明；带参有名声明可写 `算 名称 参数:` / `作 名称 参数:`，也可在参数后显式标注类型。因此 `值 取 算 参数: … 法.` 是匿名表达式，而独立的 `算 参数: … 法` 是零参有名声明。没有头部冒号的 `算 名称 为 句` / `作 名称 为 阵` 仍是原有的引用加转换，不会变成不完整字面量。引用目标的圆括号规则保持不变：`算 (表达式)` / `作 (表达式)` 不会解释为匿名参数表。

无类型参数头可能与引用后的命名实参重叠，例如 `算 回 值:1.`。消歧优先采用具有完整正文及对应结束词的有名声明或匿名字面量；若不能形成完整声明／字面量，而整段可按既有引用调用解析，则保留引用调用。位置引用调用 `算 回 值.`、命名引用调用 `算 回 值:1.` 和表达式中的 `显 算 回 值:1.` 均保持原有含义：取得 `回` 的函数值后调用它。单凭实参名后的冒号不会把一个完整引用调用改成未闭合字面量；需要清楚分组时仍可写 `(算 回) 值:1`。

```ru
算 回 值: 得 值. 法
算 回 值:1.
显 算 回 值:2.             # 2
内容 取 3.
显 算 回 内容.             # 3
显 ((算 回) 值:4).         # 4
```

字面量的 `法` / `为` 只关闭这个表达式。上例最终句点属于赋值语句；返回匿名值时写 `得 算 … 法.`，句点属于 `得`。作为实参、阵元素或其他子表达式时，结束词后可以继续外层逗号、括号和后续表达式，不要求也不能多插一个“字面量结束句点”；字面量正文内部的简单语句仍须以句点结束。

```ru
算 应用 回调 为 算 值 为 数:
    得 回调 值.
法
显 (应用 (算 值 为 数: 得 值 * 值. 法) 5). # 25
操作们 取 [算: 得 1. 法, 作: 显 '完成'. 为].
显 操作们[0]().
操作们[1]().
显 ((算 值 为 数: 得 值 + 1. 法) 4).      # 5
```

对刚创建的字面量立即带参调用时，用括号先分组字面量，再按原规则写实参：`(算 值 为 数: … 法) 4`，不是 `算 (值 为 数): …` 或 `回调(4)`。零参调用可写 `(算: … 法)()`。调用仍遵守 4.2 的实参边界、全位置或全命名和从左到右求值规则。

每次实际求值字面量都会创建一个新闭包，不提前运行正文，也不提升成有名定义。字面量可赋值、传参、返回、放入阵 / 对 / 字段，或在条件、循环和受保护的试正文中的表达式位置创建。正文可包含嵌套有名声明、匿名字面量和控制流。参数与有名函数采用相同类型 / 数量 / 名称检查；匿名算的实际路径必须 `得`，匿名作不能 `得`，可用 `完.` 提前返回 `空`。`破` 不能跨越匿名函数 / 过程的调用边界。捕获及状态更新完全沿用 6.1、6.4 的共享词法绑定规则。

## 5. 值、转换、算术与比较

### 5.1 值种类与真值

运行时可见值包括 `数`、`句`、`事实`、`空`、`对`、`阵`、`典`、函数/过程值、形的对象和模块值。`真`、`假` 是事实字面量，不是数或空；`假 == 空`、`假 == 0`、`真 == 1` 均为 `假`。不存在把真当作通配相等值的规则。

条件只将 `空` 与 `假` 视为假；其他值均为真，包括 `0`、`-0`、`''`、`[]` 和空典。没有 `true`、`false`、`null` 的内置别名。

`非`、相等和大小比较、标准句包含测试、`且`、`或` 返回事实 `真` 或 `假`。它们不返回原操作数：`空 或 9` 为 `真`。`且` 仅在左侧为真时求右侧，`或` 仅在左侧为假时求右侧；`假 且 (1/0)` 安全短路，`0 且 (1/0)` 会除零。

迁移：用 `值 != 0`、`句 != ''`、`阵 其 量 > 0` 显式判断非零/非空；计数或数值算法不能再直接把比较结果作 0/1。需要数字时用分支显式给出 0/1。旧比较输出、条件、数类型参数与文件 `在` 的结果须同步更新。

### 5.2 转换

仅有以下源码转换：

| 写法 | 行为 |
| --- | --- |
| `值 为 事实` | 按上述真值规则得到真或假；事实保持自身 |
| `值 为 数` | 数保持数；句按严格十进制规则转换；其他值报错 |
| `值 为 句` | 对任何值使用与 `显` 相同的显示格式 |
| `值 为 阵` | 新建只包含该值的单元素阵，不展开、不深复制 |

句转数允许首尾 ASCII 空白（空格、Tab、CR、LF、VT、FF），中间必须符合 `[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)([eE][+-]?[0-9]+)?`。所以 `'1.'` 合法；空串、只有空白、`'0x10'`、`'nan'`、`'Infinity'`、含非 ASCII 数字或内部空白的字符串不合法。结果须有限；没有自动转零或隐式转换。

`空 为 阵` 为 `[空]`；若 `甲` 是阵，`甲 为 阵` 的唯一元素是同一个 `甲`。`为` 不用于把对象强制变成另一形，也不等同于字段/参数声明中的类型要求。

### 5.3 运算

数支持 `+ - * / %` 及一元正负号；除法与余数的右侧为零时报错，非有限结果报错。`%` 使用浮点余数，符号跟随被除数，例如 `-7 % 3` 为 `-1`，不是 Python 的取模规则。

`+` 也允许两个句连接；数字与句混合时必须显式转换。阵拼接、字符串重复、幂运算符、位运算、复合赋值、自增均未实现。除同的相等协议外不支持运算符重载。

`< <= > >=` 只接受两个数或两个句；句按 Unicode 码点字典序比较，不按拼音、区域排序或视觉字形。`== !=` 对任意值可用：

- 不同种类的值不相等；`空` 只与 `空` 相等，和 `'空'`、`0`、`''` 不相等
- 数比较数值，句比较字符序列
- 事实只按真假比较；`!=` 严格是 `==` 的取反
- 对递归按左右项从左至右比较，内部阵/典按身份，对象按下述同协议比较；同一对对象的身份快捷路径不会再遍历内部成员
- 阵、典、函数/过程值、模块按身份比较；两个内容相同但分别创建的阵/典/闭包不相等。同一声明在同一激活环境中重复取得引用是同一闭包；每次求值匿名字面量或建立绑定方法引用得到新函数值，其别名保留该身份

同一具体形的两个实例：若定义或继承 `算 同 另一`，调用左实例的同，以右实例为唯一实参，必须返回事实；无同则按身份相等。不同具体形直接不相等，即使有继承关系或同名方法。显式参数类型按通常规则检查。同须为一参算；错误签名或非事实结果报错。对内嵌实例也沿用此规则。相等协议应由作者保证自反、对称、传递；运行时不会证明这些性质，也不会在编译时执行同。

### 5.4 显示

`显 表达式.` 把显示文本写到标准输出并加一个换行。句原样输出，不加引号；数最多显示 15 位有效十进制数字；事实显示 `真` 或 `假`；空显示 `空`；典显示 `{键: 值, ...}`（顺序不保证）；对显示 `(左 对 右)`；阵显示 `[甲, 乙]`。嵌套容器中的句也不加引号，因此显示文本不保证可再次解析为原值。

对象显示为 `<形 名称>`，模块显示 `<外言>`，函数/过程值分别显示为 `<算 名称>` / `<作 名称>`；容器中发现当前展开路径的循环引用时显示 `<循环>`。这不是序列化协议或调试反射接口。`显` 输出失败属于普通运行错误，不返回成果，不由 `救` 捕获。

## 6. 绑定、作用域、函数与控制流

### 6.1 绑定和作用域

`名称 取 表达式.` 或 `名称 := 表达式.` 建立或更新绑定，绑定本身不固定类型。读取沿**词法环境**向外查找，不采用调用者的局部变量。顶层绑定属于当前模块；顶层函数/方法以其声明模块为外层，嵌套函数以声明时的函数、救或显式作用域块环境为外层；匿名字面量以实际求值时的当前词法环境为外层。

函数体执行 `值 取 …` 时，先更新当前局部已有的同名绑定；若没有，则更新最近的、已经存在的被捕获**非模块**绑定（外层函数、救或显式作用域块的绑定）；若仍没有，则在当前函数局部建立绑定。不会用 `取` 修改同名模块全局，只有全局同名值时仍创建局部影子。参数始终在当前调用局部绑定。捕获按共享绑定而非一次性值快照，详细规则见 6.4。

直接执行显式作用域块正文的 `取` / `:=` 始终写当前块的局部，包括正文内不另建环境的条件、循环及试；读取右侧仍沿词法环境向外查找。直接执行救正文的 `取` 始终写救的局部，保持原有局部遮蔽；在救中声明的闭包可以读取并更新该捕获救环境。通过共享阵或对象修改内容也仍对所有别名可见。条件与循环自身不创建作用域；试正文也不创建，救正文创建子作用域，见第 10 节。需要隔离它们的局部绑定时可显式加入 6.5 的作用域块。

函数/过程名和直接声明的形名不可同时作为变量或参数名；参数名不能重复。通过 `尽取` 导入的函数/形同样受保护。形名称（包括内置形）不是运行时普通值，只用于类型注解、`新`、`如` 和合法的形导入。`别名 取 某形.` 不合法，不能将形本身显示、比较、放入容器、作为实参或返回值；通过模块成员读取形作为普通值也不合法。形实例、实例别名及函数/过程值仍可正常保存、传参和返回。

### 6.2 函数与过程

`算 名 参数: … 法` 或 `算 名 参数 为 类型: … 法` 声明函数；实际执行路径必须执行 `得 表达式.`，否则报错。返回值不声明类型，可为任何值。允许递归、前向函数调用和函数内 I/O，不要求纯函数。

`作 名 参数: … 为` 或 `作 名 参数 为 类型: … 为` 声明过程；过程内不能 `得`。自然结束和执行 `完.` / `完。` 都返回 `空`。单独过程调用在 REPL 不额外回显，放入表达式时得到 `空`。没有参数的函数/过程仍需要定义冒号。

`完.` 是不携表达式的简单语句，必须以 ASCII 或中文句点结束；`完 值.`、`完 空.` 均不合法。它立即退出当前过程调用，可从条件、循环、显式作用域块及试 / 救正文离开，清理经过的恢复处理状态，不触发 `救`，也不撤销已完成的副作用。它不关闭语法块，源码仍须写完各块结束词（包括过程的 `为`），不可达语句仍须通过语法和结构检查。

合法性按最近的函数 / 过程边界判断：有名过程、过程方法、匿名过程以及嵌套过程均可使用；顶层、形正文、任何 `算` 内均禁止，包括嵌套在 `作` 中的 `算`。嵌套过程的 `完` 只结束该次内层调用，外层继续执行。`算` 仍只能用 `得 表达式.` 返回值；裸 `得.` 不合法。

0.8.0 迁移：过程结果从空句 `''` 改为 `空`，旧结果比较、句参数和拼接须相应调整；需要真正的句结果时用 `算` 和 `得 ''.` 或在调用后显式提供文本。`完` 新增为保留字，旧同名绑定 / 参数 / 成员须改名；最长名称规则仍适用，`完成`、`完毕` 等是普通名称。

```ru
作 展示 值 为 数:
    若 值 < 0 则 完。 然
    显 值.
为
显 (展示 (-1)) == 空. # 真
```


0.9.0 起，每个参数的 `为 类型` 均可省略；适用于有名／匿名算与作、方法、嵌套声明及闭包。省略类型的参数接受任何运行时值，包括 `空`、模块值、对象和函数值；不做类型推断或隐式转换，正文中的非法运算仍报错。形名称仍不是运行时值，不能因为参数省略类型而传入形本身。不新增 `Any` 或 `任意` 等公开内置类型／关键字。

声明可混用有类型与无类型参数，空白和逗号均可分隔，例如 `算 重复 内容, 次数 为 数:` 或 `算 重复 内容 次数 为 数:`。这里省略的是类型，不是实参：所有用户参数仍必需，没有默认值或可省略实参；数量、名称检查、全位置／全命名调用和求值顺序不变。`元初` 仍必须显式声明唯一的 `句 阵` 参数（见第 10 节）。

```ru
算 原样 值: 得 值. 法
算 配对 左, 右 为 数: 得 左 对 右. 法
显 (原样 空).                    # 空
显 (配对 '内容' 2) 其 囫.         # 内容
传回 取 算 值: 得 值. 法.
显 (传回 [1, '二']) 其 量.        # 2
```

调用时检查显式声明的参数类型，不做隐式转换。可用类型为 `数`、`句`、`事实`、`空`、`对`、`阵`、`典`、`算`、`作`、直接声明或经 `尽取` 导入的用户形名、内置形名，以及重复后缀 `阵`：

- `列 为 阵` 接受任意元素的阵
- `列 为 数 阵` 要求调用时每个元素均为数；空阵满足此检查
- `矩阵 为 数 阵 阵` 逐层检查二维阵；类似地可使用自定义形的阵
- `对象 为 父形` 接受该形或其子形的实例
- `操作 为 算` 只接受算的函数值，`操作 为 作` 只接受作的过程值；不混同两类。注解不编码参数数量/返回类型，真正调用时还需匹配被调用声明的参数
- `操作们 为 算 阵` 可约束函数值阵；不存在把任意值 `为 算` 或 `为 作` 的转换
- 参数 `数`、`算`、`作` 等不接受 `空`；字段普遍允许 `空` 是独立的字段规则

类型注解只在参数进入/字段写入等检查点检查，不给可变阵附加永久元素类型限制。例如参数接受 `数 阵` 后，函数仍可向该阵追加句；以后的受类型约束调用可能因此失败。

调用嵌套上限为 128，跨函数、方法和模块共享调用深度计数。源码表达式/块嵌套及模块依赖也有限制；应拆分深层表达式，而非利用实现栈极限。没有尾调用优化保证。

### 6.3 条件与循环

```ru
累计 取 0.
循 5 次
    累计 取 累计+1.
环
若 累计 == 5 则
    显 '完成'.
另
    显 '未完成'.
然
```

`若 条件 则 … [另 …] 然` 求条件一次，只执行选中正文。

`循 次数表达式 次 … 环` 进入循环时只求次数一次，要求数值为 `0` 到 `9007199254740991`（2^53−1）的整数。次数为零不执行正文；后来修改计算次数用到的变量不改变本轮总次数。

`循 … 环` 不带次数，是无限循环。`破.` 退出当前最内层循环；在函数/过程内部不能越过调用边界破外层循环。循环中允许函数 `得`、过程 `完` 或 `卒` 离开；没有隐式循环索引或 `continue`。无限循环需要程序自身 `破` 或由使用者中断。

### 6.4 词法闭包、提升与共享状态

嵌套有名 `算` / `作` 与匿名字面量都是一等词法闭包：即使外层调用已经返回，保存的函数值仍保留需要的词法环境。不会复制捕获值，也不会退回到调用者环境寻找同名变量。每次调用工厂函数创建独立环境；同一次调用产生的多个闭包共享该环境中的绑定。

```ru
算 造计数 起点 为 数:
    数值 取 起点.
    算 增加 步 为 数:
        数值 取 数值+步. 批. 更新外层已捕获的数值绑定
        得 数值.
    法
    算 查看:
        得 数值.
    法
    得 [算 增加,算 查看].
法
第一组 取 造计数 0.
第二组 取 造计数 10.
加一组 取 第一组[0].
看一组 取 第一组[1].
显 (加一组 2).       # 2
显 看一组().         # 2，同组闭包共享状态
显 (第二组[0] 3).    # 13，另一工厂调用相互独立
显 看一组().         # 2
```

直接嵌套函数/过程声明在每次进入其所属模块、函数/方法、救或显式作用域块环境时预先登记，支持前向引用、自递归和同一作用域的相互递归。匿名字面量不提升，只在表达式实际求值时建立新函数值。提升的是有名定义，不是普通 `取` 语句：捕获值在实际读取时必须已经绑定，普通赋值仍按顺序执行。尚未建立的局部不会被提前初始化为 `空`。

写捕获绑定使用 6.1 的“最近已有非模块绑定”规则：内层参数/局部优先；其次是最近捕获的函数、救或显式作用域块绑定；模块全局不在更新目标内。如果内层在外层建立某名字之前就写该名字，该次写入会建立内层局部，不预先为未来的外层绑定建单元。条件、循环、试不创建新的捕获环境，因此循环中反复保存同一闭包仍共享同一环境；想获得独立状态，可逐次调用工厂函数，或在循环正文中显式执行作用域块；每次进入显式块均创建新环境。

救直接正文的局部遮蔽不变，救中声明或通过字面量创建并返回/保存的闭包保留救的原因和局部绑定，救结束不使它们悬空。方法内嵌套函数可捕获自身及方法局部；模块内产生的闭包保留原模块环境。闭包退出、返回或卒时捕获环境仍按可达性存活，不能依赖确定的销毁时刻。

若需要由闭包生成若干互不相同的对象，使用已有 `循` 与 `其 增`，每次实际调用生成器并执行一次 `新`；没有新增“填充阵”或按索引隐式生成的语法。完整例见 `examples/closures.ru`；匿名工厂、传参及共享状态见 `examples/anonymous.ru`。

### 6.5 显式语句作用域块

`段: … 落.` 与语句位置的 `{ … }` 具有完全相同的语义，支持全角 `段：…落。` 和 `｛…｝`，可任意交错嵌套。`段` 后的冒号与 `落` 后的句点必需；右花括号后的句点可省略。空块写 `段: 落.` 或 `{}`。块不是表达式、没有值，也不是函数调用。

```ru
外值 := 10.
段:
    外值 取 外值 + 1. 批. 先读外值 10，再建立块局部 11
    若 真 则 临时 := 外值. 然
    显 临时.           批. 11，若沿用当前块环境
    { 外值 := 20. 显 外值. }
    显 外值.           批. 11
落.
显 外值.               批. 10
```

每次实际进入块都创建新的词法子环境，直接绑定只属于该环境、遮蔽同名外部绑定；离开块后不泄露。块内的条件、循环和试正文仍沿用当前块环境，救正文仍建立独立子环境，嵌套显式块也另建环境。这里的局部规则针对名称绑定，修改已有阵、典或对象内容仍共享；`取` 与 `:=` 一致。

块中直接声明的有名算／作在该次块入口提升，支持前向调用、自递归、相互递归；只在块内可见，也可通过保存函数值使闭包逸出。匿名字面量在实际求值时捕获块环境。同次进入产生的闭包共享绑定，循环中每次进入块产生的闭包环境互相独立。闭包沿 6.1 的函数赋值规则更新最近已有的非模块捕获绑定，包含块局部；局部存活以可达性为准，不以块文本结束为准。普通赋值不会提升或预先初始化。

块不引入新的函数、过程或循环边界：`得` 返回最近的算，`完` 结束最近的作，`破` 退出当前调用中的最近循环；`卒` 继续寻找外部救。所有合法性检查沿用所在上下文，不能仅因包一层块就在模块顶层使用 `得` / `完` / `破`。离开经过的块会恢复外部执行环境；闭包仍保留捕获环境，副作用不回滚。形和 `尽取 外言` 仍只允许模块顶层，不能放入块；普通 `模块 := 外言 '路径.ru'.` 可在块内建立局部模块值。

花括号由位置消歧：等待一条语句时总是块，因此裸 `{}` 是空块，裸 `{'键': 1}.` 不是典表达式语句。需要典表达式时写 `表 := {'键': 1}.`、`显 {}.`、`得 {}.`、`({}).`，或文字形式 `典: 成.`。表达式位置的花括号仍使用 7.6 的键值规则，不能装语句；`段: … 落.` 也不能放进赋值右侧或调用实参。实用示例见 `examples/scoped_blocks.ru`。

## 7. 对、阵和句的标准成员

### 7.1 空与不可变对

`甲 对 乙` 创建一个二元组，左右项可为任意值。`其 囫` 读取左项，`其 囵` 读取右项，两者都无参数且不能赋值。它不复制项中的阵/对象。

```ru
链 取 1 对 2 对 3 对 空.
和 取 0.
循
    若 链 == 空 则 破. 然
    和 取 和+链 其 囫.
    链 取 链 其 囵.
环
显 和. # 6
```

`对` 自身不可变，但内部共享对象可变；用 `空` 作为链尾是约定，不是对的强制结构限制。

### 7.2 可变阵

**数组字面量是当前 0.5 原型约定，构造语法尚未冻结**；这里准确记录已经实现的 `[]` / `[甲,乙]`，不把它解释为未来版本永久承诺。数组元素访问与改写使用第 7.3 节的零起点方括号规则。

`[]` 创建空阵，`[甲,乙]` 创建可混装任意值的阵，元素之间必须有逗号，允许尾逗号。每次字面量创建新阵。赋值、实参、返回值和对象字段传递同一引用。

数组元素中的带参数调用应加括号：`[(平方 2),3]` 或 `[(平方 2),(平方 3)]`。由于调用自身也接受逗号分隔实参，`[平方 2,3]` 会把 `2` 和 `3` 都读成 `平方` 的实参，不能表示“平方结果和 3”两个元素。

带字段实参的 `新` 构造同样应加括号，避免元素逗号被继续读为构造实参。阵可以直接保存学生等对象，下面创建两个独立学生对象：

```ru
形 学生:
    名 为 句.
    龄 为 数.
象
学生们 取 [(新 学生 名:'小明' 龄:8),(新 学生 名:'小红' 龄:9)].
显 学生们[0] 其 名.   # 小明
显 学生们 其 量.      # 2
```


标准成员和索引：

| 接收者 | 操作 | 参数名 | 结果 |
| --- | --- | --- | --- |
| 阵或句 | `其 量` | 无 | 数，元素数/码点数 |
| 阵或句 | `其 位 索引` 或 `[索引]` | `位` | 对应元素/单码点句 |
| 阵或句 | `其 段 始 终` | `始`、`终` | 浅切片阵/子句 |
| 阵 | `其 增 值` | `值` | 在尾部追加一项，返回**同一个阵** |
| 句 | `其 含 子句` | `句` | 包含返回真，否则假 |
| 对 | `其 囫`、`其 囵` | 无 | 左项、右项 |

数组可用 `列[索引] 取 值.` 或 `列 其 位 索引 取 值.` 改写已有位置；没有自动扩容赋值。追加使用 `增`。阵另提供 `删 位`、`弹`、`查 值`，见 11.12.2；另提供稳定浅复制 `排序`、逐项构造新阵的 `另成` 与带位置遍历的 `逐位`，见11.12.2a；不提供插入成员；典的哈希映射接口见第 7.6 节。

### 7.3 严格索引与浅切片

阵和句的索引从 `0` 开始，必须为数且是整数，满足 `0 <= 索引 < 长度`。负索引、小数、句索引、越界和对空集合取元素均报错，不作自动转换或回绕。

阵和句的 `值[始:终]` 左闭右开，要求 `0 <= 始 <= 终 <= 长度`。省略始为 `0`，省略终为长度，`[:]` 取全部，`[长度:长度]` 为空。越界不截断，反向区间报错；没有步长参数、负步长或切片赋值。

`其 段` 必须提供两个参数；要省略边界使用方括号形式。阵切片产生新的外层阵，但元素引用保留，所以是浅复制：

```ru
内 取 [1].
原 取 [内,2].
副 取 原[:].
副[1] 取 8.
副[0][0] 取 9.
显 原[1].       # 2
显 原[0][0].    # 9
显 原 == 副.   # 假
显 原[0] == 副[0]. # 真
```

### 7.4 二维与不规则嵌套阵

本版用“阵中存阵”表示二维数据，没有额外的矩阵类型。下面使用当前原型的数组字面量构造写法：

```ru
矩阵 取 [[1,2,3],[4,5,6]].
显 矩阵[0][1].     # 第 0 行、第 1 列：2
矩阵[1][2] 取 9.
显 矩阵[1][2].     # 9
```

行、列均从 0 开始，连续索引逐次检查对应阵的边界。各行可不同长度，例如 `[[1],[2,3]]`，没有隐式矩形形状约束。参数 `矩阵 为 数 阵 阵` 要求每行均为数阵，不要求行数或列数相同。

每次内层字面量创建独立行；如果刻意重复同一行引用，则两行共享：

```ru
行 取 [1,2].
矩阵 取 [行,行].
矩阵[0][1] 取 8.
显 矩阵[1][1].     # 8，两项指向同一个行阵
```

### 7.5 Unicode 句操作

句长度、索引和切片按 **Unicode 码点**，不是 UTF-8 字节、显示宽度或字素簇。`'甲😀é乙'` 长度为 4；组合附加符、emoji ZWJ 序列可占多个位置。句不可改字符或追加。

```ru
文 取 '甲😀é乙'.
显 文 其 量.       # 4
显 文[1].          # 😀
显 文[1:3].        # 😀é
显 文 其 段 始:1 终:3.
显 文@含 '😀é'.     # 真
```

`含` 测试连续子句包含，没有取反含义，也不进行 Unicode 规范化；空句包含于任意句。取反写 `非 (文 其 含 '子句')`。阵没有内置包含测试。

### 7.6 典：可变哈希映射

典的每个条目由**目（key）**与**相（value）**组成：目用于查找，相是该目对应的值。`目`、`相` 是教学术语，不是新增关键字；`值` 仍是语言的通用概念。典的成员命名实参统一使用 `目:`、`相:`：`查 目:`、`增 目: 相:`、`除 目:`；不再接受旧名 `键:`、`值:`。位置实参不变；遍历改为 `逐目 回调:`，回调内部参数名由用户自定。

```ru
方向 取 典: ‘上’ 对 0. ‘下’ 对 2. ‘中’ 对 1. 成.
空表 取 典:成.
显 方向 其 查 ‘上’.
显 方向[‘上’].      # 同样输出 0
显 方向[‘未知’].    # 空
方向 其 增 ‘右’ 3.
显 方向 其 除 ‘下’.
显 方向 其 量.
方向 其 逐目 作 目 相: 显 目. 显 相. 为.
```

典字面量有两种可混用的等价写法，生成同一种典表达式，不改变运行时语义：

- 文字形式 `典: 目表达式 对 相表达式. 成`：每项以句点结束，整个典以 `成` 结束；空典写 `典:成`
- 符号形式 `{目表达式: 相表达式, 目表达式: 相表达式}`：条目以逗号分隔，允许尾逗号；空典写 `{}`。不能用句点分隔符号条目，也不能省略目、冒号或相
- 两种形式的结束符都只关闭典表达式；所在简单语句仍另需终止句点。支持全角 `｛｝`、`：`、`，`，且可与 ASCII 混用；字符串和注释中的这些字符不作标点替换
- 表达式位置的花括号构造典；语句位置的花括号是 6.5 的独立作用域块。裸 `{}` 是空块；要单独求值空典可写 `({}).`。赋值、显、得、容器元素和实参等表达式位置的典规则不变

符号形式的目和相都是完整表达式，允许换行、嵌套典／阵和匿名算／作。作为目的名称求名称的当前值，不自动转换为同名字符串：`目 取 '上'. 表 取 {目: 1}.` 存的是字符串 `'上'`，文字目必须写引号。符号形式的冒号分隔目和相；调用内 `参数名:表达式` 的冒号仍是命名实参。目和相里的带参数调用、带字段实参的 `新` 构造应以括号包围，与阵元素规则一致，防止调用吞掉外层逗号或把目与相之间的冒号读作命名实参；例如 `{(f 1): (g 2), 'x': 3}`。调用的结果作为相时也不能省略括号，否则逗号可能继续分隔调用实参。命名调用写 `{'x': (f 值:1), 'y': 2}`，其内部冒号不分隔典条目。花括号不改变原有实参、匿名函数或切片的冒号规则。

```ru
算 f 值: 得 值 + 1. 法
算 g 值: 得 值 * 2. 法
目 取 '上'.
表 取 {
    目: 0,
    (f 1): (g 值:2),
    '嵌套': [{'下': 2}, 典: '中' 对 1. 成],
    '旧式': 典: '内' 对 {'值': 3}. 成,
}.
全角 取 ｛‘上’：0，‘下’：2，｝。
空表 取 {}.
显 表[目].
显 表[2].
显 全角['下'].
```

两种写法的条目都按源码顺序逐项求值：先目、后相，然后插入，再求下一项。同目后相覆盖前相，保留已存的键对象；不会以新等价键替换原键引用。文字形式的键表达式若含对须用括号，但对本身不是合法键。实现使用实际哈希索引与冲突处理，不是逐项线性查找。显示和逐目的枚举顺序不作保证，不应依赖当前后端的遍历次序。

键只能为有限数、句、事实或实现同和印的用户形实例。空、对、阵、典、函数/过程、模块及不支持协议的内置实例均拒绝。数按数值比较，0与负零同键；句按字符内容；事实与数分离，真不等于1、假不等于0。

形实例键必须同时具备一参 `算 同 另一: … 法` 与零参 `算 印: … 法`，继承的方法也可用。同的参数类型可省略或按普通规则显式标注；同必须返回事实。印必须返回有限、无小数且绝对值不超过 9007199254740991 的数，不接受事实。同一具体形且印值相同的候选键再调用已存键的同；同印不意味着相等，不同具体形不相等。缺少任何一项或错误签名/返回类型均报错，不降级为身份键。作者必须保证相等键有相同印，以及同的等价关系；不满足时查询结果无语义保证。

```ru
形 坐标:
    横 为 数.
    算 同 另一 为 坐标: 得 其 横 == 另一 其 横. 法
    算 印: 得 其 横. 法
象
表 取 典: (新 坐标 横:2) 对 ‘二’. 成.
显 表 其 查 (新 坐标 横:2).
```

- `典 其 查 目` 或 `典值[目]`：返回已存的相，缺失返回空。因此无法区分缺失与已存空，这是本版明确选择
- `典 其 增 目 相`：新增或覆盖，返回同一个典；命名实参为 `目:`、`相:`
- `典 其 除 目`：删到返回真，否则假
- `典 其 量`：返回当前条目数（数）
- `典 其 逐目 回调`：回调可为算或作，必须接受两个位置实参（目、相）。忽略回调结果，完成返回空；从调用开始的浅条目快照遍历，顺序不保证。回调内可增删原典，不影响本轮条目集合；共享可变值的后续改变仍可见。完只结束当前过程回调，卒按普通调用传播；空典也验证二参算或作。旧典列已移除并给出迁移错误，目录列不变

`典值[键]` 先求接收者，再求键，各一次，使用与 `查` 完全相同的合法键类型、同／印、版本保护、卒传播和共享值规则。数键不受阵的零起点整数范围限制；事实键与数键分离。连续读取逐层按实际接收者分派，例如 `表['项'][0]` 或 `列表[0]['心']`。不提供典的方括号赋值或切片、`其 位`／`其 段`、隐式含测试或深复制；更新仍使用 `其 增 目:… 相:…`。典本身可变且别名共享；键和值中的对象、阵、典保留共享引用，数按值，句共享不可变内容。典参与身份相等和循环垃圾回收，循环显示为 `<循环>`。作者自行负责插入后修改键字段或影响同/印的方法导致的索引失效；实现不冻结、重新索引或新增任意方法修改机制。若同/印执行期间修改正在查找的典，本次操作报清晰的运行错误，以避免使用失效索引；先前已完成的修改不会回滚。协议回调只在运行时调用，受通常调用深度、卒及垃圾回收规则约束。

## 8. 形、对象、继承与方法

### 8.1 声明和构造

```ru
形 计数器:
    值 为 数.
    作 增加 步 为 数:
        其 值 取 其 值+步.
    为
    算 报数:
        得 其 值.
    法
象
形 命名计数器 如 计数器:
    名 为 句.
    算 报数:
        得 其 值+1.
    法
象
甲 取 新 命名计数器 名:'计数' 值:2.
乙 取 甲.
乙 其 增加 3.
显 甲 其 报数. # 6
```

字段仍须显式写类型：`名称 为 类型.`，不是变量绑定，也不支持字段声明中的初始化表达式。字段、方法在同一形中不能重名。

`新 形名称 字段名:值 …` 只接受命名字段；未知或重复字段报错，可初始化继承字段。用户形的所有省略字段缺省为 `空`；字段也可稍后重新赋为 `空`。除 `空` 外，写入值必须满足字段类型。内置 I/O 形的缺省值见第 11 节。

构造器只分配对象和写字段，不隐式调用任何用户初始化方法。没有 `构造`、`析构`、访问修饰符或计算属性语法。`新` 后必须是单一形名称，来源为直接声明、`尽取` 导入或内置形；不能写普通值别名或 `新 模块 其 类型`。跨模块构造须先使用 `尽取` 导入形，或调用原模块中返回实例的工厂函数。需要保存或传递构造行为时，使用返回实例的函数值，例如 `算 造 值 为 数: 得 新 计数器 值:值. 法 工厂 取 算 造. 甲 取 工厂 1.`。工厂返回的是对象，不是形。

### 8.2 成员和自身

`对象 其 字段` 读取，`对象 其 字段 取 值.` 写入。只能写已声明字段；不能动态新增字段，不能给方法、对成员、模块导出或字符串元素赋值。

`对象 其 方法 实参` 调用方法，位置和命名规则同函数。方法内裸 `其` 是当前对象，`其 字段` 是自身字段的简写；方法及其词法闭包之外不能使用自身形式。方法局部变量不自动映射为字段，必须显式写 `其 字段`。方法通过其声明模块读取全局，但自身保留实际对象身份。

### 8.3 单继承和覆写

`形 子 如 父` 只支持单继承。父形须为本模块直接声明或通过已执行的 `尽取 外言` 导入的形名；不存在普通运行时形值别名。直接形声明允许前向引用，但导入的父形仍要求导入语句先执行。

子形继承字段与方法。新增字段不能与继承字段/方法冲突；方法不能覆盖字段。覆写方法必须保持**参数名字、类型及算/作种类完全一致**。无类型只与对应的无类型参数匹配；无类型与任何显式类型均不兼容，不能在覆写时增加或去掉注解。类型在各方法的声明模块中解析：用户形按声明身份比较，同名但不同模块的形不相同；经导入或转导出的同一形仍保留身份。有元素类型的阵逐层比较元素类型及阵层数，内置类型按其类型类别比较，不能仅比较签名中的名称文字。没有按参数类型重载。继承循环报错，过深继承受实现嵌套限制。

方法参数的类型身份在所属形解析时绑定，之后调用该方法使用已绑定的身份；继承来的方法保留原声明模块及原参数身份。形解析也检查字段注解引用的类型是否存在。因此字段／方法注解使用的导入形必须通过已经执行的 `尽取` 可见，不能把相应导入放在形语句之后；若构造或继承使形更早解析，导入也须在该解析之前完成。同一模块／同次 REPL 提交中的直接形声明会预先登记，仍允许本地形名前向引用。

REPL 后续重新声明同名形会创建新的身份，不改变旧实例或旧方法参数已绑定的身份。普通函数（包括嵌套与匿名函数）的参数注解则在调用时按其声明模块解析；这不提供形值别名，也不意味着所有函数签名都在声明时固定。

方法内部通过 `其` 再调用其他方法，按实际对象类型动态分派，因此继承来的方法可调用子形覆写的方法。父形类型参数接受子形对象；不相关的同字段形不是彼此兼容的结构类型。没有父方法调用语法、多继承或接口。内置 `件`、`录`、`件作成果` 虽能作为参数类型或用于 `新`，但不能作为 `如` 的父形；它们的内部 I/O 方法不是可继承的用户方法。

### 8.4 成员名与特殊协议

成员语法不固定全局签名。对象字段和用户方法可以使用 `含`、`位`、`段`、`增`、`量` 等普通名称；参数与返回值按声明决定。`同` 和 `印` 仅在相等及典键协议中有额外约束，见 5.3、7.6。普通调用本身仍使用方法原有签名。

## 9. 本地模块与程序入口

### 9.1 外言的解析和初始化

```ru
数学 取 外言 'modules/math.ru'.
显 数学 其 平方 9.
```

`外言` 后必须是**非空字符串字面量**，内容只能是本地文件路径、已知标准外言名称或明确列出的随附三方库名；不能是变量、插值或任意表达式，不允许含 `://` 的 URL。以 `如:` 开头的名称保留给随工具链发布的标准库。本版接受 `如:竞`、`如:观`、`如:文本`、`如:数学`、`如:随机`、`如:密`，分别解析到包内 `stdlib/` 对应的 `.ru` 文件；未知 `如:` 名称直接报错，不回退到本地同名文件。当前目录、导入文件目录中的同名文件不能替换标准外言。旧精确名称 `如竞`、`如观`、`如:竞赛` 直接给出迁移错误，分别提示改为 `如:竞`、`如:观`、`如:竞`；不保留兼容别名，也不回退到同名本地文件。产品／功能名称仍为如竞、如观。

精确裸名称 `如见` 解析到独立目录中的随附三方库。它使用 `如:密` 实现 Win32 绑定，现阶段不属于语言标准，也没有 `如:见` 别名。当前目录同名文件不能替换此随附库；显式本地路径仍按本地模块处理。库分发身份不赋予执行权限，原生能力是后端／宿主权限边界，详见后面的“如:密与随附三方库如见”一节。

除上述保留名称外，其他字符串为本地相对/绝对路径，路径相对**写下导入语句的源码文件目录**，不相对进程工作目录。REPL 没有源文件时，以当前工作目录为基准。若确实要导入本地带此名字的文件，可显式写 `./如竞`，它属于普通本地导入而非标准库名称。模块不要求在线注册或下载；标准库也按下面的规范化路径缓存、检查和打包规则处理。

文件命令 `run`、`check`、`build` 及生成结果验证会规范化绝对路径，并预先解析所有静态出现的导入，包括函数和不可达分支中的导入；这些源文件仍必须存在且语法/结构合法，静态依赖图中的循环即使不会执行也报错。模块依赖嵌套上限为 128。

REPL 提交本身不预先构建整个导入图：仅在某个导入表达式实际执行时才加载其依赖图，随后对该图中的静态依赖应用上述检查。因此 REPL 中暂未调用的函数内导入可延后到调用时才发现路径或依赖错误；不要据此推断同一文件程序也能通过检查。

解析和检查不执行模块顶层。运行时第一次实际执行某导入表达式，才按顺序执行该模块顶层；相同规范化路径成功初始化一次，后续返回同一模块实例，包含菱形依赖复用。不同拼写规范化为同一路径时共用缓存。

原生编译在构建时把依赖图一起编入输出；运行二进制不会再读取 `.ru` 文件，但模块初始化语句仍在首次实际导入时执行。

### 9.2 导出、限定访问与尽取

模块导出自己的顶层函数/过程、形与实际建立的全局绑定，没有额外 `export` 声明；也可转导出通过 `尽取` 导入的名字。内置名称本身不是用户模块的导出内容。函数的全局环境始终属于原定义模块。

模块顶层的条件、循环和试正文沿用模块环境，其中实际建立的函数值绑定也可以经 `尽取` 导入后正常带参调用，包括转导出；救、显式作用域块或函数内部的局部不因此导出。编译时允许可能建立的绑定，不等于运行时必然有值；未执行的分支不创建绑定，实际名称冲突和缺失仍按运行时规则报错。

`模块 其 导出名` 读取普通绑定，或调用导出的零参函数；形导出仅供 `尽取` 引入类型名称，不能通过成员读取变成普通值。有参数函数写 `模块 其 函数 实参`。模块导出的 `量` 等同名函数也使用普通实参语法，按实际声明调用。

```ru
尽取 外言 'modules/math.ru'.
显 (平方 4).
```

`尽取` 把导出名字引入当前模块顶层，不能放入条件、循环、函数、救或显式作用域块正文。与已存在绑定、声明或内置名称冲突时明确报错，不默默覆盖。某些冲突能在检查阶段发现，依赖实际执行分支的冲突在运行时发现。

尽取的普通值绑定可在导入方重新绑定而不改变原模块绑定；阵/对象仍共享原引用。尽取函数/形名称受保护，不能重新绑定。导入不是目录权限隔离，源码可导入有读权限的本地文件。

### 9.3 初始化失败

循环导入报错，不向外返回半初始化模块。初始化期间若发生未被模块内部处理的 `卒`，外部生效的 `试` 可以救；此路径被记为失败模块。该模块环境会保留，使初始化前已通过共享容器传出的对象仍有有效所属环境。

同一路径再次导入时，重新抛出缓存的原始原因和来源位置，**不重新执行初始化，不重复已发生副作用**。重新启动进程，或 REPL `:reset`，才清空此缓存。这个可恢复失败缓存约定针对显式 `卒`；普通模块读取、语法、类型/运行错误不是可救的模块失败结果。

### 9.4 元初与退出码

```ru
显 '先执行顶层'.
算 元初 外参 为 句 阵:
    显 外参 其 量.
    得 0.
法
```

主文件可不声明 `元初`，正常执行后退出码为 0。若声明入口，必须是主文件自己声明的 `算 元初`，恰好一个 `句 阵` 参数，参数名可自定。先执行主文件顶层，再调用入口一次，外参数组不含程序文件名。

入口必须返回数值为 `0` 到 `255` 的整数；空、句、小数或范围外数值报错。导入模块的 `元初` 不因导入或尽取自动执行；REPL 也不自动调用入口。可通过 `ru run source.ru -- 你好 世界` 或原生程序 `./app 你好 世界` 传参。

## 10. 卒、试、救与终

```ru
算 检查 值 为 数:
    若 值 < 0 则 卒 '值不能为负数'. 然
    得 值.
法
试
    显 (检查 (-1)).
救 原因
    显 '已处理：'+原因.
终
显 '继续'.
```

`卒 表达式.` 先求表达式，结果必须为句；不是句会产生**普通类型错误**，不会转成可救的卒。合法卒携带原因句及原始源码位置，寻找最近的**动态生效** `试`，可跨函数、方法及模块边界传播。

`试 … 救 原因 … 终` 必须有 `救` 和一个合法原因名称，正文可以为空。无卒时跳过救正文；有卒时中止试正文的剩余执行，在救正文中以原因名称绑定该句。处理结束从 `终` 后继续，不返回到卒发生位置。

- 试正文与外部同一作用域，之前完成的绑定可继续使用
- 救正文具有以外部作用域为父级的子作用域；原因名以及救中 `取` 的绑定不覆盖或泄露到外部，包括与外部同名绑定
- 救仍可通过读取外层引用修改阵/对象内容，改动共享且不会回滚
- 原因名不可与函数名、形名或受保护内置名称冲突
- 救内再次 `卒` 向外层动态生效的试传播，不被自己处理；可显式写 `卒 原因.` 传播原因，但这是新的卒位置，没有独立“原样重抛”语法
- `得`、`完`、`破` 可以正常离开试/救，并清理对应处理状态；其合法性仍由所在函数/循环结构决定
- 无匹配救时，命令非零结束，在 stderr 报告原因和源位置；REPL 报告后等待下一段输入
- 没有 finally、异常对象、可救错误类层次、自动资源管理或隐式事务

除零、未定义名称、普通类型错误、越界、调用深度超限、传统 `显`/`读` 的错误等不是 `救` 可捕获的卒。I/O 成果的 `'失败'` 也不是卒，需要程序显式选择 `卒 成果 其 错误信息.`。

## 11. 标准 I/O 与如竞库的完整接口

### 11.1 形、字段及缺省值

本节的方法“签名”表示参数要求及默认值，不是可直接粘贴的用户方法定义。除传统 `读`、`显` 外，下述真实 I/O 均返回一个新的 `件作成果`。

| 名称 | 构造/获得方式 | 字段与缺省值 |
| --- | --- | --- |
| `件` | `新 件 [路径:句]` | `路径` 缺省 `''` |
| `录` | `新 录 [路径:句]` | `路径` 缺省 `'.'` |
| `件作成果` | 操作返回；也可 `新 件作成果` | `结果:'成功'`、`值:空`、`错误信息:''` |
| `读取` | 已有标准输入对象 | 无公开字段 |
| `显出` | 已有标准输出对象 | 无公开字段 |
| `错误` | 已有标准错误对象 | 无公开字段 |

`件`、`录`、`件作成果` 为可直接使用的内置形名，跨模块类型身份一致。标准流对象的内部显示名称为输入流/输出流，但没有提供可用于 `新 输入流`、`新 输出流` 的公开内置形名，也不提供用户打开/关闭流的接口。

构造件/录只创建对象，不读、写、创建或探测路径。路径相对**运行进程工作目录**，与 `外言` 相对源码文件的规则不同；语言 I/O 不自动展开 `~`、环境变量或通配符。

三个内置形的字段按普通对象规则可修改，字段允许 `空`。`件作成果` 的 `结果`、`错误信息` 除空外须为句，`值` 可保存任意如值，包含阵/对象引用；手动改写成果不改变已完成的操作，不保证三字段之间的逻辑一致。业务代码应检查操作原样返回的成果。

### 11.2 成果协议与错误分类

成功时：`结果 == '成功'`，`值` 按操作定义，`错误信息 == ''`。失败时：`结果 == '失败'`，`值 == 空`，`错误信息` 是说明原因的句。没有公开的数值错误码字段；错误文字中可能含 errno，但不是稳定解析协议。

必须区分：

1. **调用形状错误**：未知成员、缺少/多出参数、重复或未知参数名、混用位置和命名形式，是普通语言错误，不能靠检查成果或救恢复
2. **操作输入/系统错误**：在合法签名下，内容不是句、路径为空/不可用、`追加` 不是数 0/1、UTF-8 无效、NUL、权限、读写刷新关闭失败等，返回失败成果
3. **构造/字段赋值错误**：例如 `新 件 路径:3` 违反普通字段类型，构造直接报普通语言错误；`路径:空` 可按字段规则构造，但之后操作返回失败成果

每个成果是普通引用对象。`值` 中的有效载荷不深复制；例如目录列表内的各件和列表阵可按普通引用规则继续使用。

### 11.3 件的方法

| 调用 | 参数 | 成功的值 | 说明 |
| --- | --- | --- | --- |
| `文件 其 读` | 无 | 句 | 一次读完整文件文本，保留文件内原有换行 |
| `文件 其 写 内容:句 追加:数` | `内容` 必需，`追加` 缺省 `0` | 空 | 0 截断/创建，1 追加/创建；不自动加换行 |
| `文件 其 在` | 无 | 事实真或假 | 路径指向普通文件为真；不存在/非普通文件为假 |
| `文件 其 除` | 无 | 空 | 删除普通文件或符号链接自身；不删除目录 |

位置形式也可用，例如 `文件 其 写 '文本'`、`文件 其 写 '文本' 1`；命名形式允许重新排序。`追加` 只能是数 `0` 或 `1`，不是任意真值，句 `'1'`、空、其他数返回失败成果。

- `读` 的空文件成功返回 `''`，不是 EOF 的 `空`
- `读`/`写` 只操作普通文件。FIFO、设备、套接字、目录等不受支持；POSIX 用非阻塞打开和文件类型检查避免把特殊文件当普通文本流等待
- 写入先检查内容/追加等参数；默认写入会截断已有文件。没有覆盖确认机制，程序作者必须控制目标路径
- `在` 遇到不存在或路径中某段不是目录时成功返回事实假；权限等 stat 失败则返回失败成果，不将所有错误伪装成不存在
- `除` 遇到不存在、普通目录、其他不支持文件种类返回失败；删除符号链接时允许其目标是目录或已经不存在，因为删除的是链接自身
- 每次操作独立打开并关闭，没有持久文件句柄、游标、seek、二进制模式参数或锁接口

### 11.4 录的方法与符号链接

`目录 其 列` 无参数，非递归返回一个阵，元素是新建 `件` 对象，各项 `路径` 是目录路径和文件名连接而成的可继续使用路径。按文件名 Unicode 字符序排序，不按文件大小/时间，且不受区域排序规则控制。空目录成功返回 `[]`。

只包含普通文件及指向普通文件的符号链接，不包含子目录、指向目录的链接或特殊文件。列表不是原子快照：遍历时已经消失的项或悬空链接略过；其余扫描、文件检查或关闭错误使整个操作失败，不返回貌似完整的部分列表。

文件读、写、存在判断及列目录时的文件判断**跟随符号链接**；删除操作只删除链接。`录` 的路径本身可以通过系统路径解析指向目录。常规文件权限和 umask 生效，不提升权限、不主动修改既有权限。检查与实际操作之间存在常规文件系统竞争，不能把这些接口当作安全路径沙箱。

### 11.5 标准流与传统便捷写法

| 调用/语句 | 参数 | 返回/行为 |
| --- | --- | --- |
| `读取 其 读` | 无 | 成果；成功值为一行句或 EOF 的空 |
| `显出 其 写 内容:句` | 必需 `内容` | 成果；写 stdout，不加换行，返回前刷新 |
| `错误 其 写 内容:句` | 必需 `内容` | 成果；写 stderr，不加换行，返回前刷新 |
| `读` / `读 提示:句` | `提示` 可省略，缺省 `''` | 直接返回一行句，EOF/失败为普通运行错误 |
| `显 表达式.` | 任意值表达式 | 直接显示并加换行，失败为普通运行错误 |

标准流写可使用一个位置实参；**不接受 `追加`**。标准流操作不关闭标准流。

行读取以 LF 分行，去掉末尾 LF，再去掉末尾一个 CR；因此普通 LF/CRLF 都不保留，末行没有 LF 也可读，末行尾部单个 CR 也被去掉。单独 CR 不作为中途分行符。到 EOF 且本次未读到字符时，`读取 其 读` 返回成功且 `值 == 空`；用户按回车的空行返回成功且 `值 == ''`。不要只按值的真值判断 EOF。

传统 `读` 先把提示写到 stdout，不加换行并刷新；提示必须为句。`读 '输入：'` 等价于 `读 提示:'输入：'`。它在 EOF 报错以避免旧程序无输入时不停循环，不返回空哨兵；传统 `显`/`读` 不返回 `件作成果`。

### 11.6 编码、失败和平台界限

源码、语言字符串、件文本与标准输入均按 UTF-8 处理；无效 UTF-8 和 NUL 不受支持。文件内容不做 BOM 去除或换行标准化；读取到的文本 BOM 是普通字符。目录文件名也须可作为有效 UTF-8 句表示。

所有已返回的成功都经过该操作需要的读写/刷新/关闭检查，包括短写检查。失败可能已发生部分写入、截断、创建或部分输出；无事务、回滚、原子替换、持久化 `fsync` 或断电恢复保证。极端资源耗尽等运行时致命错误不能保证转成成果。

当前原生 I/O 在 Linux/POSIX 上验证；源码有 Windows 宽字符路径分支，但 Windows 原生编译/运行未实测，macOS/其他架构也不能由 Linux 测试推定兼容。原生输出按目标平台重新构建。该原型没有权限隔离、网络文件协议抽象或异步 I/O。

### 11.7 如竞标准外言与公开函数

如竞是 0.5.0 引入的竞赛模块，当前唯一标准导入名为 `如:竞`。旧导入 `如竞` 与 `如:竞赛` 会提示改用 `外言 '如:竞'`，不保留导入别名。它是普通如源码模块，公开函数均为 `算`，沿用普通调用、类型要求、命名实参、尽取冲突及函数引用规则。它不自动导入，也不新增词法保留字或数组构造语法。

```ru
竞 取 外言 '如:竞'.
入 取 竞 其 读入.
拆分 取 算 竞 其 拆词.
显 (拆分 '甲 乙').
```

或在模块顶层使用 `尽取 外言 '如:竞'.` 后直接调用公开名称。下面是本版完整导出清单，表中参数按位置声明顺序列出；所有参数均必需，无参函数除外：

| 公开算 | 参数 | 返回值 |
| --- | --- | --- |
| `读入` | 无 | 剩余标准输入的读流对象 |
| `扫句` | `文 为 句` | 在该句上建立的新读流对象 |
| `拆词` | `文 为 句` | 按 ASCII 空白分割的句阵 |
| `拆行` | `文 为 句` | 按下述行规则分割的句阵 |
| `字列` | `文 为 句` | 每个 Unicode 码点各为一个句的阵 |
| `合句` | `列 为 句 阵`、`隔 为 句` | 以隔连接元素得到的句 |
| `排序` | `列 为 阵`、`比较 为 算` | 稳定排序得到的新浅复制阵 |
| `取整` | `值 为 数` | 向零截断后的数 |
| `小` | `左 为 数`、`右 为 数` | 较小者 |
| `大` | `左 为 数`、`右 为 数` | 较大者 |
| `绝对` | `值 为 数` | 值的绝对值 |
| `整除` | `左 为 数`、`右 为 数` | 先执行普通数除法，再向零截断 |
| `蓄出` | 无 | 新的标准输出缓冲对象 |

所有公开函数都能取引用，例如 `算 读入`、`算 竞 其 排序`。保存的零参函数值需显式调用，例如 `造入 取 算 竞 其 读入. 入 取 造入().`。这与下述内置对象成员不提供函数引用的限制不同。

受保护名称 `__如竞` 是实现桥接；不从该模块导出，也不是应用代码的公开接口。读流与出流是可保存、共享引用、由闭包捕获的对象，但不导出可供 `新` 或 `为 类型名` 使用的类型名，所以本版不能直接为读流／出流声明专用类型参数。需要传递读取或输出能力时，可直接传给无类型参数，也可用捕获该对象的算／作回调，或把对象装入阵／对后传参。不提供公开字段、游标重置、文件路径或关闭成员。只使用下列成员。两份变量指向同一个读流时共享游标，指向同一个出流时共享缓冲；两次 `扫句` / `蓄出` 则建立独立对象。

### 11.8 如竞读流、EOF 与编码

`读入` 不打印提示，**一次读取到标准输入 EOF**，并在返回前验证整份输入为有效 UTF-8 且不含 NUL。错误字节即使在尚未扫描的后半段，也使这次读入失败；不会先返回合法前缀的词。BOM 不去除，是普通字符。后续游标读取不重新验证整份输入。空间与整份输入大小成正比，不是定长流式读取；交互式题不能用它等待下一条消息。一般程序只调用一次 `读入`，后续调用只会读到标准输入尚未消费的部分。

`扫句 文` 使用已有有效句建立游标，不读标准输入。两种读流具有相同的三个无参成员：

| 调用 | 返回与游标效果 |
| --- | --- |
| `入 其 词` | 跳过当前 ASCII 空白，读取最长非空白片段为句；没有片段时返回空 |
| `入 其 数` | 按词的规则读取并按第 5.2 节严格转数；EOF 返回空，坏数字或非有限结果报错 |
| `入 其 行` | 从当前游标读到下一个 LF，返回去掉 LF 及紧靠它之前一个 CR 的句；已经处于 EOF 时返回空 |

这里的 ASCII 空白**只有**空格 U+0020、Tab U+0009、LF U+000A、CR U+000D、VT U+000B、FF U+000C。全角空格、不换行空格、其他 Unicode 空白均是词内容；此规则不同于源码词法的 Unicode 空白规则。数字输入可用正负号、十进制小数和指数，不能用全角数字、`nan`、十六进制或千位逗号；`数` 不限于整数，也不会把坏词变成零或 EOF。

读词/数只跳过**读取前**的空白，读到词尾即停止，不消费尾部分隔符。之后读行从该位置继续，所以当前行剩余部分可以以空白开头；如果词紧接 LF，下一次读行返回 `''` 并消费该 LF。不要把词读取和行读取混用时的一次空行误当成 EOF，或假设读词已自动跨行。

行读取不跳过开头空白，不以独立 CR 分行。没有结尾 LF 的非空剩余内容仍是一行，且其尾部 CR 保留。`''` 是真正空行，EOF 是 `空`，必须以 `值 == 空` 判断；数值 `0` 同样不是 EOF。末尾一个 LF 不会额外产生空行，连续两个 LF 则在两者之间有一个空行。到 EOF 后继续任意次读取均返回空。

```ru
尽取 外言 '如:竞'.
入 取 扫句 '12 rest\r\n\n尾\r'.
显 入 其 数.   # 12
显 入 其 行.   # 句 ' rest'
显 入 其 行.   # 句 ''
显 入 其 行.   # 句 '尾\r'，保留未跟 LF 的 CR
显 入 其 行.   # 空
```

成员使用裸写法 `入 其 词` / `数` / `行`。**不能写 `入 其 数()`，也不能取 `算 入 其 数` 引用**；这些是内置成员，不是普通用户方法。需要回调时，可声明普通算在正文中执行该读取，再取该算的引用。读流成员的参数数量必须为零。

如竞库的读入、坏数字和类型错误属于普通致命运行错误：文件执行终止、诊断写 stderr、非零退出，不返回 `件作成果`，也不是可由 `救` 捕获的 `卒`。这不替换第 11.1–11.6 节的受检查 I/O 协议。特别地，原有 `读取 其 读` 对未终止末行尾部 CR 的处理不同，不能用两者混读来推断新库的游标行为。

### 11.9 有界缓冲输出

`出 取 蓄出.` 建立标准输出缓冲，支持以下内置成员；既可用全位置实参，也可用表中的全命名实参：

| 调用 | 行为与返回 |
| --- | --- |
| `出 其 写 内容:句` | 追加该句，不加换行；成功返回空 |
| `出 其 行 值:句或数` | 追加句原文或数的显示，再加一个 LF；成功返回空 |
| `出 其 清` | 输出待写字节并刷新标准输出；空缓冲也刷新；成功返回空 |

`写` 只接受句。`行` 只接受句或有限数，不接受事实、空、对、阵、典、对象或函数；要显示这些值先显式 `为 句`。数使用第 5.4 节的 `.15g` / 15 位有效数字格式，没有固定小数位、填充、科学记数格式选择或 64 位整数专用输出。位置例子为 `出 其 写 '答案：'. 出 其 行 42. 出 其 清.`。这三个成员不提供函数引用；零参 `清` 使用裸成员写法，不能附加 `()`。

缓冲待写内容最多为 **65536 字节（64 KiB）**，不是 65536 个码点。达到容量或剩余容量放不下下一整个 UTF-8 码点时自动刷新；刷新边界不截断码点。单次写入很大的句也会分段输出，不把整次写入长期保存在一个无界缓冲中。`写` / `行` 成功只表明内容已接受并完成当时需要的写入，不代表缓冲中所有内容已经送至标准输出。

**最后必须显式 `出 其 清.`**。正常进程退出、`得`、`完`、`卒`、其他错误或垃圾回收均不承诺自动清空最后一段。清后对象仍可继续写。多个出流有独立缓冲，混用 `显`、`显出` 或另一个出流前应先清，以免输出次序与调用次序不符。缓冲不关闭标准输出。

底层写入或刷新失败为普通致命错误并写 stderr，不返回成果，不由 `救` 恢复。失败可能已经写出部分答案，没有回滚保证。

### 11.10 拆分、码点与合句

`拆词` 等价于在同一文本上从头反复读取 `词`，把非空结果加入新阵，直到 EOF。连续 ASCII 空白不产生空词；空文本或只有 ASCII 空白的文本返回空阵。

`拆行` 等价于从头反复读取 `行`，保留真正的空行，不添加末尾虚构的行：`拆行 ''` 是 `[]`，`拆行 '\n'` 是 `['']`，`拆行 '甲\n'` 是 `['甲']`，`拆行 '甲\n\n'` 是 `['甲','']`，`拆行 '甲\r'` 是 `['甲\r']`。CR 只在紧贴实际 LF 时剔除。

`字列` 逐 Unicode 码点返回新句阵，每个元素含一个码点；中文汉字和一个单码点 emoji 各算一个元素，组合附加符和多码点 emoji 序列分别拆开。空句得到空阵；不按 UTF-8 字节、字素簇、单词或拼音拆分，也不规范化文本。

`合句 列 隔` 只接受句阵及句分隔符，不把其他元素隐式转句。空阵返回 `''`，单元素阵返回该元素的内容，其他情况只在相邻两项之间插入隔，不在开头/结尾额外加隔。`合句 ['甲','乙'] ','` 得到 `'甲,乙'`。以上操作不修改输入句或阵；返回内容保留原来的 Unicode 和空白。

### 11.11 稳定排序与数值辅助

`排序 列 比较` 在调用开始时浅复制列中元素，并返回一个**新的阵**，空阵及单元素阵也不会返回原阵本身。按比较器确定的顺序稳定排列：比较结果为零的元素保持输入次序。排序操作本身不重排原阵；其中的对象、嵌套阵、闭包等仍是原引用，不做深复制。

比较器必须为 `算` 函数值，可以是词法闭包或绑定用户算方法，不可为 `作`。库以两个位置实参（左项、右项）调用它；参数数量和类型仍按普通调用检查。结果必须是有限数：负数表示左项排在前面，零表示同序，正数表示右项排在前面。返回数的真值不是比较协议；返回 `左 < 右` 所得的事实会报类型错误，不能表达三向顺序。

```ru
尽取 外言 '如:竞'.
算 造比较 方向 为 数:
    算 比较 左 为 数 右 为 数:
        若 左 < 右 则 得 -方向. 然
        若 左 > 右 则 得 方向. 然
        得 0.
    法
    得 算 比较.
法
原列 取 [3,1,2,1].
比较器 取 造比较 1.
有序 取 排序 原列 比较器.
显 有序.  # [1, 1, 2, 3]
显 原列.  # [3, 1, 2, 1]
```

比较器须为同一批元素提供一致的顺序（含传递的同序关系），应避免副作用。它的调用次数、顺序和算法细节不保证在各后端一致；不能依赖次数计数或在比较中改变排序键。若回调主动修改原阵、对象或其他共享状态，该修改照常生效，库不承诺撤销。输入快照防止回调改变原阵长度影响这次待排元素集合，但共享对象内容仍可被回调改变；这样的不一致比较不受排序结果契约保护。

比较器中的显式 `卒` 按正常调用规则向外传播，可由外层 `救` 恢复；这次排序不返回结果，排序本身没有改动原阵次序，但此前回调的副作用保留。错误的比较结果或参数则为不可救的普通运行错误。空/单元素输入可能根本不调用比较器，不据此推断一个回调在更多元素时一定合法。实现使用至多 `O(n log n)` 次比较和 `O(n)` 额外阵空间，回调自身的时间、内存及副作用另计。

`取整` 朝零截断，例如 `取整 2.9` 为 `2`、`取整 (-2.9)` 为 `-2`。输入已经没有小数部分时保持数值；负数截断到零时可以保留负零。`整除 左 右` 的定义就是 `取整 (左/右)`，不是向负无穷取整，也不引入整数类型；除零及除法的非有限结果仍报错。`小` / `大` 对相等值返回右实参；`绝对` 仅在值小于零时取负，所以负零不变。

所有数仍是 binary64，连续整数可精确表示到正负 `2^53`，更大的整数可能已舍入，运算及 `.15g` 显示还可能进一步失去十进制精度。没有 int64、大整数、位运算、整数格式化或数组填充构造。不能把这些辅助函数用于规避原有数值边界。

EOF 求和、前缀区间和、逐行数词、闭包比较器记录排序的完整原创题目、样例及源码见 `../docs/contest-library.md` 与 `../examples/contest_*.ru`。库随依赖图内联到输出 C 或 JavaScript，复制完整输出即含实现；目标编译器及资源限制仍需验证。C99/C11 `-O2` 的普通竞赛程序可测试无 `-lm` 复编，使用 `%` 的程序仍可能需要 `-lm`，不保证任意题目或 Windows 原生环境的兼容性。

### 11.12 文本、数学、随机与阵实用成员

先学三个小例子。模块需要导入，阵的成员直接使用。`如竞` 保留更名前的全部公开函数接口。

#### 11.12.1 整理名字和分数

```ru
文 取 外言 '如:文本'.
名单 取 文 其 拆分 '小明,小红,小青' ','.
显 名单[1].                         # 小红
显 文 其 去空白 '  你好  '.           # 你好
显 文 其 替换 '小明喜欢苹果' '苹果' '梨'.
显 文 其 定点 3.5 2.                 # 3.50（句）
```

| 算 | 必需参数 | 结果与边界 |
| --- | --- | --- |
| 拆分 | 文为句、隔为句 | 按字面分隔句，返回新句阵，保留空项；隔不可为空 |
| 替换 | 文为句、旧为句、新文为句 | 从左到右替换全部不重叠匹配；旧不可为空，新文可为空 |
| 去空白 | 文为句 | 仅去掉首尾ASCII空白，中间不动 |
| 定点 | 值为数、位数为数 | 固定小数位的句；位数须为0到15的整数 |

拆分 `'a,,b,'` 按 `','` 得到四项，其中两项是空句；拆分空文得到一个空句，不是空阵。需要按空白拆词或逐码点拆开，继续使用 `如竞` 的拆词／字列。

替换不扫描新插入的内容：把 `'a'` 中的 `'a'` 换成 `'aa'` 只得到 `'aa'`，不会无限重复。无正则表达式、Unicode规范化或忽略大小写行为。命名实参用 `新文:`，不能用语言保留字 `新`。

去空白只处理空格、Tab、LF、CR、VT、FF，与既有拆词和句转数一致。全角空格与不换行空格保留；它不删中间空白。

定点按实际 binary64 数值取最近值，恰好半单位时远离零：1.25保留一位为 `'1.3'`，-1.25为 `'-1.3'`。小数位不足补零，零位不带小数点，不用科学记数法。负零符号保留，例如 -0保留两位为 `'-0.00'`。

注意：如的数不是精确十进制。2.675在binary64中略小于这个十进制值，所以保留两位为 `'2.67'`。定点改变显示，不让金额计算变得精确；原有 `为 句` 仍用最多15位有效数字的简洁显示。

#### 11.12.2 操作阵：删、弹、查

```ru
玩具 取 ['球','车','船'].
显 玩具 其 查 '车'.                 # 1，从0开始
显 玩具 其 删 位:1.                 # 车，原阵变成 ['球','船']
显 玩具 其 弹.                      # 船，原阵变成 ['球']
显 玩具 其 查 '车'.                 # 空，未找到
```

| 成员 | 必需参数 | 返回与修改 |
| --- | --- | --- |
| 删 | 位为数 | 原地删除指定位置，返回原元素，其后项左移 |
| 弹 | 无 | 原地移出最后项，返回原元素 |
| 查 | 值，任意种类 | 第一个相等项的零起点位置；未找到返回空 |

删的位须为合法非负整数，不能负索引；空阵弹出、越界删除、错误参数均报普通运行错误，不能由救捕获。要安全弹出，先看量。移出空元素会正常返回空；它不表示删除失败。

阵的别名共享修改；移出的对象、阵和典仍是原来的引用，没有深复制。查不修改阵，比较使用原有 `==`／形的同协议，不把0当作假，也不把内容相同的两个独立阵当成相等。

查在开始时取得浅元素快照，从左到右比较，元素作为同的左方。相等方法若修改原阵，扫描仍用开始时快照，返回位置也是快照位置，未必还对应修改后的原阵。共享元素本身的修改仍可见；卒照常传播、既有副作用不回滚。查的时间通常为O(n)，快照另占O(n)引用空间。

典的 `查 目:` 按键返回值；阵的 `查 值:` 按元素返回位置。接收者不同，参数和结果含义不同。典使用 `目:`／`相:` 命名参数，不引入新保留字。

#### 11.12.2a 返回新阵：排序与另成

`阵 其 排序` 与 `阵 其 另成 算法:回调` 是普通成员调用，不需导入。两个成员在 Python、C、Node.js 与如书 browser-js 上遵循相同契约，名称不是保留字。

| 成员 | 参数 | 结果 |
| --- | --- | --- |
| 排序 | 可选 `先于:`，须为恰有两个参数的算 | 稳定排序后的新阵 |
| 另成 | 必需 `算法:`，须为恰有一个参数的算 | 从左到右将每项的返回值收集成新阵 |

两者先取得输入的浅元素快照，始终返回新阵，空阵与单项阵也不会返回原阵本身；操作本身不修改原阵。对象、内层阵、典与闭包保留引用，不深复制。回调修改原阵的长度或次序，不改变这次处理的快照元素集合；共享元素的修改仍可见。回调副作用不回滚，显式 `卒` 向外传播，可由外层 `救` 恢复；普通参数、类型与返回值错误不可救。

排序省略 `先于:` 时，整阵须属于以下一种情况：全为有限数，按数值升序；全为句，按 Unicode 码点字典序；或全为同一个形身份的对象，由其自有或继承的单参数 `算 先于 另一` 比较。父形与子形不是同一形身份，同名但不同声明的形也不是。事实、空、混合种类、非有限数及不支持默认排序的元素报错。默认对象排序不要求定义 `同`；不修改 `<`、`>`、`==` 等现有运算符的规则。

显式 `先于:` 优先于默认规则，可为其他元素提供顺序；每次调用传入左、右两个元素。无论显式算还是形的 `先于` 方法，都必须返回精确的事实 `真` 或 `假`，不能返回数0/1、三路数值、空或其他真值。真表示左项先于右项；双方都不先于对方即为同序，保持输入次序。比较算法应只判断先后，不修改参与排序的数据，也不依赖比较次数或调用顺序；须形成一致的严格弱序。实现不检测或回滚比较中的副作用；回调自行造成的修改仍会生效。调用次数、先后与排序算法细节不作跨后端保证。空阵可能不比较，单项阵也可能不比较，但显式回调的算种类与参数个数仍先验证，默认规则仍验证所有现有元素。

另成只接受恰有一个参数的 `算`，不接受 `作`；即使输入为空，也验证回调种类及参数个数。它按快照次序对每项调用一次，只有元素参数，没有隐式位置参数。每个结果占新阵的一项，包括空和返回的阵，不筛选、不展开。返回原对象仍共享引用；想要新对象，须在算法中显式 `新`。

```ru
# 排序和另成均返回新阵；只复制引用，不深复制元素。
自然数 取 [3,1,2,1].
显 自然数 其 排序.                 # [1, 1, 2, 3]
显 自然数.                        # [3, 1, 2, 1]
显 自然数 其 排序 先于:(算 左, 右: 得 左 > 右. 法).
# [3, 2, 1, 1]；显式先于是二参算，返回事实，不是三路数值比较器。

形 记录:
    名 为 句.
    分 为 数.
    算 先于 另一:
        得 其 分 < 另一 其 分.
    法
象
甲 取 新 记录 名:'甲' 分:2.
乙 取 新 记录 名:'乙' 分:1.
丙 取 新 记录 名:'丙' 分:2.

    得 新 记录 名:(项 其 名) 分:(项 其 分).

显 甲 其 分.                     # 7；返回原元素仍共享同一对象。
```

`外言 '如:竞'` 的旧 `排序 列 比较` 接口不变，仍用返回负／零／正数的三路比较器。不要把它的比较器直接当作阵成员的 `先于:`。目录的 `列` 不变；典遍历改为 `逐目`，见下文。

#### 11.12.2b 带位置或目的遍历：逐位与逐目

`阵 其 逐位 回调:…` 先取浅元素快照，再按原位置从0开始依次调用二参算或作，两个位置实参为（位、值）。不受回调改变原阵长度、次序影响；位置属于初始快照。`典 其 逐目 回调:…` 沿用旧典列的浅条目快照，两个位置实参为（目、相），遍历顺序不保证。两者均忽略回调返回值，包括假与空；整体完成返回空。空容器也检查回调为二参算或作。回调中的 `完` 只结束当前作，下一项继续；不能用 `破` 跳出回调外的遍历。显式卒正常传播，既有副作用不回滚。共享元素仍是原引用。

典的旧 `其 列` 已移除并给出迁移错误，没有兼容别名；改写为 `其 逐目`，命名参数仍为 `回调:`。目录的 `其 列` 不变；自定义对象的同名方法仍按其声明。

```ru
水果 取 ['梨','桃'].
水果 其 逐位 回调:(作 位, 值:
    显 位.
    显 值.
为).
# 输出0、梨、1、桃。追加/删改水果不改变本轮快照位置。
成绩 取 {'甲': 90, '乙': 80}.
成绩 其 逐目 回调:(作 目, 相:
    显 目.
    显 相.
为).
# 每个条目访问一次；甲、乙先后不保证。
```

#### 11.12.3 算数与取整

```ru
数学 取 外言 '如:数学'.
显 数学 其 平方根 81.               # 9
显 数学 其 幂 2 5.                  # 32
显 数学 其 取整 (-1.8).              # -1，向零
显 数学 其 向下取整 (-1.8).          # -2
显 数学 其 向上取整 (-1.8).          # -1
显 数学 其 四舍五入 (-1.5).          # -2，负半单位也远离0
```

数学导出十五个普通算与一个数值常量 `圆周率`（3.141592653589793，π 的最近 binary64 表示）。旧五项 `取整 值`、`小 左 右`、`大 左 右`、`绝对 值`、`整除 左 右` 与如竞库同名接口行为相同，这些函数也继续由 `如竞` 导出。这里是新的普通函数入口，不承诺两处函数引用身份相等。同时尽取两个模块会因重名报错；应使用模块别名。

新增：

- 平方根 值：值须非负；负零合法且保留
- 幂 底数 指数：实数幂；负底数要求整数指数；零不能取负指数；0的0次幂按空乘积约定为1
- 向下取整 值：不大于值的最大整数
- 向上取整 值：不小于值的最小整数
- 四舍五入 值：最近整数，恰好半单位远离0
- 正弦 弧度、余弦 弧度：弧度制的正弦和余弦，直接调用宿主数学函数
- 角度转弧度 角度：角度乘以 `圆周率 / 180`（180 度为 π 弧度）
- 弧度转角度 弧度：弧度乘以 `180 / 圆周率`；结果溢出报错
- 方向角 纵 横：即 `atan2(纵, 横)`，返回从正横轴到向量 `(横, 纵)` 的方向，范围为 [-π, π] 弧度；数学坐标中逆时针为正，画布纵轴向下时视觉上顺时针为正

三角函数不隐式转换角度。例：`数学 其 正弦 (数学 其 角度转弧度 90)` 得 1；轨道坐标可写 `横心 + 半径 * (数学 其 余弦 弧度)` 与 `纵心 + 半径 * (数学 其 正弦 弧度)`。圆周率可用 `数学 其 圆周率` 读取，也支持尽取。普通算支持命名参数与算引用；正弦、余弦的参数名明确为 `弧度`，不能写 `角度:90`。

正弦和两种转换保留负零；余弦的正负零输入均得 1。方向角遵循宿主 signed-zero 规则：`方向角 (-0) 1` 为 -0；正负零纵分量配正零横分量分别得正负零，配负零横分量分别得正负 π。不要把方向角的 `(0, 0)` 结果当作几何上唯一的方向。转换先形成有限比例再相乘，避免大角度中间乘 π 溢出。

所有参数均为数，事实不算数。数学函数返回数，定点返回句。取整类操作保留舍入为零时的原负号；数仍为有限binary64，没有整数新类型、复数或大整数。域错误、除零及非有限结果均为普通运行错误，极小结果可以下溢为零。

三后端保持相同接口、域与范围规则；定点、取整和随机序列按明确算法验收。幂、正弦、余弦、方向角等宿主数学函数的末尾舍入位可能因平台数学库不同而不同，不能用它们承诺跨平台逐位相等，或把有限精度结果当作符号代数答案。

#### 11.12.4 用固定种子重现骰子与洗牌

```ru
随 取 外言 '如:随机'.
源 取 随 其 造源 种子:42.
显 源 其 整数 下:1 上:6.            # 两端都包含
纸牌 取 ['甲','乙','丙','丁'].
打乱后 取 源 其 洗牌 纸牌.
显 纸牌.                            # 原阵不改
显 打乱后.
```

造源是普通算，必需参数种子为0到4294967295的整数。每次调用创建独立状态；同种子、同调用顺序在三个后端得到相同序列。别名共享同一个源并共同推进。独立状态不表示不同种子在统计上独立。

随机源只提供两个成员：

- 整数 下 上：闭区间整数。两个端点都须为安全整数，范围为正负9007199254740991以内；候选数目 `上-下+1` 不超过4294967296。单点直接返回，不消耗随机状态；结果为零时为正零。
- 洗牌 列：返回新的浅复制阵。原阵不改，内层对象仍共享。空阵与单项阵也返回新阵，且不消耗状态；阵长不能超过4294967296。

所有参数先验证；无效参数报错且不抽取随机数。程序错误不是可救的卒。随机源没有公开状态字段、重设种子方法或公开形名；重新开始请造一个新源。普通造源可取算引用，随机源成员与其他内置成员一样不能直接取引用，需用闭包包装。

算法固定为PCG32 XSH-RR，序列选择54，采用两步种子初始化、64位模运算及32位输出；区间通过拒绝采样去掉取余映射偏差。洗牌从末项向前做Fisher–Yates交换，每轮抽取包含两端的0到当前位置。拒绝重抽可能消耗多个底层输出；插入不同的随机调用会改变随后序列。

种子42的完整32位范围首六项为：2707161783、2068313097、3122475824、2211639955、3215226955、3421331566。没有自动时钟种子，没有隐式全局源。此库是可复现的非加密伪随机，不可用于密码、验证码、令牌或安全抽签。参考算法与许可见[第三方说明](../docs/third-party-notices.md)。

## 12. CLI、检查与 REPL

```sh
python3 ru --version
python3 ru                    # 默认进入 REPL
python3 ru repl
python3 ru check source.ru                 # 默认 C 目标
python3 ru check --target python source.ru # 只解析、校验 Python 导入图
python3 ru run --allow-native native.ru    # 仅 Windows x64 本地 Python，审阅后显式启用
python3 ru check --target c --allow-native native.ru # 静态 C 原生签名检查，不执行
python3 ru build --allow-native native.ru -o native.exe # 须 Windows x64 C 工具链
python3 ru run source.ru -- 参数一 参数二
python3 ru build source.ru -o app --emit-c app.c
python3 ru build source.ru -o app-full --emit-c app-full.c --full-runtime
python3 ru build source.ru --target js -o app.js
node app.js 参数一 参数二
python3 -m rulang --help
```

`run` 执行解释器，原生能力默认关闭；仅 `run --allow-native 文件` 在 Windows x64 本地 Python 中显式启用如:密，选项必须位于文件名前，文件后的选项形状文字仍是程序外参。如书、REPL、生成后自动执行没有此能力入口。

`check` 默认目标为 C；C／Node.js 检查解析依赖并调用对应编译前端完成结构/调用检查，不运行用户顶层，也不需要 C 编译器或 Node。`check --target python 文件` 只解析、校验源码和静态导入图，不执行模块顶层、不加载 DLL、不调用原生函数；它不授予原生权限，也不验证 DLL 存在、真实 ABI 或所有运行时类型。C 默认拒绝原生依赖；显式 `check --target c --allow-native` 允许检查本规范列出的有限静态原生签名，不执行代码或加载 DLL。Python 源码检查不接受也不需要该开关。Node.js／browser-js 目标仍明确拒绝原生依赖，包含间接与不可达分支导入。`build` 默认 `--target c`：生成 C99 并调用编译器，不自动运行输出。C 编译器依次选 `--cc`、环境变量 `CC`，否则自动找 `clang`、`gcc`、`cc`；参数以 argv 调用，不经 shell。`build --allow-native` 才启用 C 原生后端；JavaScript 构建拒绝该开关，即使程序未导入原生模块。编译宿主不等于运行目标，含原生依赖的 C 要求真正的 Windows x64 目标编译器与系统库，不能在其他操作系统上作为原生程序执行。

C 默认输出为源文件去扩展名路径（Windows 添加 `.exe`）；`build --target js` 默认输出为同名 `.js`，也可用 `-o` 指定 `.cjs`。构建 JavaScript 不需要或调用 Node / C 编译器，不读取 `CC`，不接受 `--cc` 或 `--emit-c`。通过 `node app.js` 执行产物；`元初` 的外参为脚本路径之后的参数，退出码规则不变。

CLI `--target js` 产物是 CommonJS：放在 `package.json` 含 `"type":"module"` 的目录树中时，应使用 `.cjs` 扩展名（例如 `-o app.cjs`）；不支持把该产物当 `.mjs` / ES module 或浏览器脚本直接加载。文件路径 I/O 仍相对运行进程的当前工作目录，而不是输出脚本的目录。

`build --full-runtime` 同时适用于 `--target c` 和 `--target js`。它保留完整目标运行时及所有已导入随附标准库声明，用于和默认裁剪输出作诊断对比，不自动导入额外标准库，不改变检查、程序语义或执行方式。默认输出及完整输出均为独立产物；裁剪不保证所有程序都符合特定平台的源码长度、编译时间或内存限制。

C `build` 可显式重复使用 `--source-prefix-map OLD=NEW`，仅重写产物中的运行时源码标识，不改导入解析、模块身份、源码正文或编译期原始诊断。完整路径分量匹配，最长前缀优先，同长后者优先；相对旧前缀按构建工作目录解析，Windows 盘符／UNC 路径忽略大小写与斜杠方向。它不是语言语法，不是普通生成所必需，也不清除用户字符串、DLL 路径或外部编译器调试信息。完整规则见[命令行说明](../docs/command-line.md#产物源码路径映射0212)。

两种构建都在完整生成成功后才原子替换既有程序输出，输出不得覆盖源码/外言依赖。程序输出与 `--emit-c` 输出彼此也须不同；输出 C 内联运行时，普通程序可独立用 `cc -std=c99 -O2 app.c -lm -o app` 构建；含原生依赖时必须改用 Windows x64 目标工具链。`--emit-c` 文件可能在之后 C 编译失败前就已经写出。JavaScript 运行仍受 Node、操作系统、调用栈和时间 / 内存限制约束；Windows 与 macOS 的 Node 路径尚未在本次环境实测。

正常无入口退出为 0，入口返回其有效退出码，常规错误为 1，CLI 参数解析错误为 2，文件命令 Ctrl-C 取消为 130。

REPL 重定义同名形会产生新身份；旧方法参数保留已绑定的原身份，普通函数参数注解按调用时的声明模块解析（详见 8.3）。

REPL 跨提交保留变量、函数、形及模块缓存；多行输入在所需句点/结束词尚未齐全时继续等待。单独表达式会回显，文件模式中则丢弃其结果。提交中已经执行的副作用在错误后不回滚。`读` 和 REPL 消费同一 stdin；它会读取后续输入行。

`:help` 显示帮助；`:退`、`:quit`、`:q`、`:exit` 等价退出；`:reset` 清空状态并新建解释器；Ctrl-C 取消当前输入/执行。REPL 命令单独占一行，不加句点，允许前后空白；仅在没有待续源码时识别。多行字符串里的 `:退` 等仍是源码文本，不能当命令执行。管道输入不显示交互提示符。REPL 不自动调用 `元初`，也不自动联网生成代码。

配套 Emacs 模式的 `C-M-n` / `C-M-p`（Ctrl+Alt+n / p）成对跳过同层下一 / 上一完整代码块或括号；`C-M-u`（Ctrl+Alt+u）回到最内层包围结构开头，再按回到外层。结构配对包括算 / 法、作 / 为、形 / 象、若 / 然、循 / 环、试 / 终、典 / 成、段 / 落及语句花括号块，括号含半角与全角形式，忽略字符串和注释中的伪结构。没有同层目标或目标不完整时前后跳转提示且不移动；向外跳转仍可回到未闭合结构的开头。原有 `C-c C-n` / `C-c C-p` / `C-c C-u` 行为保留；详细边界与数字前缀见 `emacs/README.md`。编辑模式只提供容错辅助，不改变源码语义。 如书、Emacs 和 VS Code 对代码中的 `取` 提供保守的赋值规则提示，解释当前局部、已有非模块捕获绑定和新建局部的顺序，以及直接救正文的局部写入规则；提示不声称已判断具体名称在运行时绑定到哪里。

## 13. 如是我言：意图生成及规范传输契约

### 13.1 文档边界

“如是我言”不是普通 `.ru` 执行语句，而是**显式意图文档入口标记**。最后一个非空行必须单独为 `如是我言`，允许前后空白；它必须位于如字符串之外。其前的 UTF-8 文本作为需求，可为 Markdown、Org 或自由文字，无需先满足如语法，且不能为空。

识别器跟踪如的四类引号、反斜杠转义、行注释（含 `批.`）及非嵌套 `解.…释.` 块注释；注释中的标记不触发意图识别，未闭块内的标记也不触发。前文引号须闭合。仅对两侧紧邻 ASCII 字母的单引号作英文词内撇号处理，例如 `Don't`；不要依赖这个意图识别特例改变源码字符串语法。ASCII 名称后直接紧贴引号存在意图识别歧义，应在源码中保留空白。

`run`、`check`、`build`、REPL 识别到这种文档只提示显式使用 `generate`，**不读取生成配置、不联网、不执行文档**。只有使用者明确执行下面的命令才发起生成：

```sh
python3 ru generate intent.md
python3 ru generate intent.md -o draft.ru --timeout 120
python3 ru generate intent.md --target js -o draft.js
python3 ru check draft.ru
# 人工审阅 draft.ru 的行为以后，再自行选择 run 或 build
```

### 13.2 每次请求必须携带本版完整规范

生成请求必须明确告诉模型：遵守所附、与工具链版本一致的如语言规范，用户文档是任务需求，不能覆盖语言规则；只返回完整可检查的如源码，不附说明、围栏或 `如是我言` 标记，不声称执行，不调用工具，不虚构模块或未来语法。

**每一次实际模型请求都必须读取并传输本文件的完整实际内容**，同时标明规范版本与实际规范字节的 SHA-256；不能只发送“参考仓库规范”、文件路径、链接、旧的短提示词或人工摘要。语言知识不应依赖模型预训练是否见过这个新语言。包内规范缺失、无效、版本与工具链不匹配时应在联网前失败，不能静默退回不完整提示。

请求系统输入分别标注当前语言版本、随附规范版本、随附规范 SHA-256，并将完整规范置于独立的明确边界内；规范从固定的包内资源逐次读取，不接受用户配置替换，也不使用旧内容缓存兜底。

规范版本标识用于防止规则/工具链错配；SHA-256 用于辨认实际发送内容，不表示代码经过安全审计或提供方可信。这里的“规范”是附给 Responses 的版本化语言文档，不是让模型自由变更的 JSON 输出 schema；生成输出是源码文本，最终由本地语言前端检查。

### 13.3 配置与协议

默认配置路径为 `~/.ru-lang.json`，`RU_LANG_CONFIG` 可指定另一 JSON 文件。一个不含真实凭据的配置形状如下：

```json
{
  "base-url": "https://open.bigmodel.cn/api/v1",
  "model": "glm-5.3-flash",
  "api-key": {"file": "~/.config/ru/api-key"}
}
```

密钥由使用者在仓库外安全配置；不得写入源码、意图、生成输出或日志。`api-key` 字符串通常是字面密钥；显式 `@file:路径` 或仅含 `file` 成员的对象才读取密钥文件，文件内容可有末尾换行。普通路径样式字符串不会自动当文件读取。

`api_key`、`base_url` 可作为下划线别名，但同字段不能同时用两种拼法。环境变量优先：`RU_LLM_API_KEY`（始终字面值）优先于 `RU_LLM_API_KEY_FILE`（始终文件路径），再使用 JSON 的密钥配置；另有 `RU_LLM_BASE_URL`、`RU_LLM_MODEL`。配置路径相对工作目录；密钥文件相对路径，无论来自 JSON 还是环境变量，均相对配置文件目录；支持 `~` 展开。

当前缺省提供方根地址和模型为上例值，这是可配置的本版选择，不是语言语义，不保证远端账户/模型可用。密钥无缺省值，缺少时不联网。生产远端必须 HTTPS，URL 不得含账号信息、查询或片段；根地址不得已带 `/responses`，实现固定追加该路径。仅本地协议测试支持实现规定的假令牌和字面回环 IP 的 HTTP 组合，不允许用此例外传送真实密钥。

输出预算为可选配置：JSON `max-output-tokens` 或别名 `max_output_tokens` 仅接受正整数数值，不能同时写两种拼法；环境变量为 `RU_LLM_MAX_OUTPUT_TOKENS`，CLI `ru generate` 与如书启动均可用 `--max-output-tokens 正整数`。优先级为 CLI／如书启动参数 > 环境变量 > JSON > 省略。有效范围为 1 至 2147483647；环境变量与 CLI／启动参数仅接受最多 10 位 ASCII 十进制数字，不接受空格、正负号或科学计数法。无效预算在发送提供方请求前拒绝。0、负数、小数、布尔值，以及 JSON 字符串／`null` 不表示有效预算或省略；省略配置时应不写字段。默认请求中不带 `max_output_tokens`，由提供方／模型决定默认限制，其具体值可能未知，不能解释为无限。显式数值不保证提供方接受该预算。

一次调用发一个非流式 `POST /responses` 请求，`stream:false`、`store:false`，不启用模型工具，不自动切到 Chat Completions，不自动换提供方/模型，不跟随重定向，不自动重试。默认连接/读取超时为 1800 秒（半小时），可用 `--timeout 秒数` 覆盖；须为有限正数，没有固定 300 秒上限；超时/取消后提供方仍可能计费。等待秒数不控制 token 预算，增加超时不能解决已经返回的输出预算耗尽。提供方接收用户意图及完整规范，凭据仅用于请求认证。

### 13.4 响应、验证与保存

只接受已完成 Responses 响应中的 assistant 输出文本；忽略 reasoning 内容。拒绝未完成/取消/失败、拒绝消息、工具调用、非文本项目、无效 JSON 或空输出；兼容只返回已完成响应 `output_text` 的服务形式，但仍检查所有结构化项，不允许其中隐藏工具调用。

未完成响应必须区分 `incomplete_details.reason` 中的 `max_output_tokens` 与 `content_filter`，分别说明输出预算耗尽与内容过滤，不将它们统一归因为账号权限或额度。未知未完成原因保持未知。诊断可以保留响应已返回的助手可见部分文本，但不得把未完成响应保存为生成产物、写入如书源码／模型版本或执行；失败不自动重新请求。

模型按要求应输出纯源码；清理器兼容恰好一段完整 Markdown 源码围栏（空语言标记或 `ru`/`rulang`/`text`）或 Org `ru`/`rulang` 源码块。混合说明、多段、残缺围栏、仍为意图文档或空程序均拒绝。

输出先进行词法/语法、结构、显式调用和本地外言依赖检查，不执行源码或模块顶层；文件模式中生成代码的外言相对**输出源码路径**解析；`--stdout` 模式则相对意图文档所在目录解析。检查通过只证明这些有限检查通过，仍需人工阅读文件读写/删除及其他副作用。

`generate` 默认 `--target ru`，输出为意图文件旁的 `原名.generated.ru`；显式 `-o` 必须为 `.ru` 路径，默认要求新文件。`--target js` 仍要求模型生成符合本规范的如源码，经过相同检查后由本地 JavaScript 后端编译，输出默认为 `原名.generated.js`，显式 `-o` 必须为 `.js` 或 `.cjs` 路径，默认要求新文件。它不请求模型直接编写 JavaScript、不发起第二次模型请求，也不另存中间 `.ru` 文件；默认不调用 Node 或执行，只有显式 `--run` 才运行已保存的程序。要审阅并保留两种产物，先 `generate -o draft.ru`，再 `build draft.ru --target js -o draft.js`。

两种生成目标在文件模式下都相对最终输出文件所在目录解析静态外言；JavaScript 会将依赖内联。父目录必须已存在，默认不能覆盖既有文件；始终禁止覆盖输入意图、符号链接（包括悬空链接）、目录、特殊文件或已有外言依赖，也拒绝与意图/依赖同 inode 的输出。完整输出写到同目录临时文件、刷新同步后，默认以不覆盖现有目标的原子发布方式保存；未启用 `--force` 时，目标在检查后被他人创建也会拒绝覆盖。JavaScript 编译失败同样不保存输出，不自动创建目录。显式 `--force` 才允许替换已有普通输出文件；仍在完整验证、写入和同步临时文件后原子替换，生成或验证失败保留旧产物。可与 `-o`、`--run` 组合；失败生成不会自动运行旧文件。

响应最多 2 MiB，意图与生成源码最多 1 MiB，配置最多 64 KiB，密钥文件最多 16 KiB；包内规范最多 1 MiB，并以严格 UTF-8 校验。生成错误不回显密钥、认证头、提供方原始错误正文或无效生成源码；检测到当前密钥出现在意图、实际构造的系统提示/规范、返回源码、JavaScript 编译产物或输出路径时停止处理。这不是任意秘密探测器，不能据此把其他秘密放入文档。

`--stdout` 在所有检查和目标编译完成后将完整产物写入标准输出，不创建默认文件或临时输出文件；诊断写入标准错误。与 `-o` / `--output`、`--run`、`--force` 互斥，冲突在配置读取和联网前拒绝。依赖相对意图文档目录解析，与 shell 重定向的目标无关；shell 本身可能在命令启动前创建或截断重定向文件。

`--verbose` 仅在标准错误汇报真实的读取、请求、等待、检查等阶段及累计耗时，等待时定期更新；同时汇报请求是否显式携带输出预算、提供方实际返回的数值 usage（包括返回时的 `reasoning_tokens`）、`output` 项类型摘要及无可见助手文本的情况。缺少的用量不能编造为零，reasoning 项类型或用量计数不包含推理正文；非流式接口无法提供模型 token 进度或百分比。通讯错误安全区分 TLS 证书验证、其他 TLS 错误、HTTP 状态、超时、连接失败和响应中断，不泄露原始报文或凭据。

**默认生成只保存，不执行。** 只有显式 `--run` 才在检查并保存成功后运行本次文件：Ru 使用普通 `ru run` 的解释器、入口及退出码语义；JavaScript 使用 Node，缺少 Node 时在请求前拒绝。标准输入/输出/错误继承正常交互行为，生成提示写入标准错误；运行失败保留已保存文件，不自动重试生成。`--run` 执行具有当前用户权限，检查不是安全审计或沙箱，需由用户明确选择承担跳过人工审阅的风险。如书生成仍须另行手动运行，不因本开关改变。

如书的生成请求默认也等待 1800 秒，启动时可用 `--generation-timeout 秒数` 配置有限正数。提供方连接/读取和服务端等待使用同一值，页面不另设短截止时间；取消等待不会保证取消远端请求，服务端在真实请求结束前保留并发保护。可展开低调的诊断区域查看可观察阶段、耗时及安全错误类别。

如书可显示一次生成的阶段诊断、提供方实际返回的助手可见文本（含未完成响应中的部分文本）及完整结果提取后的源码，还可显示与 CLI 相同的预算、数值用量和输出项摘要；无可见助手文本须明确说明。不展示隐藏推理，不伪造 token 流或完成百分比。诊断按生成标识隔离、内存有界且有时限，不自动存入书本；清除日志不保证取消远端请求或费用。请求正文、配置和认证头不进入日志，文本展示前须脱敏。生成与诊断都不得触发源码执行或自动付费重试。

如书生成默认按 Python 做语法／结构检查，不读取外言依赖。显式 browser-js 目标复用浏览器编译器的内置模块白名单、能力与编译检查；只编译并丢弃 JavaScript 产物，不执行生成源码，不读取生成代码指定的本地或网络外言。失败只返回安全检查类别与属于生成源码的行列；不会把随附模块行列误标到代码格。检查失败的源码仍可审阅修改，运行始终另行手动触发；检查通过不保证运行正确、安全或性能。生成等待期间源码、意图或执行目标改变时，旧结果不得覆盖当前代码格。

离线 `rushu-prompt` 与 `ruguan-prompt` 均接受 `--target python|browser-js`，默认 Python。两者复用系统提示构建器、当前完整规范及 SHA-256；如观导出仅追加图形任务指导，不维护独立规范副本。导出不读取生成配置、不联网、不运行源码。

本地模拟协议测试不等同于真实提供方账户、端点、计费或模型兼容性验证。

## 14. 完整可运行示例

下面各段除明确的双文件模块示例外，均可单独保存为 `.ru`，先执行 `python3 ru check 文件.ru`，再按注释选择运行。短例优先演示可预测输出；不会自动调用外部模型。

### 14.1 函数、数组与显式转换

```ru
算 总和 列 为 数 阵:
    和 取 0.
    位 取 0.
    循 列 其 量 次
        和 取 和+列[位].
        位 取 位+1.
    环
    得 和.
法
数据 取 [3,1,2].
显 '总和：'+((总和 数据) 为 句).
```

输出 `总和：6`。数组长度返回数；计次循环不隐式创建索引，故显式维护 `位`。

### 14.2 检查标准输入并处理 EOF

```ru
循
    一行 取 读取 其 读.
    若 一行 其 结果 != '成功' 则
        卒 一行 其 错误信息.
    然
    若 一行 其 值 == 空 则 破. 然
    输出 取 显出 其 写 内容:(一行 其 值)+'\n'.
    若 输出 其 结果 != '成功' 则
        卒 输出 其 错误信息.
    然
环
```

此程序回显每一行，空行也会回显，真正 EOF 才退出；最后无换行的输入仍会得到一个输出换行。I/O 失败显式卒，若调用上下文无试则以错误退出。

### 14.3 只读目录清单

```ru
目录 取 新 录 路径:'.'.
清单 取 目录 其 列.
若 清单 其 结果 == '成功' 则
    文件们 取 清单 其 值.
    序 取 0.
    循 文件们 其 量 次
        显 文件们[序] 其 路径.
        序 取 序+1.
    环
另
    显 清单 其 错误信息.
然
```

此程序只读取当前工作目录中的普通文件清单，不写文件、不递归。结果取决于运行目录。

### 14.4 救的局部绑定与共享修改

```ru
原因 取 '外部原因'.
状态 取 '原状态'.
共享 取 [1].
试
    卒 '需要处理'.
救 原因
    状态 取 '仅救内可见'.
    共享[0] 取 2.
    显 原因.
终
显 原因.
显 状态.
显 共享[0].
```

依次输出 `需要处理`、`外部原因`、`原状态`、`2`。

### 14.5 两个文件组成的模块程序

同一目录的 `math.ru`：

```ru
算 平方 根 为 数:
    得 根*根.
法
```

同目录的 `main.ru`：

```ru
数学 取 外言 'math.ru'.
算 元初 外参 为 句 阵:
    显 数学 其 平方 9.
    得 0.
法
```

`python3 ru run main.ru` 输出 `81`，退出码 0。也可构建 `main.ru` 后运行独立程序，依赖模块已静态打包。

## 如观二维图形（0.13.0）

如观的精确标准导入名为 `如:观`。`观 取 外言 '如:观'.` 后，`观 其 画布 宽 高` 返回不可伪造原生字段的画布对象，如书默认 Python 会话与显式 browser-js 代码格提供宿主；CLI 执行画布和 C／Node.js JavaScript 编译（含 check）仍明确报能力错误，不静默省略。模块仍是普通外言，闭包和捕获规则不变。完整公开签名和示例见 [如观指南](../docs/ruguan-guide.md)。

画布采用左上角原点，矩形／椭圆／弧／扇形以外接框表示，文字横纵是当前文字对齐方式的锚点，默认左／上；颜色只接受 `#RRGGBB` 或 `#RRGGBBAA`，填色及描边可用 `空` 取消；文字对齐、透明度规则与 `颜色` 函数见下节。绘制操作和设置操作返回空（缓存返回图像），宽／高／帧以及经过秒／间隔秒返回数。每帧回调接受从 1 开始的帧序号；鼠标按下／松开接受横、纵、按钮三参，移动接受横、纵二参；按键／松键接受键名句一参。算／作均可作为回调，结果忽略。相同事件重注册替换旧回调。每帧注册开始动画，停仅暂停帧，继续恢复帧，关闭释放全部回调。

每次回调形成完整命令帧；输入回调没有绘图时保留旧画面，只有样式或数据变化也保留。Python 回调执行在原有持久解释器，真实更新捕获的数据。显式 browser-js 的回调在本格独立 Worker 中更新捕获的数据；每次运行均从零开始，不共享 Python 或其他 JS 格的变量。每会话最多一个活动画布；新建画布、执行新格、停止、重启、关闭会话都失效旧交互。旧输出可保留静态。保存及打开书本不保存／恢复回调或变量。

宿主只接收有当前 session、generation、execution_count、cell_id、canvas_id 身份的事件；每次至多一个回调，Python 帧率 1～30，过快事件限流。宽高各 1～2048，命令每帧最多 2048 条、约 256 KiB，文字最多 4096 字符。Python 回调预算为 1 秒／500000 Python 跟踪行／64 MiB 新增分配；支持 RLIMIT_AS 的系统另设回调期间 512 MiB 地址空间上限，其他平台仍有分配检查与看门狗。10 秒硬看门狗可终止阻塞进程并重启会话，明确丢失全部会话变量；普通预算错误只关闭交互。若恢复 RLIMIT_AS 失败，宿主报告友好错误并关闭交互，要求重启会话；这不是对未知操作系统原因已修复的保证。Python 沿用既有时间、跟踪行、内存和硬看门狗阈值，保留软／硬时间 1:10 比例；Python 帧率、命令数与输出容量不变。不得在回调中请求交互输入。保护不构成不可信代码安全沙箱。

### 预算诊断（0.19.7／如书 0.8.7）

本批只细化预算错误消息，不改变限额、采样频率或资源保护。Python 仍逐行跟踪，每 128 个宿主 Python 跟踪行及回调正常返回后检查；执行行不是如源码行。检查依次为执行行、时间、新增内存，分别严格大于阈值才报错，等于阈值不报错。执行行超限先短路，不再读取时间或内存；时间超限不再读取内存。这个优先级只是既有检查顺序，不表示先报告的项目是根因，也不证明其他项目未超限。

Python 时间是执行预算独立采样的单调墙钟耗时，不是线程／进程 CPU 时间，也不是 `经过秒`／`间隔秒` 的冻结值。起点采样一次并沿用原有截止时刻比较：检查时同一次单调采样值严格大于起点加 1 秒才超限；消息中的实际秒数取该采样值减起点，不在构造消息时再次读钟，也不额外格式化舍入。浮点相减本身可能将极小超限显示成恰好 1 秒；时间显示统一标为“实际约”，仅在这种边界补充“微小超限差额经浮点运算舍入”，不显示底层绝对单调时刻；实际触发条件仍是采样值严格大于截止时刻，不改变原有比较。

Python 新增内存仍按 `tracemalloc` 当前跟踪字节数减去创建画布时记录的基线检查，阈值为 67108864 字节（64 MiB）；不是进程总内存、历史峰值或每次回调重新归零的分配总量。实际差额在检查时采样一次，并将同一值用于判定及消息。

错误示例中的实际值仅用于说明格式；运行时报告触发检查时的数值，不将示例数值写死：

- 如观回调超过执行行预算（实际 500001 Python 跟踪行，阈值 500000 行）；已关闭交互，请简化回调后重跑
- 如观回调超过时间预算（实际约 1.0000000000000002 秒墙钟耗时，阈值 1 秒）；已关闭交互，请简化回调后重跑
- 如观新增内存超过分配预算（实际 67108865 字节，阈值 67108864 字节／64 MiB）；已关闭交互，请减少数据后重跑

由于每 128 行检查并在回调返回时补查，实际行数可以大于 500001；这些消息不是逐行触发或绝对实时中断承诺。错误仍按既有来源定位，关闭交互，恢复调用方原有 trace 与系统资源限制；原有回调异常仍优先于资源恢复异常。新增消息只提供项目、数值、单位与操作建议，不附带源码正文或私密配置。

browser-js 仍以独立的语句／循环计数检查每次执行最多 500000 步，严格超过时报告实际 500001 步及阈值 500000 步。外层看门狗只报告“达到配置的等待上限”及本次配置值，默认初始化 5000 毫秒（5 秒）、回调 1000 毫秒（1 秒），并说明已终止独立 Worker；不能伪称观测到了 Worker 实际执行耗时。Python 跟踪行、64 MiB 新增分配及平台地址空间限制不适用于 JS，浏览器没有可强制的 64 MiB Worker 堆内存配额。

[0.19.6 验证记录](../docs/ruguan-0.19.6-validation.md)已观察到旧太阳系／气温例子的偶发墙钟预算超限，根因尚未定位。0.19.7 不提高预算、不禁用 GC、不改用 CPU 钟、不增加自动重试，也不承诺消除那些异常；诊断值不能单独证明 GC、宿主负载或某个图形成员是根因。

### 贝塞尔（0.19.6／如书 0.8.6）

`图 其 贝塞尔 起横 起纵 控一横 控一纵 控二横 控二纵 终横 终纵` 是普通画布成员，返回空，不是新增保留字。八个参数均必需；一次调用全部使用位置实参，或全部使用命名实参。命名参数精确为 `起横:`、`起纵:`、`控一横:`、`控一纵:`、`控二横:`、`控二纵:`、`终横:`、`终纵:`，不能省略、混用或以其他名称代替。

这是单段三次贝塞尔曲线：曲线经过起点与终点，两个控制点影响切向与弯曲，不是必须经过的点；不是二次贝塞尔，也不是通用路径构造器。八个局部坐标均须为绝对值不超过 100000 的有限数，拒绝事实、空、句与其他类型，不转换或钳位。点重合、共线、起终点相同与全部重合均合法，沿用原生 Canvas 退化路径行为；不自行补画圆点，不改成其他图元，也不因此删除命令。

每段使用一次 `moveTo` 到起点和一次 `bezierCurveTo`，有描边时只调用一次 `stroke`；不调用 `closePath` 或 `fill`，起终点相同仍保留开放路径语义。只使用当前描边和线宽，忽略填色且不修改当前填色；不能用许多短线近似，以免半透明描边重复叠色或改变曲线精度。需要封闭填充区域时使用既有 `多边形`。

### 折线（0.19.5／如书 0.8.5）

### 弧与扇形（0.19.4／如书 0.8.4）

`图 其 弧 横 纵 宽 高 始角 转角` 与 `图 其 扇形 横 纵 宽 高 始角 转角` 是普通画布成员，返回空，不是新增保留字。六个参数均必需；一次调用全部使用位置实参，或全部使用命名实参。命名参数精确为 `横:`、`纵:`、`宽:`、`高:`、`始角:`、`转角:`，不得混用或省略。

外接框与 `椭圆` 相同：`横`／`纵` 是左上角，`宽`／`高` 是局部坐标中的宽高。六个参数均须为绝对值不超过 100000 的有限数，宽高还须非负；拒绝事实、空、句与其他类型。零宽或零高合法，按原生 Canvas 的退化椭圆路径处理，不改成另一个形状，也不因此拒绝调用。

`始角`／`转角` 均用弧度，零角在椭圆右侧；始角可为任意符合数值限额的正负角度。转角是带符号的扫过量，不是终止角：未镜像的局部屏幕坐标中，正转角顺时针，负转角逆时针。负倍率缩放会把视觉方向一并镜像，不改变转角的含义。非圆椭圆使用参数角：设中心为 `(cx, cy)`，半宽高为 `rx`、`ry`，参数角 `θ` 的端点为 `(cx + rx*cos(θ), cy + ry*sin(θ))`；它不是从中心看端点的几何极角。

- `转角 == 0` 不绘制像素，但仍保留并计数为一条绘制命令；在回调内单独提交它也形成新的完整命令帧，不保留旧画面。
- `abs(转角) >= 2π` 绘制一整圈椭圆，只绕一圈，不对转角取模归零；`2π`、`-2π` 和更多圈均不会变为空路径。整圈扇形与椭圆相同，没有中心径向辐条；整圈弧仅描边。
- `弧` 是开放弧线，只使用当前描边和线宽，忽略填色。`描边 空` 时不绘制弧，即使填色不为空也不会填充。
- 部分 `扇形` 从中心连到起点，沿椭圆弧到终点，再闭合到中心；按当前填色和描边绘制，描边包含两条半径边。填充采用 nonzero（非零环绕）规则；`填色 空`／`描边 空` 分别取消对应绘制，两者均空时没有像素。

```ru
观 取 外言 '如:观'.
数学 取 外言 '如:数学'.
图 取 观 其 画布 360 200.
图 其 背景 '#fff7e8'.
图 其 填色 '#eaa74c'.
图 其 描边 '#9b5d35'.
图 其 线宽 3.
图 其 扇形 30 40 120 120 (-数学 其 圆周率 / 2) (数学 其 圆周率 / 2).
图 其 描边 '#247b78'.
图 其 弧 横:205 纵:40 宽:120 高:120 始角:0 转角:(数学 其 圆周率 * 1.5).
```

两种形状在提交时快照样式、透明颜色、变换和裁剪，后续设置不会移动或改写已提交图形；背景、保存／恢复及每回调状态重置规则不变。每帧仍最多 2048 条／约 256 KiB，零转角和不可见样式也计入预算。保存及重新打开仅重放静态画面，不恢复回调；旧快照保持原有重放行为。Python 与 browser-js 使用相同契约，普通 CLI／C／Node.js 仍不提供画布。

原生弧无需用折线近似；本版不提供弦形、二次贝塞尔或路径构造器，不用细小线段或多边形近似原生弧。完整 [披萨分份示例书](../rushu/examples/pizza-portions.rushu.json) 与 [如源码](../rushu/examples/ruguan/pizza-portions.ru) 完全同源：点击增减按钮或按左右方向键选择八份中的几份，扇形表示份额，弧表示外圈进度；默认 Python 或显式「JS 加速」运行同一格，无持续动画。

### 真实时间（0.19.3／如书 0.8.3）

`图 其 经过秒` 与 `图 其 间隔秒` 是只读、零参、返回数的普通画布成员，不是新增保留字。不得赋值、传入参数或在成员名后加 `()`。数值单位都是秒，可以有小数；不是日期、时区或墙钟时间。

- 创建画布时两者均为 0；初始绘图期间不随读取而变化。宿主在每次有效回调开始时，用本机单调时钟采样一次。同一回调内反复读取均得到冻结的同一快照；回调结束后保留该快照，直到下一次有效回调开始。
- `经过秒` 是自本画布创建起的经过时间，包含显式 `停` 的暂停和标签页隐藏期间的间隔。它不会因为继续动画或重新注册回调而归零；新画布重新从 0 开始。输入回调也取得新的经过时间。
- `间隔秒` 在每帧回调中是本次与上次实际帧回调开始之间的原始真实间隔。首帧为 0；从 `停` 到 `继续` 后的第一帧也为 0。已经运行时重复 `继续`，或在运行中重新注册 `每帧`，均不重置上一帧基准。
- 输入回调的 `间隔秒` 为 0，而且不改写上一帧基准。无回调、无效或被拒绝的事件不推进时间快照；客户端传来的时间值不能覆盖宿主采样。`每帧` 仍只接收一个从 1 开始的帧序号，不增加时间参数。
- 标签页隐藏会暂停事件交付；恢复可见后的下一实际帧保留隐藏间隔，既不钳位也不补帧。它不等同于显式 `停`／`继续`。设备休眠是否计入单调时钟取决于宿主，不保证不同平台一致；不能用这些数值推断日期或跨设备绝对时刻。

动画位置可由 `经过秒 - 开始秒` 计算，速度积分可用 `间隔秒`。不要把“帧数／目标帧率”当真实时间；帧率只是请求上限。若物理积分不宜跨越很长一步，可在程序中显式把自己的积分步长限制为例如 0.05 秒，但这只影响应用自己的模拟，不能改写原始时间接口。若要暂停动画进度，程序须记录暂停时刻并在恢复时调整自己的开始秒；`经过秒` 本身继续计时。

反复读取冻结快照的忙循环不能等待时间变化，会占住回调并触发原有预算；请用下一次回调推进状态。时间接口不延长回调预算，不增加等待、定时器、墙钟或文字测量接口。保存书本只保存静态画面，不恢复时间基准或回调。默认 Python 与显式 browser-js 使用相同语义，精度与实际数值由各宿主决定。

完整 [星港航班示例](../rushu/examples/elapsed-time.rushu.json) 和 [如源码](../rushu/examples/ruguan/elapsed-time.ru) 使用同一份源码：用共享阵保存待发／航行／暂停／抵达状态，以相对经过时间决定航程，并单独限制装饰动画的积分步长。点击按钮或按空格切换，暂停时按 `r` 继续；暂停与完成时停止逐帧回调，输入仍然可用。

### 文字对齐（0.19.2／如书 0.8.2）

`图 其 文字对齐 横向 纵向` 设置后续文字的锚点方式，返回空。两个参数均必需，必须是精确的句值：横向只接受 `'左'`、`'中'`、`'右'`；纵向只接受 `'上'`、`'中'`、`'下'`、`'基线'`。不接受英文别名、前后空白、空或其他类型。一次调用全部使用位置实参，或全部使用命名实参；命名参数精确为 `横向:`、`纵向:`。它是普通画布成员，不是新增保留字。新画布默认横向 `'左'`、纵向 `'上'`；这是初始样式，不表示调用时可省略参数。

`文字 文 横 纵` 的参数和单行绘制方式不变，横、纵给出当前局部坐标中的文字锚点。横向对应 Canvas 原生 `textAlign` 的 `left`／`center`／`right`，纵向对应 `textBaseline` 的 `top`／`middle`／`bottom`／`alphabetic`；`'基线'` 是字母基线。纵向 `'中'` 使用字体 em 框的中线，不保证可见字形墨迹包围盒精确居中；不同字体、中英文字符与字形回退可有视觉差异。无需估算字符宽度或手动减去半个字符串宽度来居中。没有文字测量、自动换行、多行排版或字体选择接口，不得虚构 `文字宽度`、`测量文字` 等成员。

文字对齐与填色、描边、线宽、字号一样属于持久样式，跨回调保留，并由 `保存`／`恢复` 一并保存和恢复；每次回调的矩阵、裁剪与保存栈仍按下节规则重置。每条文字命令在提交时冻结当前对齐、填色、字号、变换及裁剪，后续改样式不会移动旧文字。对齐可与平移、旋转、缩放、裁剪和透明颜色组合；`背景` 不重置对齐。旧书本中缺少对齐字段的静态文字按左／上重放，不恢复交互。

```ru
观 取 外言 '如:观'.
图 取 观 其 画布 320 160.
图 其 背景 '#f4f6fb'.
图 其 填色 '#25344a'.
图 其 字号 24.
图 其 文字对齐 横向:'中' 纵向:'中'.
图 其 文字 '如观 / Ru' 160 80.
图 其 保存.
图 其 文字对齐 '右' '基线'.
图 其 文字 '右侧基线 / Ag' 300 140.
图 其 恢复.
```

完整双后端示例：[text-alignment.ru](../rushu/examples/ruguan/text-alignment.ru) 与同源的 [text-alignment.rushu.json](../rushu/examples/text-alignment.rushu.json)。

### 透明度与颜色（0.19.1／如书 0.8.1）

颜色接受六位 `#RRGGBB` 或八位 `#RRGGBBAA` 十六进制句，字母大小写均可。旧六位写法保持完全不透明；八位的最后两位 `AA` 是不透明度：`00` 全透明，`ff` 完全不透明，`80` 为 128/255。不得使用三／四位缩写、颜色名称、`rgb()`／`rgba()` 或句前后的空白。`填色 空`、`描边 空` 仍表示跳过对应绘制；合法的零不透明度色值仍是颜色，不能当作 `空`。

`观 其 颜色 红 绿 蓝 不透明度` 是 `如:观` 模块导出的普通算，返回小写八位色值 `#rrggbbaa`，可保存、作为实参传递或取函数引用。四个参数均必需，全部为 0～255 的有限整数；拒绝越界、非整数小数、事实（真／假）、空和其他类型，不钳位、不舍入。`不透明度` 为 0 时全透明，为 255 时完全不透明。沿用普通调用规则：一次调用全部使用位置实参，或全部使用命名实参；命名参数精确为 `红:`、`绿:`、`蓝:`、`不透明度:`，不是画布成员，也不是新增保留字。Python 解释器中仅调用 `颜色` 不需要画布宿主；创建画布仍需如书宿主，C／Node.js 编译目标仍拒绝如观模块，构色函数不会绕过该能力边界。

```ru
观 取 外言 '如:观'.
半透明红 取 观 其 颜色 255 64 64 128.
半透明蓝 取 观 其 颜色 红:64 绿:112 蓝:255 不透明度:128.
图 取 观 其 画布 240 160.
图 其 背景 '#00000000'.
图 其 描边 空.
图 其 填色 半透明红.
图 其 椭圆 35 30 100 100.
图 其 填色 半透明蓝.
图 其 椭圆 95 30 100 100.
```

`背景` 必须提供颜色，不能为 `空`。它先清除此前的绘制命令与整幅画布像素，再在透明底上绘制指定背景色；零不透明度背景得到透明画布，半透明背景不会与此前图形或上一帧叠加。背景忽略当前变换与裁剪，保留变换、裁剪、样式和保存栈。

每个提交的命令帧都在透明底上完整重绘，不保留上一帧像素；同一帧中图形按提交顺序叠色。不调用 `背景` 也不会产生上一帧残留。若需要轨迹，应在程序中保存历史点并每帧重新画出；本版不承诺 p5／Processing 的半透明背景拖尾。透明度小批（0.19.1）未引入渐变、混合模式或 HSB；当前文字对齐与真实时间见前节，文字测量仍未提供。

### 路径形状、变换与裁剪（0.19.0／如书 0.8.0）

Python 与 browser-js 使用同一公开接口。`三角形` 和 `多边形` 使用原生闭合路径，按当前填色、描边及线宽绘制；填充采用 Canvas nonzero（非零环绕）规则，不用重复线段或逐像素模拟。`多边形 点阵` 只接受如的阵，包含 3～256 个点；每个点也必须是阵且恰有两个有限数坐标。重复点、退化形状及自交路径允许，按相同填充规则处理；提交后修改点阵不会改写已经绘制的形状。本版不提供任意路径裁剪、渐变、外部图像加载或新的路径构造器。

矩阵为 Canvas 顺序 `[a,b,c,d,e,f]`，即 `x' = a*x + c*y + e`、`y' = b*x + d*y + f`。初始为 `[1,0,0,1,0,0]`。`平移`、`旋转`、`缩放`、`变换` 都将新矩阵右乘到当前矩阵；先平移再旋转，形状先在局部坐标旋转，再移到目标位置。旋转参数是弧度，正角在纵坐标向下的画布上呈顺时针；缩放的零倍率和负倍率合法。所有数字参数以及每次累积后的六个矩阵分量必须有限且绝对值不超过 100000；形状及裁剪的宽高还必须非负。非法参数或累积矩阵越界报错。

每个形状在提交时快照当前矩阵及裁剪集合，后续更改状态不会改写它。`裁剪` 在调用时快照矩形及当时的矩阵，之后的变换不会移动已有裁剪；连续裁剪取交集。零宽或零高裁剪为空区域。`取消裁剪` 清空当前集合；`重置变换` 仅重置当前矩阵，不影响已有裁剪。`背景` 清除整幅画布像素和此前绘制命令，再在透明底上绘制指定色；不受变换与裁剪限制，同时保留当前变换、裁剪、样式及保存栈。

`保存` 将变换、裁剪、填色、描边、线宽、字号和文字对齐一并压栈，`恢复` 恢复最近一项。最多 64 层保存、当前最多 32 个裁剪。空栈恢复或超限报错；初始绘图结束以及每次回调结束时，保存栈必须配平，否则报错并关闭交互。显式关闭画布或创建新画布可以丢弃旧画布保存栈，无需先调用恢复；关闭前已经绘制的图形仍可保留为静态画面。`段: … 落.` 和 `{ … }` 只是词法作用域，离开块不会自动恢复绘图状态，必须显式配对 `保存`／`恢复`。

每次回调开始，矩阵恢复为单位矩阵，裁剪集合与保存栈清空；填色、描边、线宽、字号和文字对齐仍按原有规则跨回调保留。鼠标回调的横纵始终是画布坐标，不逆变换为局部坐标。初始绘图与回调每帧仍最多 2048 条绘制命令、约 256 KiB，点阵、矩阵及裁剪快照都计入数据限额；新增状态接口不提高既有预算。旧版无矩阵或裁剪字段的静态画面按单位矩阵和无裁剪重放，不恢复交互。

### 如书 browser-js 显式执行目标（0.18.1）

如书代码格默认 Python；只有显式勾选「JS 加速」才使用 browser-js。它把如 AST 编译为 JavaScript，在每次独立新建的浏览器 Worker 内执行，主页面绘制如观完整命令帧。不是如自己实现机器码 JIT；优化和机器码生成由浏览器引擎决定。CLI `--target js` 仍是 Node.js 目标，不能因此获得如观支持。

browser-js 的帧率请求允许 1～60 整数，调度使用 requestAnimationFrame，单飞派发回调；实际速度须实测，不保证 60 FPS。独立 Worker 不读取、继承或更新 Python 会话及其他 JS 格的状态；所有导入、初始化和回调应在同一格。停止、重跑、切换书本或重启使旧交互失效，保存／打开只有静态快照。browser-js 不提供交互输入、文件、网络或命令行能力，不支持时明确报错，不隐式切回 Python。

JS 宿主限制执行时间、消息／命令和输出量；浏览器没有可强制的 64 MiB Worker 堆内存配额，Python 跟踪行／新增内存预算不适用于 JS。快速大分配可能影响标签页或浏览器进程。这些防护不是不可信代码安全沙箱。详见 [浏览器 JS 执行](../docs/browser-js.md)。

### 生成所需的完整接口与示例


模块导入名是精确的 `'如:观'`；旧 `'如观'` 给出迁移错误，不保留别名，也没有 `'如:如观'` 别名。这里用 `观 取 外言 '如:观'.` 绑定模块，便于在同一会话反复运行；不要用重复 `尽取` 导入来重建画布，以免触发已有名称冲突规则。

| 调用 | 用途 |
| --- | --- |
| `观 其 画布 宽 高` | 创建本次活动画布 |
| `观 其 颜色 红 绿 蓝 不透明度` | 四个 0～255 有限整数生成小写 `#rrggbbaa` |
| `图 其 背景 色` | 清除此前命令／像素，再在透明底绘背景色 |
| `图 其 填色 色` / `图 其 描边 色` | 设置后续图形样式，空取消 |

## 如:密与随附三方库如见（0.20.0 引入，0.21.0 增加 C 目标）

### 模块身份、权限与执行目标

`密 取 外言 '如:密'.` 是标准原生库入口；`见 取 外言 '如见'.` 是独立目录中的随附三方 Win32 库入口。如见现阶段不属于如语言标准。机器类型与通用调用放在如:密的原生适配边界，Win32 API 名称、常量、结构和消息循环放在如见。当前平台驱动只有 Windows x64／Win32；如见的长期跨平台 GUI 方向不是已经实现的 Linux、macOS 或 Android 支持。没有 `ffi.ru` 入口，没有新增保留字，也没有把全局 `数` 改为机器整数。

原生能力是**后端／宿主权限边界**，不是靠导入语法获得的权限。执行平台仅为 Windows x64：本地 Python 默认拒绝，使用者审阅后显式运行 `ru run --allow-native 文件.ru`，开关须在文件名前；0.21.0 的 C 后端默认也拒绝，须显式使用 `ru build --allow-native 文件.ru`。如书 Python、如书 browser-js、REPL 和 Node.js 均不能启用。未启用原生的 C，以及 Node.js／browser-js 编译或检查整个静态依赖图时拒绝原生模块，间接、未调用函数及不可达分支中的导入也不能绕过。

`ru check --target python 文件.ru` 只解析、校验源码与静态导入，不执行模块顶层、不加载 DLL、不调用原生函数。检查不需要原生授权，也不验证真实 DLL、导出符号或 ABI。默认 `check` 仍为 C。`ru check --target c --allow-native 文件.ru` 检查有限静态原生签名，不执行源码、不加载 DLL，也不需要 C 编译器；`check --target python` 不接受也不需要该开关。生成器与离线提示导出携带本节知识，不授予原生能力，不得自动启用 `--allow-native` 或用 `generate --run` 执行原生程序。

原生 DLL 使用当前进程的真实权限，可能读写文件、访问网络或执行任意本机操作；显式启用**不是沙箱**。错误 ABI、结构布局、无效指针或资源生命周期会造成进程崩溃与内存破坏，不能承诺被如的 `试`／`救`、Python 异常或回调错误成果收束。调用者必须信任 DLL 并核对其实际接口合同。

### 类型描述符与精确标量

如:密导出 `i8`、`u8`、`i16`、`u16`、`i32`、`u32`、`i64`、`u64`、`intptr`、`uintptr`、`f32`、`f64`、`指针`、`无值` 不透明描述符。前八项为指定位宽的有／无符号整数；指针宽度整数与地址在当前目标上为 64 位。浮点描述符为 32／64 位机器浮点。`无值` 只用作无返回值签名。它们是库值，不是 `为` 后的新类型注解或可用 `新` 构造的语言形。

`描述符 其 值 输入` 接受受检查的如数、精确十进制句或已有原生标量；整数转换必须为整数且落在目标类型范围，不截断、不绕回、不钳位。事实不作为数。整数经如数传入时只接受 ±(2^53−1)，即 `-9007199254740991` 至 `9007199254740991` 内的安全整数；更大的精确机器整数须从十进制句或原生标量构造。普通 `数` 仍为有限 binary64，不能用先舍入的数值字面量恢复原位模式。指针描述符另接受空生成空指针；`f32`／`f64` 接受有限数或原生数值、按宽度舍入并拒绝非有限结果，不接受十进制句作为浮点输入。

```ru
密 取 外言 '如:密'.
无号长 取 密 其 u64.
最大值 取 无号长 其 值 '18446744073709551615'.
显 最大值 其 句.
显 最大值 其 位段 0 16.
```

原生标量公开成员为：

| 成员 | 合同 |
| --- | --- |
| `数` | 显式转为如数；整数超出 ±(2^53−1) 则报错，不近似返回句柄／地址 |
| `句` | 文本表示；机器整数和地址为精确十进制 |
| `为空` | 检查零值，返回事实；不要用不透明对象的真值判断空地址 |
| `位段 起 宽` | 整数／指针按无符号机器位提取，从最低位 0 开始，位宽为 1～53、范围须在原宽度内，结果为安全如数 |

`目标描述符 其 重释 原生标量` 仅对同位宽整数／指针执行 bitcast，不做数值转换；拒绝跨宽度截断与浮点重释。指针／句柄必须保留为不透明值，不经浮点往返。指针标量不提供任意地址解引用。

### 结构、缓冲与编码内存

`密 其 结构 字段阵` 的字段阵为 `[[字段名句, 类型描述符], …]`，返回 Windows x64 自然布局的结构描述符，支持嵌套结构，不暴露如对象布局。字段为 1～128 项，名字非空、不重复、不能以下划线开头，不可用无值作字段。描述符成员为只读 `大小`／`对齐`（字节）、`偏移 字段名`（零起点字节偏移）和零参 `新建`。结构不是如的 `形`；首版不支持结构按值传参或返回，须通过指针传递。

结构内存提供 `读 字段名`、`写 字段名 值`、`地址`、`大小`、`关闭`。字段读取得到类型标量或嵌套结构内存，写入按字段类型检查。嵌套读取返回锚定父内存的视图，父关闭后失效；嵌套写入须来自同一结构描述符。`密 其 缓冲 字节数` 分配 1～16777216 字节（16 MiB）的受管理字节缓冲；结构和编码内存也受 16 MiB 上限约束，编码的终止零计入大小。`密 其 UTF8 文本` 和 `密 其 UTF16 文本` 分配带终止零的编码内存，拒绝文本内已有 NUL，UTF-16 使用 UTF-16LE。

`内存 其 解UTF8`／`内存 其 解UTF16` 均无参数，只在本库拥有的内存边界内严格解码至第一个界内 NUL，不扫描任意外部地址；没有界内终止零、编码无效或 UTF-16 字节数为奇数时报错。指针和 DLL 返回值不是可解码内存。`地址` 返回带所有权关联的不透明地址，重释保留该关联，调用期间保持实参及关联资源；`关闭` 后不能再读取、写入或把旧地址用于调用。嵌套结构不构成越界或外部指针读取能力。

```ru
密 取 外言 '如:密'.
整型 取 密 其 i32.
点型 取 密 其 结构 [['横', 整型], ['纵', 整型]].
点 取 点型 其 新建.
点 其 写 '横' 12.
点 其 写 '纵' (-3).
横 取 点 其 读 '横'.
显 横 其 数.
点 其 关闭.
```

在原生 API 可能使用内存或地址期间必须保持资源存活。原生端若保存地址，需要先按其合同解除使用，再显式关闭；库不能替调用者识别原生端所有权转移。首版没有任意外部指针读取、裸指针算术、自动资源管理或如对象内存布局接口。

### 库、签名与调用成果

`密 其 系统库 基名` 仅从 Windows System32 加载系统 DLL，基名不能含目录。`密 其 动态库 绝对路径` 加载指定 DLL，拒绝相对路径，不隐式搜索当前目录。路径限制不证明 DLL 安全，也不限制 DLL 的系统权限。

`密 其 签名 返回描述符 参数描述符阵 调用约定` 创建至多 64 个参数的固定参数签名，调用约定仅接受句 `'win64'`／`'cdecl'`；首版平台均为 Windows x64，不表示支持 x86 或其他架构。`无值` 只能作返回描述符。`库 其 绑定 导出名 签名` 返回绑定函数；`函数 其 调用 实参数阵` 调用并返回成果。标量参数接受合适的原生标量或受检查的安全数；指针参数只接受空、原生指针标量、受管理内存或原生回调，不把普通数当地址；整数位置也不隐式接收指针，须先用 intptr／uintptr 显式重释。

成果的 `值` 为有类型的原生标量，无返回值则为空；`错误码` 为调用边界捕获的 Windows 错误码数；`回调错误` 为无错误时的空或错误说明句。错误码不是统一成功标志，必须按具体 API 的返回值及 last-error 合同判断；有些 API 成功时不清零，其他 API 使用返回码或另外的错误机制。返回零的原生标量不等同于如的空。

```ru
密 取 外言 '如:密'.
系统 取 密 其 系统库 'kernel32.dll'.
无号整 取 密 其 u32.
签 取 密 其 签名 返回:无号整 参数:[] 约定:'win64'.
进程号 取 系统 其 绑定 'GetCurrentProcessId' 签.
成果 取 进程号 其 调用 [].
结果 取 成果 其 值.
显 结果 其 数.
```

`库 其 关闭` 使库及其已有绑定函数不可继续使用，但不主动卸载 DLL，避免原生端仍持有地址时提前卸载。

首版不支持可变参数、COM、C++ 类 ABI、结构按值 ABI 或任意 Python／JavaScript 调用。签名只检查如侧边界，不能验证 DLL 真实声明或防止错误 ABI 破坏进程。

### C 原生后端的静态签名与独立产物（0.21.0）

C 后端只接受编译期可确定的有限 ABI 形状。返回类型与参数类型限上述机器标量／指针描述符，`无值` 仅作返回；结构按值、可变参数、COM 和 C++ 类 ABI 仍不支持。单个签名至多 64 个参数，约定必须静态归入 `'win64'`／`'cdecl'`，当前 Windows x64 下二者使用相同 ABI。

静态分析支持可追踪的描述符、模块与函数引用别名、`尽取`、命名实参、包装函数与闭包，以及能收敛的分支／循环描述符数据流或固定阵中的类型选择；这不等于执行如程序或完整类型推断。返回描述符、参数描述符阵或约定无法确定时明确报原生编译错误，包括不能追踪的输入／传参，以及无法证明安全的可变容器／可调用对象逃逸；不回退为运行时 ABI 猜测。签名参数阵在整个分析中须保持可证明不变，后续在回调、方法或其他路径中发现的修改也会保守拒绝，即使运行时曾先保存签名快照。未调用函数及不可达分支仍被检查。整个程序最多 1024 种 ABI 形状，单处有限参数类型组合最多 128 种；超限或静态分析过于复杂时报错。

原生分析在候选过多时，可将纯数值常量保守合并为未知数值；再次用作索引须包含全部可能元素，不能作为已确定的 ABI 类型或约定。事实与数值分别保留，非数值候选及可变数组／可调用对象的身份不能被该合并丢弃。大量嵌套可变行或字符串候选仍受原有有限值预算限制；这只影响静态抽象，不改变运行时数值、容器或求值语义。

分析器复用的函数／块环境可能包含早先动态作用域或另一条分支的局部记录。本版原生静态分析保守保留实际存在的同名外层绑定作为读取候选，不能据历史局部假定本次路径已建立它；候选含无法确定的类型或超过有限值预算时仍编译报错。参数、入口必然建立的声明与救的原因变量仍确定地遮蔽外层。

C 原生分析不能把早先调用建立的局部名称，直接当作后续调用必然存在的局部。若外层随后出现同名绑定，使复用分析作用域时的局部／捕获目标无法证明稳定，编译必须保守拒绝；可在第一次闭包调用前建立需要捕获的外层绑定，或以不同名称区分局部值。参数与函数入口必然建立的声明仍按原有规则遮蔽外层名称；该静态限制不改变运行时闭包语义，也不禁止正常的预先建立捕获。

原生分析允许可证明与 ABI 无关的纯标量直接自递归，例如阶乘，也可从按钮回调调用。该子集只读取参数／局部标量，使用标量运算及直接自调用，不读取捕获值、不访问成员／容器、不调用其他函数，返回值必须可证明为普通标量（数／事实／句）。其他无法证明与描述符无关的递归路径编译报错。未启用原生后端的普通 C 程序不受上述原生静态分析限制。

DLL 路径、系统库基名、导出名、调用实参和回调失败默认值仍可由运行时值提供，按原有加载规则和类型边界检查。签名能静态确定不证明实际 DLL 声明正确。C 为每个已知形状生成精确函数类型、调用与回调跳板，不依赖 Python、libffi、运行时机器码生成或动态链接的如运行时。

`--emit-c` 的单文件包含所需运行时与跳板，可独立复编；实际编译目标必须为 Windows x64，并有对应头文件及系统库。生成／检查 C 的宿主可以不同，但不开放 Linux、macOS、Android、Windows ARM64 或 32 位 Windows 的原生运行能力。构建得到的 `.exe` 运行不需要 Python、`ru`、原始源码或项目头文件，仍依赖 Windows、目标 C 运行库及被调用 DLL。

未导入原生依赖的普通 C 程序不加入原生运行时／跳板；保留普通运行时和标准库裁剪，普通 OJ 用例的 64 KiB 预算另行检查。含回调的原生 GUI 输出可以更大，不承诺所有生成 C 都小于该预算。

### 同步回调与失败钩子

`密 其 回调 签名 如算 安全默认值` 创建原生回调，必须使用参数数目与签名一致的算；默认值预先按返回类型检查，无值返回用空，指针返回的失败默认值只能为空指针。回调参数是对应的原生标量，返回值也须满足签名。回调只允许在创建它的所属执行线程同步执行，并在原生端可能调用期间固定保持；不提供异步、外部线程执行如代码或任意线程安全承诺。

`密 其 回调中` 是零参只读查询，表示所属线程是否仍处在本执行上下文的原生回调中。正在返回的已关闭回调仍计入；正常或错误退出都会撤销活动计数。上层库可据此拒绝不支持的重入操作。

`回调 其 地址` 返回不透明地址；`回调 其 关闭` 结束可用生命周期。必须先解除原生端注册或销毁会调用它的资源，再关闭回调。不能把作用域退出当作解除注册，也不能继续使用已关闭回调。已进入的同步回调可在逻辑关闭后完成标量／空返回，但不能在关闭中返回拥有型非空指针。关闭后保留不执行如代码的安全占位，避免已泄露可执行地址成为悬空地址。本进程累计创建回调上限为 1024，包括已关闭占位，达到上限需要重启进程。

如回调中的错误、主动卒或无效返回值被收束为安全默认值，把首个回调错误记录到相关原生调用成果的 `回调错误`，不穿过 C ABI 抛出。Python 与 C 遵守同一合同，如侧仍须在调用返回后检查；不自动重试，不回滚先前副作用，也不覆盖 DLL 内部崩溃、访问违规或内存损坏。

C 原生回调内不能首次初始化外言；所有可能在回调中需要的依赖须在第一次可能触发回调的原生调用之前导入并完成初始化。已成功初始化模块的重复导入允许。静态依赖收集不执行模块顶层，也不满足这项运行时要求；首次初始化被拒绝时以回调错误收束，不让模块停留在半初始化状态。此限制不改变普通程序按实际导入顺序初始化模块的语义。

可选的 `回调 其 失败时 原生绑定函数 实参数阵` 设置错误后的原生失败钩子，目标必须是已绑定原生函数，参数事先检查并浅复制实参数阵、保留资源引用，不允许在错误路径执行另一段任意如代码；这些资源也必须保持未关闭。如见的 Win32 驱动用 `PostQuitMessage` 使同步消息循环能返回，在清理后以 `卒` 报告回调错误；通用库不硬编码窗口事件循环，也不保证能解除任意阻塞调用。

学习示例与资源责任说明见 [如:密指南](../docs/native-library.md)。非 Windows 平台的解析／模拟测试不能代替真实 Windows x64 DLL、ABI、回调与窗口验证。


命名实参必须使用实际参数名，不与位置实参混用：密模块普通算为 `结构 字段`、`UTF8 句`、`UTF16 句`、`缓冲 字节数`、`系统库 路径`、`动态库 路径`、`签名 返回 参数 约定`、`回调 格式 算值 失败值`。描述符成员为 `值 值`、`重释 值`、`偏移 字段`；标量为 `位段 起 宽`；内存为 `读 字段`、`写 字段 值`；库为 `绑定 名称 签名`；函数为 `调用 参数`；回调为 `失败时 函数 参数`。其他已列成员无参。普通模块算可按既有语言规则取引用，内部桥接名不是应用 API。

回调返回受管理资源的非空地址时，每个回调最多保持 128 个不同资源到关闭；超限作为回调错误返回，关闭前须确认原生端已不再使用这些地址。
