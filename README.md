# 如（ru-language）· 0.6.0 元初实现

一个能实际运行的原型：中文关键词、保留状态的多行 REPL，以及将 `.ru` 源码编译为原生机器码的 C99 后端和独立 Node.js 程序的 JavaScript 后端。

未发布更新支持匿名函数 / 过程字面量：`平方 取 算 值 为 数: 得 值 * 值. 法.`、`报到 取 作: 显 '到了'. 为.`。沿用有名闭包的词法共享捕获；可赋值、传参、返回，零参函数值用 `报到()` 显式调用。解释器、C 与 JavaScript 后端使用同一语义，示例见 [`examples/anonymous.ru`](examples/anonymous.ru)。

0.6.0 新增真正的 AST → JavaScript 后端：`ru build --target js` 输出包含运行时和静态外言的独立 CommonJS 文件，通过 Node.js 18+ 运行。`ru generate --target js` 把意图先生成合规如源码，再本地编译为 JavaScript；仍逐次传输完整当前规范，不自动执行。语言语法及数值语义保持不变。

默认生成的 C 会按实际依赖裁剪运行时，并保守地移除未引用的随附标准库声明；JavaScript 同样裁剪随附标准库声明和未引用的可选运行时区段。输出仍可读、独立，不做压缩或针对题目的改写。可用 `ru build --full-runtime` 保留完整运行时与已导入标准库，供诊断对比，详见下方命令说明。

0.5.0 新增 `如:竞赛` 标准外言：整份输入游标、词 / 数 / 行读取、拆词 / 拆行 / 码点、合句、64 KiB 缓冲输出、稳定排序与数值辅助。普通如函数可配合闭包比较器使用；四道原创题目、完整解法和提交 C 的步骤见 [竞赛指南](docs/contest-library.md)。本次不新增语法、int64 或数组填充构造。

0.4.0 新增一等词法闭包：嵌套函数、显式算 / 作引用、捕获共享绑定、函数值传参 / 返回 / 保存和显式零参调用。解释器与独立 C99 后端同步支持，示例见 `examples/closures.ru`。

0.3.0 新增带检查结果的 `件` / `录` 和标准 I/O、`卒` / `试…救…终`，以及显式调用 Responses API 的意图生成。生成结果先检查并保存，默认不执行；凭据仅由使用者本地配置。

0.2.0 新增 `空`、二元组 `对`、可变引用数组 `阵`、Unicode 字符串索引 / 切片、对象 / 继承 / 方法、相对路径模块与 `元初` 程序入口。解释器和原生后端实现相同语义；新增算法示例见下文。

上一版 0.1.1 新增按声明顺序匹配的位置实参：`显 (平方 9.9).` 现在输出 `98.01`；原有 `平方 根: 9.9` 仍然可用。完整示例见 `examples/square.ru`，多实参示例见 `examples/positional.ru`。

完整的实现语义以 [如语言规范 0.6.0](rulang/language-spec.md) 为准。它是学习者、工具作者与 LLM 共用的唯一规范文本；README 提供入门和操作摘要。

待逐项解决或确认忽略的审查事项见 [语言审查追踪](docs/language-review-tracker.md)。清单区分实现缺陷、现有设计取舍与未定提案，不替代语言规范。

**本版不是自举编译器。** 编译器和 REPL 使用 Python；原生输出经过 C 编译器编译，执行时不需要 Python、`ru`、原始 `.ru` 文件或生成的 `.c` 文件。JavaScript 输出只需要 Node.js 内置标准库，不需要 Python、项目文件、原 `.ru` 文件或 npm 包。两种生成程序都没有如词法分析器、语法分析器或源码 / AST 解释器。

## 如书：本地网页笔记本（第一版）

在同一仓库的独立 `rushu/` 目录开发；不改变如语言语法。Python 3.10+ 即可运行，不需要安装 npm 包或联网下载编辑器：

```sh
python3 -m rushu
# Windows：py -3 -m rushu
```

打开终端显示的本机地址，即可混写 Markdown 与如代码、逐格执行、在格内输入、停止 / 重启会话以及保存 / 重新打开书本。详细说明与安全边界见 [如书使用说明](rushu/README.md)，[示例书本](rushu/examples/first-book.rushu.json) 可在界面中打开。

## 30 秒开始

Linux / WSL，克隆私有仓库（需要有访问权限）并进入项目目录：

```sh
git clone https://github.com/uppet/ru-language.git
cd ru-language
python3 ru --version
python3 ru repl
```

REPL 中输入：

```text
如> 数值 取 3.
如> 数值 + 4.
7
如> :退
```

解释执行示例：

```sh
python3 ru run examples/hello.ru
python3 ru run examples/add.ru
python3 ru run examples/square.ru   # 98.01
```

编译并运行独立程序：

```sh
python3 ru build examples/hello.ru -o bin/my-hello --emit-c dist/my-hello.c
./bin/my-hello

python3 ru build examples/add.ru -o bin/my-add
./bin/my-add
```

输出：`你好，世界`。加法示例会询问两个数并显示和。

编译为 JavaScript 并用 Node.js 运行：

```sh
python3 ru build examples/hello.ru --target js -o dist/hello.js
node dist/hello.js
```

构建 JavaScript 只需要 Python；执行产物才需要 Node.js。

`ru` 本身也是可执行脚本；可使用 `./ru repl`，或始终使用 `python3 ru`。

## 环境与已验证范围

- 编译器 / REPL：Python **3.10+**，只用标准库，无 pip 依赖
- 原生编译：Clang、GCC 或兼容的 C99 编译器；依次自动查找 `clang`、`gcc`、`cc`
- JavaScript 执行：Node.js **18+**，使用内置标准库，无 npm 依赖；不是浏览器 / DOM 目标
- 可通过 `--cc gcc` 或 `CC=gcc` 指定编译器；参数通过 argv 传递，不经过 shell
- 仓库初始化验证：Linux x86-64、Python 3.12.3、GCC 13.3.0；位置调用更新验证：Linux x86-64、Python 3.12.14、GCC 14.2.0。各次记录见 `VALIDATION.md`
- 仓库只保存源码；`bin/`、`dist/` 由 `make examples` 或 `ru build` 在本机生成。原生程序依赖构建时的目标架构和系统库，应在目标系统重新构建
- Windows：可在已有 WSL 中按上述命令使用。也提供 `ru.cmd`，可通过 `py -3 ru repl` 运行 Python 前端；Python 解释器对 Windows 控制台使用 Unicode 输出（含 `add.ru` 中文输入提示），重定向输出保持 UTF-8，无需修改系统代码页。Windows 原生 Clang/GCC 编译以及 `.exe` **未实测**，不承诺即开即用
- macOS、其他架构和 Python 3.10/3.11 未在本次环境实测

如需研究静态输出，工具链支持时可使用 `--cc "gcc -static"`；静态库、目标平台兼容性及第三方库再分发义务由该工具链决定。默认构建使用动态链接。

## 命令

```sh
python3 ru                         # 等同 repl
python3 ru repl                    # 交互模式
python3 ru run source.ru           # 解释执行
python3 ru check source.ru         # 检查语法、结构和显式函数调用
python3 ru build source.ru -o app  # 原生编译
python3 ru build source.ru -o app --emit-c app.c
python3 ru build source.ru -o app-full --emit-c app-full.c --full-runtime
python3 ru build source.ru -o app --cc clang
python3 ru build source.ru --target js -o app.js
python3 ru build source.ru --target js -o app-full.js --full-runtime
node app.js 参数一 参数二         # 传给元初；脚本路径不计入外参
python3 ru generate intent.md      # 明确请求在线生成；先配置提供方和凭据
python3 ru generate intent.md --target js -o draft.js
python3 -m rulang --help           # 模块入口也可用
```

`build` 不会自动运行程序。默认 `--target c`，输出为去掉扩展名的源文件路径（Windows 加 `.exe`）；`--target js` 默认为同名 `.js`。两种目标都在完整编译成功后才原子替换既有输出，不能覆盖源文件或静态外言依赖。JavaScript 构建不调用 Node / C 编译器、不使用 `CC`，也不接受 `--cc` / `--emit-c`。

JavaScript 产物采用 CommonJS。在 `package.json` 含 `"type":"module"` 的目录树中，使用 `-o app.cjs` 并执行 `node app.cjs`；不要把输出作为 `.mjs`、ES module 或浏览器脚本加载。文件 I/O 路径相对运行时工作目录；打包的静态外言不需要源文件。Node 的最大递归深度、垃圾回收及资源限制与 Python / C 不相同；栈溢出报告运行错误。Node 在 Windows / macOS 上尚未实测。

C 目标的 `--emit-c` 会额外保存一个可独立编译的 C 文件；该路径也不得覆盖源文件、依赖或程序输出。运行它不需要这个项目的头文件：

```sh
cc -std=c99 -O2 dist/my-hello.c -lm -o another-hello
```

默认 C 输出保留生成代码所需的运行时函数及其传递依赖，也按整个模块图中出现的成员名称保留动态分派分支。 若依赖闭包中没有对／阵构造器，会省去不可达的容器遍历；没有用户形或受检查 I/O 时省去用户字段／方法查找；全模块图没有「卒」或「试」时省去异常传播状态。随附的 `如:竞赛` 只在能安全证明时移除未引用声明；别名、函数引用、闭包和转导出都参与分析，模块值逃逸或无法确定时保守保留。用户源码和用户模块的函数、初始化副作用不会因此删除；裁剪前仍检查完整依赖图。

`build --full-runtime` 对 C / JavaScript 都有效：关闭随附标准库声明裁剪，C 保留完整动态运行时，JavaScript 保留完整 I/O / 竞赛运行时区段。它不会额外导入未使用的标准库，也不改变语言语义、错误检查或执行方式。两种输出都可用于排查差异，正常构建无需此选项。源码长度取决于程序所用功能；请按目标平台限制检查最终文件的字节数，而非假定所有程序都能通过同一源码长度上限。

常规错误退出码为 `1`，命令行参数错误为 `2`，取消文件执行为 `130`。错误通常包含文件名、行号；前端和解释器还提供列号。原生运行错误只提供行号。

## 用如写题，复制 C 提交

先从没有提示语、一直读到 EOF 的 [成对求和](examples/contest_sum_eof.ru) 开始：

```ru
尽 取 外言 '如:竞赛'.
入 取 读入.
出 取 蓄出.
循
    左 取 入 其 数.
    若 左 == 空 则 破. 然
    右 取 入 其 数.
    出 其 行 (左+右).
环
出 其 清.
```

输入保证是完整的整数对；`0` 不是 EOF。读流成员用裸写法 `入 其 数`，出流最后必须显式 `清`。准备、验证并生成单文件：

```sh
printf '1 2\n-5 8\n0 0\n' > /tmp/ru-contest-input.txt
python3 ru check examples/contest_sum_eof.ru
python3 ru run examples/contest_sum_eof.ru < /tmp/ru-contest-input.txt
python3 ru build examples/contest_sum_eof.ru -o bin/contest_sum_eof --emit-c dist/contest_sum_eof.c
cc -std=c11 -O2 dist/contest_sum_eof.c -o bin/contest_sum_eof_c11
./bin/contest_sum_eof_c11 < /tmp/ru-contest-input.txt
```

两个运行结果都应是三行 `3`、`3`、`0`。把 `dist/contest_sum_eof.c` **全部内容**复制到评测提交框，选择站点提供的 **C11 / GNU C11、O2**。标准库及运行时已经内联，提交时不需要 Python、`.ru` 或项目头文件。

生成 C 仍受目标编译器、源码长度与时间 / 内存限制约束，未声称在外部评测站通过。普通样例可用上述无 `-lm` 命令复编；**使用 `%` 浮点余数的程序仍可能需要 `-lm`**。`ru build` 自身在适用平台会链接它。Windows 原生构建未实测。

[竞赛指南](docs/contest-library.md) 包含四道原创练习：EOF 求和、前缀区间和、逐行数词、闭包比较器稳定排序，也解释如何把题目交给「如是我言」生成。输入一次读完并验证 UTF-8 / NUL，词只按 ASCII 空白分隔；空行与 EOF 不同。数仍为 binary64，显示至多 15 位有效数字，不承诺精确 64 位整数解题。

## 语言约定

这些是本次原型的明确约定，尚非冻结的正式语言规范。调用写法、数值细节和比较运算是为使原型完整可跑所补充的设计。

### 字符、语句和数值

- UTF-8 源码；关键词、名称一般用空白分开。`信@含`、`左+右` 可以紧贴运算符
- 0.2 新增保留字 `空`、`对`、`形`、`象`、`如`、`新`、`外言`、`尽`；旧代码中的同名变量 / 函数需要改名。`阵` 是类型名称，并非词法保留字；`为乐` 这样的完整名称不会因包含关键词 `为` 被拆开
- 简单语句以 `.` 或 `。` 结束；换行只作为空白，块结束关键词后的句点可省略
- 支持 `:` / `：`、`()` / `（）`、`,` / `，`
- 字符串支持 `'…'`、`"…"`、`‘…’`、`“…”`；支持 `\n`、`\r`、`\t`、`\\` 和被转义的引号
- 字符串允许换行，不允许 NUL；源码和标准输入需为有效 UTF-8
- `#` 和 `//` 开始行注释
- 值包括 `句`（不可变字符串）、`数`（IEEE-754 双精度浮点数）、`空`、不可变 `对`、可变引用 `阵`、对象与模块
- 不是大整数 / 十进制定点语言。超过约 15 位有效数字会有精度限制；输出最多 15 位有效数字。不要用于金额或精确整数大数计算
- `1`、`-2.5`、`.5`、`1e3` 可用；尾部句点是语句结束符，因此源码中 `1.` 表示数值 `1` 加终止符
- 拒绝 NaN、Infinity 和非有限运算结果；除以零报错

### 显示、绑定、赋值和转换

```text
显 ‘你好，世界’.

左 取 (读 提示: '输入第一数：') 为 数.
右 取 (读 提示: '输入第二数：') 为 数.
中 取 左 + 右.
显 中.

中 取 中 + 1.
显 中 为 句.
```

`显` 输出一行。`取` 新建或更新绑定，不固定绑定的类型；函数内可更新最近已有的非模块捕获绑定，详见下方闭包规则。`为 数` 和 `为 句` 是显式值转换；转换结合整个左侧表达式，必要时用括号明确范围。

`句` 转 `数` 接受前后 ASCII 空白、正负号、十进制与科学计数法。空串、乱码式数字、`0x10`、`nan` 等报错，不悄悄变成零。`数` 转 `句` 使用与 `显` 相同的格式。

`读` 返回标准输入的一行，去掉结尾换行。`读 提示: '…'` 先显示提示且不换行。真正到达 EOF 时会报错退出，避免没有新输入的循环不断输出；按回车得到的空行仍是合法空串。

### 函数、过程和调用

```text
算 平方 根 为 数：
    得 根 * 根.
法

显 (平方 9.9).
显 (平方 根: 9.9).

作 祭拜 :
    显 ‘叩’.
    显 ‘叩’.
    显 ‘叩’.
    循 9 次
        显 ‘拜’.
    环
为 .

祭拜.
```

- `算` 以 `法` 结束，使用 `得 表达式.` 返回结果；某条实际执行路径没有 `得` 会报错
- `作` 以 `为` 结束，不允许 `得`；在表达式中调用会得到空 `句`。正常单独调用不会额外显示返回值
- 不强制 `算` 纯函数，可以使用 `显`、`读` 等
- 参数写作 `名称 为 数`、`名称 为 句`、`名称 为 阵`、`名称 为 句 阵` 或 `名称 为 自定义形` 等；类型需要匹配，不自动转换
- **位置实参**：`函数名 表达式`。例如 `平方 9.9`；多个位置实参按参数声明顺序匹配，可用空白或逗号分隔，例如 `差 9 4`、`差 9, 4`
- **命名实参**：`函数名 参数名: 表达式`。例如 `平方 根: 9.9`；多个命名实参按名字匹配，可调整顺序，例如 `差 右: 4 左: 9`
- 同一次调用不能混用位置实参与命名实参；两种写法的实际值都按源码从左到右求值，参数个数和类型必须匹配
- 直接声明的零参数函数 / 过程保留裸名称调用，例如 `祭拜.`；`读` 也是如此。保存到变量或参数中的函数值不会因裸名称自动执行，无参数时用 `回调()`
- 每个实参都是尽量向右读取的完整表达式：`平方 2 + 1` 是对 `3` 求平方。要把调用结果参与运算，请写 `(平方 2) + 1`；命名实参规则相同
- 实参中再调用带实参的函数，必须加括号，例如 `差 (平方 3) (平方 根: 2)` 或 `差 左: (平方 3) 右: 2`。`差 甲 乙` 中的 `甲`、`乙` 各是一个实参，不会隐式变成 `差 (甲 乙)`；普通变量和零参函数不需括号
- `+`、`-` 不会在函数名后直接开启位置调用，仍按加减运算解析，以保留 `变量 - 2`、`零参函数 - 2`。第一个负数位置实参写 `平方 (-2)`；后续负数写 `差 2 (-3)` 或 `差 2, -3`。`差 1 -2` 只有一个实参 `1-2`，会提示缺少参数。命名写法 `平方 根: -2` 仍直接可用
- 实参列表属于函数名后面的序列；`差 9 4` 或 `(差 9, 4)` 可用，不采用 `差(9, 4)` 形式的括号实参列表
- 内置 `读` 也接受位置提示：`读 '输入：'` 等价于 `读 提示: '输入：'`，省略提示时仍可直接写 `读`
- 函数 / 过程可直接定义在模块、函数 / 方法或救的正文中，形内可定义方法；条件、循环、受保护的试正文不能直接声明。定义在所属作用域进入时预先登记，支持前向调用和递归；调用深度上限 128
- 源码表达式 / 块的嵌套也有限制（原型上限 128 层），过深时给出诊断，不显示 Python 回溯
- 函数按词法环境读取变量。函数内 `取` 更新当前局部或最近已有的捕获函数 / 救绑定，否则新建局部；**不会修改同名模块全局绑定**。参数始终局部，直接救正文的 `取` 仍只写救的子作用域。条件、循环不新增作用域
- 直接声明的函数名、过程名、内置 `读` 不能同时作为变量名或参数名

### 0.4 函数值与词法闭包

```ru
算 造计数 起点 为 数:
    数值 取 起点.
    算 增加 步 为 数:
        数值 取 数值+步.
        得 数值.
    法
    得 算 增加.
法
甲 取 造计数 0.
乙 取 造计数 10.
显 (甲 2). # 2
显 (甲 3). # 5
显 (乙 1). # 11
```

`算 增加` 取得函数本身，不调用它；过程引用使用 `作 名`。即使工厂已返回，闭包仍保留外层环境。一次工厂调用里产生的闭包共享捕获绑定，不同调用分别保存自己的状态。函数值可以放入阵、对、字段，也可传参和返回；参数 `回调 为 算` / `回调 为 作` 分别检查种类，真正调用时继续检查参数签名。

保存的零参函数值写 `回调()`；裸 `回调` 只读取该值。带参调用仍写 `回调 3` 或 `回调 参数名:3`，不新增 `回调(甲,乙)` 风格参数列表。索引得到的回调可写 `回调们[0] 3` 或 `回调们[0]()`，对象的函数值字段可写 `对象 其 回调 3`。

用户方法引用写 `算 对象 其 方法` 或 `作 对象 其 方法`，以后调用仍绑定同一对象；模块函数引用写 `算 模块 其 函数`。同一闭包的别名共享身份，分别取得的绑定方法引用是不同函数值。内置 `读`、集合成员和 I/O 方法暂不支持取引用。

直接救正文的变量绑定不向外泄露；救内定义的闭包能保留该救环境。方法内闭包也可保留自身及方法局部。捕获采用词法作用域，不使用调用者的局部变量；函数中的 `取` 不更新模块全局。完整约束和求值边界见唯一规范第 4.5、6.4 节。

[`examples/closures.ru`](examples/closures.ru) 同时演示共享计数状态、两个独立工厂实例，以及每次调用生成器执行一次 `新`，再用已有的 `循` 和 `其 增` 得到独立对象阵。未新增数组填充语法。

### 匿名函数与过程字面量

在表达式中省略函数名，参数仍直接写 `名称 为 类型`，冒号必需：

```ru
平方 取 算 值 为 数:
    得 值 * 值.
法.
问候 取 作 名 为 句:
    显 ('你好，' + 名).
为.
报到 取 作:
    显 '到了'.
为.
显 (平方 4).       # 16
问候 '小如'.      # 你好，小如
报到().           # 到了
```

`算 … 法` 和 `作 … 为` 本身产生函数值；结束词后的句点结束外层赋值、返回或表达式语句。作为阵元素或实参时，结束词后直接接外层逗号、括号或后续实参，不在字面量内部额外加句点。正文中的简单语句仍各有句点。

```ru
算 应用 回调 为 算 值 为 数:
    得 回调 值.
法
显 (应用 (算 值 为 数: 得 值 * 值. 法) 5). # 25
显 ((算 值 为 数: 得 值 + 1. 法) 4).      # 5
算 造计数 初值 为 数:
    当前 取 初值.
    得 算 步 为 数:
        当前 取 当前 + 步.
        得 当前.
    法.
法
计数 取 造计数 10.
显 (计数 2). # 12
显 (计数 3). # 15
```

- 零参写 `算: … 法` 或 `作: … 为`；无箭头语法，也不用圆括号包参数声明
- `算 名` / `作 名` 仍是有名引用，`算 名 为 句` 仍可转换引用的显示值；完整类型参数头后的冒号才区分匿名字面量；`算 (表达式)` / `作 (表达式)` 仍按原有引用目标规则解析，不是括号参数表
- 字面量按表达式执行，每次求值创建新函数值；保存到同一变量的别名保留身份。正文只在调用时执行，不会像有名声明一样提升
- 捕获共享词法绑定，外层返回后仍存活；同次工厂调用的闭包共享状态，不同工厂调用相互独立。更新捕获、模块全局保护、自身和救作用域与有名闭包一致
- 匿名正文可有嵌套声明、匿名字面量和控制流；字面量也可出现在条件、循环或试正文的表达式中。有名声明的位置限制保持不变
- 匿名 `算` 仍须实际执行 `得`，匿名 `作` 不能 `得`；参数数量、名字、类型和循环 `破` 的调用边界沿用原规则
- 保存后的调用沿用空白 / 命名实参；立即带参调用用 `(算 参数 为 类型: … 法) 实参` 分组函数值，零参用 `(算: … 法)()`

完整的赋值、传参、返回与共享状态示例见 [`examples/anonymous.ru`](examples/anonymous.ru)，规范见第 4.6、6.4 节。

### 条件、循环、成员语法

```text
信 取 '空'.
循
    显 信.
    信 取 (读) 为 句.
    若 信@含 '再见' 则
        破.
    另
        显 信.
    然
环
```

`信@含 '再见'` 和 `信 其 含 '再见'` 完全等价，都是**包含**测试，没有取反含义。

`若 条件 则 … 另 … 然` 的 `另` 可省略。`循 次数 次 … 环` 为计次循环；不写次数就是无限循环；`破.` 退出当前最内层循环。计次表达式只在进入循环时求值一次，必须是 0 到 2^53−1 之间的整数。无限循环由程序自己 `破`，终端中也可以 Ctrl-C 中断。

### 运算

运算顺序从高到低：括号 / 调用 / 索引 / 成员，一元 `+ - 非`，`* / %`，`+ -`，`< <= > >=`，`== !=`，`且`，`或`，`对`，`为 类型`。`对` 是右结合运算；组合复杂表达式时建议显式加括号。

- 数字支持普通算术；`%` 采用浮点余数，符号跟随被除数，例如 `-7 % 3` 是 `-1`
- 两个 `句` 可用 `+` 连接；不会自动把数字转成字符串
- 比较、包含、`非`、`且`、`或` 返回 `数`：真为 `1`，假为 `0`
- 条件中，`0`、空串、`空` 和空阵是假；非空阵、二元组、对象和模块为真
- `且` / `或` 短路求值；例如 `0 且 (1 / 0)` 不会除以零
- 大小比较需要相同类型；字符串按 Unicode 字符顺序比较，不是拼音排序
- 跨类型 `==` 为假，`!=` 为真；二元组按结构比较，数组 / 对象 / 函数值 / 模块按引用身份比较；不支持链式比较的数学简写，请写 `值 > 1 且 值 < 5`

## 0.2 数据结构、对象、模块与入口

以下是原型 0.2 的明确默认规则，不代表已经冻结的正式语言规范。

### 空与对：一条不可变链表

```text
链 取 1 对 2 对 3 对 空.
显 链 其 囫.                # 1，左项
显 (链 其 囵) 其 囫.        # 2，右项的左项
显 (1 对 空) == (1 对 空).  # 1，按结构比较
```

`空` 是独立值，显示为 `空`，与句 `'空'`、数 `0`、空句 `''` 都不相等。`对` 右结合，上面的链等价于 `1 对 (2 对 (3 对 空))`；`囫` / `囵` 只能读取，不能用 `取` 改写。二元组中的数组 / 对象仍保持引用身份，不会深复制。

完整遍历、求和、逆序示例：`examples/linked_pairs.ru`。

### 阵：共享引用、索引与浅切片

`[甲, 乙]` 及嵌套数组字面量是当前 0.5 原型支持的构造约定，构造语法尚未冻结；下列示例记录当前实现行为。

```text
数列 取 [3,1,2].
别名 取 数列.
别名[0] 取 9.
数列 其 增 4.
显 数列[0].                 # 9
显 数列 其 量.              # 4
显 数列 其 位 1.            # 1
显 数列[1:3].               # [1, 2]
显 数列 其 段 始:1 终:3.    # [1, 2]
```

- `[]` 新建空阵，`[甲, 乙]` 按源码顺序求值，可混装不同类型
- `值 为 阵` 总是创建**包含这个值的单元素阵**：`空 为 阵` 是 `[空]`，已有阵或对象也只是包装一层，不会展开或复制
- 阵赋值、实参、返回值均共享引用；`其 增 值` 追加一项，并返回同一个阵
- `其 量` 返回长度；`其 位 索引` 与 `[索引]` 等价，均可作为 `取` 左侧。`位` / `增` 的命名实参分别写 `位:索引` / `值:值`
- 标准成员的位置操作数结合得紧：追加和写作 `列 其 增 (1+2)`，复合索引写作 `列 其 位 (位+1)`，复合范围写作 `列 其 段 (始+1) (终-1)`。命名形式如 `列 其 增 值:1+2` 接受完整表达式。普通函数 / 自定义方法仍遵循前述贪婪实参规则
- 名称后紧贴 `[` 表示索引，如 `列[0]`；空白分隔的阵字面量可作位置实参，如 `求和 [1,2]`。复杂场合可写 `求和 ([1,2])` 明确边界
- 索引从 `0` 开始，必须是整数，满足 `0 <= 索引 < 长度`；负数、小数、越界均报错
- `[始:终]` 和 `其 段 始 终` / `其 段 始:始 终:终` 左闭右开，要求 `0 <= 始 <= 终 <= 长度`，不自动截断。方括号中省略始 / 终分别取 `0` / 长度；`[:]` 取全部
- 切片创建新阵，但里面的阵 / 对象仍共享引用，是**浅复制**。本版不支持切片赋值
- 阵的 `==` 检查是否同一实例；两个内容相同的新阵并不相等
- 参数 `列 为 阵` 接受混合阵；`列 为 数 阵` / `列 为 句 阵` 在调用时检查各元素。此注解不把阵变成不可变或永久限定元素类型的容器

原地排序及别名示例：`examples/array_sort.ru`。

### 句：Unicode 码点索引与切片

```text
文 取 '甲😀é乙'.
显 文 其 量.      # 4
显 文[1].         # 😀
显 文[1:3].       # 😀é
显 文[:1].        # 甲
显 文[3:].        # 乙
```

`句` 支持同样的 `量` / `位` / `段` 和方括号读操作，仍然不可变；给字符赋值或追加会报错。位置按照 **Unicode 码点**，不是 UTF-8 字节，也不是视觉字形：组合附加符号、emoji ZWJ 序列可能占多个位置。示例：`examples/unicode_slices.ru`。

### 形、对象、继承和方法

```text
形 计数器:
    值 为 数.
    作 增加 步 为 数:
        其 值 取 其 值+步.
    为
    算 报数:
        得 其 值.
    法
象
形 命名计数器 如 计数器:
    名 为 句.
    算 报数:
        得 其 值+1.
    法
象
甲 取 新 命名计数器 名:'计数' 值:2.
乙 取 甲.
乙 其 增加 3.
显 甲 其 报数.    # 6
```

- `形 名 [如 父形]: … 象` 声明对象类型；字段写作 `字段 为 类型.`，方法使用原有 `算 … 法` / `作 … 为` 语法
- `新 形名 字段名:值 …` 以命名字段初始化；实参按源码顺序求值，继承字段也可初始化。省略字段默认为 `空`，字段均允许 `空`；其他赋值必须符合声明类型
- `对象 其 字段` 读取；`对象 其 字段 取 值.` 修改。对象按引用传递，别名会看到修改
- `对象 其 方法 实参` 支持位置与命名调用；方法里 `其 字段` 简写当前对象字段，裸 `其` 返回自身。方法外使用自身会报错
- 子形继承字段与方法；覆盖方法必须保持参数名字、类型和算 / 作类别。继承方法内部调用其他方法仍按实际对象类型动态分派
- `如 父形` 的父形必须是直接声明或通过 `尽 取 外言` 导入的形名称，不能使用运行时形值别名；普通形值别名可用于 `新` 或重新绑定
- 父形参数接受子形实例；同名字段冲突、不兼容方法覆盖和继承循环报错。不支持多继承
- 原型解析器对标准成员名称有语法约束：`含`、`位`、`段`、`增` 不能作为字段名；同名方法须保持标准参数名 / 数量（`含 句`、`位 位`、`段 始 终`、`增 值`）。`囫`、`囵`、`量` 是零参成员；建议业务方法使用其他名称
- 对象的相等性是引用身份。构造器不隐式执行用户初始化方法

完整别名、继承、动态分派示例：`examples/objects.ru`。学生 / 上进学生、`名` / `龄` / `族`、`报道` 与班级数组示例：`examples/students.ru`。`助人`、`为乐` 不属于内置命令；`为乐` 可以作为普通函数或变量名，但需要自行定义。

### 外言：相对路径模块与标准库

```text
数学 取 外言 'modules/math.ru'.
显 数学 其 平方 9.

# 也可把导出名称导入当前模块，但名称冲突会明确报错
尽 取 外言 'modules/math.ru'.
显 (平方 4).
```

`外言` 后必须是字符串字面量。普通本地路径相对**写下该导入的文件**；`如:竞赛` 则解析到随工具链发布的标准库。以 `如:` 开头的名称保留给标准库，未知名称报错，不会退回当前目录寻找同名文件。相同规范化路径只初始化一次，返回同一模块实例。模块导出顶层作用域中的定义 / 绑定，函数保留所属模块的全局作用域；模块中的 `元初` 不会因为导入而自动执行。

标准成员名的语法约束也适用于限定访问：例如导出一个带参数的函数 `量` 后，`模块 其 量 参数` 不能作普通方法调用；可改用 `尽 取 外言` 后按原函数名调用，或为模块导出选择其他业务名称。

循环导入会报告错误，不暴露半初始化模块。`尽 取 外言` 只允许出现在模块顶层，不会悄悄覆盖同名定义。没有在线包管理或隐式下载；编译时静态解析并把模块一起编入输出，运行时不读取 `.ru` 源文件。

示例可从任意工作目录通过文件路径运行：

```sh
python3 ru run examples/modules/main.ru
python3 ru build examples/modules/main.ru -o bin/modules --emit-c dist/modules.c
./bin/modules
```

### 仍然保留的边界

数字仍是 IEEE-754 双精度；本次没有引入任意精度整数、位运算、自举或优化器；词法闭包已在 0.4 实现。0.3 的显式 `卒` 可由 `救` 处理；一般运行错误仍按原有方式报错。Python 解释器由 Python 的追踪式 GC 管理引用图；原生运行时使用根引用与追踪回收，能回收数组 / 对象之间的不可达循环。可用 `RU_GC_THRESHOLD=1 RU_GC_STATS=1 ./bin/objects` 压测频繁回收并查看退出统计；统计不是完整内存安全审计。不要把这个原型当作生产级执行沙箱。

## 0.3 文件、目录与可检查的 I/O

`件`、`录`、`件作成果` 是内置形；`读取`、`显出`、`错误` 分别是标准输入、标准输出、标准错误对象。它们使用已有 `其` / `@` 成员调用语法。`读`、`显` 便捷写法保持兼容。

```text
文档 取 新 件 路径: '笔记.txt'.
成果 取 文档 其 读.
若 成果 其 结果 == '成功' 则
    显 成果 其 值.
另
    显 成果 其 错误信息.
然

# 写会截断原文件；追加:1 才追加。请检查每次返回的成果。
写入 取 文档 其 写 内容: '你好\n'.
追加成果 取 文档 其 写 内容: '再会\n' 追加: 1.
存在 取 文档 其 在.
目录 取 新 录 路径: '.'.
清单 取 目录 其 列.
# 删除操作为 文档 其 除，只在确实需要时调用。
```

每次真实 I/O 返回 `件作成果`，具有三个成员：

- `结果`：`'成功'` 或 `'失败'`
- `值`：成功时的有效载荷；失败时为 `空`
- `错误信息`：成功时为空句，失败时为原因。错误文字可随操作系统变化，不应靠完整文字判断逻辑

`件作成果` 的字段可按普通对象规则修改；`值` 可持有任何如值。通常应直接检查操作返回的原始结果，而非改写其状态。

操作约定：

- `新 件` 默认 `路径:''`，`新 录` 默认 `路径:'.'`；构造只创建值，不接触文件系统。相对路径相对于进程工作目录
- 件的 `读` 一次读取完整 UTF-8 文本，空文件成功返回空句。暂不支持二进制、NUL、无效 UTF-8；文本保留原有换行
- 件的 `写 内容:句 追加:数` 默认 `追加:0`，截断 / 创建文件；`追加:1` 为追加，不自动添加换行。成功的 `值` 为 `空`
- 件的 `在` 成功返回数 `1` 或 `0`。路径指向普通文件为 `1`，不存在或指向目录等非普通文件为 `0`；权限等检查失败仍是失败成果
- 件的 `除` 删除该文件，成功返回 `空`；不存在或尝试删除目录返回失败
- 录的 `列` 非递归、按名称排序，返回由 `件` 组成的阵，各项 `其 路径` 可继续读取。只列普通文件，不列子目录
- 文件读、写、存在判断以及目录列举中的文件判断跟随符号链接；删除符号链接只删除链接本身。列举不是原子快照；已消失的项和悬空链接略过，其余扫描、检查或关闭错误返回失败，不把部分结果冒充成功
- 文件每次操作独立打开并关闭；读取、短写、刷新与关闭错误都要检查。写入失败可能已经改变文件的一部分，不提供事务、回滚、持久化 `fsync` 或原子替换保证
- 程序使用当前进程的文件权限；不会修改权限。I/O 接口不是访问沙箱；本轮原生 I/O 在 Linux / POSIX 上验证，Windows 原生分支未实测

标准流：

```text
循
    一行 取 读取 其 读.
    若 一行 其 结果 != '成功' 则
        卒 一行 其 错误信息.
    然
    若 一行 其 值 == 空 则 破. 然
    输出 取 显出 其 写 内容: (一行 其 值) + '\n'.
    若 输出 其 结果 != '成功' 则 卒 输出 其 错误信息. 然
环
```

`读取 其 读` 每次读取一行，去掉行尾 LF / CRLF；EOF 为成功且 `值 == 空`，空行为成功且 `值 == ''`。`显出 其 写 内容:句` / `错误 其 写 内容:句` 不加换行，返回前刷新，成功值为空；它们不关闭标准流。传统 `读` 仍在 EOF 报错，传统 `显` 仍输出一整行。

## 0.3 卒与恢复

```text
算 检查 值 为 数:
    若 值 < 0 则 卒 '值不能为负数'. 然
    得 值.
法

试
    显 (检查 (-1)).
救 原因
    显 '已处理：' + 原因.
终
显 '继续'.
```

- `卒 表达式.` 要求表达式为 `句`，将原因传到最近动态生效的 `试`，包括被调用函数、方法与模块内的 `卒`
- `试 … 救 原因 … 终` 必须带 `救` 和原因名称；正常路径跳过救的正文
- 试的正文与外部共用作用域；救的正文有子作用域。原因名称和救中 `取` 的本地绑定不会覆盖或泄露到外部；修改已有阵 / 对象的内容仍然共享
- 恢复后从 `终` 后继续，不恢复卒位置；救中再次卒向外层试传播，不被自己捕获。允许嵌套、函数返回与循环 `破`
- 没有匹配救时，命令以非零状态结束并在 stderr 报告原因和源位置；REPL 报告后继续接收下一段输入
- 已经完成的变量变更与 I/O 不会回滚。模块初始化卒后会保留其环境，使已经对外共享的对象仍可用；再次导入会重抛缓存的原始原因与位置，不自动重做初始化副作用。重新启动程序或 REPL `:reset` 才清空这项状态
- 普通 I/O 失败只是成果，需由程序决定是否卒；除零、类型错误、未定义名称等一般运行错误暂不属于救的捕获范围
- 新保留字为 `试`、`救`、`卒`；`终` 是上下文结束词，原有 `其 段 始:0 终:2` 保持可用。尚无 finally / 自动资源管理语法
- 原生后端显式传递 panic 并逐层清理临时根、局部环境与调用状态，仍输出独立 C99 程序

示例见 `examples/checked_io.ru`、`examples/recovery.ru`；`ru-lang-mode` 同步支持新块的高亮、缩进与跳转。

## REPL

变量、函数会跨提交保留。输入多行函数、条件、循环时，REPL 等待对应结束关键词；简单语句仍需句点。

```text
如> 算 平方 根 为 数:
… 得 根 * 根.
… 法
如> 平方 9.9.
98.01
如> 平方 根: 12.
144
```

单独的表达式在 REPL 会回显；文件模式丢弃表达式结果，应显式使用 `显`。`:reset` 清空变量 / 函数，`:help` 查看提示，`:退`、`:quit`、`:q`、`:exit` 退出。REPL 命令单独输入一行，不加句点；仅在没有待续源码时识别，字符串中的 `:退` 仍是普通文本。Ctrl-C 取消当前未结束的输入或执行。

提交发生运行错误时，会恢复提示符，但不会回滚之前已经执行的赋值或输入输出；这不是事务式 REPL。管道输入不显示提示符。`读` 使用同一个标准输入流，会消费下一行输入。

## 「如是我言」与 Responses 生成

`examples/wish.md` 示范自由 Markdown 文档；Org 或其他 UTF-8 文本也可使用。最后一个非空行必须单独写 `如是我言`，且不能位于如的字符串内部。前面的文本作为生成意图，不要求预先符合如语法。为避免把多行源码字符串误当文档，引号需成对；两侧紧邻 ASCII 字母的单引号按英文词内撇号处理（如 `Don't`）。ASCII 函数名后直接贴字符串起始引号可能有歧义，源码应在两者之间加空格。

仅显式执行 `ru generate` 会联网，将这份意图和当前语言规则发给配置的提供方。每次请求都会重新读取包内 [完整语言规范](rulang/language-spec.md)，明确要求按该规范生成，并把实际全文、规范版本和 SHA-256 放入模型上下文；不会仅发送私有仓库链接，也不依赖模型已经知道如。缺失、无效或版本不一致的规范会在联网前报错。`run`、`check`、`build` 与 REPL 遇到意图文档会提示先生成，始终不会代为联网。生成后也不会自动执行。

### 配置与间接密钥文件

默认读取 `~/.ru-lang.json`，可用 `RU_LANG_CONFIG` 指向另一份 JSON 文件：

```json
{
  "base-url": "https://open.bigmodel.cn/api/v1",
  "model": "glm-5.3-flash",
  "api-key": {"file": "~/.config/ru/api-key"}
}
```

请由使用者通过安全方式把凭据配置到仓库外的密钥文件；文件只包含密钥本身，可带末尾换行。不要将真实密钥写进 `.ru`、意图文档、提交记录、错误截图或公开聊天。此仓库不含可用凭据。

- `api-key` 普通字符串是字面密钥；以 `@file:` 开头则读取文件内容，例如 `"api-key": "@file:~/.config/ru/api-key"`
- `{"file":"路径"}` 也是文件引用，仅支持 `file` 一个成员。文件引用支持 `~`，相对路径以配置文件所在目录为基准
- JSON 也接受 `api_key` / `base_url` 别名，但同一字段不能同时写两种拼法
- 环境变量优先于 JSON：`RU_LLM_API_KEY`（始终为字面值）优先于 `RU_LLM_API_KEY_FILE`（始终为文件路径）；另有 `RU_LLM_BASE_URL`、`RU_LLM_MODEL`
- 环境的密钥文件相对路径也以配置文件目录为基准；`RU_LANG_CONFIG` 的相对路径以工作目录为基准
- 未配置提供方 / 模型时，当前默认是上例指定的 BigModel API 根地址和 `glm-5.3-flash`。密钥没有默认值，缺失时不联网

也可只配置环境变量：

```sh
export RU_LLM_BASE_URL='https://open.bigmodel.cn/api/v1'
export RU_LLM_MODEL='glm-5.3-flash'
export RU_LLM_API_KEY_FILE="$HOME/.config/ru/api-key"
python3 ru generate examples/wish.md -o examples/wish.generated.ru
```

`base-url` 是 API 根地址，不要附加 `/responses`；实现会请求 `POST /responses`。不自动改成 Chat Completions，不自动替换提供方地址或模型。普通远程地址必须 HTTPS，禁止含 URL 用户信息、查询参数或片段；重定向会停止，不会把认证头转发到另一地址。

### 保存、审阅与运行

```sh
python3 ru generate intent.md                  # 默认 intent.generated.ru
python3 ru generate intent.md -o draft.ru --timeout 120
# 直接保存编译后的 JavaScript；不会另存中间 .ru：
python3 ru generate intent.md --target js -o fresh.js
python3 ru check draft.ru
# 先阅读 draft.ru，确认其行为，再决定执行：
python3 ru run draft.ru
python3 ru build draft.ru -o bin/draft
python3 ru build draft.ru --target js -o dist/draft.js
node dist/draft.js
```

- 单次非流式 Responses 请求，无自动重试。默认超时 60 秒，可用 `--timeout` 设为大于 0、至多 300 秒；超时或取消后服务端可能已计费
- 不启用模型工具，忽略 reasoning 内容，只提取完成的 assistant 文本；工具调用、拒绝、错误、空输出、未完成 / 取消响应都不会执行或保存
- 接受纯源码，或恰好一段完整的 Markdown / Org 如代码围栏；混合说明、多段或残缺围栏拒绝
- 输出先通过 lexer / parser、结构及显式调用检查，包括已有本地外言依赖。不会执行源码或导入模块的顶层语句；这不是静态证明或安全审计
- 默认 `--target ru` 保存新的 `.ru`，默认 `原名.generated.ru`；`--target js` 保存新的 `.js` / `.cjs`，默认 `原名.generated.js`。父目录须已存在；输出、原文、符号链接和依赖都不能覆盖。完整内容验证并同步后原子发布，不自动创建目录
- JavaScript 目标仍只向模型索取如源码，再由本地编译器降为 JavaScript；不增加第二次模型请求、不调用 Node、不执行，也不保存中间 `.ru`。需要审阅和保留如源码时使用上面的两步生成 / 编译流程
- 外言相对最终输出路径所在目录解析；JavaScript 将已检查的静态依赖内联。编译失败不留下半份输出
- 响应上限 2 MiB，意图 / 生成源码上限 1 MiB；配置和密钥文件也有读取上限
- 不回显密钥、请求认证头、提供方原始错误正文或无效生成源码；发现意图、返回源码或输出路径含当前密钥也会拒绝处理
- 生成源码可能调用文件写入 / 删除等真实操作，必须先审阅；生成成功不代表程序正确或安全

提供方依据：[BigModel OpenAI 兼容说明](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)、[Responses 指南](https://docs.bigmodel.cn/cn/guide/develop/responses/introduction)、[GLM-5.3-Flash](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)。本实现不强制关闭该模型的 thinking。**协议模拟通过不等于真实 GLM 端点、账号权限或模型兼容性已验证**；本轮未使用真实提供方凭据，也未发出真实 GLM 请求。

两个编译后端把表达式和控制流直接翻译成 C 或 JavaScript 语句 / 函数；每个值的类型仍在运行时表示和检查，这是动态值模型，不是静态类型推断。集合、对象和模块使用统一的运行时值表示，赋值 / 调用 / 返回保留引用语义。

JavaScript 后端会保守扫描完整已解析的模块依赖图 AST：只有整图未引用相应内置名称 / 类型时，才省略受检查 I/O 或竞赛辅助运行时区段。经别名访问或外言依赖所需的区段仍保留，包括尚未执行的分支与函数。这是通用运行时裁剪，不做压缩混淆或针对某道题重写源码。

目前没有箭头函数、优化器、包管理或自举。`check` 不是完整静态类型分析：例如未绑定变量、数值转换、实际参数类型仍可能在运行时报错。编译过程检查整个程序，因此即使某个分支不执行，其中无效的显式函数调用也会阻止编译。
